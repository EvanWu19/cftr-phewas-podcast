Ep2 (Track B — AI tooling): MedCP — an agentic LLM connected to an OMOP EHR and a biomedical knowledge graph

Bellucci and colleagues (Frontiers in Artificial Intelligence, 2026) build MedCP, an open-source (MIT license) Model Context Protocol server that lets a language model query, within a single agentic workflow, a de-identified OMOP-standardized electronic health record database (>6 million patients, UCSF) and SPOKE, a curated biomedical knowledge graph (~45 million nodes, ~133 million edges). Read-only access is enforced three times — at the prompt, the connector, and the database account level — and every query the LLM generates is preserved for audit. Across a 100-question clinical benchmark, knowledge-graph access improved mean scores for both GPT-5.5 and Claude Opus 4.8; on a 617-question gene-disease factual-accuracy benchmark (BiomixQA), grounding in SPOKE cut errors by 35.6% to 60.5%. A five-phase "clinical-replication" skill reproduced a UCSF-internal multiple-sclerosis safety study directionally, but was underpowered on an external GLP-1-versus-dementia replication. The buildable artifact is a minimal Registry MCP Query Harness — a read-only, audited natural-language query layer over a registry's own OMOP-mapped tables, modeled on MedCP's three-layer defense, that returns the exact SQL behind every answer.

Plain-English glossary

  • Model Context Protocol (MCP) — An open standard for connecting an AI model to external tools and data through a uniform interface, often compared to USB-C for AI applications.（中文：一个让AI模型通过统一接口连接外部工具和数据的开放标准，常被比作AI应用的USB-C接口。）
  • Knowledge graph (nodes and edges) — A data structure where entities (genes, drugs, diseases) are nodes and documented relationships between them are edges, allowing traversal across relationship types rather than fixed table joins.（中文：一种数据结构，实体（基因、药物、疾病）是节点，它们之间有文献记录的关系是边，允许沿不同关系类型遍历，而不是依赖固定的表连接。）
  • SPOKE — A large biomedical knowledge graph assembled from dozens of expert-curated sources (ChEMBL, GWAS Catalog, MeSH, Reactome, etc.), used here to ground an LLM's EHR-derived findings in documented molecular biology.（中文：一个由数十个专家整理的来源（ChEMBL、GWAS目录、MeSH、Reactome等）构建的大型生物医学知识图谱，这里用来让LLM从EHR得出的发现扎根于有文献记录的分子生物学。）
  • OMOP Common Data Model (OMOP CDM) — A standardized table structure and vocabulary layer (SNOMED CT for diagnoses, RxNorm for medications, LOINC for labs) that different source EHR systems can be mapped into, so the same analytic query can run across institutions.（中文：一套标准化的表结构和词汇层（诊断用SNOMED CT，用药用RxNorm，检验用LOINC），不同来源的EHR系统可以映射到其中，使同一个分析查询能够在不同机构间运行。）
  • Cipher — Neo4j's own query language for traversing a graph database, the graph-world analog of SQL for relational tables.（中文：Neo4j图数据库自带的查询语言，用于遍历图数据库，相当于图谱世界里关系型数据库的SQL。）
  • Agentic AI / ReAct — An LLM usage pattern where the model interleaves reasoning with external tool calls — planning, querying, refining — across multiple steps, rather than returning one response to one prompt.（中文：一种LLM使用模式，模型在多个步骤中把推理和外部工具调用交织在一起——规划、查询、迭代改进——而不是针对一个提示只给出一次性回答。）
  • Retrieval-augmented generation (RAG) — An approach that grounds an LLM by fetching relevant external text at inference time, typically via vector databases and embeddings that require tuning and periodic re-indexing.（中文：一种让LLM扎根于外部知识的方法，在推理时检索相关外部文本，通常依赖需要调优并定期重新索引的向量数据库和嵌入。）

Full citation

Bellucci G, et al. "An agentic AI framework connecting language models to electronic health records and a biomedical knowledge graph for real-world evidence." Frontiers in Artificial Intelligence. 2026. PMID: 42761240 | PMCID: PMC13585945 | DOI: 10.3389/frai.2026.1883853

Methods / tools to lift

  • Three-layer read-only enforcement — prompt-level instruction, connector-level query scanning for write operations, and database-account-level read-only roles, stacked so any one layer's failure is caught by the next.
  • MCP server pattern over a structured database — expose a small number of schema-aware, audited tools (query execution, schema discovery) rather than a general-purpose SQL/Cipher passthrough.
  • Five-phase study-replication protocol — study deconstruction, OMOP concept mapping via concept_ancestor hierarchies, adaptive cohort extraction, statistical replication, and side-by-side validation reporting.
  • Permutation-based negative controls — testing a cross-source correlation (EHR co-occurrence vs. knowledge-graph similarity) against degree- and size-preserving randomized graphs to rule out structural artifacts.

Where it lands + buildable artifact

Lands on AI-tooling / career (not Karen/Liz/colocalization) — a query-and-evidence-generation framework, not a variant classifier or outlier detector. Buildable artifact — Registry MCP Query Harness: a minimal MCP server exposing one or two audited, read-only tools over a registry's own OMOP-mapped tables (if and when such a mapping exists), built on MedCP's three-layer read-only enforcement, returning the exact query behind every natural-language answer. MVP: a schema-aware tool definition plus read-only credentials in, a structured result table plus its literal query out. Difficulty: M (medium).

What to verify first

  • Whether the registry's own data already sits in an OMOP-mapped form, or would require a separate mapping effort first — an open question this framework does not answer for any particular registry.
  • What LLM-hosting and data-governance constraints would actually apply, given MedCP's own deployment routed all model traffic through an institutional, BAA-covered gateway so no prompt or tool-call traffic left the institutional network.
  • How to mitigate the query-correctness gap this episode flagged — concept-set validation, temporal-cohort templates, and denominator checks, all recommended in the paper's own discussion, none of them optional for anything beyond exploratory use.

JORDAN Before the mechanics — what is SPOKE, concretely, and what's the difference between a knowledge graph's "nodes and edges" and the kind of relational database I already think in? 在讲机制之前——SPOKE具体是什么？知识图谱里的"节点"和"边"，和我已经很熟悉的关系型数据库思维方式有什么区别？

ALEX SPOKE (Scalable Precision Medicine Open Knowledge Engine, 一个整合了数十个专家维护来源的生物医学知识图谱) is a Neo4j-backed knowledge graph where every biomedical entity — a gene, a drug, a disease, a pathway — is a node, and every documented relationship between two entities — "gene encodes protein," "drug treats disease" — is an edge, each one tagged with which curated source it came from. SPOKE（Scalable Precision Medicine Open Knowledge Engine，一个整合了数十个专家维护来源的生物医学知识图谱）是一个基于Neo4j构建的知识图谱，其中每一个生物医学实体——基因、药物、疾病、通路——都是一个节点（node），而两个实体之间每一条有文献记录的关系——"基因编码蛋白质""药物治疗疾病"——都是一条边（edge），每条边都标注了它来自哪个经过整理的来源。 The snapshot used here holds roughly 44.7 million nodes and 132.7 million edges, assembled from dozens of sources including ChEMBL, the GWAS Catalog, MeSH, and Reactome. 这里使用的快照大约包含4,470万个节点和1.327亿条边，整合自数十个来源，包括ChEMBL、GWAS目录（GWAS Catalog）、MeSH和Reactome。 Where a relational table forces you to pre-decide which joins matter, a graph lets you traverse outward from any node through whichever relationship types are relevant to the question, which is why "find diseases biologically related to X" is a natural graph query but an awkward relational one. 关系型表格要求你提前决定哪些连接（join）是重要的，而图谱则允许你从任意一个节点出发，沿着与问题相关的任意关系类型向外遍历，这就是为什么"找出与X生物学上相关的疾病"这类查询，用图谱做起来很自然，用关系型数据库做就会显得笨拙。 MedCP's EHR side runs on OMOP (Observational Medical Outcomes Partnership Common Data Model, 一种将不同医院的电子健康记录统一成同一张标准化表结构的通用数据模型), which standardizes diagnoses, medications, and labs from different source systems into one common vocabulary layer — SNOMED CT for diagnoses, RxNorm for medications, LOINC for lab tests — so the same question can in principle be asked the same way across different institutions' data. MedCP的EHR端运行在OMOP（Observational Medical Outcomes Partnership通用数据模型，一种把不同医院的电子健康记录统一成同一套标准化表结构的通用数据模型）之上，它把来自不同源系统的诊断、用药和检验结果统一到同一套词汇层——诊断用SNOMED CT、用药用RxNorm、检验用LOINC——这样同一个问题原则上可以在不同机构的数据上用同样的方式提出。 Cipher is simply Neo4j's own query language for traversing a graph, the graph-world analog of SQL for relational tables. Cipher只是Neo4j自己用来遍历图谱的查询语言，是图谱世界里对应关系型表格SQL的那个角色。

ALEX The motivating gap is blunt: accessing large clinical and biomedical databases requires query-language fluency most clinicians and even many researchers don't have, and the paper cites an 一个让AI应用以统一接口连接外部工具和数据的开放标准), introduced as a standardized way to connect an AI model to external tools and data — often compared to USB-C for AI applications — had been discussed conceptually for clinical medicine, and separate pilot work had used MCP to query FHIR records or evaluated an LLM connected to a single hospital EHR, but nothing had yet combined institutional-scale EHR access with a MedCP明确提出的目标，是降低真实世界证据生成的技术门槛，同时让每一步都可审计、处于专家监督之下——它不是要取代研究者的判断，而是要压缩从一个临床问题到一个结构化、可追溯答案之间的距离。

JORDAN What's actually in the repository, architecturally — walk me through what MedCP built. 从架构上看，代码仓库里到底有什么——带我过一下MedCP具体构建了什么。

ALEX MedCP is an MCP server exposing a small set of audited, read-only tools — query_clinical_records for SQL against the OMOP database, query_knowledge_graph for Cipher against SPOKE, plus schema-discovery helpers — and read-only enforcement is layered three times: the system prompt instructs the LLM to generate only read queries, the MedCP connector itself scans every query and rejects anything containing write operations (MERGE, CREATE, SET, DELETE for Cipher; INSERT, UPDATE, DELETE, DROP, ALTER, EXEC for SQL), and the underlying database service accounts are registered with read-only roles regardless of what gets past the first two layers. MedCP是一个MCP服务器，暴露出一小组经过审计、只读的工具——query_clinical_records用于对OMOP数据库执行SQL查询，query_knowledge_graph用于对SPOKE执行Cipher查询，再加上几个模式发现（schema discovery）辅助工具——而只读强制措施分了三层：系统提示（system prompt）指示LLM只生成只读查询，MedCP连接器本身会扫描每一条查询并拒绝任何包含写操作的语句（Cipher里的MERGE、CREATE、SET、DELETE；SQL里的INSERT、UPDATE、DELETE、DROP、ALTER、EXEC），而底层数据库的服务账户本身就被注册为只读角色，不管前两层是否被绕过，这一层都生效。 Everything runs locally within the health system network, with configuration, credentials, and execution logs stored on the user's own machine, and only de-identified or aggregate results ever leave the underlying systems. 所有运行都在医疗系统网络内部本地完成，配置、凭证和执行日志都保存在用户自己的机器上，只有去标识化或汇总后的结果才会离开底层系统。 They benchmarked GPT-5.5 and Claude Opus 4.8 across 100 hand-drafted clinical questions spanning 10 complexity tiers, with and without knowledge-graph access, plus a 617-question gene-disease factual-accuracy benchmark called BiomixQA, and then built a reusable "clinical-replication" skill — a five-phase protocol (study deconstruction, OMOP concept mapping, cohort extraction, statistical replication, validation reporting) for replicating published observational studies end to end. 他们在覆盖10个复杂度层级的100道手工撰写的临床问题上，分别测试了有无知识图谱访问权限时的GPT-5.5和Claude Opus 4.8，再加上一个名为BiomixQA的617题基因-疾病事实准确性基准测试，并进一步构建了一个可复用的"clinical-replication"技能——一个五阶段协议（研究拆解、OMOP概念映射、队列提取、统计复现、验证报告），用于端到端地复现已发表的观察性研究。

ALEX Here's my pushback on the design, though — all three read-only layers check whether a query is a write operation, but none of them check whether a syntactically valid read query is actually correct, and the paper's own failure analysis found exactly that: submaximal runs clustered around things like missing washout periods and denominator errors, which are perfectly legal SQL that quietly produces a wrong answer. 不过我对这个设计有一点不同看法——这三层只读防护，检查的都是"这是不是一个写操作"，但没有一层检查"一条语法合法的读查询，是否真的查对了"，而论文自己的失败分析恰恰印证了这一点：表现不佳的运行，往往集中在诸如缺失洗脱期（washout period）、分母计算错误这类问题上——这些都是完全合法的SQL，却悄无声息地产生了错误的答案。 Hallucination-style failures and query-correctness failures are a different risk category, and the three-layer defense here is really solid against the first but doesn't touch the second at all. 幻觉式错误和查询正确性错误，属于两种不同性质的风险，这里的三层防御对第一种确实很扎实，但对第二种完全没有触及。

JORDAN Did it actually deliver on the stated aim — did knowledge-graph access make the agent better, and did the replication framework actually hold up? 它在既定目标上真的做到了吗——知识图谱访问权限真的让代理表现更好了吗？复现框架真的站得住脚吗？

ALEX On the 100-question benchmark, knowledge-graph access raised the mean score for both models — GPT-5.5 from 1.05 to 1.27 (odds ratio 1.78, p = 0.0029) and Claude Opus 4.8 from 0.84 to 1.02 (OR 1.50, p = 0.013) — though the tier-specific pattern differed between the two models rather than showing a clean "harder questions benefit more" trend. 在100道问题的基准测试中，知识图谱访问权限提升了两个模型的平均得分——GPT-5.5从1.05提升到1.27（比值比，odds ratio，OR为1.78，p=0.0029），Claude Opus 4.8从0.84提升到1.02（OR为1.50，p=0.013）——不过两个模型在不同复杂度层级上的表现模式并不一致，并没有呈现出一个干净的"题目越难、获益越大"的趋势。 On BiomixQA, grounding in SPOKE lifted multiple-choice gene-disease accuracy from 0.807 to 0.876 for Opus 4.8 and from 0.752 to 0.902 for GPT-5.5, a 35.6% and 60.5% relative reduction in errors respectively, with a worked example showing the graph correcting both models away from a plausible-sounding but wrong gene (RBFOX1, chosen from parametric memory) toward the graph-verified answer (ADGRV1). 在BiomixQA上，接入SPOKE让Opus 4.8的多选题基因-疾病准确率从0.807提升到0.876，GPT-5.5从0.752提升到0.902，分别对应62%和79%的相对错误率下降，其中一个具体案例显示，知识图谱把两个模型都从一个"听起来合理但错误"的基因（仅凭参数化记忆选出的RBFOX1）纠正到了经图谱验证的正确答案（ADGRV1）。 The disease co-occurrence case study found that clinical co-occurrence patterns extracted from over three million EHR subjects correlated with SPOKE-derived molecular similarity between disease pairs (Spearman ρ = 0.58, p < 0.0001), robust to permutation-based negative controls. 疾病共现（disease co-occurrence）案例研究发现，从三百多万名EHR受试者中提取出的临床共现模式，与SPOKE推导出的疾病对之间的分子相似性存在相关性（斯皮尔曼相关系数ρ=0.58，p<0.0001），并且在基于置换检验的阴性对照下依然稳健。 The replication framework held up directionally on an internal multiple-sclerosis safety study (hazard ratio 1.94 versus the original 2.27) but was clearly underpowered on an external GLP-1-versus-dementia replication, recovering only 3.2% of the original study's sample size — so the framework executed the full pipeline correctly, but a correct pipeline on a much smaller cohort is still a much weaker answer. 复现框架在一项内部的多发性硬化安全性研究上，方向上得到了印证（风险比HR为1.94，对照原始研究的2.27），但在一项外部的GLP-1受体激动剂与痴呆风险复现研究上，明显样本量不足，只恢复了原始研究样本量的3.2%——也就是说，框架正确地执行了完整流程，但在一个规模小得多的队列上执行一个正确的流程，得到的仍然是一个弱得多的答案。

JORDAN How does this compare to the existing OHDSI analytic ecosystem that OMOP users already rely on — doesn't something like ATLAS already cover cohort definition? 这和OMOP用户本来就在用的OHDSI分析生态系统相比怎么样——像ATLAS这样的工具不是已经覆盖了队列定义（cohort definition）这部分了吗？

ALEX ATLAS and CIRCE are the OHDSI community's standard tools for defining cohorts programmatically and deterministically, and the HADES package suite covers population-level estimation and prediction — all of that remains the validated, reproducible backbone for observational analysis on OMOP data, and the paper is explicit that MedCP is meant to complement rather than replace it.
