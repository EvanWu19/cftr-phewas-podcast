Track B — Enhancing semantic interoperability in precision medicine: converting OMOP CDM to Beacon v2 in the Spanish IMPaCT-Data project

Note on sourcing: this paper is not open access (OA=N, no PMCID in our index). Europe PMC and PubMed MCP full-text routes were unavailable; this episode is sourced from the abstract only.

Blurb

Rueda and colleagues (BMC Medical Informatics and Decision Making, 2026) built a bridge between two data worlds that don't natively speak to each other: OMOP CDM, the standard for clinical/phenotypic data, and GA4GH Beacon v2, the standard for federated genomic-variant queries. Their tool, Convert-Pheno, offers two architectures — a simple, auditable file-based batch conversion, and a real-time "on-the-fly" architecture connecting a live PostgreSQL-based OMOP CDM instance directly to the Beacon v2 API. Applied across three Spanish research centers (CNAG, IIS La Fe, Hospital del Mar) as part of the national IMPaCT-Data precision-medicine program, the conversion held ≥99.9% data completeness across most domains — a strong structural-completeness result, though the abstract doesn't speak to semantic-mapping correctness underneath it. This is squarely an AI-tooling/career-track episode: the transferable pattern is a general one — build a small, auditable converter from your own data model into a widely adopted external standard so it can, in principle, be queried without exposing row-level data. Buildable artifact: registry-beacon-bridge.

Plain-English glossary

  • GA4GH (Global Alliance for Genomics and Health) — an international body that sets interoperability standards so genomic data infrastructure across countries and institutions can work together.（中文:一个国际组织,制定互操作性标准,让不同国家和机构的基因组数据基础设施能够协同工作。）
  • Beacon / Beacon v2 — a federated query protocol: you ask a Beacon "does any sample carry variant X" and get yes/no/count back, without row-level data ever leaving the source institution; v2 extends this toward broader phenotypic/clinical queries.（中文:一种联邦式查询协议:向Beacon询问"是否有样本携带变异X",得到是/否/计数的回答,而逐行数据从不离开源机构;v2版本将其扩展到更广泛的表型/临床查询。）
  • OMOP CDM (Observational Medical Outcomes Partnership Common Data Model) — a standardized schema letting clinical data from different institutions be queried the same way.（中文:一种标准化数据模式,让来自不同机构的临床数据能用同样的方式被查询。）
  • Structural vs. semantic completeness — structural completeness means a data field exists and is populated; semantic completeness/correctness means the underlying concept was mapped to the right meaning — a high structural-completeness number does not by itself guarantee correct mapping.（中文:结构完整度指字段存在且已填充;语义完整度/正确性指底层概念被映射到了正确的含义——高结构完整度本身并不能保证映射正确。）
  • Convert-Pheno — the paper's tool for transforming OMOP CDM exports into GA4GH Beacon v2 format.（中文:本文提出的工具,用于将OMOP CDM导出数据转换为GA4GH Beacon v2格式。）

Methods / tools to lift

  • Convert-Pheno — OMOP CDM → GA4GH Beacon v2 format converter.
  • File-based batch conversion architecture — simple, auditable, but introduces staleness between export runs.
  • On-the-fly architecture — direct PostgreSQL-based OMOP CDM-to-Beacon v2 API connection for real-time queries, trading staleness for a larger operational/security surface.

Where it lands + buildable artifact

Buildable: registry-beacon-bridge (M) — take a de-identified, OMOP-mapped registry export and write a converter into GA4GH Beacon v2's schema, starting with the file-based batch approach (simpler to audit, no production-database access needed); validate structural completeness first, then hand-audit a sample of semantic mappings against source OMOP concepts. Chains downstream of the previously sketched registry-vocab-harmonizer and phenotype-definition tooling: harmonize → define → expose.

What to verify first

  • Abstract-only limitation: no methods section, so exact field-level mapping logic, validation beyond the completeness metric, and edge-case handling (multi-valued/missing OMOP concepts) are unknown.
  • GA4GH Beacon's privacy model needs deeper review before considering any real linkage — federated presence/absence queries carry known re-identification risks with rare variants in small cohorts.
  • Nothing in this paper describes how any specific registry's genotype data is structured internally.
