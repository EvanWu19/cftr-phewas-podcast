Ep4 — Evaluating Foundational Data Quality in PCORnet (Qualls et al., 2018)

Track C — registry data quality — second of today's two Track C episodes.

Blurb

PCORnet is one of the first distributed research networks to pull electronic health record data from multiple domains at a national scale, spanning 13 clinical data research networks, 20 patient-powered research networks, and 2 health plan research networks. This paper, from the PCORnet Coordinating Center (Duke Clinical Research Institute, Genetic Alliance, Harvard Pilgrim Healthcare Institute), describes "data curation" — a recurring, five-step process for checking foundational data quality (model conformance, completeness, plausibility) across every data partner's DataMart before any research query is run on it. It's not a flagging algorithm; it's the operational machinery for running checks, documenting findings, and routing them back to the people at each site who can fix them, then tracking whether the fix actually happened. It pairs most naturally with the ~0.05% human-review slice of a registry QC pipeline — the part where a flagged record has to land in front of the right person. The buildable artifact is a Site Exception Digest: a periodic, per-care-center report of flagged records modeled on PCORnet's Empirical Data Characterization Report, routing review out to sites instead of concentrating it on one central adjudicator.

Glossary

  • CDM (common data model) — A standardized schema that every data partner maps its local data into, so the same query runs identically everywhere.（中文：通用数据模型，所有数据合作方都将本地数据映射为相同结构，以便同一查询可在各处一致运行。）
  • Coordinating Center — The entity (here, jointly Duke Clinical Research Institute, Genetic Alliance, and Harvard Pilgrim Healthcare Institute) responsible for running network-wide data quality assessment and aggregating results across data partners.（中文：负责在整个网络范围内运行数据质量评估并汇总各数据合作方结果的机构。）
  • data curation — PCORnet's term for its recurring process of querying, documenting, and communicating with network partners to assess "fitness-for-use" of their data before research use.（中文：PCORnet 用于描述其周期性查询、记录并与网络合作方沟通，以评估数据"适用性"的流程的术语。）
  • data partner — An institution (hospital, clinic, health plan, etc.) that contributes data to the network and maintains its own local DataMart.（中文：向网络贡献数据并维护自己本地 DataMart 的机构，如医院、诊所或健康计划。）
  • DataMart — A data partner's local instance of the common data model.（中文：数据合作方本地的通用数据模型实例。）
  • distributed query model — The design where patient-level data stays at each site; only a standardized query is sent out, run locally, and the aggregated results are returned to the requestor.（中文：分布式查询模型——患者层面数据始终留在各站点，只有标准化查询被发出、在本地运行，汇总结果才返回给请求方。）
  • EDC report (Empirical Data Characterization Report) — The Coordinating Center's summary report, sent to each data partner, that displays the data quality measures and highlights exceptions.（中文：协调中心发给每个数据合作方的摘要报告，展示数据质量指标并突出显示异常项。）
  • foundational data quality — Checks that apply broadly across nearly any study (conformance, completeness, plausibility), as distinct from study-specific checks tailored to one research question.（中文：几乎适用于任何研究的通用性检查——符合性、完整性、合理性——区别于针对某一研究问题定制的专项检查。）
  • Kahn DQA framework — The data quality assessment framework (conformance / completeness / plausibility) this paper's checks are organized under, the same framework ep3's taxonomy paper mapped its checks onto.（中文：数据质量评估框架，将检查分为符合性、完整性、合理性三类，也是 ep3 分类论文所使用的框架。）
  • mitigation plan — Documentation created when an analyst and data partner identify an opportunity for improvement, specifying whether and when it will be fixed.（中文：当分析师与数据合作方发现改进机会时创建的文档，说明是否以及何时修复。）
  • OMOP — A different common data model (used by networks such as OHDSI) than PCORnet's own CDM; same concept, different schema — mentioned here only for contrast.（中文：另一种通用数据模型，被 OHDSI 等网络使用，与 PCORnet 自己的 CDM 概念相同但模式不同，这里仅作对比提及。）
  • PCORnet — The National Patient-Centered Clinical Research Network, a "network of networks" funded by PCORI, combining clinical data research networks, patient-powered research networks, and health plan research networks.（中文：美国国家患者为中心临床研究网络，由 PCORI 资助的"网络的网络"，整合临床数据研究网络、患者驱动研究网络和健康计划研究网络。）

Citation

PMID: 29881761, PMC5983028, DOI

Methods / tools to lift

  • Five-step recurring curation cycle: diagnostic query (table-level CDM conformance) → data dictionary + data characterization query → Empirical Data Characterization Report → analyst review → partner discussion and mitigation plan.
  • Classifying checks as "required" (must be fixed, e.g. conformance errors) vs. "investigative" (permissible but must be explained/classified as remediable or a source-data limitation) to prioritize review effort.
  • Self-contained analysis packages data partners can run themselves, rather than central-team-only tooling, to improve turnaround.
  • REDCap-based data dictionaries to standardize provenance/implementation documentation across partners.
  • Replacing resource-intensive one-on-one calls with recorded, network-wide discussion forums for common issues and mitigation strategies.
  • Summarizing exceptions at the top of the report to speed review triage.

Where it lands + buildable artifact

Primary pipeline stage: (c) human review budget — this paper is fundamentally about routing findings back to people and tracking resolution, which maps onto shrinking/structuring the human-eyeball-review slice of a QC pipeline. Secondary: (e) vocabulary/framework — the conformance/completeness/plausibility split and required-vs-investigative check classification are reusable even outside PCORnet's own process.

Buildable artifact — Site Exception Digest (difficulty: M). Input: flagged height/weight records plus a CF care-center identifier. Output: a short periodic per-care-center report (flag counts, trend chart, a few representative examples) modeled on PCORnet's Empirical Data Characterization Report, routing review to sites instead of concentrating it on one central adjudicator.

What to verify first

  • Whether CFFPR already routes flagged records back to individual care centers in any form, or whether that plumbing would be new.
  • Whether care centers would have the bandwidth or incentive to review a periodic digest (PCORnet partners had a data sharing agreement and PCORI requirements driving engagement).
  • What review cadence would fit CFFPR's own data refresh cycle (PCORnet moved from semi-annual to quarterly curation, but CFFPR's cadence is unknown here).
  • Whether a site-level digest could mask individual-record errors that don't cluster by site (e.g., a single transposed digit).

Pipeline stage

(c) human review budget — primary. (e) vocabulary/framework — secondary.

Error types covered / not covered

  • Covered (process-level, not algorithmic): data model conformance errors (values outside spec, bad source mapping, referential integrity problems), implausible aggregate values (e.g., implausible height/weight/blood pressure at the DataMart/population level), missing/incomplete key fields, misclassification of codes (e.g., ICD-9 vs ICD-10), duplicate records.
  • Not covered: no individual-record statistical flagging method; no thresholds or model for distinguishing a single data-entry error from a real clinical event; no unit-conversion-specific check, digit-transposition-specific check, decimal-shift-specific check, or carry-forward-specific check described in the text; no sensitivity/specificity/PPV evaluation against a gold standard — this is an operational/process report, not a validated detection method.
