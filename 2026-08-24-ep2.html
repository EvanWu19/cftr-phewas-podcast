Blurb

MHCquant2, published in Genome Biology (2025), is a modular Nextflow/nf-core pipeline for immunopeptidomics -- identifying which peptides a tumor or tissue sample is actually displaying on its HLA molecules, via mass spectrometry, for cancer immunotherapy target discovery. Nothing about the biology maps onto CF; this episode reads it purely for the engineering pattern. MHCquant2 orchestrates established tools (Comet, Percolator, OpenMS FeatureFinder) and adds MS2Rescore-integrated peptide-property predictors (DeepLC for retention time, MS2PIP for fragment intensity) as extra scoring features, improving low-abundance peptide identification by up to 27% over its predecessor and outperforming FragPipe and PEAKS on a new timsTOF benchmark. The transferable lesson is architectural: separate core pipeline logic from a swappable scoring layer, version-release on GitHub, and lean on nf-core's shared testing/containerization infrastructure. Buildable artifact: refactor one existing internal script's I/O boundary and one step into an nf-core-style module (main.nf process + versioned container + a CI test profile) without attempting a full pipeline rewrite.

Plain-English glossary

  • HLA (human leukocyte antigen) -- the surface molecule that displays short peptide fragments from a cell's own proteins, allowing T cells to scan for foreign or abnormal content.（中文：细胞表面展示自身蛋白短肽片段的分子，供T细胞扫描识别外来或异常内容。）
  • immunopeptidomics -- the mass-spectrometry-based discipline of directly measuring which peptides are physically presented on a sample's HLA molecules, as opposed to predicting binding from sequence alone.（中文：通过质谱直接测定样本HLA分子上实际展示哪些肽段的学科，区别于仅凭序列预测结合能力。）
  • neoantigen -- a peptide derived from a tumor-specific mutated protein sequence, absent from normal tissue; an ideal immunotherapy target with low off-tumor risk.（中文：源自肿瘤特异性突变蛋白序列、正常组织中不存在的肽段；理想的免疫治疗靶点，脱靶风险低。）
  • tumor-associated antigen (TAA) -- a peptide from a normal, unmutated protein that is over- or abnormally expressed in tumor vs. healthy tissue; useful but carries more off-tumor toxicity risk.（中文：来自正常未突变蛋白、但在肿瘤中过度或异常表达的肽段；有用但脱靶毒性风险更大。）
  • Nextflow / nf-core -- Nextflow is a workflow-orchestration language for portable, parallelizable pipelines; nf-core is a community framework of curated, standardized Nextflow pipelines sharing testing, documentation, and containerization infrastructure.（中文：Nextflow是用于构建可移植、可并行化流程的编排语言；nf-core是共享测试、文档与容器化基础设施的社区标准化Nextflow流程框架。）
  • false-discovery rate (FDR) threshold in proteomics search -- the statistical cutoff (here 1%) controlling what fraction of accepted peptide identifications are expected to be false positives; achieved via Percolator rescoring in this pipeline.（中文：控制被接受的肽段鉴定结果中预期假阳性比例的统计阈值（本文为1%），本流程通过Percolator重打分实现。）
  • peptide-property predictor (DeepLC, MS2PIP) -- machine-learning models predicting a peptide's expected chromatographic retention time (DeepLC) or fragment-ion intensity pattern (MS2PIP), used as extra features to separate true identifications from noise.（中文：预测肽段预期色谱保留时间（DeepLC）或碎片离子强度谱（MS2PIP）的机器学习模型，作为区分真实鉴定与噪声的额外特征使用。）

Methods / tools to lift

  • nf-core module architecture -- separating a pipeline's core search/quantification backbone from a swappable scoring-feature layer, packaged as a numbered GitHub release.
  • MS2Rescore integration pattern -- plugging external peptide-property predictors (DeepLC, MS2PIP) into an existing rescoring step (Percolator) as additional features rather than replacing the core search engine.
  • Benign reference dataset construction -- building a matched non-diseased benchmark (benignMHCquant2, n=92) specifically to distinguish tumor-associated antigens from neoantigens.

What to verify first

  • Sensitivity gains from peptide-property predictors here are benchmarked on benign tissue immunopeptidomics data -- whether an analogous "add a property predictor" trick generalizes to a different data type (e.g. variant-calling confidence scoring) would need separate validation.
  • nf-core integration carries real maintenance overhead (CI, containerization, module conventions) -- worth scoping against the size of whatever internal tool is refactored first.

JORDAN Let's define the domain first. What is immunopeptidomics, and why does it need its own specialized pipeline? 我们先把领域背景讲清楚。什么是免疫肽组学，为什么它需要专门的分析流程？

ALEX Every cell in your body constantly chops up a sample of its own proteins and displays fragments -- short peptides -- on its surface, docked onto molecules called HLA, human leukocyte antigen. 人体内每一个细胞都在持续地将自身的一部分蛋白质切割成短肽段，并展示在细胞表面，这些短肽段被装载在一种叫做HLA（人类白细胞抗原，human leukocyte antigen）的分子上。 T cells constantly scan those displayed peptides, and if one looks foreign or abnormal -- say, derived from a mutated cancer protein -- the T cell can trigger an immune attack on that cell. T细胞会持续扫描这些被展示出来的肽段，如果某个肽段看起来是异常的或"外来的"——比如来自一个突变的癌症蛋白——T细胞就可能针对这个细胞发起免疫攻击。 Immunopeptidomics is the experimental discipline of directly measuring, via mass spectrometry, exactly which peptides a given cell or tumor sample is displaying on its HLA molecules -- as opposed to just predicting which peptides should bind HLA from sequence alone. 免疫肽组学是通过质谱（mass spectrometry）直接测定某个细胞或肿瘤样本HLA分子上究竟展示了哪些肽段的实验学科——而不仅仅是根据序列信息去预测哪些肽段"应该"能结合HLA。 That distinction matters for cancer immunotherapy: a tumor-specific or tumor-associated antigen is only useful as a vaccine or T-cell target if it's actually, physically presented on the cell surface, not just theoretically capable of binding. 这一区别对癌症免疫治疗至关重要：一个肿瘤特异性或肿瘤相关抗原，只有在它真正、实际地被展示在细胞表面时，才能作为疫苗或T细胞靶点使用，而不仅仅是理论上具备结合能力。

JORDAN And what makes this a hard computational problem, not just a wet-lab one? 那这为什么会是一个困难的计算问题，而不仅仅是湿实验室的问题？

ALEX Compared to standard proteomics, where you digest proteins into predictable tryptic fragments, HLA-presented peptides are naturally variable in length, present at very low abundance -- a given peptide might be copies in the single digits per cell -- and there's no enzyme step to make the search space predictable. 与标准蛋白质组学不同，标准方法中蛋白质会被酶切成长度可预测的胰蛋白酶片段，而HLA展示的肽段天然长度不一，丰度极低——某个特定肽段在单个细胞中可能只有个位数拷贝——而且没有酶切步骤能让搜索空间变得可预测。 That makes identifying them from mass spectrometry data a much harder search-and-scoring problem, and it's compounded by newer, more sensitive instruments -- like the timsTOF platform used here, which adds an ion-mobility separation dimension -- generating more complex data that existing pipelines weren't tuned for. 这使得从质谱数据中识别这些肽段成为一个远比常规蛋白质组学更困难的搜索与打分问题，而更新、更灵敏的仪器——比如本文所用的timsTOF平台，它增加了离子淌度分离这一维度——又让数据变得更复杂，超出了现有分析流程的适配范围。

JORDAN One more term before we move on -- what's a neoantigen versus a tumor-associated antigen? I keep seeing both. 再问一个术语——新抗原（neoantigen）和肿瘤相关抗原（tumor-associated antigen）有什么区别？我总看到这两个词。

ALEX A neoantigen is a peptide derived from a mutated protein sequence that exists only in the tumor, never in normal tissue -- because the underlying DNA change is tumor-specific, the immune system has never seen that exact peptide before, making it, in principle, an ideal T-cell target with no risk of attacking healthy cells. 新抗原是来自突变蛋白序列的肽段，只存在于肿瘤中，从不出现在正常组织里——因为其背后的DNA变化是肿瘤特有的，免疫系统此前从未见过这个确切的肽段，这在原理上使其成为理想的T细胞靶点，没有攻击健康细胞的风险。 A tumor-associated antigen, by contrast, comes from a normal, unmutated protein that's simply overexpressed or abnormally expressed in the tumor compared to healthy tissue -- still a useful immunotherapy target, but with more risk of off-tumor toxicity since the peptide sequence itself isn't unique to cancer. 相比之下，肿瘤相关抗原来自一个正常、未突变的蛋白，只是在肿瘤中相对于健康组织被过度表达或异常表达——它仍是有用的免疫治疗靶点，但由于肽段序列本身并非癌症所独有，脱靶毒性的风险更大。 MHCquant2's benign reference dataset is specifically built to help distinguish the two: if a peptide already shows up in the benign atlas, it's more likely tumor-associated than a true neoantigen. MHCquant2的良性参考数据集正是为了帮助区分这两者而构建的：如果某个肽段已经出现在良性图谱中，它更可能是肿瘤相关抗原，而非真正的新抗原。

JORDAN What existed before MHCquant2, and why wasn't it enough? 在MHCquant2之前有过什么工具，为什么它们还不够？

ALEX There was a first-generation MHCquant, written in the older Nextflow DSL1 dialect, which improved scalability and quantification for large datasets but plateaued on sensitivity -- it kept missing low-abundance antigens that matter most for immunotherapy targeting. 此前存在第一代MHCquant，用较旧的Nextflow DSL1方言编写，它在大数据集的可扩展性和定量能力上有所改进，但在灵敏度上遇到了瓶颈——始终会漏掉那些对免疫治疗靶点选择最为关键的低丰度抗原。 Outside the Nextflow ecosystem, FragPipe with its MSFragger search engine introduced a fast fragment-ion-index algorithm and its own rescoring tool called MSBooster, but the authors note it isn't straightforward to deploy on shared high-performance-computing or cloud infrastructure the way a Nextflow pipeline is. FragPipe及其MSFragger搜索引擎则采用了一种更快的碎片离子索引算法，并配有自己的重打分工具MSBooster，但作者指出，它不像Nextflow流程那样便于部署在共享的高性能计算集群或云端基础设施上。 And PEAKS, a closed-source commercial pipeline, uses de novo sequencing-assisted deep learning for higher sensitivity but is comparatively slow and resource-hungry at scale, and being closed-source, it can't be inspected or modified. 而PEAKS作为一款闭源商业流程，采用从头测序辅助的深度学习方法来提升灵敏度，但在大规模应用时相对较慢、资源消耗更大，并且由于闭源，无法被检视或修改。 So the gap MHCquant2 targets is specifically: open-source, inspectable, cloud/cluster-portable, and sensitive enough to catch low-abundance peptides -- no existing tool combined all four. 因此MHCquant2瞄准的正是这样一个空白：开源、可审查、可在云端/集群间移植，并且灵敏度足以捕捉低丰度肽段——此前没有任何工具能同时满足这四点。

JORDAN So what's actually in MHCquant2 -- what did they build, and on what data? 那MHCquant2里到底有什么——他们具体构建了什么，用的是什么数据？

ALEX MHCquant2 is written entirely in Nextflow and packaged as an nf-core pipeline -- nf-core is a community framework of curated, standardized bioinformatics pipelines, so integrating into it means the pipeline gets shared infrastructure for testing, documentation, containerization, and cloud/cluster portability rather than each lab reinventing that scaffolding. MHCquant2完全用Nextflow编写，并作为一个nf-core流程发布——nf-core是一个由社区维护的、经过标准化整理的生物信息学流程框架，加入这个框架意味着该流程能共享统一的测试、文档、容器化以及云端/集群可移植性基础设施，而不必由每个实验室各自从头搭建这套脚手架。 The core search engine is Comet, with Percolator doing rescoring and false-discovery-rate control, and OpenMS's FeatureFinder handling quantification -- all established open-source proteomics tools MHCquant2 orchestrates rather than replaces. 核心搜索引擎是Comet，由Percolator负责重打分和假发现率（false-discovery-rate）控制，OpenMS的FeatureFinder负责定量——这些都是成熟的开源蛋白质组学工具，MHCquant2的作用是编排它们，而不是取而代之。 The key addition is MS2Rescore, a framework the authors integrated to bring in two peptide-property predictors -- DeepLC, which predicts a peptide's expected retention time on the chromatography column, and MS2PIP, which predicts a peptide's expected fragment-ion intensity pattern -- as extra scoring features that help Percolator distinguish true identifications from noise, especially for low-abundance peptides. 关键的新增之处是MS2Rescore，这是作者整合进来的一个框架，引入了两个肽段属性预测器：DeepLC，用于预测肽段在色谱柱上的预期保留时间；以及MS2PIP，用于预测肽段的预期碎片离子强度谱——这两者作为额外的打分特征，帮助Percolator区分真实鉴定结果与噪声，对低丰度肽段尤其有帮助。 To benchmark it, they built a new reference dataset called benignMHCquant2 from 92 non-cancerous autopsy tissue samples across the University Hospital Zürich, and also reprocessed the existing HLA Ligand Atlas, a large public benign-tissue immunopeptidomics resource. 为了做基准测试，他们基于苏黎世大学医院提供的92例非癌症尸检组织样本，构建了一个新的参考数据集benignMHCquant2，并同时重新处理了现有的公开良性组织免疫肽组学资源HLA配体图谱（HLA Ligand Atlas）。

MHCquant2固定接入了恰好两个肽段属性预测器——DeepLC和MS2PIP，二者都来自同一个MS2Rescore生态系统——这是一个合理且整合良好的选择，但也意味着该流程的架构把这一特定工具组合硬编码了进去，而不是把预测器当作一个可替换、可与其他方案做基准对比的独立层。 The paper does compare against FragPipe, which uses a different predictor (MSBooster), and against PEAKS, a closed-source deep-learning pipeline -- so there is external benchmarking -- but within MHCquant2 itself, swapping in a different predictor would mean a real code change, not a config flag. 论文确实与使用不同预测器（MSBooster）的FragPipe，以及闭源深度学习流程PEAKS做了外部对比——所以确实存在外部基准测试——但在MHCquant2内部，换用不同的预测器就意味着要真正改代码，而不是改一个配置项。
