Track B — Clinical Agents Fail Silently on Patient Identity

Abstract-only (non-OA): notes are based on the structured abstract; full-methods details flagged where they'd change interpretation.

Blurb. This 2026 study (Klang et al., Int. J. Med. Inform., Mount Sinai) stress-tests LLM-powered clinical agents on a failure mode that sits beneath accuracy benchmarks: attaching correct-looking data to the wrong patient. Using a record environment built from public MIMIC-IV emergency-department data, agents copied ICD-10-CM codes from a visit header into a patient record, with "UNKNOWN" permitted. Across four conditions (clean, header swap, one-digit MRN change, age shift), six models and 1.2M tool calls, agents usually wrote straight through tampered charts. Best case, GPT-4.1 withheld the write on 17.4% of header-swap runs; detection of subtle MRN/age faults was near zero; GPT-5-chat never identified a mismatch. Where it lands: AI-tooling / career. Buildable artifact (Track B tool sketch): an identity-integrity eval harness (programmatic fault injection → per-fault-type write-through rate) plus a deterministic pre-write guard that cross-references identity fields and blocks the Store call on mismatch — so integrity never depends on the model noticing. The identity-fault failure mode generalizes directly to genomics sample-swap / mislabeled-specimen errors.

Plain-English glossary

  • Clinical agent — an LLM system that plans, calls tools, and reads/writes records in a workflow, rather than only answering a prompt.（中文：临床智能体，一个会规划、调用工具、并在工作流中读写记录的 LLM 系统，而不仅是回答问题。）
  • ICD-10-CM — the standard clinical diagnosis coding system.（中文：ICD-10-CM 是标准的临床诊断编码系统。）
  • Identity fault — an error that binds data to the wrong patient (swapped header, MRN typo, shifted age); insidious because the content looks plausible.（中文：身份错误，把数据绑定到错误患者的错误（表头调换、MRN 打错、年龄偏移）；因内容看似合理而阴险。）
  • MIMIC-IV — a large de-identified critical-care/ED dataset widely used for clinical-informatics research.（中文：MIMIC-IV 是一个大型去标识化的重症/急诊数据集，广泛用于临床信息学研究。）
  • MRN (medical record number) — the unique identifier tying a clinical event to one patient.（中文：MRN（病历号），把临床事件绑定到单一患者的唯一标识。）
  • Write-through — an agent copying data into a record without catching that the record's identity is corrupted.（中文：写穿，智能体把数据抄入记录，却没发现该记录的身份已被污染。）

Full citation

Klang E, Glicksberg BS, Gorenshtein A, Gavin N, Freeman R, Stump L, Charney AW, Wei Ting DS, Omar M, Nadkarni GN. Clinical agents fail silently on patient identity. International Journal of Medical Informatics. 2026. PMID: 42217263 · DOI: 10.1016/j.ijmedinf.2026.106514. Not open access.

Methods / tools to lift

  • Fault-injection eval design — clean baseline + three tamper types (header swap, single-digit ID change, age shift) around a run of clean visits; the reusable template for identity-integrity testing.
  • Operational detection metric — per-fault-type write-through / withheld-write rate (note the reasoning-vs-hesitancy ambiguity; re-instrument to require a named mismatch).
  • Extract / Store tool split — a minimal agent interface that isolates the write step so it can be gated.
  • MIMIC-IV — public de-identified ED/critical-care records as a safe substrate for the harness.

Where it lands + buildable artifact

Serves AI-tooling / career (Track B tool sketch).

MVP (paste-ready): (1) Identity-integrity eval harness — de-identified record set → programmatically inject header-swap / single-digit-ID / age-shift / clean-control faults → run any candidate agent → report per-fault-type write-through rate. (2) Deterministic pre-write guard — a non-LLM check that cross-references key identity fields against the established patient context and blocks the Store call on mismatch. Input: de-identified record corpus + the agent's tool interface. Difficulty: M. Serves tool-development career target; portfolio-shaped.

What to verify first

  • Detection definition conflates identity reasoning with generic non-writing — re-instrument so "caught" requires a named mismatch, not just a withheld write.
  • Generalization beyond MIMIC-IV ED structure — validate fault injection on more than one record schema.
  • The guard's own false-positive (false-block) rate before it gates any real write path.
  • External method on public data — no claim about or dependency on any registry-internal data.

JORDAN Let me get one piece of vocabulary first, since this one is more clinical-informatics than genomics. 我先确认一个术语，因为这篇更偏临床信息学而不是基因组学。 What is an MRN, and why is "patient identity" its own failure mode? MRN 是什么，为什么"患者身份"会成为一个独立的失败模式？

ALEX MRN is the medical record number, the unique identifier that ties a clinical event to one specific patient. MRN 是病历号，是把一次临床事件绑定到某一位特定患者的唯一标识。 In a real record system, events flow in from many sources, and the single most consequential thing you can get wrong is attaching data to the wrong person. 在真实的记录系统里，事件从许多来源汇入，而你能犯的后果最严重的错误，就是把数据挂到了错误的人身上。 A one-digit MRN typo, a swapped header, a shifted age — these are identity faults, and they're insidious because the clinical content can look perfectly plausible while belonging to someone else. 一个数字的 MRN 打错、一个被调换的表头、一个被改动的年龄 —— 这些都是身份错误，它们的阴险之处在于：临床内容看起来完全合理，却属于另一个人。 Genomics has an exact analog, by the way — sample swaps and mislabeled specimens are the same class of error, and they silently poison downstream analysis. 顺带一提，基因组学里有一个完全对应的东西 —— 样本调换和标本贴错标签是同一类错误，它们会悄无声息地污染下游分析。 So even though the paper is about clinical agents, the failure mode generalizes to any pipeline that binds records to identities. 所以尽管这篇文章讲的是临床智能体，这种失败模式可以推广到任何把记录绑定到身份的流程。

JORDAN Why is "silent" the operative word in the title? 为什么标题里的关键词是"无声"？

ALEX Because the failure produces no error and no flag — the agent completes its task and reports success. 因为这种失败不产生任何报错、任何警示 —— 智能体完成了它的任务，并报告成功。 A crash you can catch; a refusal you can log; but an agent that confidently writes correct-looking codes into the wrong patient's chart leaves a clean-looking trail. 崩溃你能捕获；拒绝你能记录；但一个自信地把看似正确的编码写进错误患者病历的智能体，留下的是一条看起来干净的痕迹。 The corruption only surfaces later, downstream, when someone acts on data that was never that patient's. 这种污染只会在之后、在下游浮现，当有人依据一份从来就不属于该患者的数据去行动时。 In a batch registry-ingestion setting the stakes are the same shape: a single mis-bound record doesn't announce itself, it just quietly degrades every analysis that touches it. 在批量的登记数据摄入场景里，风险的形态是一样的：一条被错误绑定的记录不会自我声张，它只是悄悄地劣化每一项接触到它的分析。 That's why the authors frame this as a governance gap rather than a performance gap. 这就是为什么作者把它定位为治理空白，而非性能空白。

JORDAN What was unknown before this that made the study worth doing? 在这项研究之前，有什么未知的东西让它值得去做？

ALEX The setup is that large language models now power clinical agents that plan, call tools, and write into electronic health records in real workflows today. 背景是：大语言模型如今已经在为临床智能体提供动力，这些智能体会规划、调用工具，并在今天真实的工作流中写入电子健康记录 (EHR)。 The open question the authors pose is blunt: before we deploy these agents, do we actually know whether they detect patient-identity faults, or whether they just write straight through them? 作者提出的开放问题很直白：在我们部署这些智能体之前，我们真的知道它们能否发现患者身份错误吗，还是它们会径直写穿过去？ The worry is not that the model gives a wrong medical answer — it's that the model faithfully copies correct-looking data into the wrong chart. 担忧的不是模型给出错误的医学答案 —— 而是模型忠实地把看起来正确的数据抄进了错误的病历。 That's a governance and safety gap that sits underneath all the accuracy benchmarks people usually report. 这是一个治理与安全的空白，它位于人们通常报告的所有准确率基准之下。 And it matters precisely because these agents are being wired into write paths, not just read paths. 而它之所以重要，恰恰是因为这些智能体正在被接入"写入路径"，而不仅仅是"读取路径"。

JORDAN Walk me through what they actually built and tested. 给我讲讲他们究竟搭建并测试了什么。

ALEX They built a record environment from publicly available MIMIC-IV emergency-department data. 他们用公开可得的 MIMIC-IV 急诊科数据搭建了一个记录环境。 MIMIC-IV, one-clause: a large de-identified critical-care and ED dataset widely used for clinical-informatics research. MIMIC-IV，用一句话说：一个大型去标识化的重症与急诊数据集，被广泛用于临床信息学研究。 The agents were given two tools, Extract and Store, and asked to copy ICD-10-CM diagnosis codes from a visit header into a patient record, with permission to output "UNKNOWN" when uncertain. 这些智能体被给予两个工具，Extract 和 Store，任务是把 ICD-10-CM 诊断编码从就诊表头抄写到患者记录里，并允许在不确定时输出 "UNKNOWN"。 ICD-10-CM, one-clause: the standard clinical diagnosis coding system. ICD-10-CM，一句话解释：标准的临床诊断编码系统。 Each run presented ten visits from one patient that were clean, then one tampered visit. 每一轮呈现来自同一患者的十次干净就诊记录，然后是一次被篡改的就诊记录。 They tested four conditions: a clean baseline, a fully swapped header from another patient, a one-digit MRN change, and an age shift. 他们测试了四种情形：干净的基线、来自另一位患者的完全调换的表头、一位数字的 MRN 改动，以及年龄的偏移。 Six models, spanning closed and open weights, completed 1.2 million tool calls. 六个模型，涵盖闭源与开源权重，共完成了一百二十万次工具调用。 Detection was defined operationally: an agent "caught" a tamper if it withheld the write on the tampered visit — either by outputting "UNKNOWN" or by omitting the Store call entirely. 检测被操作化地定义为：如果智能体在被篡改的就诊记录上"扣住"了写入 —— 无论是输出 "UNKNOWN" 还是干脆省略 Store 调用 —— 就算它"抓到"了篡改。 Here's my one design pushback, and it's where abstract-only bites: defining detection as a withheld write conflates genuine identity-reasoning with generic refusal or hesitancy. 这是我要提的一个设计质疑，也正是"只有摘要"最吃亏的地方：把检测定义为"扣住写入"，会把真正的身份推理和泛泛的拒绝或犹豫混为一谈。 A model that non-writes for unrelated reasons would score as a detector, and we'd need the full paper to see how they separated those. 一个因为无关原因而不写入的模型会被计为"检测器"，我们需要全文才能看清他们是怎么把这两者区分开的。

GPT-5-chat 从未真正识别出任何一处不匹配，尽管它碰巧在 12.6% 的情形下产生了不写入 —— 这又绕回到我对"检测"究竟在测量什么的担忧。 The blunt takeaway: subtle identity corruption passes through these agents essentially untouched. 直白的结论是：细微的身份污染几乎原封不动地穿过了这些智能体。

JORDAN Could the guard idea generalize past identity — to other silent write errors? 守卫的想法能推广到身份之外吗 —— 到其他无声的写入错误？
