Ep2 (Track B — AI tooling): Health-Analytics Data to Evidence Suite (HADES)

HADES is OHDSI's open-source R package suite for running observational research — characterization, causal effect estimation, and patient-level prediction — directly against OMOP Common Data Model data, including across federated networks where patient data never leaves its home site. This is a software-description paper, not a results paper: its own stated "impact" evidence is a 14-day download-count snapshot and an unverified count of papers using the tools, which is thin by the paper's own admission. What makes it worth an episode is what HADES studies have actually been cited for — including EMA regulatory decisions on hydroxychloroquine and renin-angiotensin-system blockers during COVID-19 — and the fact that the whole stack (Apache 2.0, cross-platform, CI-tested) is something anyone can pull down and run today. The buildable artifact is a small starter kit built against OHDSI's own synthetic Eunomia dataset: a DataQualityDashboard conformance pass, a CohortMethod causal estimate, and an EmpiricalCalibration pass on top using negative controls — the same workflow, in miniature, that underlies the regulatory-grade studies this paper name-drops.

Plain-English glossary

  • Cyclops — HADES's core C++ regression engine, built to fit large-scale regression models (e.g. propensity scores) against datasets with over 100 million patient-lives.（中文：HADES的核心回归引擎，用C++编写，专门用于在超过一亿患者规模的数据集上拟合大规模回归模型(如倾向评分)。）
  • Empirical calibration — adjusting the confidence interval and p-value of a real effect estimate using the observed distribution of negative- (and positive-) control estimates, so uncertainty reflects a method's real, empirically observed error rate.（中文：利用阴性(及阳性)对照估计值的实际分布，对真实效应估计的置信区间和p值进行调整，使不确定性反映该方法在实际观测中的真实错误率，而非理论错误率。）
  • Negative control (exposure-outcome pair) — an exposure-outcome pair known to have no causal relationship, used diagnostically: a strong "effect" found for it signals residual bias in the analysis method, not biology.（中文：一对已知不存在因果关系的"暴露-结局"组合，用作诊断工具：若对它算出较强的"效应"，说明的是分析方法本身的残余偏倚，而非真实生物学现象。）
  • OMOP Common Data Model (CDM) — a standardized table schema that EHR and claims data get transformed into, so the same analysis code runs unmodified across very different source databases.（中文：一套标准化的表结构，电子健康记录和保险理赔数据都被转换为这种结构，使同一套分析代码能在完全不同的原始数据库上原样运行。）
  • OHDSI (Observational Health Data Sciences and Informatics) — pronounced "Odyssey"; the international collaborative building OMOP and its associated open-source tooling, including HADES.（中文：读作"Odyssey"，一个国际合作组织，构建了OMOP通用数据模型及其配套的开源工具生态，包括HADES。）
  • Large-scale propensity scores (LSPS) — propensity-score models fit at scale (many covariates, many patients) for causal-effect estimation in comparative-cohort designs.（中文：在比较队列研究设计中，用于因果效应估计的、在大规模(多协变量、多患者)条件下拟合的倾向评分模型。）
  • PatientLevelPrediction (PLP) framework — OHDSI's standardized specification for a prediction problem (target cohort, outcome, time-at-risk, covariates via FeatureExtraction) that makes a trained model's specification portable for external validation across network sites.（中文：OHDSI用于预测问题的标准化规格说明(目标队列、结局、风险时间窗、经FeatureExtraction提取的协变量)，使训练好的模型规格可移植，便于在网络内其他站点做外部验证。）

Methods / tools to lift

  • HADES (github.com/OHDSI/Hades) — the full R package suite: Capr, CirceR, CohortGenerator, PhenotypeLibrary, CohortDiagnostics, PheValuator (cohort layer); CohortMethod, PatientLevelPrediction, EvidenceSynthesis, EmpiricalCalibration, DataQualityDashboard (analytic layer).
  • Eunomia — OHDSI's small bundled synthetic OMOP dataset, designed for exactly this kind of dry-run / learning exercise.
  • DataQualityDashboard — runs conformance, completeness, and plausibility checks against OMOP CDM data.
  • EmpiricalCalibration — applies negative-control-based correction to causal-effect confidence intervals and p-values.

Where it lands + buildable artifact

Serves AI-tooling / career priority (infrastructure fluency, not a Karen/Liz-specific finding). Buildable: OHDSI HADES Starter Kit — run DataQualityDashboard against Eunomia to see what its checks flag; pick a toy exposure-outcome pair plus a small negative-control list; run CohortMethod for a causal estimate; run EmpiricalCalibration on top to see how much the negative controls shift the confidence interval. One MVP line: input = Eunomia (bundled) + a negative-control list → output = a DataQualityDashboard report plus a before/after calibration plot. Difficulty: M.

What to verify first

  • Whether a calibration result that looks clean on the small, synthetic Eunomia dataset generalizes at all to a real, much larger and messier OMOP instance — it would need re-checking there before drawing any conclusion.
  • What, exactly, DataQualityDashboard's plausibility checks parameterize as "implausible" — undocumented in this paper, and decisive for whether the tool meaningfully complements (or mostly duplicates) other registry-quality tools.
  • Each individual HADES package's current maintenance activity (commit history, open issues) before depending on it for anything real — CI keeping a package installable is not the same guarantee as it reflecting current OHDSI methods guidance.
  • Nothing here should be read as a claim about whether or how CFFPR is mapped to (or could be mapped to) OMOP today — that's outside what this paper can tell us.

ALEX Today's Track B pick is short and almost deliberately unglamorous — "Health-Analytics Data to Evidence Suite (HADES): Open-Source Software for Observational Research," by Martijn Schuemie and a long list of OHDSI collaborators, published in 2024 in Studies in Health Technology and Informatics. 今天B赛道选的这篇论文篇幅很短，内容也近乎刻意地朴实——《健康分析数据转证据工具集(HADES)：用于观察性研究的开源软件》，作者是Martijn Schuemie和一长串OHDSI合作者，2024年发表在《健康技术与信息学研究》(Studies in Health Technology and Informatics)上。 It's a software-description paper, not a results paper — there's no benchmark table — but it's the connective tissue behind an enormous share of published OMOP-based real-world evidence research, including studies that have directly informed EMA regulatory decisions. 这是一篇软件描述论文，不是结果论文——里面没有基准测试表格——但它正是支撑着大量已发表的、基于OMOP的真实世界证据 (real-world evidence, RWE) 研究背后的"连接组织"，其中一些研究直接影响了欧洲药品管理局(EMA)的监管决策。

JORDAN Let's ground the acronyms first, since this whole episode runs on them. 先把这些缩写讲清楚，因为整集内容都建立在它们之上。 OHDSI — pronounced "Odyssey" — stands for Observational Health Data Sciences and Informatics, an international collaborative that builds open standards and open-source tools for analyzing healthcare data at scale. OHDSI——读作"Odyssey"——全称是Observational Health Data Sciences and Informatics (观察性健康数据科学与信息学)，是一个国际合作组织，致力于构建用于大规模分析医疗数据的开放标准和开源工具。 OMOP, the Observational Medical Outcomes Partnership, is the common data model, or CDM, at the center of that effort — a standardized table schema that electronic health records and insurance-claims data get transformed into, so the same analysis code can run unmodified against very different source databases. OMOP，全称Observational Medical Outcomes Partnership，是这个项目核心的通用数据模型 (common data model, CDM)——一套标准化的表结构，电子健康记录和保险理赔数据都被转换成这套结构，这样同一套分析代码就能在完全不同的原始数据库上原样运行。 HADES is the R package suite that actually executes against OMOP-formatted data once it's in that shape. HADES就是一旦数据转换成这种结构之后，真正用来在OMOP格式数据上执行分析的那套R语言包工具集。

JORDAN Two more terms worth pinning down before the methods: negative controls and empirical calibration. 在讲方法之前，还有两个术语值得先讲清楚：阴性对照 (negative control) 和经验校准 (empirical calibration)。 A negative control, in this observational-research sense, is an exposure-outcome pair known not to have a causal relationship — used not as a comparison group in the clinical sense, but as a diagnostic: if your analysis pipeline finds a strong "effect" for a pairing that shouldn't have one, that tells you something about residual bias in the method itself, not about biology. 在观察性研究的语境下，阴性对照指的是一对已知不存在因果关系的"暴露-结局"组合——它不是临床意义上的对照组，而是一种诊断工具：如果你的分析流程对一个本不该有效应的组合算出了很强的"效应"，这说明的是分析方法本身存在残余偏倚，而不是真实的生物学现象。 Empirical calibration then uses a whole distribution of these negative-control estimates — plus, ideally, some positive controls with known effect sizes — to adjust the confidence interval and p-value on your actual estimate of interest, so your uncertainty reflects the method's real, empirically observed error rate rather than its theoretical one. 经验校准接着利用这一整批阴性对照（理想情况下还会加上一些已知效应大小的阳性对照）估计值的分布，对你真正关心的那个估计的置信区间和p值进行调整，使你的不确定性反映的是该方法在实际观测中的真实错误率，而不是理论上的错误率。 Both ideas run through almost every HADES package we're about to describe. 这两个概念贯穿了我们接下来要介绍的几乎每一个HADES包。

ALEX So what's actually in the box? 那这个工具箱里到底有什么？ HADES is organized around three analytic goals — characterization, population-level causal effect estimation, and patient-level prediction — built on top of a shared cohort layer. HADES围绕三个分析目标组织起来——特征刻画 (characterization)、人群层面的因果效应估计，以及患者个体层面的预测——这些都建立在一个共享的队列(cohort)层之上。 The cohort tools are Capr for authoring cohort definitions in R, CirceR for converting those definitions between SQL and a human-readable format, CohortGenerator for actually instantiating a cohort against a given CDM instance, PhenotypeLibrary for storing community-vetted, reusable cohort definitions, and CohortDiagnostics paired with PheValuator for checking whether a cohort definition actually captures the population you think it does. 队列相关的工具包括：用R语言撰写队列定义的Capr，在SQL和人类可读格式之间转换这些定义的CirceR，把队列定义真正实例化到某个具体CDM数据库上的CohortGenerator，存放社区审核过、可复用的队列定义的PhenotypeLibrary，以及用来检验一个队列定义是否真的捕捉到你以为的那群人的CohortDiagnostics和PheValuator组合。 On top of that sit the analytic engines: CohortMethod runs comparative-cohort causal-effect estimation using what they call large-scale propensity scores; PatientLevelPrediction implements OHDSI's standardized predictive-modeling framework across a wide range of algorithms, built to make external validation across the OHDSI network straightforward; EvidenceSynthesis does cross-database meta-analysis, including a method the authors developed for combining Cox models when event counts are small or zero; EmpiricalCalibration applies the negative-control correction we just defined; and DataQualityDashboard runs conformance, completeness, and plausibility checks against the CDM data itself before any of the above is trusted. 在这之上则是分析引擎：CohortMethod用他们所说的大规模倾向评分 (large-scale propensity scores) 来进行比较队列的因果效应估计；PatientLevelPrediction实现了OHDSI标准化的预测建模框架，涵盖多种算法，并专门设计成便于在OHDSI网络内做外部验证；EvidenceSynthesis做跨数据库的meta分析，其中包括作者们自己开发的、用于在事件数很少或为零时合并Cox模型的方法；EmpiricalCalibration应用我们刚才定义的阴性对照校正；而DataQualityDashboard则在上述所有分析被信任之前，先对CDM数据本身做符合性、完整性和合理性检查。

JORDAN PatientLevelPrediction keeps coming up whenever I read about OHDSI — what does "standardized predictive-modeling framework" actually buy you beyond just training a model yourself? 每次读到OHDSI相关内容，PatientLevelPrediction总会反复出现——这个"标准化预测建模框架"除了让你自己训练一个模型之外，到底还多提供了什么？

ALEX Mainly reproducibility and portability across sites that don't share patient data. 主要是可复现性，以及在不共享患者数据的多个站点之间的可移植性。 PLP standardizes how a prediction problem is specified — the target cohort, the outcome, the time-at-risk window, the covariate set pulled automatically from CDM fields via a companion package called FeatureExtraction — so that once a model is trained at one site, the exact same specification, not just the fitted model object, can be shipped to another site in the network for external validation against data the original developers never touched. PLP把一个预测问题的定义方式标准化了——目标队列、结局、风险时间窗，以及通过一个叫FeatureExtraction的配套包自动从CDM字段中提取出来的协变量集合——这样一旦某个站点训练出了模型，就可以把完全相同的规格说明（而不仅仅是训练好的模型对象）发送到网络中的另一个站点，在原开发者从未接触过的数据上做外部验证。 It supports the usual range of algorithms — regularized regression, gradient boosting, and others — through a common interface, so swapping the learner doesn't mean rewriting the cohort or feature-extraction logic. 它通过一个统一接口支持常见的一系列算法——正则化回归、梯度提升等等——所以更换学习器并不需要重写队列定义或特征提取逻辑。 That standardization is the actual product; the algorithms themselves are nothing Runyu hasn't already built from scratch. 这种标准化才是真正的产品所在；算法本身对Runyu来说完全不是什么新鲜事，他自己早就从头实现过。

JORDAN That DataQualityDashboard piece is interesting given where we are in the week — it's doing a version of exactly what Track C has been circling for two episodes a day. 考虑到我们这周正讲的内容，DataQualityDashboard这部分很有意思——它做的正是C赛道这两周每天两期节目一直在反复讨论的那类事情。

ALEX Right, though notice how thin the description of it actually is in this paper — one sentence: "checks conformance, completeness, and plausibility through extensive tests." 没错，不过注意这篇论文对它的描述其实相当单薄——只有一句话："通过大量测试检查符合性、完整性和合理性。" There's no description of what counts as a flag, no false-positive or false-negative rate, nothing about how a plausibility check is parameterized. 完全没有说明什么情况算被标记、没有误报率或漏报率，也没有说明合理性检查本身是如何参数化的。 That's my pushback on this paper overall: it's a software-announcement paper, and the one sentence of "evidence" for its real-world traction is a count of package downloads over fourteen days in late 2022, ranging from 2 to 1,046 depending on the package, plus an unverified tally of 38 clinical and 29 methods papers using HADES — the authors themselves write "there are likely more," which is honest but also tells you this isn't a rigorous adoption metric. 这就是我对这篇论文整体的质疑：这是一篇软件发布型论文，而它给出的"现实影响力"证据只有一句话——2022年末14天窗口期内的包下载量，从2次到1046次不等——外加一个未经验证的统计：38篇临床论文和29篇方法学论文使用了HADES，作者自己也写道"可能还有更多"，这话很诚实，但也说明这不是一个严谨的采用率指标。 Software-tooling papers like this one get judged by what's actually in the repo and what's been built on top of it, not by the paper's own prose. 像这样的软件工具论文，真正该被评判的标准是代码库里到底有什么、以及在它之上又构建了什么，而不是论文本身的文字描述。

JORDAN Fair — so what has been built on top of it, concretely? 说得对——那具体来说，在它之上又构建了什么？

ALEX The paper names a handful of studies that give a sense of scale and consequence. 论文列举了几项研究，能让人感受到这套工具的规模和影响力。 A comparative-effectiveness study of first-line antihypertensive drug classes ran across a multinational network. 一项针对一线降压药物类别比较疗效的研究跨越了多个国家的数据网络。 "Seek COVER" used a disease-proxy approach to rapidly stand up and validate a COVID-19 outcome risk calculator in an international network during the pandemic. "Seek COVER"项目在疫情期间用一种"疾病替代"思路，在国际网络中快速搭建并验证了一个COVID-19结局风险计算器。 A multinational retrospective study of hydroxychloroquine, alone and combined with azithromycin, in rheumatoid arthritis patients was cited by the EMA in its decision not to recommend those drugs for COVID-19. 一项针对类风湿关节炎患者使用羟氯喹（单用及联用阿奇霉素）的多国回顾性研究，被EMA在其不推荐将这两种药物用于COVID-19治疗的决定中引用。 And a study of renin-angiotensin-system blockers and COVID-19 susceptibility, run as an open-science cohort analysis across the OHDSI network, was endorsed by the EMA as an example of best practice. 还有一项关于肾素-血管紧张素系统 (renin-angiotensin system) 阻断剂与COVID-19易感性的研究，以开放科学队列分析的形式在OHDSI网络中完成，被EMA作为最佳实践的范例加以推荐。 Those are concrete regulatory touchpoints, even if the paper's own quantitative "impact" metric is thin. 这些都是具体、真实影响到监管决策的例子，即便论文自身给出的量化"影响力"指标相当薄弱。

JORDAN What's the licensing and deployment story — is this actually something Runyu could stand up himself, or is it one of those tools that only works inside a specific institutional pipeline? 那授权和部署方面是怎样的——这真的是Runyu能自己搭起来的东西吗，还是那种只能在特定机构内部流程里跑的工具？

ALEX It's Apache 2.0 licensed, which is about as permissive as it gets, and the core regression engine, Cyclops, is written in C++ specifically so the large-scale propensity-score and outcome models can run against datasets with over a hundred million patient-lives without falling over. 它采用Apache 2.0许可证，这几乎是最宽松的开源许可类型了；核心回归引擎Cyclops是用C++写的，专门为了让大规模倾向评分和结局模型能在超过一亿患者规模的数据集上稳定运行而设计。 SQL across the packages is translated through a shared rendering layer so the same analysis code runs against SQL Server, PostgreSQL, Redshift, BigQuery, and others without a rewrite, and continuous integration runs across Windows, macOS, and Linux. 各个包里的SQL语句都通过一个共享的渲染层来做跨平台转换，所以同一套分析代码能原样跑在SQL Server、PostgreSQL、Redshift、BigQuery等多种数据库上，不需要重写；而持续集成测试则覆盖Windows、macOS和Linux三大操作系统。 For a federated setup specifically — multiple sites, patient data staying local — the packages have built-in privacy protections like blinding small cell counts, and what gets shared out of each site is a human-reviewable CSV of aggregated statistics, not raw patient rows. 对于联邦化部署场景——多个站点、患者数据各自留在本地——这些包内置了隐私保护机制，比如对小样本量的格子进行遮蔽处理，每个站点对外共享的是一份人类可审阅的汇总统计CSV文件，而不是原始的患者级数据。 So yes — a motivated individual, or a small team, really can pull this down and run it against any dataset already in OMOP shape. 所以是的——一个有动力的个人，或者一个小团队，确实可以把这套工具拉下来，直接在任何已经转换成OMOP格式的数据集上跑起来。

JORDAN That "already in OMOP shape" caveat is the whole catch, though. 不过"已经转换成OMOP格式"这个前提条件，恰恰是关键所在。
