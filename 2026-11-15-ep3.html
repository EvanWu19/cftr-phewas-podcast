Ep3 (Track C — registry QC, 1/2): Informative presence bias in analyses of EHR-derived data

Harton, Mitra, and Hubbard formalize and extend prior work on "informative presence bias" — the fact that whether and when a patient generates an EHR visit is itself correlated with their health, so a biomarker's recorded values are not a random sample of that biomarker over time. Using pediatric EHR data plus simulation studies (abstract-only coverage — full text wasn't retrievable), they show that estimating a biomarker's effect on a health event using all available visit data produces minimal bias when the biomarker is stable over time, but substantial bias when it's volatile; adjusting for the number of prior visits in a fixed look-back window reduces but does not eliminate this. The mechanism transfers directly to anthropometric outlier flagging: any model treating height/weight measurements as randomly-timed samples is making the assumption this paper shows can fail. The buildable artifact is a visit-informativeness stratified sensitivity check — comparing a flagging model's outputs across visit-type strata to see whether flag-rate differences look like a visit-timing artifact rather than a true data error.

Plain-English glossary

  • Fixed look-back window — a defined span of time before an index event (e.g. the prior 12 months) over which prior visit count is tallied, as a crude proxy for monitoring intensity.（中文：索引事件之前设定的一段固定时间(例如过去12个月)，用于统计既往就诊次数，作为监测密切程度的粗略代理指标。）
  • Informative presence (bias) — the phenomenon where whether/when a patient generates a healthcare visit is itself correlated with their underlying health, so EHR-recorded biomarker values are not a random sample over time.（中文：患者是否及何时产生就诊记录本身与其潜在健康状况相关的现象，导致EHR中记录的生物标志物数值并非随时间的随机采样。）
  • Visit process — the (often non-random) pattern by which a patient generates healthcare encounters over time, as distinct from their underlying disease process.（中文：患者随时间产生医疗就诊记录的(往往非随机的)模式，区别于其潜在的疾病进程本身。）
  • Visit-type stratification (as a sensitivity analysis) — restricting an analysis to only visits judged likely informative, or only those judged likely noninformative, based on visit type, to bound the potential magnitude of informative presence bias.（中文：根据就诊类型，把分析限定在仅判断为"知情性"或仅判断为"非知情性"的就诊记录上，作为一种敏感性分析，用来界定知情性存在偏倚的潜在规模。）

Methods / tools to lift

  • Visit-type-stratified sensitivity analysis — the paper's own suggested mitigation: restrict analysis to visits judged likely informative, or likely noninformative, based on visit type, to bound potential bias magnitude.
  • Look-back-window visit-count adjustment — a standard (if only partially effective, per this paper) EHR-epidemiology adjustment for monitoring intensity.

Where it lands + buildable artifact

Serves the CFFPR outlier pipeline — pipeline stage (a) candidate generation, primary: any spline/mixed-effects "expected trajectory" model used as the substrate for flagging implicitly assumes measurements are sampled at uninformative times, an assumption this paper shows can produce substantial bias when the underlying biomarker is volatile; (d) evaluation, secondary: a gold-standard review sample drawn disproportionately from one visit type would inherit the same selection logic. Buildable: Visit-Informativeness Stratified Sensitivity Check — given a longitudinal extract with a visit-type/reason proxy, re-run a flagging model's output separately by stratum and compare flag rates/residual distributions; a sharp, systematic difference signals a visit-timing artifact worth routing differently in adjudication. Difficulty: S-M.

What to verify first

  • Whether a usable visit-type or visit-reason field exists at the granularity needed to distinguish informative from noninformative visits — the check is moot without it.
  • Whether the specific biomarker being flagged behaves more like the paper's "stable" or "volatile" case — the abstract doesn't specify how volatility was operationalized (coefficient of variation threshold vs. within-person variance ratio vs. something else), so this would need to be pinned down before applying the lesson.
  • Whether the pediatric, well-visit-structured setting this was studied in (a predictable scheduled baseline plus informative extra visits) generalizes its specific bias magnitudes — the qualitative lesson likely transfers more safely than any specific number would.
  • This is a methods-transfer question only — nothing here should be read as a claim about CFFPR's own current visit scheduling, visit-type coding, or flagging logic.

Pipeline stage

(a) candidate generation — primary; (d) evaluation — secondary.

Error types covered / not covered

Covered (conceptually, as a confound rather than a detection method): bias from visit-timing / informative presence affecting biomarker-event associations, and by extension, "expected trajectory" models used as a flagging substrate. Not covered: unit conversion errors, digit transposition, decimal-shift errors, carry-forward errors, or any direct distinction between a true data-entry error and a real clinical event — this paper addresses a sampling/timing confound, not a record-level error-detection rule.
