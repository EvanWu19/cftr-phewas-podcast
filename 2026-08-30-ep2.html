Ep2 — Track B: AssemblyQC: a Nextflow pipeline for reproducible reporting of assembly quality

Not a registry paper at all — a genome-assembly QC pipeline — but the transferable content is architecture, not biology. Rashid and colleagues built a four-section Nextflow pipeline (validate inputs → screen for contamination → run parallel QC modules — BUSCO gene-space completeness, LAI repeat-space quality, telomere detection, Hi-C mapping, synteny plotting, Kraken2 taxonomy, Merqury k-mer/phasing → aggregate into one Jinja-templated HTML report), built on the nf-core template with per-module nf-test coverage and version-locked Bioconda containers. It's an engineering paper, not a benchmark — there's no ground-truth accuracy comparison — but it demonstrates a working, documented, testable, comparison-capable system whose four-section shape (validate, screen, parallel-check, report) is directly copyable for a CFFPR anthropometric QC pipeline template, independent of any of its specific genomic tools.

Plain-English glossary

  • Genome assembly — the computational process of stitching short/moderate-length sequencing reads back into long continuous sequences, ideally whole chromosomes.（中文：把测序得到的短或中等长度读段重新拼接成长而连续序列（理想情况下是完整染色体）的计算过程。）
  • Contiguity / completeness / correctness — the three axes of assembly quality: how few/long the assembled pieces are; whether all expected sequence is present; whether the sequence is accurate rather than a chimeric artifact.（中文：装配质量的三个维度：拼接片段是否少而长；预期序列是否齐全；序列是否准确而非人为拼接出的嵌合产物。）
  • BUSCO (Benchmarking Universal Single-Copy Orthologs) — a tool that checks gene-space completeness by searching for a curated set of genes expected as single copies in nearly every species of a lineage.（中文：通过搜索某谱系中几乎所有物种都应以单拷贝存在的一组基因，来检查基因区完整性的工具。）
  • LAI (LTR Assembly Index) — a repeat-space quality metric based on how intact long terminal repeat (LTR) retrotransposons look in the assembly.（中文：基于装配结果中长末端重复反转录转座子（LTR）的完整程度，衡量重复序列区域质量的指标。）
  • Telomere — the repetitive DNA sequence capping the ends of chromosomes; its presence/absence in the right places is a correctness check.（中文：染色体末端的重复DNA序列"帽子"；其在正确位置的有无是一项正确性检查。）
  • Hi-C contact map — a chromosome-conformation-capture technique showing which genomic regions are physically close in the nucleus, used to catch mis-joined fragments.（中文：染色质构象捕获技术，显示细胞核内哪些基因组区域物理上相邻，用于发现错误拼接的片段。）
  • Synteny — conserved gene order between assemblies or against a reference, visualized to catch large rearrangements or inversions.（中文：不同装配之间或与参考基因组之间保守的基因顺序，通过可视化发现大的重排或倒位。）
  • k-mer / Merqury — a k-mer is a short fixed-length substring of sequence; Merqury compares k-mer content between raw reads and the finished assembly to assess completeness, consensus accuracy, and haplotype phasing.（中文：k-mer是固定长度的短序列子串；Merqury通过比较原始读段与最终装配之间的k-mer组成，评估完整性、一致性准确度和单倍型分相情况。）
  • nf-core — a community-curated collection of standardized, containerized Nextflow pipeline modules and conventions.（中文：一个由社区维护的标准化、容器化Nextflow流程模块与规范的集合。）

Methods / tools to lift

  • Four-section pipeline shape — validate inputs → screen for contamination/malformed records → run QC checks in parallel as independent modules → aggregate into one report.
  • nf-core template + nf-test — standardized module conventions with per-module unit testing.
  • Version-locked Bioconda/Docker/Singularity containers — every module runs in a pinned environment rather than relying on host-installed dependencies.
  • Jinja-in-Python HTML report generation — aggregates heterogeneous tool outputs into one shareable report.
  • Pairwise + chromosome-level comparison sub-workflows — built-in support for comparing multiple runs/assemblies against each other, not just single-run QC.

Where it lands + buildable artifact

Serves the AI-tooling / career-positioning priority. Difficulty: M — architecture is copyable from AssemblyQC's public GitHub template; most effort is in the QC modules themselves.

What to verify first

  • Whether Nextflow's channel/process model, built for sequence-file DAGs, is the right level of machinery for a QC pipeline over tabular records, versus a lighter framework.
  • That "reproducible" here means deterministic given fixed inputs/container versions — it does not by itself validate that the QC logic inside each module is correct.
  • Whether containerizing every module is worth the setup/maintenance overhead at this project's scale versus a simpler versioned script.
  • Whether nf-core's module-reuse ecosystem (built around genomic file formats) has an equivalent maturity level for tabular/EHR-style data before committing to it as the long-term convention.

ALEX Today's paper is "AssemblyQC: a Nextflow pipeline for reproducible reporting of assembly quality," by Rashid and colleagues, published in Bioinformatics in 2024. 今天的论文是Rashid等人2024年发表在《Bioinformatics》期刊上的《AssemblyQC：一个用于可复现装配质量报告的Nextflow流程》。This is Track B — AI tooling with a tool-development lens, the track that serves the career-positioning priority. 这是Track B——带有工具开发视角的AI工具选题，服务于职业定位这一优先方向。It's not about registry data at all — it's a genome assembly quality-control pipeline — but the thing worth stealing is the architecture, not the biology. 这篇论文跟注册库数据完全无关——它是一个基因组装配质量控制流程——但真正值得借鉴的是它的架构，而不是其中的生物学内容。

JORDAN Genome assembly — walk me through what that even means before we get into the QC part. 基因组装配——在讲质控部分之前，先给我讲讲这到底是什么意思。

ALEX Sequencing machines only read DNA in short or moderately long fragments, never a whole chromosome at once, so assembly is the computational process of stitching those overlapping fragments back into long, continuous sequences — ideally whole chromosomes. 测序仪只能读取DNA的短片段或中等长度片段，永远不可能一次读出整条染色体，因此装配（assembly）就是把这些相互重叠的片段重新拼接成长而连续的序列——理想情况下拼出完整染色体——的计算过程。The paper frames assembly quality along three axes: contiguity, how few and how long the resulting pieces are; completeness, whether all the expected sequence is actually present; and correctness, whether the assembled sequence is actually accurate and not a chimeric artifact. 论文把装配质量归纳为三个维度：连续性（contiguity），即拼出的片段数量少不少、长度长不长；完整性（completeness），即预期的序列是否都齐全；以及正确性（correctness），即拼装出来的序列本身是否准确，而不是一个嵌合的人为产物。

JORDAN And the specific tools they bundle in — BUSCO, LAI, that kind of thing — what are those actually checking? BUSCO、LAI这些具体工具——它们到底在检查什么？

ALEX BUSCO, Benchmarking Universal Single-Copy Orthologs, checks gene-space completeness — it has a curated list of genes expected to exist as a single copy in nearly every species in a lineage, and it searches the assembly for how many of them are present, duplicated, fragmented, or missing. BUSCO（Benchmarking Universal Single-Copy Orthologs，单拷贝直系同源基因基准评估）用来检查基因区完整性——它有一份经过整理的基因清单，这些基因预期在某一谱系几乎所有物种中都以单拷贝形式存在，它会在装配结果中搜索有多少这样的基因是完整存在的、重复的、碎片化的或缺失的。LAI, the LTR Assembly Index, checks the repeat-space instead — it looks specifically at long terminal repeat retrotransposons, LTRs, a class of repetitive mobile DNA elements, and uses how intact they look as a proxy for how well the assembly resolved repetitive regions, which are notoriously hard to assemble correctly. LAI（LTR装配指数）检查的则是重复序列区域——它专门关注长末端重复反转录转座子（LTR），这是一类具有重复性的可移动DNA元件，并利用这些元件看起来的完整程度，作为装配对重复区域解析好坏的替代指标，而重复区域一向是最难正确装配的部分。The pipeline also checks telomeres — the repetitive sequence caps at chromosome ends — using a tool called tidk, and produces Hi-C contact maps, a chromosome-conformation-capture technique that shows which genomic regions are physically close together in the nucleus, which helps catch cases where two distant fragments were wrongly stitched together as neighbors. 该流程还会用一款叫tidk的工具检查端粒——染色体末端的重复序列"帽子"——并生成Hi-C接触图，这是一种染色质构象捕获技术，能显示细胞核内哪些基因组区域在物理空间上彼此靠近，有助于发现两个原本相距很远的片段被错误地拼接成相邻区域的情况。Synteny plots, generated with tools like MUMmer4 and Circos, compare gene order between assemblies or against a reference to visually catch large rearrangements or inversions. 用MUMmer4和Circos等工具生成的共线性（synteny）图，则通过比较不同装配之间、或与参考基因组之间的基因顺序，以可视化方式发现大的重排或倒位。

JORDAN Why does the field need a dedicated pipeline for this instead of just running each tool by hand? 为什么这个领域需要一个专门的流程来做这件事，而不是手动分别运行每个工具？

ALEX Scale and reproducibility. 因为规模和可复现性的问题。The paper notes that reference genome assemblies now exist for over 700 plant species, and as of May 2024 the NCBI Assembly Database returned more than 2.3 million search results — a number driven by the continued collapse in sequencing costs, which keeps making genome assembly accessible to more and more labs that don't necessarily have dedicated bioinformatics infrastructure. 论文指出，目前已有超过700个植物物种拥有参考基因组装配，截至2024年5月，NCBI装配数据库返回的检索结果已超过230万条——这一数字的增长，源于测序成本的持续下降，使得越来越多本身未必具备专门生物信息学基础设施的实验室，也能承担基因组装配工作。Assessing quality properly requires running many separate tools, each covering one narrow aspect, and each with its own installation quirks and update cadence — the authors point out that BUSCO alone had eleven separate updates within a single year, January 2022 through June 2023. 要做好质量评估，需要运行许多各自独立、只覆盖某一狭窄方面的工具，而每一款工具都有自己的安装门道和更新节奏——作者指出，仅BUSCO一款工具，在2022年1月到2023年6月这一年里就单独发布过11次更新。That churn is exactly what breaks reproducibility: if you don't pin the exact tool version used, a report generated today may not be regeneratable, or comparable, six months later. 这种频繁更新恰恰是破坏可复现性的元凶：如果不锁定所使用的具体工具版本，今天生成的报告可能在六个月后就无法重新生成，也无法与之比较。Two prior efforts, GenomeQC — an R/Shiny web app — and wrapper scripts from the Vertebrate Genomes Project, addressed pieces of this, but AssemblyQC aims to be more comprehensive and to inherit the reproducibility guarantees of the nf-core ecosystem specifically. 此前已有两项尝试——GenomeQC（一个R/Shiny网页应用）和脊椎动物基因组计划（VGP）的包装脚本——分别解决了部分问题，而AssemblyQC的目标是做得更全面，并特别继承nf-core生态系统所带来的可复现性保障。

JORDAN You said k-mer analysis too, with a tool called Merqury — what's that checking that BUSCO and LAI don't? 你还提到用一款叫Merqury的工具做k-mer分析——它检查的是BUSCO和LAI没有覆盖到的什么内容？

ALEX A k-mer is just a short substring of fixed length, k bases long, taken from a sequencing read or an assembled sequence. k-mer就是从测序读段或装配序列中截取出的一段固定长度（k个碱基）的短子串。Merqury compares the k-mer content of the raw sequencing reads against the k-mer content of the finished assembly — if a k-mer that's well-supported by the reads is missing or duplicated in the assembly, that's evidence of a completeness or consensus error the read-alignment-based checks might miss. Merqury把原始测序读段中的k-mer组成，与最终装配序列中的k-mer组成做比较——如果一个在读段中有充分支持的k-mer，在装配结果中却缺失或重复出现，这就说明可能存在完整性或一致性错误，而这类错误未必能被基于读段比对的其他检查方法发现。For diploid or otherwise multi-haplotype assemblies, Merqury can also assess phasing — whether the two parental haplotypes were kept properly separated rather than mixed together into a single mosaic sequence, a distinct kind of correctness problem specific to non-haploid genomes. 对于二倍体或其他多单倍型的装配结果，Merqury还能评估分相（phasing）质量——即两个亲本单倍型是否被正确地分开保留，而不是混杂成一条镶嵌序列，这是非单倍体基因组特有的一类正确性问题。The pipeline also runs Kraken2 for taxonomic assignment, which is a second, independent way of catching contamination beyond the FCS step — it classifies each assembled sequence against a reference database of known organisms, which can catch cross-domain contamination, like bacterial sequence mixed into a plant genome, that adapter-focused screening might miss. 该流程还会运行Kraken2做物种归类，这是在FCS之外，用来发现污染的第二种、独立的方法——它会将每一条装配出来的序列与已知物种的参考数据库做比对分类，从而发现跨域污染，例如混入植物基因组中的细菌序列，这类问题是以接头序列为重点的筛查可能会漏掉的。

JORDAN What does the actual pipeline architecture look like? 这个流程的实际架构是什么样的？

ALEX Four sections, run largely in parallel. 一共四个部分，大多可以并行运行。Section one validates the input files themselves — FASTA sequence integrity, duplicate detection, and GFF3 annotation validity — to catch malformed inputs before anything downstream wastes compute on them. 第一部分验证输入文件本身——FASTA序列的完整性、重复序列检测，以及GFF3注释文件的有效性——目的是在下游任何步骤浪费算力之前，先把格式错误的输入拦截下来。Section two screens for contamination using NCBI's Foreign Contamination Screen, catching adapter sequences or DNA from the wrong organism; assemblies that fail can be configured to skip the remaining checks. 第二部分使用NCBI的外源污染筛查（Foreign Contamination Screen）工具检测污染，捕捉接头序列或来自错误物种的DNA；未通过检测的装配结果可以配置为跳过后续检查。Section three runs the substantive checks in parallel — contiguity statistics, BUSCO, LAI, telomere detection, optional Hi-C mapping, synteny plotting, Kraken2-based taxonomic assignment, and Merqury k-mer analysis for consensus quality and haplotype phasing. 第三部分并行运行核心质控检查——连续性统计、BUSCO、LAI、端粒检测、可选的Hi-C比对、共线性绘图、基于Kraken2的物种归类，以及用于评估一致性质量和单倍型分相的Merqury k-mer分析。Section four gathers every tool's output and renders it into one shareable HTML report using Jinja templating in Python. 第四部分汇总所有工具的输出，并使用Python中的Jinja模板引擎渲染成一份可共享的HTML报告。Under the hood, it follows the nf-core template, uses nf-test for per-module unit testing, and every module runs in a version-locked Bioconda container rather than relying on whatever happens to be installed on the host system. 在底层实现上，它遵循nf-core模板，用nf-test为每个模块做单元测试，并且每个模块都运行在版本锁定的Bioconda容器中，而不依赖宿主系统上恰好安装了什么软件。ALEX pushes back here: bundling a dozen third-party tools into one pipeline doesn't make any individual tool more reproducible on its own — it centralizes the maintenance burden onto whoever keeps the container definitions current, and if that maintenance lapses, you get a pipeline that reproducibly reproduces last year's bugs. 这里ALEX要提出一点质疑：把十几款第三方工具打包进一个流程，并不会让每一款工具本身变得更加可复现——它只是把维护负担集中到了负责保持容器定义更新的人身上，一旦这种维护跟不上，你得到的就是一个"可复现地复现着去年那些bug"的流程。

JORDAN Since this is an engineering paper, not a benchmark — did they actually show it works, or is it more of a "trust the design"? 既然这是一篇工程类论文，而不是一篇基准测试论文——他们是真的展示出它有效，还是更多靠"相信设计本身"？

ALEX It's honestly the latter, and that's worth being upfront about. 老实说更接近后者，这一点值得坦率承认。There's no accuracy benchmark here in the sense we'd expect from Track A — no ground-truth comparison showing AssemblyQC catches more real assembly errors than running the tools separately would. 这里没有我们在Track A那种意义上的准确性基准测试——没有金标准比较来证明AssemblyQC比单独运行这些工具能捕捉到更多真实的装配错误。What they do demonstrate is a working, documented, testable system: the code and an example report are public on GitHub, each module has nf-test coverage, the pipeline supports evaluating multiple assemblies in parallel, and any of the optional checks — contamination screening aside — can be skipped through configuration rather than by editing code. 他们真正展示出来的是一个可运行、有文档、可测试的系统：代码和示例报告都公开在GitHub上，每个模块都有nf-test测试覆盖，该流程支持并行评估多个装配结果，除污染筛查外的其他可选检查都可以通过配置而非修改代码来跳过。That's a meaningful claim on its own — "this is reproducible and maintainable" is a legitimate, if more modest, thing to demonstrate — but it's a different kind of evidence than "this correctly classifies X% of true positives," and it's worth not conflating the two when judging whether to adopt an architecture like this. 这本身就是一个有意义的主张——"这个流程是可复现、可维护的"，虽然比较朴素，但确实是一个站得住脚的论证目标——但这与"这个流程能正确分类出百分之多少的真阳性"是两种不同性质的证据，在判断是否要采用这样一种架构时，不应把两者混为一谈。

JORDAN One more design question — why build a whole new pipeline instead of extending GenomeQC, the existing R/Shiny tool you mentioned? 还有一个设计上的问题——为什么要新建一整套流程，而不是直接扩展你提到的那个现成的R/Shiny工具GenomeQC？

ALEX That's exactly the kind of build-vs-extend call worth sitting with before starting any tooling project, registry-QC included. 这正是在启动任何工具类项目——包括注册库质控项目——之前，都值得认真权衡的"重建还是扩展"的问题。The paper's implicit argument is that GenomeQC and the VGP wrapper scripts each cover part of the space but neither inherits a shared, actively maintained module ecosystem the way nf-core does — Nextflow plus nf-core means new checks can be added as standardized modules that other pipelines in the same ecosystem can also reuse, rather than one-off R functions tightly coupled to a single Shiny app. 论文隐含的论点是，GenomeQC和VGP的包装脚本各自覆盖了一部分需求，但都没有像nf-core那样继承一个共享的、持续维护的模块生态——Nextflow加nf-core意味着新的检查项可以作为标准化模块添加进来，供同一生态中的其他流程复用，而不是与单一Shiny应用紧密耦合的一次性R函数。That's a real advantage if you expect to keep adding checks over years, but it's also a heavier upfront investment — you're buying into an entire ecosystem's conventions, not just writing a script. 如果预期未来数年会持续新增检查项，这确实是一个实实在在的优势，但这也意味着更重的前期投入——你买进的是一整套生态系统的规范，而不仅仅是写一个脚本。

JORDAN So what's the buildable version of this for the registry work? 那么，把这个思路用到注册库工作上，具体可以构建出什么？
