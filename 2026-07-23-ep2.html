Show notes — RxMap: an LLM-assisted tool for medication normalization

Blurb. Korpela et al. (2026, JAMIA Open) ship RxMap, an open, researcher-oriented system that normalizes messy free-text medication strings to RxNorm ingredient-level concepts. The design is a three-stage hybrid: minimal preprocessing, then a core reconciliation of two independent candidate ingredient sets (RxNorm deterministic approximate-match vs. a constrained LLM parse), resolved by a three-tier rule-based hierarchy (perfect / normalized-perfect / subset match = high/moderate/low confidence), then post-hoc ATC annotation. On 22,624 unique MEPS medication strings, the full pipeline (Gemini-2.0-Flash) reached F1 0.966 at the concept level and 0.972 at the ingredient level, up from 0.859 for deterministic RxNorm matching alone — at ~3.7 s and ~$0.0002 per string, with caching. Most errors sit in the subset-matching (low-confidence) tier: salt-form collapse, generic-vs-specific chemical, herbal-to-compound. Where it lands: the Liz / CFFPR phenotype & data-quality work (method only). Buildable artifact: a CF-medication normalizer with a review queue that reuses the hybrid pattern and rolls ingredients up to a CF-relevant drug-class ontology.

Plain-English glossary

  • RxNorm — a US NLM standardized drug vocabulary; assigns each drug/ingredient a stable identifier (RxCUI).（中文：美国国家医学图书馆的标准化药物术语库，为每种药物/成分分配稳定标识符 RxCUI。）
  • RxCUI — RxNorm Concept Unique Identifier; the stable ID you join medication data on.（中文：RxNorm 概念唯一标识符，用于连接用药数据的稳定 ID。）
  • IN / MIN — RxNorm ingredient (IN) and multi-ingredient (MIN) concept levels; the granularity RxMap normalizes to.（中文：RxNorm 的成分（IN）与多成分（MIN）概念层级，RxMap 标准化到的粒度。）
  • Normalization (medication) — mapping a free-text drug string to a standardized drug concept.（中文：药物标准化——把自由文本药名映射到标准化药物概念。）
  • ATC — Anatomical Therapeutic Chemical classification; groups drugs into therapeutic/pharmacologic classes for roll-up analysis.（中文：解剖治疗化学分类系统，按治疗/药理类别给药物归类以便上卷分析。）
  • RxClass — an NLM API that links drugs to classes; RxMap uses it as an ATC fallback.（中文：把药物链接到类别的 NLM 接口，RxMap 用作 ATC 的回退来源。）
  • Approximate / fuzzy match — RxNorm's token-overlap (Jaccard) lexical matcher for imperfect strings.（中文：近似/模糊匹配——RxNorm 基于词元重叠（Jaccard）的词法匹配，用于不完美字符串。）
  • Combination product — a single medication containing multiple active ingredients; the hardest normalization case.（中文：复方制剂——含多种活性成分的单一药物，是最难标准化的情况。）
  • Salt form — the specific chemical salt of a drug (e.g., codeine phosphate vs. codeine); LLM generalization can collapse these.（中文：盐型——药物的具体化学盐（如磷酸可待因 vs 可待因）；LLM 泛化可能把它们坍缩。）

Full citation. Korpela E, Rubin LH, Dastgheyb RM, Xu Y. RxMap: an LLM-assisted tool for medication normalization. JAMIA Open. 2026. PMID: 42220340 · PMC: PMC13221971 · DOI: 10.1093/jamiaopen/ooag085 · Tool: rx-map.com

Methods / tools to lift

  • Hybrid candidate generation: run RxNorm getApproximateMatch AND a constrained LLM parse, in parallel, then reconcile.
  • Constrained-LLM prompting: feed the deterministic candidate as context but instruct the LLM to prioritize the raw string and ignore the candidate on conflict — reduces hallucinated mappings.
  • Three-tier rule-based confidence (perfect / normalized-perfect / subset) as an interpretable routing signal for human review.
  • Subset decomposition for combination products: peel off matched sub-concepts iteratively until the ingredient set is covered.
  • Medication-string caching + deterministic decoding for reproducible, cheap batch runs.

Where it lands + buildable artifact. Serves Liz / CFFPR phenotype & data quality (method only) and the AI-tooling / career target. MVP (paste-ready): "CF-medication normalizer with review queue — input: column of free-text medication strings; run RxNorm approximate-match + constrained LLM parse reconciled by 3-tier hierarchy → normalized RxCUIs; roll up to a CF drug-class ontology (modulators, inhaled antibiotics, mucolytics, enzymes); output RxCUI + class + confidence flag, routing low-confidence rows to a review queue. Difficulty: M."

What to verify first

  • US/English/RxNorm assumption: check behavior on the actual medication coding scheme in use and on drugs too new for RxNorm.
  • Confidence tiers are rule labels, not calibrated probabilities — measure the real error rate within each tier on your own data before skipping review.
  • Known failure mode (salt-form collapse, generic-vs-specific) — confirm it preserves clinically meaningful CF-drug distinctions.
  • LLM dependence: F1 moved ~6 points between Gemini and GPT-5-Nano — pin the model/version for reproducibility.

ALEX Today's Track B paper is "RxMap: an LLM-assisted tool for medication normalization," by Eero Korpela, Leah Rubin, Raha Dastgheyb, and Yanxun Xu, out in JAMIA Open in 2026. 今天 Track B 的论文是 Eero Korpela、Leah Rubin、Raha Dastgheyb 和 Yanxun Xu 于 2026 年发表在《JAMIA Open》上的《RxMap：一个由大语言模型辅助的药物名称标准化工具》。 It's a tooling paper — it ships a working system, a website, and a reproducible batch pipeline — which is exactly what this track is for. 这是一篇工具型论文——它交付了一个可用的系统、一个网站和一个可复现的批处理流程——正好符合本 Track 的定位。 We're reading it because medication strings are the single messiest field in almost every real-world dataset, and this paper shows a clean, honest way to tame them with an LLM. 我们读它，是因为药物字符串几乎是每个真实世界数据集中最混乱的字段，而这篇论文展示了一种干净、诚实地用大语言模型（LLM）驯服它们的方法。

JORDAN I'm comfortable with the machine-learning side, but the terminology here is drug-vocabulary stuff. 我对机器学习那一侧很熟，但这里的术语是药物词表方面的东西。 What is RxNorm, and what does "normalization" mean here? 什么是 RxNorm，这里的"标准化"又是什么意思？ ALEX: RxNorm (美国国家医学图书馆维护的标准化药物术语库，把药名映射到统一的概念标识符) is a standardized drug vocabulary maintained by the US National Library of Medicine. RxNorm 是由美国国家医学图书馆维护的标准化药物术语库。 It gives every clinical drug and every ingredient a stable identifier called an RxCUI. 它为每一种临床药物和每一种成分分配一个稳定的标识符，称为 RxCUI。 Normalization means taking a free-text medication string — whatever a pharmacy or a survey happened to type — and mapping it to the right RxNorm concept. 标准化的意思是，把一段自由文本药物字符串——无论药房或调查里恰好怎么打的——映射到正确的 RxNorm 概念上。 JORDAN: Give me a sense of how messy the input really is. 让我感受一下输入到底有多乱。 ALEX: The paper's own examples are perfect. 论文自己的例子非常到位。 You get strings like "DIPHEN-ATROP" for diphenhydramine plus atropine, "SULFAMET" as a truncation, "LO/OVRAL 28" as a brand oral contraceptive, "POTASS. CL 10MEQ @@" with literal junk characters, and "ACETAM CODEINE #3." 你会看到像 "DIPHEN-ATROP"（代表苯海拉明加阿托品）、"SULFAMET"（一个截断）、"LO/OVRAL 28"（一个品牌口服避孕药）、"POTASS. CL 10MEQ @@"（带着字面上的垃圾字符），以及 "ACETAM CODEINE #3" 这样的字符串。 Brand names, generic names, abbreviations, misspellings, truncations, and multi-ingredient combos, all mixed together. 品牌名、通用名、缩写、拼写错误、截断和多成分组合，全都混在一起。 JORDAN: And what's ATC? 那 ATC 是什么？ ALEX: ATC (解剖治疗化学分类系统，按治疗和药理类别给药物归类的编码体系) is the Anatomical Therapeutic Chemical classification. ATC 是解剖治疗化学分类系统。 It groups drugs into therapeutic and pharmacologic classes, so once you know the ingredient you can roll up to a drug class for analysis. 它把药物归入治疗和药理类别，这样一旦你知道了成分，就能上卷到一个药物类别做分析。 RxMap assigns ATC codes after normalization as an annotation step. RxMap 在标准化之后作为一个注释步骤来分配 ATC 编码。

JORDAN So why is this hard enough to need a paper? 那为什么这难到需要专门写一篇论文？ ALEX: Because the standard approach — deterministic string matching against RxNorm — breaks on exactly the messy cases. 因为标准做法——对 RxNorm 做确定性字符串匹配——恰恰在这些混乱的情况下失效。 RxNorm ships an approximate-match function that does fuzzy lexical matching, roughly token-overlap scoring. RxNorm 自带一个近似匹配函数，做模糊的词法匹配，大致是词元重叠打分。 It handles clean, well-formatted entries fine. 它能很好地处理干净、格式规范的条目。 But give it a misspelling like "BENZONATE," a truncation like "SULFAMET," or a brand like "LO-OVRAL-28," and it either misses or picks the wrong concept. 但给它一个拼写错误如 "BENZONATE"、一个截断如 "SULFAMET"、或一个品牌如 "LO-OVRAL-28"，它要么漏掉，要么选错概念。 And it's especially bad at multi-ingredient combination products, where it can't decompose the pieces. 而它在多成分组合产品上尤其糟糕，因为它无法拆解各个组成部分。 JORDAN: I'd expect people to just throw an LLM at it end to end. 我以为人们会直接端到端地丢给一个 LLM 处理。 ALEX: And that's the design tension the paper is really about. 而这正是论文真正关注的设计张力。 A raw LLM will happily hallucinate a plausible drug that isn't the right RxNorm concept, and it won't give you a stable identifier you can join on. 一个未经约束的 LLM 会乐呵呵地编造一个看似合理、却不是正确 RxNorm 概念的药物，而且不会给你一个可用于连接的稳定标识符。 So the interesting question is how to use the LLM's language flexibility without letting it invent things. 所以有趣的问题是：如何利用 LLM 的语言灵活性，同时不让它凭空捏造。

ALEX Here's what they built, and the architecture is the lesson. 下面是他们所构建的，而这个架构本身就是要点。 RxMap is a three-stage hybrid pipeline. RxMap 是一个三阶段的混合流程。 Stage one is minimal preprocessing: strip parenthetical content, normalize whitespace, uppercase — and deliberately no spelling correction or abbreviation expansion, to preserve the original meaning. 第一阶段是最小化预处理：去掉括号内容、规范空格、转大写——并且刻意不做拼写纠正或缩写扩展，以保留原始含义。 Stage two is the core: hybrid normalization. 第二阶段是核心：混合标准化。 They generate two independent candidate ingredient sets — one from RxNorm's deterministic approximate match, and one from the LLM parsing the raw string into a list of generic ingredient names. 他们生成两组独立的候选成分集——一组来自 RxNorm 的确定性近似匹配，一组来自 LLM 把原始字符串解析成一份通用成分名清单。 JORDAN: Do they let the two talk to each other? 他们让这两组互相交流吗？ ALEX: Carefully. 很谨慎地。 The deterministic candidate is fed to the LLM as context, but the LLM is explicitly told to prioritize the raw string and ignore the deterministic guess if they conflict. 确定性候选会作为上下文喂给 LLM，但 LLM 被明确告知要以原始字符串为准，若两者冲突则忽略确定性猜测。 Then they reconcile the two sets with a three-tier hierarchy. 然后他们用一个三层级结构来协调这两组。 If the sets match exactly, that's a high-confidence "perfect match." 如果两组完全一致，那就是高置信度的"完美匹配"。 If they only match after both are normalized to canonical RxNorm ingredient names — say aspirin equals acetylsalicylic acid — that's a moderate-confidence "normalized perfect match." 如果两组只有在都被标准化为规范的 RxNorm 成分名之后才一致——比如阿司匹林等于乙酰水杨酸——那就是中置信度的"标准化完美匹配"。 And if they still disagree, they fall back to subset matching: decompose the LLM's ingredient set into progressively smaller subsets, match each to valid RxNorm concepts, and peel off ingredients until the whole set is covered — that's low confidence. 如果仍然不一致，就退到子集匹配：把 LLM 的成分集分解成逐渐更小的子集，把每个子集匹配到有效的 RxNorm 概念，并逐一剥离成分，直到覆盖整个集合——这是低置信度。 JORDAN: So "confidence" here isn't a probability — it's which rule fired. 所以这里的"置信度"不是概率——而是触发了哪条规则。 ALEX: Exactly, and I appreciate their honesty about that. 正是如此，我很欣赏他们对此的坦诚。 It's a structured, rule-based label, not a calibrated score. 它是一个结构化的、基于规则的标签，而不是一个校准过的评分。 That's a design choice I'd push on — a rule tier is interpretable, but it means you can't set a probability threshold to trade precision for recall; you're stuck with three buckets. 这是我会质疑的一个设计选择——规则层级是可解释的，但也意味着你无法设定一个概率阈值来在精确率和召回率之间做权衡；你只能困在三个桶里。 Stage three assigns ATC codes, preferring RxNorm's own mappings and falling back to RxClass only when active ingredients match exactly. 第三阶段分配 ATC 编码，优先使用 RxNorm 自己的映射，仅当活性成分完全一致时才退回到 RxClass。

ALEX Now results. 现在说结果。 They evaluated on 22,624 unique medication strings from the IPUMS MEPS survey dataset, plus a smaller harmonized 1,363-string set. 他们在来自 IPUMS MEPS 调查数据集的 22,624 条唯一药物字符串，以及一个更小的、经过统一整理的 1,363 条字符串集上进行评估。 The deterministic RxNorm-plus baseline scored an F1 of 0.859 at the concept level. 确定性的 RxNorm-plus 基线在概念层面的 F1 为 0.859。 The full RxMap pipeline with Gemini-2.0-Flash as the LLM hit an F1 of 0.966 at the concept level and 0.972 at the ingredient level. 使用 Gemini-2.0-Flash 作为 LLM 的完整 RxMap 流程，在概念层面达到 0.966 的 F1，在成分层面达到 0.972。 JORDAN: So the precision and recall are both around 0.96 to 0.97. 所以精确率和召回率都在 0.96 到 0.97 左右。 ALEX: Precision 0.969, recall 0.964 on the big set. 在大数据集上精确率 0.969，召回率 0.964。 The other big number is an even older deterministic baseline, RxNorm-OHDSI, which managed only an F1 of 0.24 on this survey data — mostly because it couldn't handle multi-ingredient formulations at all. 另一个显著的数字是一个更老的确定性基线 RxNorm-OHDSI，它在这份调查数据上的 F1 仅为 0.24——主要因为它根本无法处理多成分制剂。 They also swapped in GPT-5-Nano instead of Gemini, and it did slightly worse, around 0.906 F1, which tells you the pipeline structure matters but the LLM choice still moves the number. 他们也把 Gemini 换成 GPT-5-Nano，效果略差，约 0.906 F1，这说明流程结构很重要，但 LLM 的选择仍会影响数值。 JORDAN: What about cost and speed? 那成本和速度呢？ ALEX: About 3.7 seconds per string and roughly two-hundredths of a cent per mapping with Gemini, and crucially they cache by medication string so repeated drugs don't re-hit the LLM. 用 Gemini 大约每条字符串 3.7 秒、每次映射约两百分之一美分，关键是他们按药物字符串做缓存，因此重复的药物不会再次调用 LLM。 For a registry-scale dataset with lots of repeated meds, caching makes this genuinely cheap. 对于一个有大量重复用药的登记库规模数据集，缓存让这真正变得便宜。 JORDAN: And where does it fail? 那它在哪里失败？ ALEX: Honestly, in the subset-matching tier. 老实说，是在子集匹配这一层。 Most errors are there: collapsing to a generic form instead of the specific chemical — vitamin D instead of cholecalciferol — mapping herbals to their active compound instead of the botanical, and picking the wrong salt form of a branded drug. 大多数错误都在这里：坍缩到通用形式而非具体化学物——用维生素 D 代替胆钙化醇——把草药映射到其活性化合物而非植物来源，以及选错品牌药的盐型。 That's the price of LLM generalization: robustness to misspellings, but loss of fine chemical specificity. 这是 LLM 泛化的代价：对拼写错误的鲁棒性，但丧失了精细的化学特异性。 The low-confidence flag is how they let you catch those. 低置信度标记就是他们让你捕捉这些错误的方式。

JORDAN Let me make the subset-matching step concrete, because that's the clever part. 让我把子集匹配这一步讲具体，因为那是巧妙的部分。 ALEX: Take a combination cough syrup that the LLM parses into four ingredients, but RxNorm has no single concept covering all four. 拿一种复方止咳糖浆，LLM 把它解析成四种成分，但 RxNorm 没有一个概念能覆盖全部四种。 Instead of giving up, RxMap tries the largest subset of those four that does match a valid RxNorm concept — say a three-ingredient combination — locks that in, removes those three, and then matches the remaining ingredient on its own. 与其放弃，RxMap 会尝试这四种中能匹配到一个有效 RxNorm 概念的最大子集——比如一个三成分组合——锁定它，移除那三种，然后单独匹配剩下的那一种。 The final answer might be two RxNorm concepts that together cover the original string. 最终答案可能是两个 RxNorm 概念，合起来覆盖原始字符串。 JORDAN: So it preserves the structure instead of collapsing a combo into one wrong pick. 所以它保留了结构，而不是把一个组合坍缩成一个错误的选择。 ALEX: Right, and that's why it beat the old RxNorm-OHDSI baseline so badly — that baseline simply couldn't decompose multi-ingredient products, so it scored an F1 of 0.24 on survey data full of them. 对，这就是它把旧的 RxNorm-OHDSI 基线甩开这么远的原因——那个基线根本无法拆解多成分产品，所以在满是这类产品的调查数据上只得到 0.24 的 F1。 The cost is that subset matches operate only on the LLM's ingredient list without deterministic cross-checking, which is why they're labeled low confidence and why most of the residual errors live there. 代价是子集匹配只在 LLM 的成分清单上操作，没有确定性交叉核对，这就是为什么它们被标为低置信度，也是为什么大多数残余错误都在那里。

JORDAN How does this compare to the clinical NLP toolkits I've heard of — cTAKES, MedEx, that family? 这和我听说过的临床 NLP 工具包——cTAKES、MedEx 那一类——相比如何？ ALEX: Good question, and the authors address it directly. 好问题，作者直接回应了这一点。 Tools like MedXN, MedEx, and cTAKES are built to extract medication mentions from clinical narrative text — to find the drug names inside a doctor's note. 像 MedXN、MedEx 和 cTAKES 这样的工具是为了从临床叙述文本中抽取药物提及——在医生的病历里找到药名。 RxMap assumes you already have the medication strings — from a survey, a dispensing record, a registry field — and focuses entirely on the normalization step, mapping those strings to stable identifiers. RxMap 假设你已经有了药物字符串——来自调查、配药记录或登记库字段——并完全专注于标准化这一步，把这些字符串映射到稳定标识符。 They're complementary: extraction finds the string, normalization pins it to a concept. 它们是互补的：抽取找到字符串，标准化把它钉到一个概念上。 The authors even flag that chaining an extractor in front of RxMap would give you an end-to-end pipeline from raw clinical text to analyzable drug data. 作者甚至指出，在 RxMap 前面串接一个抽取器，就能得到一条从原始临床文本到可分析药物数据的端到端流程。 JORDAN: And the reproducibility story — why does that matter for a research tool specifically? 那可复现性这一点——它为什么对研究工具尤其重要？ ALEX: Because a normalization that isn't reproducible quietly poisons every downstream analysis. 因为一个不可复现的标准化会悄悄毒害每一个下游分析。 They query the live RxNorm API, use deterministic decoding for the LLM so the same string yields the same parse, and cache every mapping so a rerun doesn't drift. 他们查询实时的 RxNorm API，对 LLM 使用确定性解码，使同一字符串产生同样的解析，并缓存每一个映射，使重跑不会漂移。 That's the difference between a demo and something you'd actually build a cohort definition on. 这就是一个演示和一个你真正能用来构建队列定义的东西之间的区别。
