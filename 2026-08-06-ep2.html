Show notes — Track B — 2026-08-06

Towards automated phenotype definition extraction using large language models — Tekumalla R, et al. Genomics & Informatics, 2024.

Blurb

Tekumalla and colleagues test a direct, practical question: can GPT-3.5 and GPT-4 draft the code lists and inclusion/exclusion logic of a computable phenotype definition well enough to speed up the weeks-long manual process clinicians and informaticians currently use? They build a first-of-its-kind ten-phenotype benchmark (five from PheKB, five from OHDSI's phenotype library), design a structured extraction prompt through iterative testing, and score GPT-3.5 vs. GPT-4 and GPT-4 vs. human-curated ground truth on code overlap, string overlap, and logic correctness. GPT models handle codes better than text strings and are genuinely solid at inferring inclusion/exclusion logic, but both hallucinate non-existent codes — GPT-3.5 more than GPT-4 — with hallucination rates tracking inversely with how well-documented a phenotype is in the literature. For us this lands on AI-tooling and career: the buildable move is a phenotype-definition drafter-and-auditor that runs the paper's exact prompt template but adds run-to-run stability checks and a code-dictionary cross-check to catch hallucinations before a human reviewer has to.

Plain-English glossary

  • Computable phenotype definition — a full, structured rule (codes + vocabulary + logic) for identifying a cohort of patients with a given condition from raw coded data, as opposed to a single diagnosis code on one visit.（中文：可计算表型定义——一套完整的、结构化的规则（编码+词汇表+逻辑），用于从原始编码数据中识别患有某疾病的患者队列，区别于一次就诊记录中的单个诊断编码。）
  • Electronic phenotyping — the broader process of extracting relevant health characteristics from structured and unstructured patient data to define a cohort or trait.（中文：电子表型分析——从结构化和非结构化患者数据中提取相关健康特征、以定义队列或性状的整体过程。）
  • PheKB — a community platform for sharing validated phenotype algorithms, not tied to any single underlying data model.（中文：PheKB——一个用于共享经过验证的表型算法的社区平台，不依赖任何单一的底层数据模型。）
  • OMOP Common Data Model (OHDSI) — a standardized schema that different institutions' data gets mapped into, so the same phenotype logic runs unchanged across sites; OHDSI's phenotype library is built on top of it.（中文：OMOP 通用数据模型（OHDSI）——一种标准化数据结构，不同机构的数据被映射到该结构中，使同一套表型逻辑可在不同机构间原样运行；OHDSI 的表型库即建立在其之上。）
  • Code vocabulary (ICD-10 / SNOMED / RxNorm) — the different standardized coding systems a phenotype definition's codes are drawn from (diagnoses, clinical concepts, and drugs respectively).（中文：编码词汇表（ICD-10／SNOMED／RxNorm）——表型定义中编码所依据的不同标准化编码体系，分别对应诊断、临床概念和药物。）
  • Cohort Diagnostics / PheValuator — OHDSI tools for validating whether a phenotype definition actually selects a sensible, accurate patient cohort when run against real data — the validation step this paper flags as future work but doesn't perform.（中文：Cohort Diagnostics／PheValuator——OHDSI 提供的工具，用于验证一个表型定义在真实数据上运行时，是否真的能筛选出合理、准确的患者队列——本文将其列为未来工作，但本身并未执行这一验证步骤。）

Methods / tools to lift

  • Iterative prompt-engineering process (zero-shot → one-shot → iterative → seeding) converging on one structured extraction prompt template.
  • PheKB / OHDSI phenotype library as ground-truth benchmark sources for a first-of-its-kind ten-phenotype evaluation set.
  • Code-overlap / string-overlap / logic-correctness scoring framework for comparing LLM output to human-curated definitions.
  • Dictionary cross-check (Biomedical Content Explorer linked to ICD-10 / ICD-10-CM) for detecting hallucinated, non-existent codes.

Where it lands + buildable artifact

Serves: AI-tooling / career. MVP (paste-ready): Given a phenotype name and short plain-language description, run the paper's exact extraction prompt template against an LLM multiple times to measure run-to-run stability (flagging codes that don't appear consistently), then cross-check every generated code against an authoritative dictionary (ICD-10/SNOMED/RxNorm) to flag hallucinated codes — output a draft code-and-logic table with per-code stability and hallucination flags for human review, never auto-deployed. Input: phenotype name + description. Difficulty: M.

What to verify first

  • Benchmark skew — the 10-phenotype eval set skews toward common, well-documented conditions (T2D, AMI); the paper's own mechanism (thin training data → thin/hallucinated output) predicts rarer, CF-specific phenotypes could perform worse, untested here.
  • No cohort-level validation performed — extracted definitions were never run against real patient data to check they select a sensible cohort; that validation step (via OHDSI Cohort Diagnostics/PheValuator) is explicitly future work, not a result of this paper.
  • Hallucination check only catches nonexistent codes — it can't detect a code that's real but simply wrong for the phenotype, a subtler failure mode a dictionary lookup alone can't flag.

JORDAN So did it actually work? What did they find? 那它到底管不管用？他们发现了什么？

ALEX Mixed, and specific about where it breaks. 结果好坏参半，而且清楚指出了具体在哪里失效。 GPT models were consistently better at generating precise codes than at generating matching textual descriptions — code overlap was a more reliable metric than string overlap across both comparison scenarios.
