gprofiler2 — an R package for gene list functional enrichment analysis and namespace conversion toolset g:Profiler

Kolberg, Raudvere, Kuzmin, Vilo and Peterson (F1000Research, 2020) describe gprofiler2, the R package that wraps the g:Profiler REST API — a central backend serving the web tool, this R package, a Python package and a Galaxy tool identically. Four functions do the work: gost for over-representation enrichment against GO/KEGG/Reactome/WikiPathways/Human Phenotype Ontology and more, gconvert for identifier namespace conversion across 30+ namespaces and 190+ species, gorth for cross-species ortholog mapping, and gsnpense for mapping SNP rs-IDs to genes and variant effects. Because every access point hits the same versioned backend — archived continuously since 2011 — results are reproducible against a fixed database snapshot, and custom annotation sets can be registered via the standard GMT file format. The paper walks a real DESeq2 RNA-seq use case end to end, including export into enrichplot/clusterProfiler and Cytoscape's EnrichmentMap. For Runyu this lands on the colocalization/MR track: candidate genes from modifier-locus hits are exactly the gene lists this tool was built to interpret, and the buildable artifact is a thin, version-pinned enrichment-and-archiving wrapper around it.

Plain-English glossary

  • GMT file (Gene Matrix Transposed) — a tab-delimited text format where each row is one functional term with its ID, description, and member gene list; the standard way to bring a custom gene set into an enrichment tool.（中文:一种tab分隔的文本格式,每一行代表一个功能term及其ID、描述和成员基因列表;是把自定义基因集带入富集分析工具的标准方式。）
  • Gene Ontology (GO) — a controlled, hierarchical vocabulary of biological processes, molecular functions, and cellular components used to annotate genes.（中文:一套受控的、分层的词表,涵盖生物过程、分子功能和细胞组分,用于注释基因。）
  • KEGG / Reactome — curated pathway databases mapping genes to specific metabolic or signaling pathways.（中文:经过整理的通路数据库,将基因映射到具体的代谢或信号通路。）
  • Namespace conversion — translating gene/protein identifiers between systems (e.g. Ensembl ID, Entrez ID, gene symbol) that most annotation databases don't natively cross-reference.（中文:在不同的基因/蛋白标识符系统(如Ensembl ID、Entrez ID、基因符号)之间转换,因为大多数注释数据库并不天然互相对照这些系统。）
  • Ordered query — an enrichment mode that reruns the test iteratively as genes are added in rank order (e.g. by fold change), reporting the minimal p-value and list size per term; conceptually related to GSEA's rank-based logic.（中文:一种富集分析模式,按排名顺序(如按fold change)逐步加入基因并迭代重新检验,为每个term报告最小p值和对应列表长度;在概念上与GSEA基于排名的逻辑相关。）
  • Ortholog mapping — identifying the corresponding gene in another species, used to transfer findings between human and model organisms.（中文:识别另一物种中对应的基因,用于在人类和模式生物之间迁移研究发现。）
  • Over-representation analysis — testing whether genes from a given annotation term appear in a gene list more often than expected by chance, given a background gene universe.（中文:检验某个注释term下的基因,在给定背景基因集合的情况下,是否比随机预期更频繁地出现在一份基因列表中。）
  • rs-ID — the reference SNP identifier (e.g. rs1042522) used to name a specific genetic variant in public databases.（中文:参考SNP标识符(如rs1042522),用于在公共数据库中指代某个具体的遗传变异。）

Methods / tools to lift

  • gost — over-representation analysis against GO/KEGG/Reactome/WikiPathways/HPO/CORUM via one API call, with query metadata recording the exact database version used.
  • gconvert / gorth — identifier namespace conversion and cross-species ortholog mapping.
  • upload_GMT_file — register a custom annotation set (e.g. a disease-gene list) and get a reusable token shared between the R package and web tool.
  • Version pinning (set_base_url, get_version_info) and short-link result archiving for reproducibility.

Where it lands + buildable artifact

Serves summary-stats colocalization/MR at known modifier loci: candidate genes from colocalization or MR hits are the input gene lists this tool is built to interpret functionally. Buildable artifact: a reproducible modifier-locus enrichment module — version-pinned gost calls over colocalization/MR candidate lists, Manhattan plots per locus (or a multi-locus comparison object), and auto-generated short-link tokens so every enrichment result in a write-up is independently re-openable. Difficulty: S.

What to verify first

  • Whether the default genome-wide background gene universe is appropriate for a modifier-locus candidate list, or whether a tissue- or LD-block-restricted background changes the enrichment picture.
  • How durable version-pinned URLs and short-links actually are over multi-year timeframes — this depends on the server's own maintenance, not on anything the paper can guarantee.
  • What has changed in the current CRAN release of gprofiler2 relative to the 0.1.9 version described here, especially the parameters reviewers flagged as under-documented.

JORDAN And namespace conversion — gene symbol, Ensembl ID, Entrez ID? 还有命名空间转换——基因符号、Ensembl ID、Entrez ID?

ALEX Same gene, three different identifier systems, and most annotation databases only speak one of them fluently, so any real pipeline spends real time just converting between namespaces before the actual analysis can start — that busywork is half of what this package is selling. 同一个基因,三套不同的标识符系统,而大多数注释数据库只能"流利地"使用其中一种,所以任何实际的流程,在真正的分析开始之前,都要花不少时间仅仅是在不同命名空间之间转换——这种繁琐工作正是这个包所要解决的一半问题。

ALEX Zoom out to the actual problem. 往大了看,这要解决的真正问题是什么。 g:Profiler the web tool has existed since 2007, handling gene lists from over 600 species, and its best-known function is exactly that over-representation analysis against GO, KEGG, Reactome and a handful of other sources. 作为网页工具的g:Profiler自2007年起就存在,处理来自600多个物种的基因列表,它最著名的功能正是针对GO、KEGG、Reactome以及其他少数几个来源进行过度代表性分析。 The gap this paper fills is programmatic access: before gprofiler2, an R user wanting this functionality inside an automated pipeline either had to scrape the website, or use an R package like topGO or clusterProfiler that manages its own local copies of annotation data — which means you own the burden of keeping that local data current as databases update. 这篇论文要填补的空白是程序化访问:在gprofiler2之前,想在自动化流程里使用这个功能的R用户,只能去爬网页,或者使用像topGO或clusterProfiler这样的R包,而这些包需要自己在本地维护一份注释数据的拷贝——也就是说,保持这些本地数据与数据库更新同步的负担,要由你自己承担。

ALEX Exactly, and the upside they're after is consistency — because the R package, the web tool, a Python package, and a Galaxy tool all hit the same backend, results computed through any of these access points are guaranteed identical, and the backend's version history going back to 2011 is kept archived specifically so a result can be reproduced against the exact database snapshot it was computed on. 没错,他们追求的好处是一致性——因为R包、网页工具、Python包和Galaxy工具都调用同一个后端,通过任何一个入口计算出的结果都保证是一致的,而且后端自2011年起的版本历史都被专门存档,这样一个结果就可以针对计算它时所用的那个确切数据库快照被复现出来。 Before this, if you ran enrichment analysis twice six months apart with a tool that silently auto-updates its local database, you had no clean way to know whether a changed result was biology or just database drift. 在此之前,如果你用一个会静默自动更新本地数据库的工具,间隔六个月跑两次富集分析,你根本没办法干净地判断,结果的变化是来自生物学本身,还是仅仅来自数据库的漂移。

JORDAN What about ordered queries — ranking genes by fold change instead of treating the list as flat? 那有序查询呢——按fold change对基因排序,而不是把列表当作一个无序集合?
