How did this episode land for you?

Large language models for data extraction from unstructured and semi-structured electronic health records

A 2025 benchmark in BMJ Health Care Informatics from a cardiac-surgery team at University Hospital Zurich and Triemli Hospital, evaluating 18 LLMs (Claude 1.0 through 3.0 Opus/Sonnet/Haiku, GPT-4 and 3.5, Gemini/Gemini Advanced, PaLM 2 chat-bison, several Llama sizes, Mistral, Cohere) against a fine-tuned RoBERTa baseline on extracting four entities (patient ID, EuroSCORE 2, admission/discharge dates) and classifying five postoperative complications from 50 synthetic, class-balanced, noise-injected cardiac-surgery notes, zero-shot, one prompt per patient. Claude 3 Opus topped the leaderboard at 0.995 overall accuracy (two errors out of 450 values), with seven more models clearing 0.98 — all far ahead of RoBERTa's 0.742. The authors themselves flag the key interpretive caveat: because prevalence was deliberately balanced at 50% per complication, accuracy here sits exactly midway between recall and specificity, and would skew toward specificity alone at the much lower prevalence any real rare-event extraction task would actually face. The paper's real-world deployment blocker, named explicitly in its own discussion, is sending real sensitive patient notes to an external cloud LLM API — "a serious, if not insurmountable, challenge." The transferable idea for registry QC is adjudication support: once a candidate-generation model flags an anthropometric value, an LLM could pull supporting or contradicting context from unstructured clinical notes to help a human reviewer decide error-vs-real-event faster — not replacing the reviewer, but shrinking the time each case takes.

Plain-English glossary

  • EuroSCORE 2 — European System for Cardiac Operative Risk Evaluation, version 2; a validated clinical score estimating a patient's predicted mortality risk from cardiac surgery, expressed as a percentage.（中文:欧洲心脏手术风险评估系统第二版;一个经过验证的临床评分,用于估计患者接受心脏手术的预测死亡风险,以百分比表示。）
  • Entity extraction — pulling a specific, discrete value (a number, a date, a name) out of free text, as distinct from classifying text into categories.（中文:从自由文本中提取出一个具体、离散的值（数字、日期、名称),区别于把文本归类到某个类别。）
  • Krippendorff's alpha — a reliability statistic (here, used to measure how consistently the same model gives the same answer across repeated identical prompts); 1.0 means perfect agreement.（中文:一种信度统计量（此处用于衡量同一模型对重复的相同提示给出相同答案的一致程度);1.0表示完全一致。）
  • Zero-shot (clinical-extraction context) — asking a model to extract or classify information using only the instructions in the prompt, with no worked examples provided beforehand.（中文:只凭提示中的指令要求模型提取或分类信息,事先不提供任何示范样例。）

Methods / tools to lift

  • 18-model LLM benchmark design — zero-shot, single-prompt-per-record, class-balanced synthetic-note construction with deliberately injected noise (semantically-related-but-distinct complications, typos, context-dependent abbreviations).
  • Multi-run consistency check (Krippendorff's alpha over 3 identical-prompt runs) — a reusable pattern for testing whether an LLM's extraction is stable, not just accurate once.
  • Synthetic-note approach to avoid ethics-committee overhead — using domain-expert-drafted synthetic notes instead of real PHI, when the goal is methods evaluation rather than deployment.

Where it lands + buildable artifact

Pipeline stage: primarily (b) adjudication, secondary (c) review budget — this paper's extraction methodology (not its cardiac-surgery-specific numbers) demonstrates that modern LLMs can reliably pull structured entities and binary flags from free-text clinical narrative, which is exactly the kind of context a human adjudicator needs when deciding whether a flagged anthropometric value is a data-entry error or a genuine clinical event.

Buildable artifact (M): LLM-Assisted Adjudication Assistant — for every anthropometric case already flagged by a candidate-generation model and routed to human review, feed relevant free-text clinical-note excerpts to an LLM with a structured prompt asking it to extract and surface supporting or contradicting context (documented illness, growth-relevant diagnosis, measurement circumstances), displayed alongside the flagged value; validate extraction accuracy against a small human-adjudicated gold set before it touches any real review queue.

What to verify first

  • This benchmark's headline numbers come from a 50/50-balanced, single-specialty, single-author, short-note (median 192 words) sample — re-run something comparable on genuinely relevant clinical note style, length, and true (not artificially balanced) prevalence before trusting the numbers.
  • The paper's own named deployment blocker — sending real sensitive patient notes to an external cloud LLM API — is unresolved here; local open-source model deployment and de-identification/date-shifting are only gestured at, not tested.
  • Whether any LLM-assisted extraction or adjudication support could ever touch real registry clinical notes, under what governance model, is entirely a question for CFF's own data-governance process — not something asserted or assumed here.

Pipeline stage

(b) adjudication — primary; (c) review budget — secondary.

Error types covered / not covered

Covered: entity-extraction errors (wrong numeric/date values) and misclassification of documented clinical events from free text — the paper's own target tasks. Not covered: unit conversion, digit transposition, decimal-shift errors, or carry-forward values — none of these are anthropometric-specific error types this paper addresses; it is about extracting what the text already says, not about judging whether a structured value itself is numerically implausible.
