Ep3 — Track C (1/2): Facilitating harmonized data quality assessments (dataquieR)

Paper: Schmidt CO, Struckmann S, Enzenbach C, Reineke A, Stausberg J, Damerow S, Huebner M, Schmidt B, Sauerbrei W, Richter A. "Facilitating harmonized data quality assessments. A data quality framework for observational health research data collections with software implementations in R." BMC Medical Research Methodology. 2021. Full text available via the PMC-OA BioC route.

A four-dimension data quality framework — integrity, completeness, consistency, accuracy — built for designed research data collections (cohort studies) rather than registries/EHRs, extending Germany's TMF guideline and shipped as the open-source dataquieR R package on CRAN. 34 named indicators (DQI-1001 and up), each mapped to one or more R functions, demonstrated end-to-end on the SHIP (Study of Health in Pomerania) cohort. No sensitivity/specificity/PPV — this is a framework-and-software paper, not a validated-classifier paper. The key decision rule for us: consistency is Boolean hard-range checking (con_limit_deviations()), while accuracy is where actual statistics (unexpected distributions/associations, disagreement of repeated measurements) live — a clean conceptual split worth borrowing as vocabulary regardless of whether the specific R functions get reused. Lands primarily on the CFFPR outlier pipeline's candidate-generation stage (cheap hard-rule pre-filtering), secondarily as a vocabulary/framework to adopt. Buildable artifact: an R script wrapping pro_applicability_matrix() and con_limit_deviations() against a toy longitudinal height/weight table with a metadata sidecar, producing a flagged subset and a dq_report()-style summary.

Plain-English glossary

  • Accuracy (dimension) — The data quality dimension covering unexpected distributions, unexpected associations with other variables or process variables, and disagreement between repeated measurements — the dimension that runs actual statistical methods.（中文:准确性维度,涵盖意外的分布、与其他变量或过程变量的意外关联,以及重复测量之间的不一致——是真正运行统计方法的维度。）
  • Completeness (crude vs. qualified missingness) — Crude missingness counts missing values regardless of cause; qualified missingness uses coded reasons (refusal, exclusion) to compute specific rates like non-response rate.（中文:完整度〔粗略缺失与限定缺失〕,粗略缺失不问原因地统计缺失值数量;限定缺失利用编码过的原因〔拒绝、排除〕来计算无应答率等具体比率。）
  • Consistency (dimension) — Boolean-type hard checks: whether a value falls within its admissible range, or whether a combination of values is possible — distinct from accuracy's statistical checks.（中文:一致性维度,布尔型硬性检查:一个值是否落在允许范围内,或多个值的组合是否可能——区别于准确性维度的统计检查。）
  • Integrity (dimension) — Structural/technical compliance: does the observed data match the expected schema, do data types match metadata, are there duplicate records.（中文:完整性维度,结构性/技术性合规检查:观测数据是否符合预期架构,数据类型是否与元数据匹配,是否存在重复记录。）
  • Intrinsic vs. contextual data quality — Intrinsic quality is a property of the data itself regardless of use (e.g. a height of 400cm is always wrong); contextual quality depends on the specific analysis the data will be used for.（中文:内在质量与情境质量,内在质量是数据本身固有的属性,与用途无关〔例如400厘米的身高永远是错的〕;情境质量则取决于数据将被用于的具体分析。）
  • TMF guideline — The German umbrella organization Technology, Methods, and Infrastructure for Networked Medical Research's data quality guideline, the direct ancestor this framework extends.（中文:TMF指南,德国伞形组织"网络化医学研究的技术、方法与基础设施"〔TMF〕发布的数据质量指南,是本框架直接继承并扩展的前身。）
  • Weiskopf & Weng framework — A widely cited EHR data-quality taxonomy naming completeness, correctness, and currency (whether a value still reflects the clinically relevant time) as core dimensions.（中文:Weiskopf与Weng框架,一个被广泛引用的电子健康记录数据质量分类法,列出完整性、正确性和时效性〔一个值是否仍反映临床相关时间点〕为核心维度。）

Methods / tools to lift

  • dataquieR R package (CRAN) — ships the full indicator computation suite plus dq_report() for all-at-once HTML reports.
  • con_limit_deviations() — hard-rule range/limit-violation checker; the function closest to anthropometric implausible-value flagging, but note it's a consistency-dimension (rule-based), not accuracy-dimension (statistical), check.
  • pro_applicability_matrix() — upstream check that study data types/structure match metadata before anything else runs.
  • Four-dimension taxonomy (integrity/completeness/consistency/accuracy) — worth adopting as shared vocabulary independent of the R code.

Where it lands + buildable artifact

Pipeline stage: (a) candidate generation, primary (cheap hard-rule pre-filter via con_limit_deviations()/pro_applicability_matrix()); (e) vocabulary/framework, secondary (the four-dimension taxonomy is worth borrowing wholesale). Buildable artifact: an R script applying pro_applicability_matrix() and con_limit_deviations() to a toy longitudinal height/weight table with a metadata sidecar (admissible types + ranges), outputting a flagged-record subset plus a dq_report()-style HTML summary. Difficulty: S–M.

Error types covered / not covered

  • Covered: data-type mismatches (e.g. the SHIP waist-circumference example), simple out-of-admissible/global-range violations, crude/qualified missingness.
  • Not covered: within-person longitudinal deviation (a value in-range globally but implausible for one individual's own trajectory — the growthcleanr/spline-model territory); no stated handling of unit-conversion errors, digit transposition, decimal shifts, or carry-forward values specifically.

What to verify first

  • Whether con_limit_deviations() supports per-individual/per-subgroup limits or only a single global range per variable (unclear from the paper for a pediatric-growth use case where admissible ranges shift with age).
  • Whether the accuracy dimension's "unexpected distributions" indicators could be adapted to within-person longitudinal deviation rather than the cross-sectional SHIP demonstration.
  • Nothing here implies anything about CFFPR's own current cleaning logic or flag rates — out of scope for this episode.

ALEX Intrinsic data quality means the data has quality problems in its own right, independent of any particular analysis you plan to run on it — a height value of 400 centimeters is wrong no matter what question you're asking. 内在数据质量指的是数据本身存在质量问题,与你打算在它上面做什么分析无关——一个400厘米的身高值,无论你要回答什么问题,它都是错的。 Contextual data quality, by contrast, is quality relative to a specific use — a dataset missing smoking status might be perfectly fine for a study of blood pressure and totally unusable for a study of lung cancer risk. 相对地,情境数据质量是相对于某个具体用途而言的质量——一个缺失吸烟状态的数据集,对血压研究来说可能完全没问题,但对肺癌风险研究来说就完全不可用。 This paper deliberately scopes itself to intrinsic quality only. 这篇论文特意把自己的范围限定在内在质量上。 It also leans on a well-known EHR data-quality taxonomy from Weiskopf and Weng, which names three core dimensions — completeness, correctness, and currency, where currency means whether a value still reflects the clinically relevant point in time — and the authors here explicitly drop currency as less important for a designed research collection, since the timing of a planned study visit is already controlled, unlike a value pulled opportunistically from an EHR. 它还借用了Weiskopf和Weng提出的一个知名的电子健康记录(EHR)数据质量分类法,其中列出了三个核心维度——完整性(completeness)、正确性(correctness)和时效性(currency,指一个值是否仍然反映临床相关的时间点)——而本文作者明确舍弃了时效性这一维度,因为在一个设计好的研究数据收集流程里,计划好的研究访视时间本身就是受控的,不像从EHR里机会性抓取的数值那样需要额外核实时效。 You'll also hear "TMF guideline" — TMF is a German umbrella organization, Technology, Methods, and Infrastructure for Networked Medical Research, and its data quality guideline is the direct ancestor this framework builds on and extends. 你还会听到"TMF guideline"这个说法——TMF是一个德国的伞形组织,全称Technology, Methods, and Infrastructure for Networked Medical Research(网络化医学研究的技术、方法与基础设施),它的数据质量指南正是这个框架直接继承并扩展的前身。
