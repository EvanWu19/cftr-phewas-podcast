Blurb

Full text plus public code. The paper proposes Medical Data Pecking, a methodology that ports software unit-testing discipline to medical data validation, and demonstrates it with a reference implementation, MDPT. The core claim is that existing data-quality tooling stalls at syntactic checks — field present, type correct, code well formed — while the failures that matter are semantic: data that is structurally perfect and epidemiologically implausible. It introduces Semantic Data Coverage (how much of your data is actually checked against epidemiological ground truth) and the Semantic Gap (syntactic integrity without semantic plausibility). Implementation: a RAG architecture that pre-embeds OMOP/ICD/LOINC/SNOMED/RxNorm vocabularies into a Chroma vector database, retrieves reference epidemiological statistics via web search with prompted preference for government health agencies and peer-reviewed literature, builds a structured test matrix of expected ranges, and then runs a second independent Auditor Agent that re-searches and corrects each proposed statistic before it becomes a test. Generation is deliberately isolated from execution — the generation module sees only the study specification and data dictionary, never raw patient data — which is a genuinely deployable design for a controlled-access environment. Evaluated on four cohorts (T2D and CKD in All of Us v7, hypertension in SyntheticMass, CHF in MIMIC-III v1.4). Not about anthropometrics, and importantly not a per-record detector: it flags a variable's distribution, not a row.

Plain-English glossary

  • Auditor Agent — A second LLM pass that independently re-searches and verifies (or corrects) each literature-derived expected value before it is committed as a test.（中文：审计智能体，第二次LLM处理，独立重新检索并核实或修正每个源自文献的期望值，然后才把它固化为一项测试。）
  • CDC vs WHO growth references — CDC charts describe how US children did grow (roughly age 2+); WHO standards prescribe how healthy children should grow (under 2, breastfed reference population). Not interchangeable.（中文：CDC生长曲线描述美国儿童实际的生长情况（约2岁以上）；WHO标准规定健康儿童应当如何生长（2岁以下，母乳喂养参考人群）。两者不可互换。）
  • Implied truth effect — The risk that a reviewer reads absence of a warning as an endorsement of data quality; the paper's tri-state protocol exists to counter it.（中文：隐含真实效应，指复核者可能把"没有警告"读作对数据质量的背书；论文的三态协议正是为对抗它而设。）
  • LMS parameters — Lambda (Box-Cox skew), Mu (median), Sigma (coefficient of variation) per age and sex; the machinery that turns a raw measurement into a z-score.（中文：LMS参数，按年龄与性别给出的Lambda（Box-Cox偏度）、Mu（中位数）、Sigma（变异系数），是把原始测量值转换为z分数的机制。）
  • Proportional tolerance — For categorical prevalence, the allowed observed-to-expected ratio band; here 0.85–1.15, so >15% deviation fails. The sensitivity analysis shows this is the knob that matters.（中文：比例容差，对分类变量患病率允许的观察/期望比值区间，此处为0.85–1.15，偏差超过15%即判失败。敏感性分析显示这是真正起作用的旋钮。）
  • RAG — Retrieval-augmented generation; the model's outputs are anchored in retrieved source documents rather than its own parametric knowledge.（中文：检索增强生成，模型输出锚定在检索到的源文档上，而不是它自身的参数化知识。）
  • Reverse ecological fallacy — Assuming a highly filtered clinical cohort (e.g. an ICU population) should mirror national averages; the paper names this as an inherent noise floor of its own method.（中文：逆生态学谬误，即假定一个经高度筛选的临床队列（如ICU人群）应与全国平均值一致；论文将其指认为自身方法的固有噪声底。）
  • Semantic Data Coverage — The fraction of your variables actually validated against epidemiological ground truth, by analogy with software test coverage.（中文：语义数据覆盖度，即你的变量中真正对照流行病学基准真值验证过的比例，类比软件测试覆盖率。）
  • Semantic Gap — A statistically significant divergence where data keeps syntactic integrity but lacks semantic plausibility.（中文：语义缺口，指数据保持句法完整性、却缺乏语义合理性的统计显著性偏离。）
  • SMD — Standardized mean difference; used here as a magnitude filter on top of a p-value, so trivially small deviations in large datasets don't trigger flags. Threshold 0.2.（中文：标准化均值差，在p值之上作为效应量过滤器，避免大数据集中微小偏差触发标记。阈值为0.2。）
  • Tri-state reporting — Passed / Failed (Semantic Gap) / Inconclusive (no reference or out of scope), with "no reference" treated as a distinct category rather than a default pass.（中文：三态报告，即通过／失败（语义缺口）／无法判定（无参考值或超出范围），把"无参考值"作为独立类别而非默认通过。）

Methods / tools to lift

  • Generation/execution isolation: the test-generating module sees only the study specification and data dictionary; the executing module runs inside the secure perimeter against raw data. Directly applicable to any controlled-access registry environment.
  • Versioning the test matrix as a static asset once generated, so a stochastic LLM/search step can't make the audit irreproducible — the audit trail is the fixed matrix, not the prompt.
  • Tri-state reporting (Passed / Failed / Inconclusive), with "no reference available" as its own category, so absence of a flag is not read as a pass.
  • Magnitude filter on top of significance: SMD ≥ 0.2 gate on a Welch's t-test result, so trivially small deviations in large N don't flag.
  • Explicit sensitivity analysis over thresholds as a standard reporting item — here it showed proportional tolerance (10–30%) dominates while the SMD cutoff (0.2/0.5/0.8) barely matters.
  • Positive-control validation in the absence of a gold standard: use a dataset with known, documented skews and check whether the method independently rediscovers them.
  • Zero-prevalence failures as a separate diagnostic class from ordinary distributional misalignment — the causes are different in kind (technical artifact vs cohort-specification gap vs granularity mismatch).

Results worth remembering

  • 55–73 tests generated autonomously per cohort; metadata/syntactic checks were <2% of the suite.
  • Auditor Agent in the CHF cohort corrected 55.0% of original tests and discarded only 10.0%.
  • Reference validity by single-reviewer curation: 35–93% across suites; 39–98% excluding drug-prevalence tests (public pharmaceutical-usage data is fragmented).
  • 90–97% of semantic tests failed across all cohorts. Restricted to the Auditor-verified correct subset: 87.1% CHF, 97.3% T2D, 100% both hypertension and CKD. T2D 54/60 failed; CKD 65/67.
  • No gold standard — real-world datasets have no answer key for data quality. Validation was a positive control: without manual configuration, the gender and race distribution tests failed in All of Us, correctly picking up its known recruitment skews.
  • Best single find: in MIMIC-III, ICD-9 codes stored without decimal points passed every syntactic check but matched no standard phenotype algorithm, so observed CHF prevalence dropped to near zero — caught only as an impossible prevalence.

Pipeline stage

(a) candidate generator — with the granularity caveat stated explicitly: candidates are generated at the variable/cohort level, not the record level. It says "this cohort's height distribution disagrees with the literature", not "this child's height entry is wrong". Secondary contribution to (e) vocabulary/framework (Semantic Data Coverage, Semantic Gap, tri-state reporting).

Error types covered / not covered

Covered: systematic distributional shifts in a variable; format-level conventions that render valid data invisible to downstream algorithms (the decimal-point case); cohort-specification gaps; concept-granularity mismatch between query and dataset; known population-composition skews.

Not covered: individual implausible records; within-patient longitudinal inconsistency (no temporal coherence tests in this implementation, though the authors say the architecture could be extended to them); anything in a subgroup whose deviation cancels at the population level — the authors name reliance on general-population benchmarks as their main limitation; and by construction it cannot distinguish a data error from a legitimate cohort-selection effect, since "failure" is defined as any objective non-alignment regardless of cause.

Where it lands + buildable artifact

Artifact: epidemiological-prior test suite for anthropometric variables. Difficulty S for the harness, M for sourcing defensible priors (the actual work).

MVP line: hand-write (not generate) ten to fifteen assertions, each stating an expected distributional property of height or weight z-scores in a defined stratum, with a literature citation and a version date — e.g. the mean z-score in a given age-and-sex stratum falls within a stated interval, or the proportion beyond a given z-score cutoff falls within a stated range — then run them as a pytest suite on any extract and report Passed / Failed / Inconclusive with the citation attached to every result.

Take the version-pinning and tri-state reporting from this paper; skip the LLM generation. Serves Liz / registry height–weight data quality (external method only; no claim about any registry's internals).

What to verify first

  • For a disease population, do published priors of the right kind exist at the stratum resolution an assertion needs, or are the available numbers only cross-sectional summaries a longitudinal extract can't be compared to?
  • In a modulator era where growth genuinely changed, what's the right vintage for a prior, and how would we detect that the reference has gone stale rather than the data having gone wrong? (The paper's own "era gap" problem; same trap as using a general-population chart on a disease population.)
  • If we adopt tri-state reporting, how many of our variables land in Inconclusive — and is that count itself the more useful deliverable?
  • Does an SMD threshold even transfer to z-score-scaled variables, given they're already standardized and the SMD denominator would be doing something different?
  • Does any format-level convention in an anthropometric extract make valid records invisible to a downstream algorithm while passing every syntactic check? (The decimal-point lesson, generalized.)
