Ep2 (Track B — AI tooling): When the databases disagree about where a domain ends

Blum and colleagues (2025, Nucleic Acids Research) present the latest InterPro update: a freely accessible, shipped resource that classifies over 200 million protein sequences into families, domains, and functional sites by integrating predictive models ("signatures") from a dozen-plus member databases (Pfam, CDD, PANTHER, SMART, and others), with deep AlphaFold structural integration. Two threads make this a strong Track B pick. First, facing a curation bottleneck — PANTHER signatures ship with no descriptive text and curator capacity can't keep pace with UniProtKB's 371% decade-long growth — the team built an LLM pipeline: GPT-4 generates family descriptions from Swiss-Prot annotations (5,491 released in version 97.0), and a fine-tuned local SciPhi-Mistral-7B-32k model was distilled to approach GPT-4 quality at lower cost (preferred over GPT-4 in 45.5% of head-to-head comparisons), scaling to 3,887 AI-generated, explicitly-flagged-unreviewed entries between versions 99.0 and 101.0. Second, InterPro now computes "representative domains" — an automated reconciliation across source databases that resolves boundary disagreements, illustrated by the PIK3CA N345K variant, which falls outside Pfam's narrower C2 domain boundary but inside CDD's, directly affecting whether a PM1 ACMG evidence code applies. That reconciliation logic transfers almost literally to CFTR, whose own domain boundaries (TMD1/NBD1/R-domain/TMD2/NBD2) are called slightly differently across the same source databases. Buildable artifact: a CFTR Representative-Domain Resolver.

Plain-English glossary

  • Protein domain — a structurally/functionally semi-independent folded region within a larger protein, often performing one specific job (e.g. membrane binding, catalysis).（中文：蛋白质结构域，较大蛋白质内部一个结构和功能上相对独立的折叠区域，通常承担某一specific功能。）
  • Signature — a predictive computational model (commonly a profile hidden Markov model, HMM) used to scan a sequence for a match to a known family, domain, or site.（中文：signature（特征模型），一种预测性计算模型（常为HMM，隐马尔可夫模型），用于扫描序列以判断是否匹配已知的家族、结构域或位点。）
  • pLDDT — AlphaFold's per-residue confidence score (0–100) for a predicted structure; higher means more confidence in that residue's predicted position.（中文：pLDDT，AlphaFold针对每个残基给出的结构预测置信度评分（0–100），数值越高表示对该残基预测位置的信心越大。）
  • Representative domains — InterPro's automated selection of the smallest set of domain calls across member databases that maximizes sequence coverage while minimizing overlap, used to resolve inter-database boundary disagreements.（中文：代表性结构域，InterPro在多个成员数据库判定之间自动选择的、能最大化序列覆盖并最小化重叠的最小结构域集合，用以解决数据库间的边界分歧。）
  • Swiss-Prot — the manually curated, high-confidence subset of UniProtKB.（中文：Swiss-Prot，UniProtKB中经人工审定、高置信度的子集。）
  • PM1 (ACMG evidence code) — the ACMG criterion for a variant located in a well-established functional/mutational hotspot or critical domain; whether it applies can depend on exactly where a domain boundary is drawn.（中文：PM1（ACMG证据代码），指变异位于已确立的功能/突变热点或关键结构域内的ACMG判定标准；该标准是否适用，可能取决于结构域边界具体划在哪里。）

Methods / tools to lift

  • InterPro REST API / match_complete.xml — programmatic access to all member-database domain/signature calls, including the representative-domains selection.
  • Representative-domains algorithm — smallest-set, maximum-coverage, minimum-overlap reconciliation across Pfam/CDD/PROSITE Profiles/SMART/NCBIFAM domain calls.
  • GPT-4-from-Swiss-Prot description pipeline + SciPhi-Mistral-7B-32k fine-tuning + Label Studio pairwise preference evaluation — a reusable pattern for LLM-assisted database curation with a cheaper distilled local model.

What to verify first

  • Whether CFTR's own domain boundaries actually show meaningful cross-database disagreement the way PIK3CA's C2 domain does.
  • That any AI-generated InterPro description is still flagged "unreviewed" until a human curator signs off, and that flag is carried forward wherever it's reused.
  • That the pairwise-preference evaluation (which description curators liked better) is not mistaken for a factual-accuracy evaluation against primary literature.
  • Exactly how the representative-domain algorithm breaks ties or handles partial overlaps, before trusting its output near a CFTR domain boundary.

ALEX Today's paper is in Nucleic Acids Research, 2025 — Blum and colleagues, the InterPro consortium update paper, "InterPro: the protein sequence classification resource in 2025." 今天的论文发表在2025年的《Nucleic Acids Research》上——作者是Blum及其同事，这是InterPro联盟的年度更新论文，题目是《InterPro：2025年的蛋白质序列分类资源》。 This is Track B, the AI-for-registry/bioinformatics-tooling track, and it earns its slot on two counts: InterPro is genuinely shipped, maintained infrastructure that annotates over 200 million protein sequences, and buried inside this update is a concrete, working example of using GPT-4 and a fine-tuned local model to scale up database curation — exactly the kind of tool-development pattern this track exists to surface. 这是Track B，面向AI在注册库/生物信息学工具化方面的赛道，它能入选有两个理由：InterPro是一个真正在运行、持续维护的基础设施，为超过2亿条蛋白质序列提供分类标注；而这次更新里还藏着一个具体、可用的案例——用GPT-4和一个微调过的本地模型来扩大数据库审定（curation）的规模——这正是这个赛道想要呈现的那种工具开发范式。 Full text came through cleanly via the BioC PMC route, so nothing here is abstract-only. 全文是通过BioC PMC渠道顺利拿到的，所以这一集没有任何内容是只靠摘要支撑的。

JORDAN Let's set up the vocabulary, because this one runs on protein-structure bioinformatics terms we haven't used much yet. 我们先把词汇讲清楚，因为这一集会用到不少我们之前没怎么用过的蛋白质结构生物信息学术语。 What's a protein "domain," what's a "signature," and what's pLDDT? 蛋白质的"结构域（domain）"是什么？"signature"（标记/特征模型）是什么？pLDDT又是什么？

ALEX A protein domain is a structurally and functionally semi-independent region within a larger protein — a folded unit that often does one specific job, like binding a membrane, catalyzing a reaction, or binding a nucleotide — and a single protein, including CFTR, is typically built from several domains strung together. 蛋白质结构域是一个较大蛋白质内部在结构和功能上相对独立的区域——一个折叠单元，通常承担某种特定功能，比如结合膜、催化反应或结合核苷酸——而包括CFTR在内的单个蛋白质，通常是由多个这样的结构域串联组成的。 A "signature," in InterPro's vocabulary, is a predictive computational model — most commonly a profile hidden Markov model, a statistical pattern built from an aligned family of known sequences — used to scan a new sequence and decide whether it matches that family, domain, or site; InterPro doesn't build these itself, it integrates signatures from a dozen-plus member databases like Pfam, CDD, SMART, and PANTHER. 在InterPro的词汇里，"signature"（特征模型）是一种预测性的计算模型——最常见的形式是一个隐马尔可夫模型（profile HMM），即从一组已知序列的比对结果中构建出的统计模式——用来扫描一条新序列，判断它是否匹配某个蛋白质家族、结构域或功能位点；InterPro本身并不构建这些模型，而是整合来自十几个成员数据库（如Pfam、CDD、SMART、PANTHER）各自的signature。 And pLDDT — predicted local distance difference test — is AlphaFold's own per-residue confidence score for its structure predictions, ranging zero to a hundred, where higher means AlphaFold is more confident that particular residue's predicted position is correct; InterPro now displays it as a 2D track alongside its domain annotations so a viewer can see which parts of a structural prediction to trust. pLDDT（预测局部距离差异检验，predicted local distance difference test）是AlphaFold为其结构预测给出的、针对每个残基的置信度评分，范围是0到100，数值越高表示AlphaFold对该残基预测位置的信心越大；InterPro现在把它作为一个二维轨道，和结构域标注并排显示，方便使用者判断结构预测里哪些部分可信、哪些不可信。

JORDAN Why does InterPro need an AI-based curation shortcut at all — what's the actual bottleneck? InterPro为什么需要一个基于AI的审定捷径——真正的瓶颈在哪里？

ALEX InterPro's core job is consolidating all those member-database signatures into unified, cross-referenced entries, each hand-annotated with a name, a descriptive abstract, and Gene Ontology terms — and that manual-annotation step is exactly where the bottleneck sits. InterPro的核心工作是把所有这些来自成员数据库的signature整合成统一的、相互交叉引用的条目，每个条目都需要人工标注名称、描述性摘要和基因本体（GO）术语——而这个人工标注环节正是瓶颈所在。 PANTHER is the specific pain point in this paper: it's the third-largest member database by number of signatures and the second-largest by number of matched UniProtKB sequences, but none of its signatures ship with a descriptive abstract, and its own names are frequently unhelpful — things like "Uncharacterised" or "Hypothetical protein." PANTHER是这篇论文里具体点名的痛点：按signature数量它是第三大成员数据库，按匹配到的UniProtKB序列数量它是第二大，但它的signature一个都没有自带描述性摘要，而且它自己给出的名称往往没什么信息量——比如"未定性（Uncharacterised）"或"假设蛋白（Hypothetical protein）"。 Meanwhile UniProtKB keeps growing — it's up 371% over the past decade — and the number of human curators obviously isn't growing at anywhere near that rate, so without some kind of automation, newly integrated signatures just pile up undescribed. 与此同时，UniProtKB还在不断增长——过去十年增长了371%——而人工审定人员的数量显然不可能以同样的速度增长，所以如果没有某种自动化手段，新整合进来的signature就只会越积越多、始终没有描述。 The team's existing LLM precedent, LitSumm, which auto-summarizes non-coding RNA genes from literature, doesn't transfer well here because PANTHER's accession numbers are rarely cited in papers and its names give the model nothing useful to search on — so they needed a different input source entirely. 他们已有的LLM先例LitSumm，可以从文献中自动生成非编码RNA基因的摘要，但这个办法在这里不太适用，因为PANTHER的编号很少被论文引用，它自己的名称也没法给模型提供什么有用的检索线索——所以他们需要一个完全不同的输入来源。

JORDAN So what did they actually build, and what's the design choice you'd push back on? 那他们到底搭建了什么？你会对哪个设计选择提出质疑？

ALEX For PANTHER signatures that match at least one Swiss-Prot entry — that's the manually curated, high-confidence section of UniProtKB, and it covers 70% of the unintegrated PANTHER signatures — they extracted the Swiss-Prot protein names and functional annotations and prompted GPT-4 to summarize the family's overall function from that information plus the model's own background knowledge, releasing 5,491 of these descriptions in InterPro release 97.0. 对于至少匹配到一条Swiss-Prot条目的PANTHER signature——Swiss-Prot是UniProtKB里经过人工审定、高置信度的部分，覆盖了70%未整合的PANTHER signature——他们提取了Swiss-Prot里的蛋白质名称和功能标注，提示GPT-4根据这些信息加上模型自身的背景知识来总结该家族的整体功能，并在InterPro 97.0版本中发布了5491条这样的描述。 To cut cost and dependency on a commercial API, they then fine-tuned a smaller open local model, SciPhi-Mistral-7B-32k — itself pretrained on scientific text from Mistral 7B — on 5,473 of those GPT-4-generated examples, training it to imitate GPT-4's responses, and held out 86 families for testing. 为了降低成本并减少对商业API的依赖，他们随后在5473条GPT-4生成的样本上微调了一个更小的开源本地模型SciPhi-Mistral-7B-32k——这个模型本身是在Mistral 7B基础上针对科学文本预训练得到的——训练它去模仿GPT-4的回答风格，并留出86个家族作为测试集。 Here's the design choice worth pushing on: their evaluation method was five human curators doing pairwise preference judgments in Label Studio — given two anonymized descriptions for the same family, which one do you prefer — aggregated as equally weighted votes, rather than any curator independently checking each description against the literature for factual correctness. 这里有一个值得质疑的设计选择：他们的评估方法是让五位人工审定专家在Label Studio里做成对的偏好判断——给定同一家族的两段匿名描述，问审定专家更喜欿哪一段——然后把投票按等权重汇总，而不是让审定专家各自独立地对照文献核查每段描述的事实准确性。 Preference tells you which text reads better or sounds more confident; it doesn't tell you which one is actually correct, and for a task whose whole point is accurate scientific description, that's a meaningful gap between what was measured and what actually matters. 偏好只能告诉你哪段文字读起来更好、听起来更有把握；它不能告诉你哪一段才是真正正确的，而对于一个核心目标就是准确科学描述的任务来说，"被测量的东西"和"真正重要的东西"之间存在一个值得注意的差距。

JORDAN What were the actual numbers? 具体数字是什么？

JORDAN There's also a domain-boundary example in here that sounds directly relevant to variant interpretation — walk me through it. 这里还有一个结构域边界的例子，听起来和变异解读直接相关——你能讲讲吗？

ALEX Right — because InterPro integrates domain calls from multiple member databases that don't always agree on exactly where a domain starts and ends, they now compute a "representative domains" track: an automated selection, comparing Pfam, CDD, PROSITE Profiles, SMART, and NCBIFAM, that picks the smallest set of domain calls maximizing sequence coverage while minimizing overlap. 对，因为InterPro整合了来自多个成员数据库的结构域判定，而这些数据库对一个结构域具体从哪里开始、到哪里结束并不总是一致，所以他们现在会计算一个"代表性结构域（representative domains）"轨道：这是一种自动化选择，比较Pfam、CDD、PROSITE Profiles、SMART和NCBIFAM各自的判定，挑选出能最大化序列覆盖、同时最小化重叠的最小结构域集合。 Their worked example is the human PIK3CA gene — which, for context, encodes the p110-alpha catalytic subunit of PI3-kinase and is one of the most frequently mutated oncogenes across human cancers — and specifically its N345K variant, which sits inside what's known to be the protein's C2 domain. 他们给出的实例是人类PIK3CA基因——补充一点背景，它编码PI3激酶的p110α催化亚基，是人类癌症中最常被突变的癌基因之一——具体是它的N345K变异，这个变异位于已知属于该蛋白C2结构域的区域。 If you relied solely on Pfam's domain boundaries for that protein, the Pfam C2 domain is drawn short enough that N345K falls just outside it — which would mean a PM1 "variant lies in a critical/functional domain" evidence code gets coded incorrectly as not applicable. 如果只依赖Pfam给出的该蛋白结构域边界，Pfam的C2结构域范围划得比较短，导致N345K刚好落在边界之外——这意味着PM1这条"变异位于关键/功能结构域内"的证据代码会被错误地判定为不适用。 Using the representative-domains logic instead, the CDD C2 domain call is selected because it covers more of the relevant sequence, and N345K correctly lands inside it — a concrete demonstration that which single source database you trust for domain boundaries can flip a piece of ACMG evidence from applicable to not applicable. 而使用代表性结构域逻辑之后，系统会选择CDD给出的C2结构域判定，因为它覆盖了更多相关序列，N345K也因此被正确地划入其中——这是一个具体的例证，说明你信任哪一个单一来源数据库来判定结构域边界，可能会把一条ACMG证据从"适用"直接翻转成"不适用"。

JORDAN Where does that land for the CFTR work specifically, and what's the tool sketch? 这一点对CFTR的工作具体意味着什么？可搭建的工具是什么？
