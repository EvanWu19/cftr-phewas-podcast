Blurb

Berthou, Vaillant, Rance, and Coulet (2026, Studies in Health Technology and Informatics) present medkit Seshat, an open-source Python pipeline built on the existing medkit library that ingests free clinical text, recognizes entities with NER, normalizes them against OMOP vocabularies, and builds a searchable index (by concept or by document) with a web UI on top. The stated problem is that clinical-text NLP extraction is usually done as a one-off, study-specific effort whose output evaporates after one paper, even though the same free-text corpus gets revisited by different studies asking different questions. This paper is genuinely closed access — no PMCID, no free full-text route — so tonight's episode is built entirely from a detailed structured abstract, which describes architecture and intent but reports no cohort size, no NER precision/recall, no document count, and no user-study evidence; it's a tool-availability data point, not an evidence data point. The transferable idea for the AI-tooling/career track is the reusable-index architecture itself — separating the expensive one-time NER-plus-normalization cost from the cheap repeated cost of querying an already-built index — sketched here as a small CFTR-registry free-text index prototype that would surface the entity-to-OMOP-concept mapping-failure rate this abstract never reports.

Plain-English glossary

  • cTAKES / MetaMap — Long-established clinical NLP tools that extract concepts from free text and normalize them against controlled vocabularies like UMLS; the historical predecessors this paper's architecture builds against.（中文：历史悠久的临床NLP工具，用于从自由文本中提取概念并对照UMLS等受控词表做归一化，是本文架构所参照的前代工具。）
  • NER (named entity recognition) — The NLP task of finding and labeling text spans that refer to a specific kind of thing (a drug, a diagnosis, a lab test) within unstructured text.（中文：命名实体识别，即在非结构化文本中找到并标注指向特定类型事物的文本片段的NLP任务。）
  • OMOP (Observational Medical Outcomes Partnership) common data model — A standardized schema and vocabulary for representing health data so different databases become comparable and queryable in the same way.（中文：观察性医学结局伙伴关系通用数据模型，一套用于表示健康数据的标准化模式和词表，使不同数据库能够以相同方式比较和查询。）
  • Phenotyping — Using data, structured or unstructured, to identify which patients actually have a given clinical condition or characteristic.（中文：表型提取，指利用数据判断哪些患者真正具有某种临床状况或特征的过程。）
  • Structured vs. unstructured (free-text) EHR data — Structured data are coded fields, lab values, and dates; unstructured free text is clinician notes and reports — richer in nuance but far harder to query.（中文：结构化数据指编码字段、检验值和日期；非结构化自由文本指临床笔记和报告——细节更丰富但难以查询得多。）

Methods / tools to lift

  • medkit — the base open-source Python library for medical text-processing pipelines this paper builds on (github.com/medkit-lib/medkit); Seshat itself is an application/packaging layer on top of it, not a from-scratch NLP framework.
  • The four-stage pipeline shape: ingest free text -> NER -> OMOP-vocabulary normalization -> dual-mode index (searchable by concept or by document).
  • Separating the expensive one-time extraction cost from the cheap repeated cost of querying a persistent index, so later studies build on prior extraction rather than re-running it.
  • A web UI layer specifically aimed at letting non-programmers search a built index without writing a database query.

Where it lands + buildable artifact

Priority served: AI-tooling / career positioning (one only).

Artifact: CFTR-registry free-text index prototype (tool sketch). Difficulty M.

MVP line: run an off-the-shelf open-source NER model on a small public or synthetic clinical-note corpus, normalize extracted entities against a public OMOP vocabulary snapshot with an existing terminology-mapping library, and build a minimal notebook-queryable document-and-concept index — no web UI yet — while honestly logging what fraction of entities fail to map cleanly to an OMOP concept.

The point of building this small first is to surface the mapping-failure rate this abstract never reports, before betting a real registry project on a similar architecture.

What to verify first

  • Is there a published precision/recall evaluation of Seshat anywhere outside this abstract-only paper?
  • If we build something like this on CFFPR free text, are we versioning the index the way we'd version a model, so a later NER update doesn't silently change past query results?
