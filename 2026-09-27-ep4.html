Ep4 (Track C, 2 of 2) -- Navigating electronic health record accuracy by examination of sex incongruent conditions

Cai L, Davies RJ, Xiang G, Zeng X, Xiao Y. 2024. Journal of the American Medical Informatics Association. PMID 39254529 / PMC11631140 / DOI 10.1093/jamia/ocae236.

Using the All of Us Research Program's v7 EHR data, the authors build a data-driven metric for a Kahn-framework "plausibility" check: does a recorded medical condition make biological sense given a participant's recorded sex? Starting from 12,744 candidate conditions, they refine down to 167 genuinely sex-specific ones and compute an overall incongruence rate (OIR) of 0.86% (0.89% female-specific, 0.79% male-specific) among 245,148 cisgender participants. Genotype-array data validates the flagged subset -- 978 of 1,134 incongruent participants had perfect concordance between genomic and self-reported sex, pointing the error to the EHR side rather than survey error. Geographic and temporal spread tracked population size rather than clustering, arguing for a systemic rather than one-off issue. This is a genuinely different flag mechanism from anything statistical: a logically impossible field combination catches errors invisible to a distributional check, and vice versa. Paired deliberately with this morning's LLM-consensus episode -- one is a candidate generator, the other an adjudication tool for values someone else already flagged.

Plain-English glossary

  • Concordance -- agreement between an independently-collected attribute (like genomically-inferred sex) and a recorded value, used here as a validation check distinct from checking a value against a statistical distribution.（中文：一个独立采集的属性（如基因组推断的性别）与一个记录数值之间的一致性，本文用它作为一种区别于对照统计分布的验证方式。）
  • Conformance / completeness / plausibility -- the three pillars of the Kahn data-quality-assessment framework: whether values match an expected format (conformance), whether expected data is present (completeness), and whether observed values are believable given accepted knowledge or reference standards (plausibility).（中文：Kahn数据质量评估框架的三大支柱：数值是否符合预期格式（一致性）、预期数据是否存在（完整性）、观察到的数值在已被接受的知识或参考标准下是否可信（合理性）。）
  • Genomics-inferred sex -- biological sex determined from genotyping-array data, used here as an orthogonal, independent signal to validate flagged EHR records.（中文：通过基因型芯片数据判定的生物学性别，本文用它作为一个正交、独立的信号来验证被标记的EHR记录。）
  • Incongruence rate (CIR / OIR) -- this paper's core metric: the proportion of participants with a condition that conflicts with their recorded sex, computed per-condition (CIR) and collectively across all sex-specific conditions (OIR).（中文：本文的核心指标：病症记录与所记录性别相冲突的参与者比例，可按单个病症计算（CIR），也可对所有性别特异病症整体计算（OIR）。）
  • OMOP Common Data Model -- the standardized vocabulary and concept-ID system used to structure the All of Us EHR data analyzed here.（中文：用于结构化本文所分析的"我们所有人"EHR数据的标准化词表和概念ID体系。）

Methods / tools to lift

  • Data-driven sex-specific condition selection -- a reusable recipe (frequency filter, >95% single-sex-occurrence filter, manual review of borderline cases) for building a condition list rather than hand-curating one.
  • CIR/OIR incongruence-rate formula -- a simple, reusable proportion-plus-confidence-interval metric for any logically-impossible field-combination check.
  • Genotype-array validation of a flagged subset -- using an orthogonal, independently-collected data source to validate flags without a hand-labeled gold standard.
  • Geographic/temporal-spread check -- a general diagnostic for whether a flagged pattern is systemic (tracks population size) or an isolated site/period glitch.

Where it lands + buildable artifact

Serves Liz / CFFPR data quality (method only). Buildable: cross-field plausibility rule bank (S-M) -- a small, versioned table of logically-impossible/improbable field combinations, built and tested on public/synthetic EHR data (e.g. Synthea), following this paper's own method shape: define a rule, compute its rate, spot-check geographic/temporal spread.

What to verify first

  • The genomic validation only checked the flagged, incongruent tail, not a random sample of the "congruent" bucket -- undetected errors landing on a sex-matching condition are structurally invisible to this method.
  • The paper explicitly targets adult populations; sex-specific-condition selection doesn't transfer cleanly to a pediatric cohort, where developmental/age-dependent conditions complicate the same logic.
  • Why non-cisgender participants were excluded from the main analysis (gender-affirming care can make a condition genuinely correct against sex at birth rather than gender identity) -- a confound any similar cross-field rule needs to handle explicitly.
  • That none of this speaks to CFFPR's own demographic fields, existing cross-field checks, or whether any such rule is even applicable there -- this is a method borrowed from a different, public dataset.

Pipeline stage

(a) candidate generation, primary -- a logically-impossible field combination flags errors a distributional/z-score check cannot see, and stays silent on genuinely extreme-but-real values that such a check would flag. (d) evaluation, secondary -- an orthogonal independent data source (genotype array) validates a flagged subset without a hand-labeled gold standard.

Error types covered / not covered

Covered: cross-field logical impossibility (a condition-sex combination that cannot occur, absent gender-affirming-care context). Not covered: unit mismatch, decimal-place shift, digit transposition, carry-forward, or real-clinical-event confusion within a single numeric field -- this method only fires when two or more fields jointly imply an impossibility, and has nothing to say about a single anthropometric value sitting alone.
