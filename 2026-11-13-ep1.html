Ep1 — Track A: Standardization of Genomic Nomenclature across a Diverse Ecosystem of Stakeholders

Paper: Conlin LK, Landrum MJ, Freimuth RR, Funke B. "Standardization of Genomic Nomenclature across a Diverse Ecosystem of Stakeholders: Evolution and Challenges." Clinical Chemistry. 2025. Abstract-only — full text was not retrievable through Europe PMC's open-access routes (fullTextXML 404 via the MED route; the PMC-OA BioC mirror returned no result for PMC11695870).

A review, co-authored by NCBI's ClinVar lead (Landrum), tracing how molecular genetics (HGVS-based small-variant nomenclature) and cytogenetics (ISCN-based structural/copy-number nomenclature) grew up as separate dialects — and why next-generation sequencing, which now reports both variant classes from a single assay, is forcing the two communities toward a shared, machine-translatable standard. The paper is diagnostic rather than a shipped fix: it reviews the history on both sides and names the implementation challenges for connecting the stakeholders — clinical labs, ClinVar, EHR vendors, standards bodies — who all consume variant descriptions. For CFTR specifically, this lands directly on the mess of legacy shorthand (ΔF508, G551D, R117H), full HGVS c./p. notation, dbSNP rsIDs, and dual genome builds (GRCh37/GRCh38) that already coexist in CFTR2 and ClinVar. The buildable artifact: a CFTR variant-notation crosswalk tool wrapping an existing HGVS normalization API (VariantValidator or Mutalyzer) to resolve mixed-notation variant lists to a canonical HGVS string and flag ClinVar/CFTR2 disagreements.

Plain-English glossary

  • Chromosomal microarray — A technology that detects DNA gains and losses (copy number changes) at finer resolution than a karyotype but coarser than sequencing.（中文:一种检测DNA增减〔拷贝数变化〕的技术,分辨率比染色体核型分析更精细,但比测序更粗糙。）
  • CNV (copy number variant) — A gain or loss of a chunk of DNA, ranging from a few kilobases to whole chromosome arms.（中文:拷贝数变异,指一段DNA的增加或缺失,范围从几千个碱基到整条染色体臂不等。）
  • Crosswalk — A mapping layer that translates between two different notations or data standards so each community can keep its own conventions while machines translate between them.（中文:交叉对照表,一种在两种不同命名法或数据标准之间进行映射转换的层,让各个社群能保留自己的惯例,同时由机器在其间转换。）
  • FISH (fluorescent in situ hybridization) — A cytogenetic technique using labeled probes that bind to and light up specific chromosomal regions under a microscope.（中文:荧光原位杂交技术,用带标记的探针结合并照亮显微镜下特定的染色体区域。）
  • GRCh37 / GRCh38 — Two successive versions ("builds") of the human reference genome; genomic coordinates differ between them, so a position must always be stated with its build.（中文:人类参考基因组的两个先后版本〔"build"〕;两者的基因组坐标不同,所以任何位置都必须注明所属版本。）
  • HGVS nomenclature — The Human Genome Variation Society's standard for describing a sequence variant relative to a reference sequence (e.g. CFTR's c.1521_1523delCTT for ΔF508).（中文:人类基因组变异学会制定的标准命名法,用于相对于参考序列描述一个序列变异,例如CFTR基因ΔF508缺失对应的c.1521_1523delCTT。）
  • ISCN (International System for Human Cytogenomic Nomenclature) — The parallel standard to HGVS used for writing karyotypes and large structural rearrangements.（中文:人类细胞基因组命名国际体系,是与HGVS平行的标准,用于书写核型和大型结构重排。）
  • Karyotyping — Staining and imaging a full set of chromosomes under a microscope to detect large structural abnormalities.（中文:染色体核型分析,对整套染色体染色并在显微镜下成像,以检测大的结构异常。）
  • Reference transcript (RefSeq) — The specific transcript sequence an HGVS coding-level (c.) variant description is written against; a gene can have multiple RefSeq transcripts, and picking the wrong one changes the notation.（中文:参考转录本,是HGVS编码层面〔c.〕变异描述所依据的具体转录本序列;一个基因可能有多个RefSeq转录本,选错了会改变命名结果。）
  • Structural variant — A large-scale rearrangement such as an inversion (a segment flipped) or translocation (a segment moved to another location), distinct from a simple gain/loss CNV.（中文:结构变异,指大规模的重排,比如倒位〔片段翻转〕或易位〔片段移动到别处〕,区别于单纯的增减型拷贝数变异。）
  • VRS (Variant Representation Specification) — GA4GH's attempt at a computable, implementation-agnostic data model for a variant, from which different notations (HGVS, VCF, etc.) can be generated as needed.（中文:变异表示规范,是GA4GH〔全球基因组学与健康联盟〕提出的一种可计算、与具体实现无关的变异数据模型,不同的命名法〔HGVS、VCF等〕都可以从它按需生成。）

Methods / tools to lift

  • VariantValidator — REST API that validates and converts variant descriptions across HGVS, VCF, and genomic coordinate formats against a chosen reference transcript.
  • Mutalyzer — Alternative REST API with similar HGVS normalization and name-checking functionality, useful as a cross-check against VariantValidator.
  • GA4GH VRS — A computable variant data model worth knowing as the likely long-term target for any crosswalk effort, even though this review doesn't commit to a single named solution.
