Show Notes — Track B — 2026-07-03

Blurb

Kim et al. (Int J Med Inform 2022) extend the OMOP common data model into radiology — a modality OMOP covers poorly — and, crucially, ship a data-quality assessment tool (RQA) alongside the schema. Their Radiology_CDM (R_CDM) adds two tables (Radiology_Occurrence, Radiology_Image) linked to the OMOP clinical data, a RadLex-based mapping of 5,753 protocol terms to the OMOP vocabulary, an ETL that "compensates for missing values," and an image-quantification step (WALTS software) that computes liver surface nodularity (LSN). At production scale they converted 368,333,676 DICOM files (~1,001,797 cases) into chronic-liver-disease R_CDM data; LSN differed significantly across METAVIR fibrosis grades (ANOVA), validating the dataset for clinical use. Honest negative result: acquisition date and resolution extracted accurately, but contrast-administration status and photography direction could not be reliably extracted from metadata. Read abstract-only (not open access, no PMC). Where it lands: AI-tooling / career — the reusable pattern is extend a data model, map the vocabulary, and audit with a paired DQ tool. Buildable artifact: a variant-CDM DQ linter for genomic data, with the discipline of marking every derived field as derived so the quality metric never grades its own imputation.

Plain-English glossary

  • DICOM — the standard medical-image file format, bundling pixels with metadata (acquisition date, resolution, scan parameters).（中文：DICOM——医学影像的标准文件格式，把像素和元数据（采集日期、分辨率、扫描参数）打包在一起。）
  • ETL (extract, transform, load) — the pipeline that pulls data from a source, reshapes it, and loads it into a target schema.（中文：ETL（抽取、转换、加载）——把数据从源头拉出、改造、再载入目标模式的流水线。）
  • Liver surface nodularity (LSN) — an image-derived quantitative measure of how bumpy the liver surface looks; higher signals fibrosis/cirrhosis.（中文：肝表面结节度（LSN）——从影像导出的量化指标，衡量肝表面凹凸程度；越高越提示纤维化/肝硬化。）
  • METAVIR — a histological liver-fibrosis grading scale from F0 (none) to F4 (cirrhosis), traditionally read from biopsy.（中文：METAVIR——肝纤维化的组织学分级量表，从F0（无）到F4（肝硬化），传统上从活检读出。）
  • OMOP-CDM — the Observational Medical Outcomes Partnership common data model; a fixed schema + standard vocabularies that lets one analysis run across many hospitals.（中文：OMOP-CDM——观察性医疗结果合作通用数据模型；固定的表结构加标准词表，让一个分析能在多家医院上运行。）
  • PACS — picture archiving and communication system; the hospital image database where DICOM files live.（中文：PACS——影像存档与通信系统；存放DICOM文件的医院影像数据库。）
  • RadLex — a controlled radiology vocabulary used to map raw scanner protocol terms to standard concepts.（中文：RadLex——受控的放射学词表，用于把原始扫描协议术语映射到标准概念。）

Methods / tools to lift

  • Schema-extension pattern — add domain tables (Radiology_Occurrence, Radiology_Image) that link into the existing CDM rather than a parallel silo.
  • Vocabulary mapping with honest coverage reporting — RadLex playbook → OMOP vocabulary, 5,753 protocol terms mapped.
  • ETL that flags un-extractable fields — documents which fields (contrast status, photography direction) cannot be trusted from metadata; a reusable negative result.
  • Paired data-quality tool (RQA) — score the converted dataset repeatably instead of eyeballing it.
  • Derived clinical readout (WALTS → LSN) — compute a quantitative feature off the pixels and validate it against an external grade (METAVIR).

Where it lands + buildable artifact

Serves AI-tooling / career. Paste-ready MVP: variant-CDM DQ linter — input a genomic-variant table mapped into an OMOP-style extension (variant → person → normalized HGVS); run three check families: completeness (required fields present), vocabulary-mapping coverage (fraction of raw calls mapped cleanly to standard notation), plausibility (genome-build consistency, reference-allele agreement, impossible coordinates); output a per-field quality report flagging which fields must be derived (e.g. normalized HGVS) vs trusted from source. Difficulty: S-M. Mark every derived field as derived so the metric never scores its own imputation. External tooling on the public data-model layer; no registry internals.

What to verify first

  • Get the full text before copying the ETL "compensation" — derive vs impute matters; design ours to be derivation-only-and-labeled.
  • Variant-notation mapping is harder than protocol-name mapping (indels, structural variants, build liftover) → lower coverage, higher-stakes failures.
  • Plausibility rules need testing against a known-good reference set before the flags are trusted.
  • External tooling exercise on the public data-model layer only; decides no research design and says nothing about any registry's internal genotype data.
