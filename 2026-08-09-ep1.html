Blurb

Everton, Botas, and colleagues (Baylor College of Medicine / Texas Children's Hospital, American Journal of Human Genetics, 2026) tackle the usability wall around MARRVEL, a rare-disease variant-lookup portal that requires precisely formatted HGVS input and returns dense, heterogeneous output. MARRVEL-MCP wraps 44 genomic and clinical tools — gene/variant utilities, pathogenicity databases (ClinVar, gnomAD), phenotype resources (HPO), expression atlases, ortholog databases, literature APIs, and GeneMatcher — behind the Model Context Protocol, letting an LLM decide for itself which tools to call and in what order to answer a plain-language clinical question. On a 100-question expert-curated benchmark, a 20-billion-parameter open model (gpt-oss-20b) scored 94% with MARRVEL-MCP versus 41% without it, and lightweight models with tool access matched or beat larger tool-less models — the paper's central claim that context engineering, not raw parameter count, drove the gain. The transfer to Karen's CFTR variant-harmonization work is close to direct: this is an architecture template, not a new predictor. Buildable artifact: cftr-variant-copilot, an MCP server wrapping a CFTR-scoped tool set (CFTR2, ClinVar, gnomAD, HGVS normalizer, AlphaMissense/REVEL fetch) behind a modestly sized LLM, with a full tool-call audit log.

Plain-English glossary

  • MARRVEL (Model organism Aggregated Resources for Rare Variant Exploration) — a web portal for looking up a single variant across human and model-organism (mouse, fly, worm, zebrafish) databases at once, requiring precisely formatted input.（中文:一个网络门户,能一次性跨人类和模式生物数据库查询单个变异,但要求输入格式精确。）
  • HGVS notation — the Human Genome Variation Society's standardized way of writing a variant, e.g. c.1521_1523delCTT for CFTR F508del.（中文:人类基因组变异学会制定的标准化变异书写方式。）
  • Pathogenicity database (ClinVar, gnomAD) — databases recording whether a variant is classified as disease-causing and how common it is in the general population.（中文:记录变异是否被归类为致病性变异及其在人群中常见程度的数据库。）
  • Ortholog resources — databases that let you check whether a gene's function is evolutionarily conserved by looking at disruption effects in another species.（中文:通过观察在其他物种中敲除同源基因的效应,来检验基因功能演化保守性的数据库。）
  • MCP (Model Context Protocol) — a standard letting a language model call external tools (databases, APIs, calculators) through a structured interface instead of guessing free-text formats.（中文:一种让语言模型通过结构化接口调用外部工具的标准协议。）
  • GeneMatcher — a matchmaking registry connecting clinicians/researchers who've each found a patient with a variant in the same obscure gene.（中文:一个"配对"登记平台,连接分别发现同一罕见基因变异患者的临床医生和研究者。）
  • HPO (Human Phenotype Ontology) — a standardized, hierarchical vocabulary of clinical signs/symptoms used to match phenotype to candidate genes.（中文:一种标准化、带层级关系的临床体征词汇表,用于将表型与候选基因匹配。）
  • Agentic system / tool-augmented context engineering — an LLM architecture where the model itself decides which external tools to call and in what sequence, rather than following a hard-coded workflow.（中文:一种由模型自主决定调用哪些外部工具及调用顺序的AI架构,而非遵循硬编码的固定流程。）
  • Diagnostic odyssey — the often years-long, multi-specialist process rare-disease patients go through before reaching a molecular diagnosis.（中文:罕见病患者在获得分子诊断之前,往往需要历经数年、辗转多位专科医生的过程。）

Methods / tools to lift

  • Tool-augmented context engineering — wrapping 44 domain tools (gene/variant utilities, pathogenicity DBs, phenotype resources, expression atlases, orthologs, literature search, GeneMatcher) behind MCP and letting the LLM choose its own tool-call sequence.
  • Benchmark design — 100 expert-curated Mendelian-disease questions, tested across model sizes (3B–20B parameters) with/without tool access, isolating the effect of tool access from model scale.
  • gpt-oss-20b + MARRVEL-MCP as a concrete open, reproducible reference configuration (94% pass rate vs. 41% without tools).

Where it lands + buildable artifact

Karen / CFTR variant interpretation & harmonization. Buildable: cftr-variant-copilot (M) — an MCP server exposing a small CFTR-scoped tool set (CFTR2 lookup, ClinVar lookup, gnomAD population frequency, HGVS normalizer, AlphaMissense/REVEL score fetch) wired to an open, modestly sized LLM; outputs a synthesized answer to a plain-language variant question plus a full audit log of every tool call and its raw output for human review.

What to verify first

  • How failure modes look on CFTR-specific edge cases (intron-8 poly-T/TG-repeat tract, complex cis alleles) where a wrong or incomplete tool chain could produce a fluent but wrong synthesis.
  • Whether the 100-question benchmark includes anything resembling CFTR-specific complexity (modifier genes, variable expressivity, CFTR2 classification) before assuming the 94% number transfers.
  • Build an independent audit layer logging every tool call and raw output, not just the model's final sentence — tool selection is this architecture's main new failure surface.
  • Full methods text (exact tool list, benchmark question composition, cost/latency numbers) was unavailable this run — worth re-checking OA/PMC status in a future pass.
