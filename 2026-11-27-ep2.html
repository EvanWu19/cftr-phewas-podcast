How did this episode land for you?

MAYA: a Snakemake architecture pattern worth stealing

MAYA (Kumar Narendran et al., International Journal of Molecular Sciences, 2026) is a Snakemake-based bacterial genome annotation pipeline that chains eighteen tools — from FastQC through antiSMASH and MOB-suite — into one reproducible workflow with per-rule Conda environment isolation, validated on both a reference strain (Bacillus subtilis 168) and a novel antifungal strain (SNUY1). The organism isn't the point for this track: the episode focuses on the architecture — rule-based dependency resolution, dual FASTQ/FASTA input handling, and strict per-tool version locking — as a pattern worth adapting regardless of what data it's processing. It lands on the AI-tooling/career priority, with a buildable MVP: rebuilding the CFTR variant-aggregator sketched in ep1 as a small three-rule Snakemake pipeline with pinned per-rule environments, trading a fragile one-off script for a versioned, rerunnable workflow. One honest caveat carried through: the paper's own GitHub repository was still private at time of writing, so the architecture claims rest on the methods text, not an inspected repo.

Plain-English glossary

AMR (antimicrobial resistance) — Genetic traits that let a bacterium survive exposure to a class of antimicrobial drugs.（中文：抗菌药物耐药性，指让细菌能够在某类抗菌药物作用下存活的遗传特征。）

BGC (biosynthetic gene cluster) — A group of physically co-located genes that jointly encode the enzymes needed to produce one secondary metabolite, such as an antibiotic or antifungal compound.（中文：生物合成基因簇，指基因组上物理相邻、共同编码合成某种次级代谢产物（如抗生素或抗真菌化合物）所需酶类的一组基因。）

BUSCO — A genome-completeness metric that checks an assembly or annotation for a curated set of universal single-copy orthologous genes.（中文：一种基因组完整度评估指标，检查组装或注释结果中是否存在一组经过筛选、跨物种保守的单拷贝直系同源基因。）

CheckM — A completeness- and contamination-estimation tool that uses lineage-specific marker genes rather than universal orthologs.（中文：一种完整度与污染度评估工具，使用特定谱系的标记基因而非跨物种通用直系同源基因。）

MLST (multilocus sequence typing) — Strain fingerprinting by comparing the allele sequences of several housekeeping genes against a reference scheme to assign a sequence type.（中文：多位点序列分型，通过比对若干管家基因的等位基因序列与参考方案，为菌株分配一个序列型，从而完成菌株的"指纹"鉴定。）

N50 — The contig length at which half of a genome assembly's total length is contained in contigs of that length or longer; a single-number summary of assembly contiguity.（中文：组装连续性的单一数值概括指标，指将所有contig按长度排序后，使累计长度达到总长度一半时那个contig的长度。）

Snakemake — A workflow-management system that expresses each pipeline step as a rule with declared file inputs and outputs, automatically building and executing the resulting dependency graph.（中文：一种工作流管理系统，把流程中的每一步定义为带有声明输入输出文件的"规则"，并自动构建和执行依赖关系图。）

Methods / tools to lift

  • Snakemake rule-based architecture — file-pattern-declared inputs/outputs so dependency resolution and selective reruns happen automatically, rather than being hand-maintained.
  • Per-rule Conda environment isolation — each of the 18 tools gets its own pinned-version environment, avoiding shared-environment dependency conflicts across the pipeline.
  • Dual input-mode design (fasta_copy vs. spades_fastq rules) — downstream rules stay agnostic to whether the input started as raw reads or a finished assembly.
  • BLASTN cross-check for annotation discrepancies — a pattern for reconciling CDS-count differences between two annotation sources (here, NCBI vs. Prokka) before concluding genes were actually missed.

What to verify first

  • Whether the MAYA GitHub repository is now public, and whether the actual rule files match the methods-section description — it was explicitly private at time of writing.
  • Whether per-rule Conda isolation is worth its setup and maintenance overhead at a 3-4 rule scale, versus one shared, carefully pinned environment.
  • That this is a single-genome proof-of-concept, not a generalization claim — any lifted architecture pattern needs its own evaluation on the CFTR pipeline rather than an assumed wholesale transfer.

JORDAN A bacterium, not CFTR — why does this matter to us? 讲的是细菌，不是CFTR——这跟我们有什么关系？

JORDAN Start me with Snakemake itself — I know it's a workflow manager, but what makes it different from just chaining shell scripts? Snakemake本身是什么——我知道它是一个工作流管理器，但它和直接串联shell脚本有什么不同？

ALEX Snakemake defines each processing step as a "rule" with declared inputs and outputs, usually file paths with wildcards like results/prokka/{sample}/{sample}.gff. Snakemake 把每个处理步骤定义为一条"规则"（rule），并声明好输入和输出，通常是带通配符的文件路径，比如 results/prokka/{sample}/{sample}.gff。Because the dependency graph is built from those file patterns, Snakemake can figure out what's already done, what needs rerunning, and run independent branches in parallel — you're not maintaining the control flow by hand. 因为依赖关系图是从这些文件模式自动构建的，Snakemake能自己判断哪些步骤已经完成、哪些需要重跑，并行执行互不依赖的分支——你不需要手动维护控制流程。

JORDAN And the genomics-specific terms — BGC, AMR, MLST? 那些基因组学专有名词呢——BGC、AMR、MLST？

ALEX A BGC, biosynthetic gene cluster, is a group of physically adjacent genes that together encode the enzymes to make one secondary metabolite — think an antibiotic or antifungal compound. BGC（生物合成基因簇，biosynthetic gene cluster）是指一组在基因组上物理相邻、共同编码合成某种次级代谢产物所需酶类的基因——比如某种抗生素或抗真菌化合物。AMR is antimicrobial resistance — genes that let a bacterium survive a drug class. AMR（抗菌药物耐药性，antimicrobial resistance）指的是让细菌能够抵抗某类药物的基因。MLST, multilocus sequence typing, fingerprints a bacterial strain by comparing the allele sequence of several housekeeping genes against a reference database to assign a sequence type. MLST（多位点序列分型，multilocus sequence typing）通过比对若干管家基因的等位基因序列与参考数据库，为菌株指定一个序列型，从而对细菌菌株进行"指纹"鉴定。

JORDAN And the assembly QC metrics — N50, BUSCO, CheckM? 还有那些组装质控指标——N50、BUSCO、CheckM？

ALEX N50 is the contig length at which half the total assembly is contained in contigs of that length or longer — a single-number summary of assembly contiguity. N50是指：把所有contig按长度从大到小排列后，恰好使累计长度达到总组装长度一半时，那个contig的长度——用一个数字概括组装的连续性。BUSCO and CheckM both estimate completeness, but differently: BUSCO checks for a curated set of universal single-copy orthologs, while CheckM uses lineage-specific marker genes and also flags contamination. BUSCO 和 CheckM 都用于评估组装完整度，但方法不同：BUSCO 检查一组经过筛选的、跨物种保守的单拷贝直系同源基因集合是否存在；而CheckM使用特定谱系的标记基因，还能同时标记出污染情况。

JORDAN What problem was MAYA actually trying to solve? MAYA到底想解决什么问题？

ALEX Bacterial genome characterization needs a long chain of tools — quality control, assembly, structural annotation, functional annotation, resistance-gene screening, secondary-metabolite prediction, plasmid typing — and historically each step is a separate tool with its own install, its own environment, and its own ad hoc glue code between steps. 细菌基因组表征需要一长串工具——质量控制、组装、结构注释、功能注释、耐药基因筛查、次级代谢物预测、质粒分型——而传统做法是每一步都是独立的工具，各自有自己的安装方式、运行环境，以及步骤之间临时拼凑的胶水代码。

JORDAN So existing pipelines didn't already solve this? 那现有的流程还没解决这个问题吗？

ALEX Partially. The paper points to Bactopia, BAGEP, nf-core/bacass, and a recent tool called BacExplorer as prior attempts, but each has gaps. 部分解决了。论文提到了Bactopia、BAGEP、nf-core/bacass，以及一个较新的工具BacExplorer，都是此前的尝试，但各自都有缺口。Bactopia is built on Nextflow rather than Snakemake and skips secondary-metabolite prediction entirely. Bactopia基于Nextflow而非Snakemake构建，而且完全跳过了次级代谢物预测这一步。BacExplorer handles both FASTQ and FASTA input, which is nice, but it's missing antiSMASH, HMMER, KofamScan, BUSCO, and a few others — so you'd still have to bolt modules on yourself. BacExplorer能同时处理FASTQ和FASTA两种输入，这点不错，但它缺少antiSMASH、HMMER、KofamScan、BUSCO等好几个模块——所以你还是得自己把这些模块补上去。MAYA's pitch is unifying eighteen tools — spanning quality control, assembly, structural and functional annotation, resistance and plasmid profiling, and secondary-metabolite prediction — into one Snakemake workflow with per-rule Conda environment isolation, so every tool gets its own locked-down software version instead of fighting over a shared environment. MAYA的卖点是把十八个工具——涵盖质量控制、组装、结构与功能注释、耐药与质粒分析、次级代谢物预测——统一进一套Snakemake工作流，并为每条规则配置独立的Conda环境，这样每个工具都有自己锁定版本的运行环境，而不必在一个共享环境里互相打架。

JORDAN Why does that per-rule isolation actually matter in practice? 这种逐条规则的环境隔离在实践中到底有什么意义？

ALEX Bioinformatics tools are notorious for incompatible dependency versions — one tool wants an old numpy, another wants a newer one — and that's exactly the kind of thing that makes a pipeline fail six months later when you try to rerun it, or fail to reproduce on a collaborator's machine. 生物信息学工具出了名地依赖版本互不兼容——一个工具要旧版numpy，另一个要新版——而这正是那种会导致流程在六个月后重跑时失败、或者在合作者机器上无法复现的问题。Locking the environment per rule, rather than per pipeline, means you can upgrade or swap one tool without risking a cascade of breakage across the other seventeen. 按规则而非按整条流程锁定环境，意味着你可以升级或替换其中一个工具，而不必冒着牵连其余十七个工具一起崩溃的风险。

JORDAN Walk me through the actual architecture. 说说具体的架构设计。

ALEX The Snakefile declares two sample lists, FASTQ_SAMPLES and FASTA_SAMPLES, merged into one SAMPLES list, and a single rule all enumerates every output file the whole pipeline should produce, letting Snakemake resolve the full dependency graph from there. Snakefile声明了两个样本列表——FASTQ_SAMPLES和FASTA_SAMPLES——合并成一个SAMPLES列表，一条名为rule all的规则列出整条流程应当产出的全部文件，Snakemake据此解析出完整的依赖关系图。For FASTA input, a trivial fasta_copy rule just stages the assembly into the same output path a FASTQ sample would land in after assembly — so every downstream rule is agnostic to which input mode produced it. 对于FASTA输入，一条简单的fasta_copy规则只是把组装结果放到FASTQ样本组装完成后会落地的同一个输出路径——这样下游的每一条规则都不需要关心输入模式是哪一种。

JORDAN And the tool chain itself? 具体的工具链是什么？

ALEX FastQC and Trimmomatic or fastp for quality control, SPAdes for de novo assembly in FASTQ mode, CheckM and BUSCO for completeness, Prokka for structural annotation — CDS, tRNA, rRNA calls — then DIAMOND against SwissProt, HMMER against Pfam-A, and KofamScan against KEGG Orthology for three complementary flavors of functional annotation, ABRicate and MLST for resistance and strain typing, antiSMASH for biosynthetic gene clusters, and MOB-suite for plasmid reconstruction and mobility typing. 质控用FastQC和Trimmomatic或fastp，FASTQ模式下用SPAdes做从头组装，CheckM和BUSCO评估完整度，Prokka做结构注释——预测CDS、tRNA、rRNA——然后用DIAMOND比对SwissProt、HMMER比对Pfam-A、KofamScan比对KEGG Orthology，做三种互补的功能注释，ABRicate和MLST做耐药与菌株分型，antiSMASH预测生物合成基因簇，MOB-suite重建质粒并判定其可移动性。Every tool version is pinned — Prokka 1.14.6, DIAMOND 2.1.8, and so on — inside its own rule-specific Conda environment. 每个工具的版本都被锁定——Prokka 1.14.6、DIAMOND 2.1.8等等——各自运行在专属的、按规则划分的Conda环境中。

JORDAN Did it actually work on validation? 验证结果如何，确实有效吗？

ALEX On the reference strain, Bacillus subtilis 168, MAYA assembled a single contig of 4,215,606 base pairs, 43.51% GC, with 98.28% CheckM completeness, zero contamination, and a perfect 100% BUSCO score across all 124 marker genes — no fragmented or missing orthologs. 在参照菌株——枯草芽孢杆菌168菌株上，MAYA组装出单个4,215,606碱基对的contig，GC含量43.51%，CheckM完整度达98.28%，零污染，BUSCO在全部124个标记基因上拿到满分100%——没有片段化或缺失的直系同源基因。

JORDAN And comparing the two input modes, FASTQ versus FASTA? 那两种输入模式——FASTQ和FASTA——对比起来如何？

ALEX Both modes landed on identical MLST sequence types and identified the same six core AMR genes, which is the result you want — the core calls should be input-mode-invariant. 两种模式都落在相同的MLST序列型上，并识别出同样的六个核心AMR基因——这正是你希望看到的结果，核心判断结论不应随输入模式而改变。But Prokka called slightly different CDS counts between modes — 4214 in FASTA mode versus 4313 in FASTQ mode — which the authors attribute to expected fragmentation in the unassembled FASTQ path, and DIAMOND hit rates against SwissProt were nearly identical, 99.9% versus 99.75% mean identity. 但Prokka在两种模式下预测的CDS数量略有不同——FASTA模式下4214个，FASTQ模式下4313个——作者将其归因于未组装FASTQ路径中预期会出现的片段化，而DIAMOND对SwissProt的命中率几乎一致，平均同一性99.9%对99.75%。

JORDAN And the novel-strain application, SNUY1? 新菌株SNUY1的应用结果呢？

ALEX A single 4,196,931 bp chromosome, 4196 predicted CDSs, and 13 biosynthetic gene cluster regions with 20 protoclusters — including a hotspot around 1.78 to 2.06 megabases packed with overlapping NRPS, PKS, and beta-lactone clusters, consistent with the strain's known antifungal activity. 单个4,196,931碱基对的染色体，预测出4196个CDS，以及13个生物合成基因簇区域、共20个protocluster——其中在1.78到2.06兆碱基处有一个热点区域，密集重叠着NRPS、PKS和beta-lactone簇，这与该菌株已知的抗真菌活性是吻合的。One interesting discrepancy: MAYA's CDS count differed from the original NCBI annotation by 76 genes, so they ran a nucleotide-level BLASTN cross-check and found 95.5% of NCBI's CDSs had strong sequence matches to MAYA's predictions — the gap looks like differing gene-model boundaries between annotation tools, not genuinely missed genes. 有一个有意思的差异：MAYA的CDS数量与原始NCBI注释相差76个基因，于是他们在核苷酸层面做了BLASTN交叉核查，发现95.5%的NCBI CDS与MAYA的预测结果有很强的序列匹配——这个差距看起来更像是不同注释工具之间基因模型边界划定方式的差异，而不是真的漏掉了基因。

JORDAN What about the plasmid side — did they find anything mobile? 质粒方面呢——有没有发现什么可移动的质粒？

ALEX MOB-suite reconstructed two plasmids from the FASTQ assembly of strain 168 — the known pAC670 and a novel 1666-base-pair plasmid — and both were classified as non-mobilizable, meaning they lack the relaxase and conjugation machinery needed to transfer themselves between cells. MOB-suite从168菌株的FASTQ组装结果中重建出两个质粒——已知的pAC670，以及一个新发现的1666个碱基对的质粒——两者都被归类为"不可移动"（non-mobilizable），也就是说它们缺少自我转移所需的relaxase和接合（conjugation）机制。That's a useful containment signal for a biocontrol strain, since it argues against the resistance genes spreading horizontally to other bacteria. 对于一个生物防治菌株来说，这是一个有用的遏制信号，因为它说明耐药基因不太可能通过水平转移扩散到其他细菌。

JORDAN And the modules that only run in FASTQ mode — what's in that part of the pipeline? 那些只在FASTQ模式下运行的模块呢——这部分流程里有什么？

ALEX fastp strips adapters and low-quality bases first, FastQC and then MultiQC visualize and aggregate the quality reports across samples, SPAdes assembles the trimmed reads in careful mode, which adds a mismatch-correction pass to reduce errors in the resulting contigs, and Jellyfish builds a k-mer frequency histogram that's useful for estimating genome size and heterozygosity before you even look at the assembly itself. fastp先去除接头和低质量碱基，FastQC和随后的MultiQC对各样本的质控报告进行可视化和汇总，SPAdes以careful模式组装修剪过的读段，该模式会额外执行一轮错配校正以减少contig中的错误，而Jellyfish则构建k-mer频率直方图，在你还没看组装结果之前，就能用它来估算基因组大小和杂合度。

ALEX This lands on the AI-tooling and career priority — not because MAYA itself touches CFTR or registry data, but because the Snakemake-plus-per-rule-Conda pattern is exactly the reproducibility architecture worth stealing for your own bioinformatics tool-building. 这对应的是AI工具化与职业发展这个优先级——倒不是因为MAYA本身涉及CFTR或登记处数据，而是因为"Snakemake加逐规则Conda环境"这套模式，正是值得你为自己搭建生物信息学工具时借鉴的可复现架构。

JORDAN So what's the tool sketch? 那工具草图是什么？

ALEX Take the CFTR variant-annotation aggregator we sketched in yesterday's episode — the one pulling dbNSFP scores for CFTR VUS — and rebuild it as a small Snakemake pipeline instead of a single script. 把我们昨天那一集里勾画出的CFTR变异注释聚合器——那个从dbNSFP里拉取CFTR VUS评分的工具——重新搭建成一个小型Snakemake流程，而不是单个脚本。One rule fetches the dbNSFP CFTR-region subset, a second rule computes the VUROC-weighted ranking and transcript-dispersal flags, a third rule renders a report table — each rule gets its own pinned Conda environment, so the pandas and numpy versions one rule depends on can't silently break another. 一条规则负责拉取dbNSFP中CFTR区域的子集，第二条规则计算VUROC加权排名和转录本离散度标记，第三条规则渲染输出报告表——每条规则都有自己锁定版本的Conda环境，这样一条规则所依赖的pandas和numpy版本就不会悄悄破坏另一条规则。

JORDAN Why does that matter more than just writing one script? 为什么这比直接写一个脚本更重要？

JORDAN Difficulty? 难度如何？
