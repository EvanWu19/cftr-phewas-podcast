Ep2 — Track B: From Study Design to Executable Code (THESEUS)

Blurb

THESEUS (Text-guided Health-study Estimation and Specification Engine Using Strategus) is a two-step LLM pipeline from Yonsei University that turns a free-text target trial emulation (TTE) study description into executable Strategus R code inside the OHDSI/OMOP ecosystem. Step 1 uses an LLM only to map prose into a small, structured JSON specification (study period, time-at-risk, propensity-score adjustment, outcome model); step 2 is fully deterministic rule-based logic that converts the human-validated JSON into HADES-module R scripts with a reproducible renv environment. Across 8 LLMs and 30 published TTE studies, standardization accuracy ran 0.82–0.97 depending on setting, with the top models holding up almost as well on reworded ("augmented") versions of the same studies — evidence the approach generalizes rather than relying on memorized text. For this show it lands squarely in the AI-tooling/career priority: the architecture (narrow versioned JSON schema → LLM-only extraction → human diff-and-approve gate → deterministic code generation) is a reusable pattern for any job that repeatedly turns prose study descriptions into code, not just TTE. The buildable artifact is "Spec-Lite," a small prototype that extracts a validated four-field JSON spec from a free-text study paragraph and diffs it against a human baseline for review.

Plain-English glossary

  • ATLAS — The OHDSI web GUI researchers currently use to configure cohorts and study settings by hand.（中文：OHDSI研究者目前用来手动配置队列和研究设置的网页图形界面。）
  • HADES — OHDSI's library of standardized R analysis modules (e.g., cohort characterization, population-level estimation) that Strategus scripts call.（中文：OHDSI开发的一套标准化R语言分析模块库，例如队列特征描述、人群水平效应估计，Strategus脚本会调用这些模块。）
  • OHDSI — The Observational Health Data Sciences and Informatics consortium, a global network that runs standardized observational-research methods on a common data model.（中文：观察性健康数据科学与信息学联盟，一个在统一数据模型上运行标准化观察性研究方法的全球网络。）
  • OMOP CDM (OMOP Common Data Model) — The standardized data structure OHDSI uses so the same analytic code can run unmodified across different hospitals' and countries' data.（中文：OHDSI使用的标准化数据结构，让同一套分析代码可以在不同医院、不同国家的数据上原样运行。）
  • Strategus — The OHDSI software layer that packages a JSON analytic specification into a reproducible pipeline calling HADES modules in the right order.（中文：OHDSI的软件层，把一份JSON分析规格说明打包成按正确顺序调用HADES模块的可复现流程。）
  • Time-at-risk (TAR) — The window after a patient starts an exposure during which an outcome event counts toward the analysis; the hardest of the four fields for LLMs to extract in this study because it's described so inconsistently across papers.（中文：患者开始暴露后，结局事件会被计入分析的时间窗口；本研究中LLM最难提取的字段，因为不同论文的描述方式差异很大。）
  • Target trial emulation (TTE) — A framework for designing an observational study to mirror a hypothetical randomized trial as closely as possible, so the causal estimate is less confounded by loose design choices.（中文：一种研究设计框架，让观察性研究尽可能模仿一个假设的随机对照试验，以减少松散设计选择带来的混杂。）

Methods/tools to lift

  • Two-step LLM-plus-deterministic-rules architecture — LLM only for free-text-to-structured-JSON extraction; all downstream code generation is fixed, auditable, rule-based logic, not LLM-written.
  • Narrow, versioned JSON schema for the fields that actually vary — restrict the extraction target to a small set of design fields (here: study period, time-at-risk, PS adjustment, outcome model) rather than trying to capture an entire protocol.
  • Human diff-and-approve gate — GUI shows field-by-field disagreement between the LLM's JSON and a human-configured baseline before anything is finalized.
  • renv-pinned reproducible environment — code generation ships with a lockfile so the runtime environment, not just the code, is reproducible.
  • Augmented/reworded-description robustness check — generate reworded variants of the same study descriptions to test whether model performance reflects genuine extraction versus memorization of published text.
  • MI-CLEAR-LLM reporting checklist — a structured checklist used to report LLM evaluation in healthcare, referenced as the reporting standard for this study.

Where it lands + buildable artifact

Priority served: AI-tooling/career. This is a pure tooling/software-engineering paper with no CF- or CFTR-specific content; the transferable method is the narrow-schema / LLM-extraction / human-gate / deterministic-codegen pattern itself, which generalizes to any workflow that repeatedly turns prose study descriptions or analysis plans into code.

Buildable artifact: "Spec-Lite."

One-line MVP: paste a free-text study-design paragraph in, get back a validated JSON spec with four fields (study period, time-at-risk, exposure-comparator definition, outcome-model type) plus a diff view against a manually-filled baseline, flagging every field the LLM disagreed on for human review.

  • Input: plain-text protocol/analysis-plan paragraphs (e.g., seeded from published-study abstracts, as THESEUS did for its own gold standard — no proprietary data needed).
  • Difficulty: S (small) — one hand-written JSON schema, one LLM call in structured-output mode, and a basic diff script; no code-generation step required for a first version.

What to verify first

  • Whether this extraction accuracy holds outside the Cohort Method scope tested here — doubly robust estimation and non-Cox/non-Poisson/non-logistic outcome models were excluded entirely.
  • Whether performance holds on genuinely unpublished protocols (zero pretraining-exposure risk), since the augmented-primary robustness check reworded existing studies rather than using fully novel ones.
  • Whether the approach actually saves researcher time or cognitive load in practice — the authors measured only extraction accuracy against a gold standard, not usability with real users.
  • Whether a non-OMOP registry's data model would be standardized enough for the deterministic code-generation half of this pattern to apply at all — this paper doesn't address that question either way.
