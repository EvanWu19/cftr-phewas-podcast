Ep4 (Track C, #2) — The Kahn Framework: Harmonized DQ Terminology

Kahn et al. (2016, EGEMS) is the de facto standard successor to yesterday's Weiskopf & Weng vocabulary — a community consensus process across ~20 major US research networks (540M+ patient records) that reorganizes the same underlying DQ concepts into three categories: Conformance (do values match formatting/relational/computational specs, regardless of believability), Completeness (is a value present, regardless of what it is), and Plausibility (is the value believable, split into uniqueness, atemporal, and temporal subcategories). Built via literature review, OMOP/OHDSI tooling, and two structured stakeholder workshops (~100 contributors total) coded qualitatively in ATLAS.ti, then validated for inclusiveness by successfully cross-mapping against ten prior DQ terminologies. The critical addition beyond yesterday's paper: every category is split into Verification (checked against internally-derived, local expectations — no external reference needed) and Validation (checked against an external gold standard or benchmark) contexts — directly answering yesterday's problem that genuine EHR gold standards rarely exist. Notably, the paper's own worked example for atemporal plausibility under Verification is, verbatim, "height and weight values are positive." Buildable artifact: extend yesterday's five-dimension crosswalk with a second column tagging each candidate flagging rule as Verification-context (buildable now, no external comparator needed) or Validation-context (blocked on acquiring an external benchmark like a growth reference).

Plain-English glossary

  • Atemporal plausibility — whether a value's distribution, or its relationship to another value, matches local or external knowledge at a single point in time (e.g. height and weight values are positive). (中文：非时序合理性，指某个数值的分布，或它与另一数值的关系，在单一时间点上是否符合本地或外部知识，例如身高体重值应为正数。)
  • Computational conformance — whether a derived/calculated value was computed correctly per its formal specification, independent of whether the result is a believable representation of reality. (中文：计算符合性，指某个衍生或计算得出的值是否按照其正式规范被正确计算，与该结果是否真实可信无关。)
  • OHDSI (Observational Health Data Sciences and Informatics) — the open-source community/tooling ecosystem built around the OMOP common data model, including a data-quality dashboard. (中文：观察性健康数据科学与信息学，围绕OMOP通用数据模型建立的开源社区与工具生态，包含一个数据质量仪表盘工具。)
  • OMOP (common data model) — a standardized data structure enabling identical studies to run across institutions with different underlying EHR systems. (中文：观察性医学结果合作项目通用数据模型，一种标准化数据结构，使不同EHR系统的机构能够运行相同的研究。)
  • Temporal plausibility — whether values change over time as expected, including event sequences (e.g. admission date precedes discharge date). (中文：时序合理性，指数值是否按预期方式随时间变化，包括事件顺序，例如入院日期应早于出院日期。)
  • Verification (DQ context) — assessing data against internally-derived expectations (local knowledge, metadata) with no external reference required. Not the machine-learning sense of the word. (中文：验证（数据质量语境），指依据内部推导出的预期——本地知识、元数据——来评估数据，不需要外部参照，注意这与机器学习中"验证集"的含义不同。)
  • Validation (DQ context) — assessing data against an external benchmark, comparator dataset, or accepted gold standard. Not the machine-learning sense of the word. (中文：确认（数据质量语境），指依据外部基准、对照数据集或公认金标准来评估数据，注意这与机器学习中的含义不同。)

Full citation

Methods / tools to lift

  • Three-category DQ framework — Conformance, Completeness, Plausibility, each with Verification/Validation contexts.
  • Verification/Validation distinction — a reusable way to classify whether a DQ check needs an external comparator or can be justified with internal/local knowledge alone.
  • Ten-terminology crosswalk methodology — a template for validating a new taxonomy's inclusiveness against prior frameworks and explicitly documenting what's deliberately out of scope.

Where it lands + buildable artifact

Primarily (d) evaluation — the Verification/Validation split directly operationalizes yesterday's "no gold standard exists" problem into a named, methodologically distinct assessment context; secondarily (e) vocabulary/framework. MVP: add a second column to yesterday's dimension crosswalk tagging each candidate flagging rule Verification-context (buildable now) vs. Validation-context (needs an external benchmark, e.g. a published growth reference). Difficulty: S.

What to verify first

  • Terminology was validated for inclusiveness against ten prior frameworks, not tested against a dataset for whether it improves detection — treat the three-category structure as a well-vetted vocabulary, not empirically optimal pipeline decomposition.
  • Explicitly excludes fitness-for-use and task-dependence from scope (deferred to future work) — this framework alone won't set acceptability thresholds for a given flagging rule.
  • Computational conformance vs. plausibility boundary can be subtle in practice (a technically correct calculation can still be implausible if its specification is wrong) — check real rules against both categories before assuming single-category membership.

Pipeline stage

(d) Evaluation, touching (e) vocabulary/framework.

Error types covered / not covered

Not a detector itself — a classification scheme for how a check is justified (internal knowledge vs. external benchmark), applicable across all error types (unit conversion, digit transposition, decimal shift, carry-forward, real-clinical-event confusion). The framework doesn't distinguish between these error types directly; it distinguishes what kind of evidence any given check for them would need.

ALEX Second Track C paper today, and it's a direct sequel to the first one — Kahn and colleagues, 2016, in EGEMS, "A Harmonized Data Quality Assessment Terminology and Framework for the Secondary Use of Electronic Health Record Data." 今天第二篇Track C的内容，是第一篇的直接续篇——Kahn等人，2016年发表于《EGEMS》期刊，题目是《面向电子健康记录数据二次利用的统一数据质量评估术语与框架》。 Where Weiskopf and Weng built five dimensions from academic literature alone, this one is a community consensus process across roughly twenty of the largest research networks in the US, representing over 540 million patient records, that reorganizes the same underlying ideas into three categories. Weiskopf和Weng是仅从学术文献中归纳出五个维度，而这一篇则是一个社区共识过程，参与方来自美国大约二十个最大的研究网络，覆盖超过5.4亿份患者记录，把同样的底层概念重新组织成了三个类别。

JORDAN Before the categories — what's OMOP and OHDSI, since they keep coming up as source material here? OMOP和OHDSI在这里作为素材来源反复出现，能先讲讲它们是什么吗？

ALEX OMOP is the Observational Medical Outcomes Partnership common data model — a standardized way of structuring clinical data so that studies can run identically across institutions that started with completely different EHR systems. OMOP是观察性医学结果合作项目（Observational Medical Outcomes Partnership）的通用数据模型（common data model）——一种标准化的临床数据结构方式，让不同机构即使原本使用完全不同的EHR系统，也能用同样的方式开展研究。 OHDSI, Observational Health Data Sciences and Informatics, is the open-source community and tooling ecosystem built around that model, including a data-quality dashboard the authors drew on directly. OHDSI，即观察性健康数据科学与信息学（Observational Health Data Sciences and Informatics），是围绕这个模型建立起来的开源社区和工具生态，其中就包括作者直接参考的一个数据质量仪表盘工具。 The other key vocabulary here is a distinction the paper makes explicit and that's easy to misread if you're used to the machine-learning sense of these same two words: Verification and Validation, in this framework, are not train/validation splits. 这里还有一组关键词汇，论文对它们做了明确区分，如果你习惯了这两个词在机器学习里的用法，很容易理解错：在这个框架里，验证（Verification）和确认（Validation）指的不是训练集/验证集的划分。 Verification means checking data against expectations derived internally — local knowledge, metadata, expert judgment — with no external reference required. 验证（Verification）指的是根据内部推导出的预期来检查数据——依据的是本地知识、元数据、专家判断——不需要任何外部参照。 Validation means checking data against an external benchmark, a trusted comparator dataset, or an accepted gold standard. 确认（Validation）指的是根据一个外部基准、一个可信的对照数据集，或者一个公认的金标准来检查数据。 That's a genuinely useful distinction to carry forward, separate from anything about model training. 这是一个真正值得延续使用的区分，和模型训练毫无关系。

JORDAN So what actually motivated pulling together twenty networks to agree on terms? 那到底是什么原因，促使二十个研究网络聚在一起就术语达成一致？

ALEX Scale, and the incoherence that scale exposes. 是规模，以及规模所暴露出的混乱。 As EHR-based research networks grew — national and international efforts pooling data across many institutions for comparative effectiveness and pragmatic trials — inconsistent DQ terminology stopped being a minor annoyance and became a real barrier: if one network reports 90% "accuracy" and another reports 90% "completeness," and those words mean different things in each report, the numbers simply can't be compared or pooled. 随着基于EHR的研究网络不断壮大——那些为了比较效果研究和实用性试验而在众多机构间汇集数据的全国性和国际性项目——不一致的数据质量术语不再只是个小麻烦，而是变成了一个真正的障碍：如果一个网络报告"准确性"为90%，另一个网络报告"完整性"为90%，而这两个词在各自报告里的含义又不一样，那这些数字根本无法比较或汇总。 The project explicitly scoped itself to the first of several needed steps — establishing shared terms and definitions — leaving the harder work of standardized measurement methods and reporting formats for later. 这个项目明确把自己定位为几个必要步骤中的第一步——建立共享的术语和定义——把标准化测量方法和报告格式这些更难的工作留到了以后。 They also explicitly separated intrinsic DQ features, properties of the data values themselves, from extrinsic ones like system access, security, and task-specific fitness for use — this framework covers only the former, deferring the latter to future work. 他们还明确把内在数据质量特征——即数据值本身的属性——和外在特征区分开来，比如系统访问、安全性，以及针对特定任务的适用性——这个框架只涵盖前者，把后者留给未来的工作。

JORDAN How did they actually run the consensus process — was it just a literature review like yesterday's paper? 那他们具体是怎么进行这个共识过程的——是不是就像昨天那篇论文一样做一次文献综述？

ALEX More structured than that. 比那更加结构化。 They started from existing DQ publications, materials from the Mini-Sentinel active-surveillance program, and the OMOP and OHDSI data-quality tooling, then ran two full-day workshops in July 2014 — one with patients, patient-advocacy groups, and policymakers focused on how DQ findings should be communicated, and a separate one with informatics and comparative-effectiveness-research experts who critiqued the draft terms directly. 他们从既有的数据质量出版物、Mini-Sentinel主动监测项目的材料，以及OMOP和OHDSI的数据质量工具出发，然后在2014年7月开展了两场为期一天的工作坊——一场面向患者、患者倡导团体和政策制定者，重点讨论数据质量发现应该如何传达；另一场面向信息学和比较效果研究领域的专家，直接对术语草案进行批判性审查。 Both workshops were recorded, transcribed, and coded in ATLAS.ti, a qualitative data analysis tool, to extract recurring themes, and a further round of revision came from a public wiki page and webinars. 两场工作坊都被录音、转录，并用ATLAS.ti（一款定性数据分析工具）进行编码，以提取反复出现的主题，之后又通过一个公开的wiki页面和网络研讨会进行了进一步的修订。 Roughly 100 individuals contributed across the full process. 整个过程中大约有100人参与贡献。 One thing worth pushing back on: this is a rigorous consensus process, but consensus and correctness aren't the same thing — the paper validates the terminology's inclusiveness by successfully mapping it against ten previously published DQ terminologies, which shows it covers what came before, not that its category boundaries are the ones that best predict or catch real data problems. 有一点值得提出质疑：这是一个严谨的共识过程，但共识和正确并不是一回事——论文验证这套术语的方式，是成功地把它和十套此前已发表的数据质量术语体系做映射比对，这证明了它覆盖了以往的内容，但并不能证明它划分类别的方式就是最能预测或捕捉真实数据问题的那种方式。

JORDAN What are the three categories they landed on? 他们最终确定的三个类别是什么？

ALEX Conformance, Completeness, and Plausibility, deliberately ordered because each one builds on the last. 是符合性（Conformance）、完整性（Completeness）和合理性（Plausibility），这个顺序是刻意安排的，因为每一个都建立在前一个的基础上。 Conformance asks only whether present values match formatting, relational, or computational specifications — does sex have exactly one of the allowed values "M," "F," or "U" — with no regard at all to whether the value is believable. 符合性（Conformance）只问已存在的值是否符合格式、关系或计算方面的规范——比如性别字段的值是不是恰好是"M"、"F"或"U"这几个允许值之一——完全不涉及这个值是否可信。 Completeness asks only whether a value is present, again without regard to what that value actually is. 完整性（Completeness）只问一个值是否存在，同样不涉及这个值本身具体是什么。 Plausibility is where believability finally enters, split into three subcategories: uniqueness, whether an object like a patient record is wrongly duplicated; atemporal plausibility, whether a value's distribution or its relationship to another value matches local or external knowledge at a single point in time; and temporal plausibility, whether values change over time the way they're expected to, including sequences like an admission date preceding a discharge date. 合理性（Plausibility）是可信度真正登场的地方，分为三个子类别：唯一性，即像患者记录这样的对象是否被错误地重复了；非时序合理性（atemporal plausibility），即某个值的分布，或者它与另一个值之间的关系，是否符合本地或外部知识（在单一时间点上）；以及时序合理性（temporal plausibility），即数值是否按预期方式随时间变化，包括像入院日期应该早于出院日期这样的顺序关系。 And here's the detail worth sitting with: the paper's own worked example for atemporal plausibility under the Verification context is, verbatim, "height and weight values are positive." 这里有个细节值得停下来看一看：论文给出的非时序合理性在验证语境下的实际范例，原文就是"身高和体重值为正数"。 That's not a coincidence worth reading too much into, but it does confirm this exact category is where a height or weight implausibility check formally belongs in their taxonomy. 这不是一个需要过度解读的巧合，但它确实证实了，身高或体重的不合理值检查在他们的分类体系中，正式归属的类别就是这一个。

JORDAN You mentioned computational conformance a second ago — how's that different from plausibility if it's still about whether a calculation is "right"? 你刚才提到了计算符合性——如果它讲的也是计算是否"正确"，那它和合理性有什么区别？

ALEX Good catch, and the paper spends real effort on exactly this boundary. 问得好，论文确实花了不少笔墨专门讲这个边界。 Computational conformance asks whether a derived value was computed correctly according to its formal specification — their example is whether a database-calculated body mass index matches a hand-calculated one from the same height and weight, using the same formula. 计算符合性问的是一个衍生值是否按照其正式规范被正确计算出来——他们举的例子是，一个数据库自动计算出的体质指数（BMI），是不是和用同样的身高体重、同样的公式手工算出来的结果一致。 Plausibility, by contrast, asks whether the result represents reality correctly, even if the arithmetic was flawless — their exact phrasing is that a calculation "may be correct according to its formal specification yet not be an accurate representation of the intended concept... because the specification is incorrect or incomplete." 而合理性问的则是，这个结果是否正确地反映了真实情况——即使算术本身完全没有问题也一样——他们的原话是，一个计算"可能按照其正式规范来说是正确的，却不能准确代表其本来想表达的概念……因为规范本身是不正确或不完整的"。 A BMI computed with the correct formula from a height value that's off by a decimal place is computationally conformant and simultaneously implausible — same number, two different diagnoses of what's wrong with it. 一个用正确公式计算出的BMI，如果所依据的身高值小数点点错了位，那么它在计算符合性上是合格的，同时在合理性上却是不合理的——同一个数字，对应着两种不同的问题诊断。

JORDAN Does the Verification-versus-Validation split actually change how the outlier work for Liz gets evaluated? 验证（Verification）与确认（Validation）这个划分，会不会真的改变Liz那项异常值工作的评估方式？

ALEX This is where it goes beyond vocabulary into evaluation, case (d) directly, and it's a nice continuation of yesterday's episode. 这正是它超越单纯词汇、直接进入评估阶段的地方，也就是第(d)类，而且很好地延续了昨天那一集的内容。 Yesterday's paper flagged that genuine external gold standards for EHR data essentially don't exist — that's exactly the Validation context here — but this framework's Verification context is the built-in answer: it explicitly permits assessing plausibility using internally-derived expectations, local knowledge, and metadata constraints, with no external benchmark required at all. 昨天那篇论文指出，对EHR数据而言，真正的外部金标准基本不存在——这正好对应这里的确认（Validation）语境——但这个框架里的验证（Verification）语境正是内置的解决方案：它明确允许仅使用内部推导出的预期、本地知识和元数据约束来评估合理性，完全不需要任何外部基准。 That reframes the evaluation-without-a-gold-standard problem from a dead end into a defined, named assessment context with its own methodology. 这就把"没有金标准该如何评估"这个问题，从一条死胡同，重新定义成了一个有名称、有自己方法论的明确评估语境。 The buildable artifact is a direct extension of yesterday's crosswalk: add a second column to that same rule-by-rule sheet, tagging each candidate flagging rule as Verification-context, meaning it only needs an internally-justifiable expectation, or Validation-context, meaning it needs an external comparator such as a published growth reference — which immediately clarifies which rules can be built and defended today versus which ones are blocked on acquiring an external benchmark. 可构建的原型是昨天那份对照表的直接延伸：在同一张按规则逐行排列的表格里加一列，把每一条候选标记规则标注为验证语境——意味着它只需要一个内部可论证的预期——或者确认语境——意味着它需要一个外部对照，比如一份已发表的生长参考标准——这样立刻就能弄清楚哪些规则今天就能构建并站得住脚，哪些规则则卡在需要先获取外部基准这一步。 Difficulty S, same as yesterday's crosswalk, and the two sheets together form a small but genuinely useful planning tool. 难度为S，和昨天的对照表一样，两张表放在一起就构成了一个虽小但确实有用的规划工具。

JORDAN What would you want to check before leaning on this Verification/Validation split for real planning? 在真正把这个验证/确认划分用于实际规划之前，你会想先核实哪些东西？

ALEX A couple of things. 有几点。 First, this terminology was validated for inclusiveness against ten other published frameworks, not tested against any dataset for whether it actually improves detection — so treat the three-category structure as a well-vetted way to talk about DQ work, not as evidence that Conformance-Completeness-Plausibility is the empirically optimal way to decompose a detection pipeline. 第一，这套术语体系是通过与十套已发表框架做映射比对来验证其涵盖性的，而不是在任何数据集上测试过它是否真的能提升检测效果——所以应该把这个三分类结构当作一种经过充分推敲、用来谈论数据质量工作的方式，而不是把"符合性-完整性-合理性"当作分解检测流程的、经过实证验证的最优方式。 Second, the paper explicitly excludes fitness-for-use and task-dependence from its scope, deferring that to future work, so this framework alone won't tell you what threshold makes a given flagging rule acceptable for a specific downstream use — that judgment still has to come from elsewhere. 第二，论文明确把适用性和任务依赖性排除在了范围之外，将其留给未来的工作，所以仅凭这个框架本身，并不能告诉你某条标记规则在特定下游用途中，应该设定在什么阈值才算合格——那个判断仍然需要从别处得出。 Third, the boundary between computational conformance and plausibility can get subtle in practice — the paper itself notes a calculation can be technically correct by specification yet still implausible if the specification itself is wrong — so any real rule set should be checked against both categories before assuming it cleanly belongs to just one. 第三，符合性中的计算符合性和合理性之间的边界，在实践中可能会变得微妙——论文自己也指出，一个计算按照规范来说可能是完全正确的，但如果规范本身有问题，结果仍然可能不合理——所以任何真实的规则集合在被归入某一个类别之前，都应该同时对照这两个类别检查一遍，而不能想当然地认为它只属于其中一个。
