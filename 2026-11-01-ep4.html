Ep4 (Track C 2/2 — registry QC): HL7-FHIR Bayesian-network data quality tool for obstetrics

Coutinho-Almeida et al.'s 2024 JAMIA Open paper builds and preliminarily validates a data quality evaluation tool for obstetrics EHR data, deployed across nine Portuguese hospitals (73,351 rows, 2019–2020). It adopts the Kahn framework's completeness/plausibility/conformance taxonomy, scoring completeness as the inverse of the null-value percentage and plausibility via two combined methods: a Bayesian network (built with pgmpy) that models conditional dependencies among fields to infer how likely a recorded value is given everything else in the record (cross-validated average AUROC 0.857 across columns), and "outlier-tree," a decision-tree-based method that flags residual outliers leaf-by-leaf so each flag comes with the specific conditions that made it look unusual. The combined score is deployed as a Docker container behind a custom HL7-FHIR operation ("$quality_check") built from Bundle, MessageHeader, Observation, and Device resources. A live deployment on 3,223 new cases produced a stable average quality score (0.75, IQR 0.016) but a genuinely preliminary human-validation step — only 4 clinician responses — which the authors themselves flag as needing a larger follow-up. The episode maps this to CFFPR as a candidate-generation method with a secondary adjudication angle: the deliberate choice of interpretable methods (Bayesian network, outlier-tree) over less transparent alternatives is explicitly about giving a human reviewer a reason a value was flagged, not just a flag.

Plain-English glossary

Bayesian network — A directed graphical model where nodes are variables and edges are conditional dependencies, used here to infer how plausible a recorded value is given the rest of the record.（中文：一种有向图模型，节点为变量、边为条件依赖关系，此处用于根据记录其余部分推断某记录值的合理程度。）

Conformance — One of the Kahn framework's three data-quality dimensions: whether data follows expected formatting and representation standards.（中文：Kahn框架三大数据质量维度之一：数据是否符合预期的格式和表示标准。）

HL7 FHIR — Fast Healthcare Interoperability Resources, a standard for structuring and exchanging healthcare data as modular "resources" (e.g., Observation, Bundle) so different systems can interoperate on a shared data model.（中文：快速医疗互操作资源标准，将医疗数据结构化为模块化"资源"（如Observation、Bundle）以便不同系统基于共享数据模型互操作。）

Kahn framework — A widely used way of organizing research-data quality into three non-overlapping dimensions: completeness (missingness), plausibility (believability of values), and conformance (format/standard compliance).（中文：一种广泛使用的框架，把研究数据质量组织成三个互不重叠的维度：完整性（缺失程度）、合理性（数值可信度）和规范性（格式/标准符合度）。）

Outlier-tree — A decision-tree-based outlier method that predicts each column's value from the others and flags residual outliers leaf-by-leaf, so each flag comes with the specific conditions that made it unusual (unlike isolation forest, which does not localize conditions this way).（中文：一种基于决策树的异常检测方法，用其他列预测某一列的值，并逐叶节点标记残差异常，因此每个标记都附带使其异常的具体条件，这是孤立森林等方法做不到的。）

Plausibility — One of the Kahn framework's three data-quality dimensions: how believable a recorded value is given other known information.（中文：Kahn框架三大数据质量维度之一：在已知其他信息的情况下，记录值有多可信。）

Robson group — An obstetric classification system bucketing deliveries into 10 groups by parity, gestational age, and labor-induction status, used to compare cesarean-section rates fairly across hospitals with different patient mixes.（中文：一种产科分类系统，根据产次、孕周和是否诱导分娩把分娩情况归入10个组别，用于在不同患者构成的医院之间公平比较剖腹产率。）

Methods / tools to lift

  • pgmpy-based Bayesian network — probabilistic graphical model for joint, cross-field plausibility scoring.
  • outlier-tree — decision-tree-based outlier flagging with per-leaf interpretable conditions.
  • HL7 FHIR custom operation ("$quality_check") — a reusable pattern for exposing a quality check as a standards-based API (Bundle/MessageHeader/Observation/Device resources).
  • Kahn framework (completeness/plausibility/conformance) — the organizing taxonomy for the quality dimensions scored.

Where it lands + buildable artifact

Pipeline stage: (a) candidate generation, primary — a working joint-field plausibility detector directly analogous to anthropometric flagging; (b) adjudication, secondary — the explicit design emphasis on interpretable methods is about giving a human reviewer a reason, not just a flag.

Error types covered / not covered: Covers implausible values relative to other correlated fields (joint-field plausibility) and structural outliers detectable by decision-tree logic. Not covered/not addressed: unit conversion, digit transposition, decimal shift, carry-forward error, or explicit real-clinical-event-vs-error disambiguation — the paper's interpretability framing supports that disambiguation as a downstream human step, but doesn't itself resolve it.

Buildable artifact: Bayesian-Network Plausibility Scorer for Anthropometric-Adjacent Fields (prototype) — train a per-field Bayesian network (pgmpy) over a handful of correlated registry fields (height, weight, age, visit type) to produce a plausibility score, cross-validated per-column, as a second interpretable signal layered alongside a spline-based flagger. Rough difficulty: M.

What to verify first

  • The clinician-comparison validation here is explicitly preliminary (4 responses only) — treat it as a pilot, not evidence the score tracks human judgment, until a properly powered follow-up exists.
  • The authors themselves note FHIR gives a shared data model but not a shared semantic/terminology layer (SNOMED CT/LOINC mapping largely absent), and don't know how well a Bayesian network trained on one vendor's data generalizes to another's.
  • The combined score's weighting (more weight to the rule-based component, less to missingness/IQR) was a stated design choice for this obstetrics use case, not something validated against clinician-perceived quality — re-derive or re-justify weights before reusing them for a different field set.
