Ep3 (Track C, 1 of 2) — LLM-DQR: LLM-based automated generation of data quality rules for EHRs

Blurb. Hand-authoring data quality rules for a large registry or EHR schema doesn't scale, and the prior automated alternative (clinical-information-model-based generation, CIM-DQR) is bounded by how complete that pre-built model is — the abstract's numbers suggest it does especially poorly on rules requiring cross-field reasoning. LLM-DQR tests whether an LLM given a schema, plain-language requirements, and sample data can draft rules more like a human domain expert would, validated in a closed loop (deduplication, sandbox execution, iterative debugging). On two public ICU datasets (PIC, MIMIC-IV), the GPT-based implementation reached 97.1% and 99.6% overall rule coverage against a reference set, with the sharpest gap on consistency-type rules (100% vs. CIM-DQR's 0% on both datasets), cut construction time more than tenfold versus manual authoring, and on PIC surfaced 89 additional expert-validated rules beyond the reference set. This episode is abstract-only — the paper is closed access with no PMCID, and Europe PMC hit the standing rate limit on the first call this run. It touches the CFFPR outlier pipeline's candidate-generator stage, specifically the rule-authoring step upstream of flagging logic, not the flagging or adjudication logic itself.

Plain-English glossary

  • Data quality dimensions (completeness, consistency, conformance, plausibility) — a standard taxonomy (traceable to frameworks like Kahn et al.) for naming exactly what kind of data problem is being checked: is a field populated (completeness), do related fields agree (consistency), does a value match an expected format/standard (conformance), and is the value itself believable (plausibility).（中文：数据质量维度——一套标准分类体系（可追溯至Kahn等人的框架），用于精确命名正在检查的是哪一类数据问题：字段是否被填写（完整性）、相关字段是否彼此吻合（一致性）、数值是否符合预期格式/标准（一致性合规，conformance）、数值本身是否可信（合理性）。）
  • PIC (Paediatric Intensive Care) dataset — a publicly available, de-identified pediatric ICU EHR dataset used as a common benchmark in clinical informatics research.（中文：儿科重症监护数据集，一个公开可用的去标识化儿科ICU电子健康记录数据集，是临床信息学研究中常用的基准数据集。）
  • MIMIC-IV — a widely used publicly available, de-identified adult ICU EHR dataset (Beth Israel Deaconess Medical Center) used as a common clinical informatics benchmark.（中文：一个被广泛使用的公开去标识化成人ICU电子健康记录数据集（贝斯以色列女执事医疗中心），是临床信息学领域的常用基准数据集。）
  • Clinical information model (CIM) — a structured, pre-defined representation of what a valid clinical record should contain, used by the comparator method (CIM-DQR) to derive rules.（中文：临床信息模型——一种预先定义好的结构化表示，描述有效临床记录应包含的内容，对比方法CIM-DQR据此推导规则。）
  • Sandbox execution — running a generated rule against real or sample data in an isolated environment to check it executes correctly, as distinct from checking whether it is clinically correct.（中文：沙箱执行——在隔离环境中，用真实或样本数据运行生成的规则，检查其是否能正确执行，这不同于检查它在临床上是否正确。）
  • Chain-of-Thought (CoT) prompting — an LLM prompting technique that has the model work through its reasoning steps explicitly rather than jumping straight to a final answer.（中文：思维链提示——一种大语言模型提示技巧，让模型明确展示逐步推理过程，而不是直接跳到最终答案。）

Methods / tools to lift

  • Schema + plain-language requirements + sample data as LLM input — a reusable input-assembly pattern for any rule-generation task, not specific to this paper's domain.
  • Chain-of-Thought prompting for rule drafting — explicit stepwise reasoning rather than one-shot rule output.
  • Closed-loop validation (dedup + sandbox execution + iterative debugging) — a general pattern for catching syntactic/execution errors in generated rules before they reach a human reviewer.
  • Coverage-against-reference-set evaluation, broken out by DQ dimension — reporting coverage separately for completeness vs. consistency vs. other dimensions surfaces exactly where an automated method's blind spots are (here, CIM-DQR's total miss on consistency rules).

Where it lands + buildable artifact

Pipeline stage: (a) candidate generator, specifically the rule-authoring step that sits upstream of any flagging/candidate-generation logic — this paper is about drafting the rules themselves faster, not about flagging or adjudicating individual records.

MVP: a small proof-of-concept feeding an LLM a toy schema resembling a registry's height/weight/visit-date fields plus plain-language plausibility requirements, checking how many rules from a hand-curated reference set it reproduces and how many additional genuinely useful rules it proposes — on synthetic or public data only, no claim about CFFPR's actual current rules. Difficulty: S for a first pass; validating clinical soundness of generated rules is the slower, open-ended part.

What to verify first

  • The actual generated rules, not just coverage percentages — PIC and MIMIC-IV are single-encounter ICU datasets, not longitudinal registries tracking the same patient's anthropometrics across years, so generalization to that setting is unverified.
  • Rule-level false-positive behavior — a rule can be syntactically valid and pass sandbox execution while still being overly strict or clinically wrong; the abstract reports only aggregate coverage, not rule-level precision.
  • Run-to-run reproducibility of LLM-generated rule sets — the deduplication step implies redundant/overlapping generation across runs, but no variability data is reported.
  • Full methodological detail (exact CoT prompt structure, model version, sandbox scoring) remains unverified until full text is available — this is a closed-access paper read from the abstract only.

Error types covered / not covered

Covered (conceptually, per the abstract): missing/incomplete fields (completeness), cross-field logical mismatches (consistency), format/standard nonconformance. Not covered: unit conversion errors, digit transposition, decimal-shift errors, carry-forward (stale value repeated across visits), real-clinical-event vs. data-error discrimination, or anything specific to longitudinal anthropometric trajectories — this paper is about generating the rule-writing layer for single-encounter ICU EHR data, not about detecting any particular error type in registry-style longitudinal records.
