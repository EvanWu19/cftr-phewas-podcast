Show notes — 2026-09-20, ep4 (Track C — registry data quality, paper 2 of 2)

Blurb

Abstract-only, genuinely closed access. This paper develops the Data Error Criteria (DEC), an explicit criteria set for evaluating a retrospective-chart-review (RCR) dataset for potential data errors. The criteria were built by identifying data coding and data entry errors through literature review and classifying them by error type, yielding a three-part structure: general errors, numerical-specific errors, and categorical-variable-specific errors — a top-level split by variable type with a type-agnostic bucket alongside. Preliminary application: two reviewers independently applied the criteria by manual review to an existing de-identified database of 28,656 data points, identifying 10,168 errors (2,515 general, 39 numerical-specific, 7,614 categorical-variable-specific), with input-related categorical errors most frequent, followed by errors secondary to blank cells, and inter-rater agreement reported as near perfect for all categories. Two things must be read carefully. First, the abstract discloses that the total includes redundancies because an error may fall in multiple categories — so every count is a count of category assignments, not of errors, and the ~35% headline ratio is not an error rate. Second, missingness is counted as an error in this rubric, defensible for a study-specific abstraction form but wrong for a longitudinal registry where a missing value at an encounter is the normal state of the world. The most provocative number is the 39: thirty-nine numerical-specific errors against 7,614 categorical ones, same dataset, same two reviewers, same criteria. Either that dataset was overwhelmingly categorical, or manual chart review is structurally weak at catching wrong numbers — which, if it holds, is an argument for a statistical candidate generator upstream of human review on anthropometrics, not against one.

Plain-English glossary

  • Adjudication — The step where a human decides what a flagged record actually is, as distinct from the step that flagged it.（中文：裁定，指由人判断一条被标记的记录究竟是什么，与产生标记的那一步相区分。）
  • Coding error vs entry error — A coding error assigns the wrong category to a real observation; an entry error is a wrong keystroke or a value placed in the wrong field.（中文：编码错误是给真实观察赋予了错误类别；录入错误是按错键，或把数值放进了错误的字段。）
  • Data Error Criteria (DEC) — The paper's three-part criteria set (general / numerical-specific / categorical-variable-specific) for classifying errors found in a retrospective chart-review dataset.（中文：数据错误准则，本文提出的三部分准则集（一般性／数值型特有／分类型特有），用于分类回顾性病历审阅数据集中发现的错误。）
  • Inter-rater agreement — How often two independent reviewers assign the same label; it measures rubric clarity, not label correctness.（中文：评分者间一致性，即两名独立复核者给出相同标签的频率；它衡量的是规则的清晰度，不是标签的正确性。）
  • Kahn framework / OHDSI DQD — Named registry-DQ frameworks that classify checks (conformance, completeness, plausibility); DEC by contrast classifies what a reviewer found, a different axis.（中文：Kahn框架与OHDSI数据质量仪表盘分类的是"检查项"（一致性、完整性、合理性）；DEC分类的则是"复核者发现了什么"，属于另一个维度。）
  • Retrospective chart review (RCR) — A study design in which trained abstractors read existing clinical documentation and transcribe values into a study dataset.（中文：回顾性病历审阅，一种研究设计，由受训摘录员阅读已有临床文档并把数值转录进研究数据集。）
  • Rubric — A fixed list of labels plus rules for applying them, so independent reviewers code the same finding the same way.（中文：编码规则表，一份固定的标签清单加上应用规则，使独立的复核者对同一个发现给出相同编码。）

Methods / tools to lift

  • The three-part structure split by variable type (general / numerical-specific / categorical-specific) as the skeleton for any error-type rubric.
  • Near-perfect inter-rater agreement as the acceptance test for whether a rubric is written clearly enough — if two reviewers disagree, the rubric is the defect, not the reviewers.
  • Two independent reviewers applying the rubric to the same records, as the minimum design for validating a rubric before deployment.
  • Literature-review-driven criteria development rather than inventing categories from the dataset in hand.
  • Explicitly reject and fix: non-mutually-exclusive categories (replace with one mandatory primary code plus optional secondary codes), and counting blank cells as an error type (move missingness to its own field).

Results worth remembering

  • 10,168 errors identified out of 28,656 data points (~35%), including redundancies — a count of category assignments, not of errors.
  • 2,515 general / 39 numerical-specific / 7,614 categorical-variable-specific.
  • Most frequent: input-related categorical-variable-specific errors; second: errors secondary to blank cells.
  • Inter-rater agreement "near perfect" for all categories (exact statistic not available in the abstract).
  • No gold standard. The reviewers are the measurement instrument; there is no independent source against which their findings were verified. So this reports rubric clarity, not sensitivity and not PPV. There is no random-stratum-vs-flagged-subset distinction because nothing was algorithmically flagged — the whole database was manually reviewed.

Pipeline stage

(b) adjudication — unambiguously. This paper has nothing to say about candidate generation, review budget, or evaluation design. Its entire contribution is the rubric a reviewer applies to a record already in front of them.

Paired deliberately with today's ep3 (Girshovitz et al., MDPT): ep3 generates candidates at the distribution level, ep4 governs what a reviewer writes down once a candidate arrives — a candidate-generation/adjudication two-layer pairing, not a topical one.

Error types covered / not covered

Covered (as classification targets): miscategorized categorical variables; input/keystroke errors; blank cells (counted as errors here, which we'd change); a numerical-specific class that exists in the taxonomy but was barely populated in practice.

Not covered: anything requiring a statistic to detect — there is no threshold, no test statistic, no model anywhere in this method. No longitudinal/within-patient error class (no carried-forward values, no implausible change between visits), since the substrate is a cross-sectional abstraction form rather than a longitudinal series. No treatment of how many records to review, and no detection performance of any kind.

Where it lands + buildable artifact

Artifact: anthropometric error-type coding rubric. Difficulty S.

MVP line: a one-page rubric with a fixed, mutually exclusive list of eight to ten height/weight-specific error types — unit mismatch; decimal-place shift; transposed digits; value belongs to a different patient; value belongs to a different visit date; height decrease beyond measurement error; value carried forward unchanged; sex or age recorded inconsistently; and an explicit "plausible, no error found" code — where each adjudication records exactly one primary type plus optional secondary types, and "missing" is a separate field, not an error type.

Cheapest item on the whole backlog and upstream of everything else, because it is what turns adjudications into labels — and labels are what make any later evaluation of a candidate generator possible. Serves Liz / registry height–weight data quality (external method only; no claim about any registry's internals).

What to verify first

  • What is actually in the criteria list? It's behind the paywall — is there a published table, appendix, or later paper that reproduces it?
  • Is the 39-vs-7,614 split a property of that dataset's composition or a property of human review? Is there any published study measuring a manual reviewer's sensitivity to numeric errors specifically?
  • How was inter-rater agreement computed — kappa, raw percentage, per-category or pooled? "Near perfect" in an abstract can mean quite different things.
  • Has anyone since applied the DEC to a longitudinal dataset rather than a cross-sectional abstraction form, and did they have to change the missingness handling to do it?
  • On our own side: would a rubric with a mandatory single primary code survive contact with real adjudications, or would reviewers hit findings that genuinely need two codes — and how often?
