An automated data cleaning method for Electronic Health Records by incorporating clinical knowledge

Shi X, Prins C, Van Pottelbergh G, Mamouris P, Vaes B, De Moor B. BMC Medical Informatics and Decision Making, 2021.

Builds an automated cleaning pipeline for 52 clinical variables in Intego, a Belgian primary-care EHR database (1994–2015, ~300,000 patients), centered on a "Clinical Knowledge Database" (CKD) — a per-variable lookup table storing legitimate units, unit-conversion formulas, and literature-derived normal/extreme ranges. Two correction steps run per variable: Levenshtein-distance fuzzy matching corrects misspelled unit strings (threshold 0.5, similarity ratio), and a two-stage value rule first tries an order-of-magnitude correction for out-of-range values (e.g. 9 mmHg → 90) then flags anything still outside the extreme range as an outlier and replaces it with a missing value. Applied across 52 variables with >100,000 observations each: completeness dropped less than 1 point for 42 variables (only outlier-to-missing conversion, no imputation), while correctness (% within normal range) rose for every variable, e.g. Monocyte 14.12%→69.93%, Leukocyte 34.04%→98.21%; automated cleaning took 5.2 minutes versus an estimated 30–40 hours manually. No independently sampled gold-standard evaluation exists — correctness is a proxy (% within normal range), and the authors themselves flag the tension between that and true plausibility. It lands mainly as a candidate-generation first-pass filter and, more durably, as a reusable vocabulary/framework (the CKD table design) — the buildable artifact ports that structure to height/weight-adjacent registry fields on synthetic data with injected errors.

Plain-English glossary

  • concordance — one of the five Weiskopf & Weng EHR data-quality dimensions: whether related data elements are consistent with each other (e.g. a prescription matching its recorded diagnosis).（中文：Weiskopf 和 Weng 提出的五个电子病历数据质量维度之一：相关数据要素之间是否彼此吻合（例如处方与所记录诊断是否相符）。）
  • Clinical Knowledge Database (CKD) — this paper's core contribution: a per-variable lookup table storing legitimate units, unit-conversion formulas, and literature-derived normal/extreme ranges, filled in by clinical expertise rather than learned from data.（中文：本文的核心贡献：一张按变量存储合法单位、单位换算公式，以及来自文献的正常/极端范围的查找表，由临床专业知识填入，而非从数据中学习得到。）
  • currency — the data-quality dimension measuring whether data is recent/relevant enough to still be useful.（中文：数据质量维度之一，衡量数据是否足够新近、相关，仍具有可用价值。）
  • extreme range — the wider, biologically-plausible outer bound for a variable's value, distinct from the narrower normal (healthy-population) range; values outside it are flagged as outliers.（中文：某变量取值在生物学上合理的更宽的外边界，区别于更窄的（健康人群）正常范围；超出此范围的数值会被标记为离群值。）
  • Kahn "fit-for-use" framework — an earlier conceptual model for systematically assessing (not fixing) EHR data quality, cited as prior work this paper builds on.（中文：一个较早的概念模型，用于系统性评估（而非修复）电子病历数据质量，本文将其作为前期工作引用。）
  • Levenshtein distance — the minimum number of character insertions, deletions, or substitutions needed to turn one string into another; used here, via a similarity ratio, to fuzzy-match misspelled unit strings.（中文：把一个字符串转换成另一个字符串所需的最少字符插入、删除或替换次数；本文通过相似度比值，用它来模糊匹配拼写错误的单位字符串。）
  • plausibility — the data-quality dimension measuring whether a value falls within a biologically credible range.（中文：数据质量维度之一，衡量某数值是否落在生物学上可信的范围内。）
  • Weiskopf & Weng dimensions — a widely cited 2013 systematic review's five named EHR data-quality dimensions: completeness, correctness, concordance, plausibility, currency.（中文：广受引用的 2013 年系统综述提出的五个电子病历数据质量维度：完整性、正确性、一致性、合理性、时效性。）

Methods/tools to lift

  • Clinical Knowledge Database (CKD) — per-variable config table: legitimate units, conversion formulas, normal/extreme ranges.
  • Levenshtein fuzzy matching — corrects misspelled unit strings against the CKD's legitimate-unit list, threshold 0.5.
  • Order-of-magnitude correction + extreme-range flagging — a two-stage rule: try a magnitude fix first, then flag anything still implausible as an outlier and set to missing.

Where it lands + buildable artifact

Serves Liz / CFFPR data quality (method only).

Pipeline stage: (a) candidate generation (coarse first-pass unit/magnitude-error filter) and (e) vocabulary/framework (the CKD table design and Weiskopf & Weng / Kahn dimension framing are reusable regardless of whether the flagging rule itself transfers).

Buildable: ckd-fuzzy-unit-cleaner-prototype (S) — build a small CKD-style config table for height/weight-adjacent registry variables (plausible unit lists, conversion formulas, normal/extreme ranges from public pediatric references), apply Levenshtein fuzzy matching to correct synthetic unit-string typos, and apply the order-of-magnitude-then-extreme-range rule as a first-pass candidate generator on synthetic longitudinal data with injected unit/magnitude errors, checking flagged-vs-injected-error recovery.

What to verify first

  • Whether unit-string inconsistency of the kind this paper corrects is a real, material problem for any specific height/weight-adjacent registry field.
  • Whether static, literature-derived normal/extreme ranges make sense for a pediatric population moving through a real modulator-era shift in typical growth trajectories.
  • Whether a "correctness = % within normal range" metric would systematically over-flag genuinely sick children's real values as errors in a disease-defined cohort.

Pipeline stage

(a) Candidate generation, primary — a coarse, fast first-pass filter for unit and order-of-magnitude errors, intended to run before finer within-patient trajectory methods. Also (e) vocabulary/framework via the CKD table design.

Error types covered / not covered

  • Covered: unit typos (fuzzy-matched against CKD), order-of-magnitude entry errors (extra/missing zeros), gross biologically-implausible values (extreme-range violations).
  • Not covered: the paper explicitly flags this itself — no longitudinal/within-patient awareness at all (each value judged in isolation against a fixed population range), so real rapid clinical change vs. data error cannot be distinguished; decimal-point shifts and carry-forward/duplicate values are not separately named as their own categories.

ALEX Today's paper is "An automated data cleaning method for Electronic Health Records by incorporating clinical knowledge," by Shi and colleagues at KU Leuven, published in BMC Medical Informatics and Decision Making in 2021. 今天这篇论文是 Shi 及其比利时鲁汶大学（KU Leuven）同事撰写的《一种结合临床知识的电子健康记录自动化数据清洗方法》，发表于 2021 年的《BMC 医学信息学与决策制定》（BMC Medical Informatics and Decision Making）期刊。 It builds an automated cleaning pipeline for 52 clinical variables in Intego, a Belgian primary-care EHR database spanning 1994 to 2015, using a variable-specific "Clinical Knowledge Database" instead of a generic, distribution-based cleaning rule. 这篇论文为 Intego——一个覆盖 1994 到 2015 年的比利时初级医疗电子病历数据库——中的 52 个临床变量，构建了一条自动化清洗流水线，使用的是一个按变量定制的"临床知识数据库"，而不是通用的、基于分布的清洗规则。 We're covering it on Track C, registry data quality, because it's a working, applied template for exactly the kind of value-plausibility and unit-error problem that shows up in any large longitudinal clinical dataset, height and weight included. 我们把它放进 C 赛道——登记数据质量——是因为它是一个真正落地应用的模板，处理的正是任何大型纵向临床数据集（包括身高体重在内）都会出现的数值合理性和单位错误问题。

JORDAN Before the details — what's this "Clinical Knowledge Database" they keep referencing, and what are these data quality dimensions they cite from the literature? 在讲细节之前——他们反复提到的这个"临床知识数据库"到底是什么？他们从文献中引用的那些数据质量维度又是什么？

ALEX Start with the dimensions, since they frame everything else. 先从维度讲起，因为它们为其他一切内容提供了框架。 The paper leans on Weiskopf and Weng's widely cited 2013 systematic review, which named five dimensions of electronic health record data quality: completeness, the percentage of data that isn't missing; correctness, the percentage of data that's accurate; concordance, whether related data elements are consistent with each other, like a prescription matching its recorded diagnosis; plausibility, whether a value falls within a biologically credible range; and currency, whether the data is recent and relevant enough to still be useful. 论文依据的是 Weiskopf 和 Weng 广受引用的 2013 年系统综述，其中提出了电子健康记录数据质量的五个维度：完整性（completeness），即数据未缺失的比例；正确性（correctness），即数据准确的比例；一致性（concordance），即相关数据要素之间是否彼此吻合，比如处方是否与所记录的诊断相符；合理性（plausibility），即某个数值是否落在生物学上可信的范围内；以及时效性（currency），即数据是否足够新近、相关，仍然具有可用价值。 A second named framework is Kahn et al.'s "fit-for-use" conceptual model, which the paper cites as an earlier attempt to systematically assess — though not itself fix — data quality along similar lines; it's a data-quality-assessment framework rather than a cleaning method, and that distinction matters a lot here, since most prior work in this space only assessed quality without automating the fix. 论文引用的第二个命名框架是 Kahn 等人提出的"适用性"（fit-for-use）概念模型，论文将其描述为一次沿类似思路系统评估——而非本身修复——数据质量的早期尝试；这是一个数据质量评估框架，而非清洗方法，这个区别在这里很关键，因为该领域此前的大多数工作只是评估质量，而没有实现自动化修复。 The Clinical Knowledge Database itself, CKD for short — not to be confused with chronic kidney disease — is the paper's own contribution: a lookup table, one row per clinical variable, storing every unit that variable might legitimately appear in, the conversion formula between those units, a "normal range" reflecting healthy population values, and a wider "extreme range" reflecting the outer bound of biological plausibility, both filled in from literature and clinical expertise rather than learned from the data itself. 临床知识数据库本身，简称 CKD——不要与慢性肾病（chronic kidney disease）的缩写混淆——是本文自己的贡献：一张查找表，每个临床变量对应一行，存储该变量可能合法出现的每一种单位、这些单位之间的换算公式、反映健康人群数值的"正常范围"，以及反映生物学合理性外边界的更宽的"极端范围"，这两个范围都是根据文献和临床专业知识填入的，而不是从数据本身学习得到的。

JORDAN So what problem motivated building this, rather than just using an existing generic cleaning tool? 那这促使他们搭建这个系统的动机是什么，而不是直接用现有的通用清洗工具？

ALEX The Intego database is large — by 2015 it held over 3 million clinical measurements, 3 million diagnoses, 14 million prescriptions, and 38 million laboratory tests spanning roughly 10,000 variables — and the authors' framing is that generic automated cleaning tools, the kind built for tabular data in general, process every variable uniformly using distribution-based statistics: flag whatever looks far from the bulk of the values for that column. Intego 数据库规模庞大——到 2015 年时，它已积累了超过 300 万条临床测量记录、300 万条诊断记录、1400 万条处方记录，以及涵盖约 1 万个变量的 3800 万条实验室检测记录——作者的论点是，通用的自动化清洗工具，也就是那些为一般表格数据设计的工具，会用基于分布的统计方法统一处理每一个变量：只要看起来偏离该列数值主体，就标记出来。 That fails specifically in clinical data because a population that mixes healthy people and genuinely sick patients has a naturally wide, sometimes multimodal distribution for many variables, so a purely statistical outlier rule will happily flag real patients' real abnormal values as errors whenever a disease is uncommon enough that its values sit in the tail. 这在临床数据中恰恰会出错，因为混合了健康人群和真正患病者的人群，许多变量本就自然呈现出较宽、有时是多峰的分布，因此一个纯统计的离群值规则，一旦某种疾病足够罕见、其数值落在分布尾部，就很容易把真实患者的真实异常值误标为错误。 Two prior efforts get named and distinguished: Phan and colleagues had already built an automated cleaning method, but scoped only to height and weight; Tang and colleagues built a broader pipeline, but it handled data extraction, feature selection, and harmonization rather than actually correcting wrongly entered values. 论文提到并区分了两项此前的工作：Phan 及其同事此前已经搭建过一种自动化清洗方法，但仅限于身高和体重；Tang 及其同事搭建了一条更广泛的流水线，但处理的是数据提取、特征选择和数据协调，而不是真正纠正录入错误的数值。 The gap the paper is filling, then, is a general-purpose method that works across many different clinical variable types — not just anthropometrics — while still respecting each variable's own clinically meaningful range, rather than falling back on population statistics whenever the variable isn't height or weight specifically. 因此，这篇论文所填补的空白，是一种跨越多种不同临床变量类型——不仅限于人体测量指标——的通用方法，同时仍然尊重每个变量自身在临床上有意义的取值范围，而不是一旦变量不是身高或体重，就退回去依赖群体统计量。

JORDAN Walk me through exactly what gets flagged, and on what statistic. 具体讲讲到底什么会被标记，依据的是什么统计量。

ALEX There are two separate correction steps, run variable by variable using each row of the CKD. 这里有两个独立的修正步骤，按变量逐一进行，依据 CKD 中对应的那一行数据。 The first is a fuzzy-search step for unit typos: using Levenshtein edit distance — the minimum number of character insertions, deletions, or substitutions needed to turn one string into another — the algorithm computes a similarity ratio between the recorded unit string and every legitimate unit listed for that variable in the CKD, and replaces the recorded unit with whichever legitimate unit scores the highest similarity, provided that similarity clears a threshold set at 0.5; below that threshold, the unit is replaced with a missing value rather than guessed at. 第一步是针对单位拼写错误的模糊搜索：使用莱文斯坦编辑距离（Levenshtein distance）——即把一个字符串转换成另一个字符串所需的最少字符插入、删除或替换次数——算法计算记录的单位字符串，与该变量在 CKD 中列出的每一个合法单位之间的相似度比值，并将记录单位替换为相似度最高的那个合法单位，前提是该相似度达到 0.5 的阈值；低于这个阈值，该单位会被替换为缺失值，而不是被强行猜测。 The second step is value correction and outlier detection, and it's a two-stage decision rule: if a recorded value falls outside the variable's normal range, the algorithm first tries an order-of-magnitude transformation — for blood pressure, a value of 9 becomes 90, a value of 16,000 becomes 160 — attempting to bring the value back toward plausibility through the single most common entry-error pattern, extra or missing zeros. 第二步是数值修正与离群值检测，这是一个两阶段的决策规则：如果记录的数值落在该变量正常范围之外，算法首先尝试一次数量级变换——对于血压，把 9 变成 90，把 16000 变成 160——通过最常见的一种录入错误模式（多写或漏写零）尝试把数值拉回合理范围。 If, after that transformation, the value is still outside the wider extreme range — the biologically-plausible outer bound, also stored in the CKD — it's classified as an outlier and replaced with a missing value rather than any further guessed correction; a value like 3000 for blood pressure, which stays implausible even reinterpreted as 30 or 300, gets dropped rather than salvaged. 如果经过这次变换后，数值仍然落在更宽的极端范围（同样存储在 CKD 中，代表生物学上合理的外边界）之外，它就被判定为离群值，替换为缺失值，而不做进一步的猜测性修正；比如血压值 3000，即使重新解读为 30 或 300 也仍不合理，会被直接丢弃而不是被强行挽救。

JORDAN Where would you push back on that decision rule? 你会在这个决策规则上提出哪些质疑？

ALEX Two places. 两个地方。 First, the normal and extreme ranges are static and clinician-filled from literature — there's no statistical learning here at all, and no mechanism for a range to reflect a value that's genuinely shifting over calendar time, whether that's a population-level secular trend or, closer to our interest, a treatment-era shift like a modulator therapy changing what a "normal" weight trajectory looks like for a specific disease population. 第一，正常范围和极端范围是静态的、由临床医生根据文献填入的——这里完全没有统计学习，也没有机制能让某个范围反映一个正在随日历时间真实变化的数值，无论是群体层面的长期趋势，还是与我们更相关的、由治疗时代转变带来的变化，比如调节剂疗法改变了某个特定疾病人群"正常"体重轨迹的样子。 Second, and the authors flag this limitation themselves quite explicitly, the method has no longitudinal awareness at all: each value is judged purely on its own, against a fixed population range, with zero information from that same patient's other visits. 第二，作者们自己也相当明确地指出了这一局限：这个方法完全没有纵向意识——每个数值都仅凭自身，对照一个固定的群体范围来判断，完全不利用同一患者其他就诊记录中的信息。 They give a genuinely good example of why that matters: a patient with cholesterol readings of 189, 174, then 700 has a value that could easily be flagged as a data error by a longitudinal method, when it's exactly the kind of real, sudden clinical deterioration you'd actually want the method to keep, not discard — and their static-range approach happens to keep it correctly here only because 700 still sits inside the extreme range for cholesterol, not because the method reasoned about the patient's trend at all. 他们给出了一个很好的例子，说明这一点为何重要：一位患者的胆固醇读数依次为 189、174，然后是 700，这个数值很容易被一个纵向方法误标为数据错误，而实际上这正是你希望方法能够保留、而不是丢弃的那种真实的、突发的临床恶化——他们这种静态范围方法之所以在这里恰好保留对了，仅仅是因为 700 仍落在胆固醇的极端范围之内，而不是因为方法真正对该患者的趋势进行了推理。

JORDAN So how well did it actually perform? 那它的实际表现如何？

ALEX The evaluation is framed around two of the five named dimensions: completeness and correctness, where correctness here specifically means the percentage of values falling within the normal range after cleaning. 评估围绕五个命名维度中的两个展开：完整性和正确性，这里的正确性具体指的是清洗后落在正常范围内的数值所占的比例。 All 52 variables started at 100% completeness before cleaning — there were no truly empty cells, only meaningless placeholder entries like commas or the string "null," which is itself a real-world data-entry pattern worth noting. 所有 52 个变量在清洗前的完整性都是 100%——不存在真正的空单元格，只有一些无意义的占位符条目，比如逗号，或者字符串"null"，这本身就是一个值得注意的真实世界数据录入模式。 After cleaning, 42 variables dropped less than 1 percentage point in completeness, 9 variables dropped between 1 and 10 points, and just one variable took a large hit, a 13.36-point drop — this decline is expected and by design, since the only way completeness can fall here is through outliers being converted to missing values, not through any imputation. 清洗后，42 个变量的完整性下降不到 1 个百分点，9 个变量下降 1 到 10 个百分点，只有一个变量出现较大跌幅，下降了 13.36 个百分点——这种下降是预期之内、且是设计使然的，因为在这里完整性下降的唯一途径，就是离群值被转换为缺失值，而不是通过任何插补造成的。 On correctness, every one of the 52 variables ended up with more than 50% of its values inside the normal range, and 43 of the 52 exceeded 70%; two headline examples from the top-10-by-volume table are Monocyte count, rising from 14.12% to 69.93% in normal range, and Leukocyte count, rising from 34.04% to 98.21%. 在正确性方面，52 个变量中的每一个，清洗后落在正常范围内的比例都超过了 50%，其中 43 个超过了 70%；表格中按数据量排名前十的变量里，有两个突出的例子——单核细胞计数（Monocyte），正常范围内比例从 14.12% 升至 69.93%；白细胞计数（Leukocyte），从 34.04% 升至 98.21%。 Efficiency numbers are striking too: the authors estimate manual cleaning of around 50 variables, based on past experience from earlier studies, takes a proficient data scientist 30 to 40 hours, whereas the automated method processed the same scale of work in 5.2 minutes. 效率数字也相当惊人：作者根据以往研究的经验估计，一名熟练的数据科学家手动清洗约 50 个变量需要 30 到 40 小时，而自动化方法完成同等规模的工作只用了 5.2 分钟。 What's missing, and worth being honest about, is any independently sampled evaluation stratum — there's no randomly drawn, expert-adjudicated set of "true" values to check the flagged-as-outlier decisions against; correctness here is entirely a proxy, defined as landing in the normal range, and the authors themselves note the tension between that and true plausibility, since a genuinely sick patient's real value can legitimately fall outside the normal range without being an error at all. 有所欠缺、也值得坦诚说明的是，这里没有任何独立抽样的评估分层——没有一组随机抽取、经专家判定的"真实"数值，用来检验被标记为离群值的判断是否正确；这里的"正确性"完全是一个代理指标，定义为落在正常范围内，作者自己也指出了这与真正的合理性之间的张力，因为一个真正患病的患者，其真实数值完全可能合理地落在正常范围之外，而不算是一个错误。

JORDAN Does this change the CFFPR outlier pipeline? 这会改变 CFFPR 的离群值处理流程吗？

ALEX Framed honestly, as an external method rather than any claim about what CFFPR currently does: this lands mainly as (a), a candidate generator — specifically a coarse, fast, first-pass filter that catches gross unit and order-of-magnitude errors cheaply, before any more sophisticated within-patient trajectory method, like a spline mixed-effects residual approach, ever runs. 老实说，把它当作一个外部方法，而不是对 CFFPR 现有做法的任何断言：这主要落在 (a) 候选生成这个环节——具体来说，是一个粗粒度、速度快的第一遍筛选，能够低成本地在任何更精细的、基于患者内轨迹的方法（比如样条混合效应模型残差方法）运行之前，捕捉到明显的单位和数量级错误。 It also lands, arguably more usefully for us, on (e) — vocabulary and framework worth borrowing even where the method itself doesn't transfer directly: the Clinical Knowledge Database's structure, a per-variable table of legitimate units, conversion formulas, and normal/extreme
