Show notes — ClinVar: improving access to variant interpretations and supporting evidence (Landrum et al., 2018)

Track A — CF/CFTR variant interpretation & harmonization

Blurb

ClinVar is NCBI's public archive of submitted human-variant interpretations, and this 2018 Nucleic Acids Research database-update paper documents the release that made it usable at scale. By that point ClinVar held >500,000 submitted records covering >331,000 distinct variants from >800 groups in 60 countries. The headline change is the VCV accession (Variation in ClinVar), which aggregates everything known about a single variant across all diseases — completing a three-tier model: SCV (one submission) → RCV (variant–disease pair) → VCV (variant). It also shipped allele-centric VCF files keyed on Variation ID with new tags (CLNHGVS canonical genomic HGVS, MC molecular consequence via Sequence Ontology, ALLELEID), a new variant-centric XML, and a genuinely new submission class: phenotype-rich submissions ("provider interpretation" and "phenotyping only," via HPO/MedGen) where a registry can contribute phenotype without voting on pathogenicity. Where it lands: the Karen / variant-interpretation priority. Buildable artifact: a CFTR ClinVar harmonization-and-reconciliation table — normalize every CFTR Variation ID to a single canonical MANE-select HGVS and flag submitter conflicts and unreconcilable notation, yielding a prioritized VUS curation worklist.

Plain-English glossary

  • allele — a single specific sequence change at a position.（中文：等位基因，指某个位置上单一的序列改变。）
  • complex allele — two or more variants inherited together on the same chromosome copy that only make sense interpreted jointly; CFTR has several.（中文：复杂等位基因，指同一条染色体上一起遗传、必须联合解读的两个或更多变异，CFTR 有几个著名例子。）
  • gnomAD — large population database of variant allele frequencies, used to judge whether a variant is too common to be highly penetrant.（中文：gnomAD，大规模人群变异频率数据库，用来判断某变异是否常见到不太可能高度致病。）
  • haplotype (in cis) — a set of variants on the same physical chromosome copy.（中文：单倍型（顺式），指位于同一条物理染色体拷贝上的一组变异。）
  • HGVS — the Human Genome Variation Society standard for writing variants relative to a named reference sequence (e.g. NM_000492.4:c.1521_1523delCTT).（中文：HGVS，变异书写的标准化规范，相对于指定参考序列来命名变异。）
  • HPO — Human Phenotype Ontology; standardized coded terms for clinical features.（中文：HPO，人类表型本体，给临床特征统一编码的术语集。）
  • MANE-select — Matched Annotation from NCBI and EMBL-EBI; the cross-agency agreed canonical reference transcript per gene.（中文：MANE-select，NCBI 与 EMBL-EBI 共同商定的每个基因的标准参考转录本。）
  • missense variant — a single-base change that swaps one amino acid for another.（中文：错义变异，单碱基改变导致一种氨基酸被换成另一种。）
  • molecular consequence — the predicted functional class of a change (missense, splice donor, etc.), here tagged with a stable Sequence Ontology code.（中文：分子后果，指改变的功能类别（错义、剪接供体等），此处用稳定的 Sequence Ontology 编码标注。）
  • review status ("stars") — ClinVar's indicator of how much scrutiny supports a call (criteria provided, submitter consensus, expert-panel review).（中文：审核状态（星级），ClinVar 标示某判断有多少审查支撑的指标。）
  • SCV / RCV / VCV — the three ClinVar aggregation tiers: a single submission, a variant–disease pair, and a per-variant aggregate.（中文：SCV/RCV/VCV，ClinVar 的三层聚合：单条提交、变异-疾病对、每个变异的汇总。）
  • VCF — Variant Call Format, the standard text format for variant sites; ClinVar's new files are allele-centric, keyed on Variation ID.（中文：VCF，存储变异位点的标准文本格式；ClinVar 新文件以等位基因为中心，用 Variation ID 作主键。）
  • VUS — variant of uncertain significance; evidence insufficient to call pathogenic or benign.（中文：VUS，意义未明的变异，证据不足以判定致病或良性。）

Full citation

Landrum MJ, Lee JM, Benson M, et al. ClinVar: improving access to variant interpretations and supporting evidence. Nucleic Acids Res. 2018;46(D1):D1062–D1067. PMID 29165669 · PMC PMC5753237 · DOI 10.1093/nar/gkx1153

Methods / tools to lift

  • Three-tier aggregation (SCV→RCV→VCV) — separates a raw submission, a variant–disease interpretation, and a per-variant aggregate; copy this rather than flattening everything into one table.
  • Versioned VCV accessions — stable identifier per variant with incremented version history when underlying submissions change; gives reproducible snapshots.
  • Allele-centric VCF tags — CLNHGVS (canonical genomic HGVS), MC (molecular consequence + Sequence Ontology ID), ALLELEID; note transcript-level HGVS lives separately in hgvs4variation.txt.
  • Phenotype-rich submission model — "phenotyping only" lets a registry contribute HPO/MedGen phenotype without contributing to the pathogenicity aggregate; clean separation of observation from interpretation.
  • Entrez indexed fields — query by HGVS, HGNC ID, HPO trait ID, rs number, clinical significance property, and "last interpreted" date range.

Where it lands + buildable artifact

Serves the Karen / variant-interpretation priority. Paste-ready MVP: Build a CFTR ClinVar harmonization-and-reconciliation table — pull every CFTR Variation ID from the ClinVar VCV XML + hgvs4variation.txt, normalize each to a single canonical MANE-select HGVS by round-tripping CLNHGVS, and flag every variant with submitter conflict or unreconcilable notation; rank the conflict set by number of conflicting submitters and "last interpreted" date to yield a prioritized VUS curation worklist. Input: ClinVar VCV XML + hgvs4variation.txt filtered to CFTR. Difficulty: S–M.

What to verify first

  • Transcript-mapping completeness: do all CFTR variants round-trip cleanly to MANE-select? Deep-intronic and complex alleles break HGVS converters.
  • Date-stamp the snapshot — ClinVar updates weekly; a reconciliation on a stale download drifts silently.
  • Define "disagreement" carefully — the star system already distinguishes criteria-backed conflict from noise; don't flatten it.
  • This touches only the public ClinVar representation — no internal registry genotype data is involved.
