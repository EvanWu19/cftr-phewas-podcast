How did this episode land for you?

Leveraging open-source large language models for clinical information extraction in resource-constrained settings

Builtjes L, Bosma J, Prokop M, van Ginneken B, Hering A. JAMIA Open 2025. Ships llm_extractinator (open-source, GitHub: DIAGNijmegen/llm_extractinator), a four-stage pipeline — task-schema specification, LangChain-built prompts, local inference through Ollama, and schema-validated post-processing with self-correction — for zero-shot clinical information extraction with open LLMs, entirely on local infrastructure. Benchmarked on DRAGON, a 28-task, 28,824-report Dutch clinical-NLP benchmark, across nine open-weight models from 2B to 70B parameters, mostly 4-bit quantized to fit a single consumer GPU. Llama-3.3-70B led (utility score 0.760), with several 14B-class models close behind (0.744–0.751) — all of them beating a fine-tuned RoBERTa baseline on roughly half the 28 tasks despite zero task-specific training, especially on regression, while collapsing on named entity recognition. Translating Dutch input to English before inference consistently hurt performance rather than helping. Lands on AI-tooling/career (not Liz/registry-QC — this is new-value extraction from free text, a different problem from flagging implausible values already in the registry) — buildable artifact: a Mini Clinical-Extraction Benchmark applying llm_extractinator's own recipe, locally via Ollama, to a handful of hand-labeled CF-relevant extraction tasks.

Plain-English glossary

  • DRAGON (Diagnostic Report Analysis: General Optimization of NLP) — A Dutch clinical-NLP benchmark covering 28 classification, regression, and named-entity-recognition tasks across 28,824 annotated medical reports from five hospitals.（中文：一个荷兰语临床自然语言处理基准，覆盖28个分类、回归和命名实体识别任务，数据来自五家医院的28,824份标注医疗报告。）
  • Krippendorff's Alpha — A statistic measuring agreement among multiple human annotators labeling the same data; lower values indicate more disagreement.（中文：一种衡量多位标注者对同一数据标注一致程度的统计量；数值越低说明分歧越大。）
  • LangChain — An open-source framework for chaining prompt construction and model calls together into a pipeline.（中文：一个开源框架，用于把提示词构建和模型调用串联成一条流水线。）
  • Ollama — An open-source tool for downloading, quantizing, and running large language models locally, with no cloud API involved.（中文：一个开源工具，用于在本地下载、量化并运行大语言模型，整个过程不涉及云端API。）
  • Quantization — Shrinking a model's numeric weights to a coarser format (e.g., 4-bit) so it fits in far less GPU memory, at some cost in precision.（中文：把模型的数值权重压缩成更粗粒度的格式（如4比特），从而大幅减少所需GPU显存，但会损失一些精度。）
  • Zero-shot — Running a model on a task with no task-specific fine-tuning and no in-context examples, relying solely on its pretrained knowledge and the prompt.（中文：在没有针对该任务做微调、也没有提供上下文示例的情况下运行模型，完全依靠其预训练知识和提示词本身。）

Full citation

Methods / tools to lift

  • llm_extractinator pipeline — task-schema specification (JSON/Pydantic) → LangChain prompt construction with zero-shot chain-of-thought → Ollama-served local inference → schema-validated post-processing with up to 3 self-correction cycles.
  • Ollama-served open LLMs — nine models (Gemma2-2B through Llama-3.3-70B), 4-bit quantized, chosen for feasibility on a single consumer-grade 12GB GPU.
  • DRAGON utility score — arithmetic mean of task-specific metrics (AUC, Cohen's kappa, RSMAPE, F1) across a diverse clinical-NLP task suite, for honest cross-model comparison.
  • Code repository: github.com/DIAGNijmegen/llm_extractinator

Where it lands + buildable artifact

Lands on AI-tooling / career (not Liz/registry-QC — no claim made about CFFPR's own free-text field structure). Buildable artifact: Mini Clinical-Extraction Benchmark — using llm_extractinator as-is, write a small number of hand-labeled extraction tasks against synthetic or de-identified CF-relevant clinical-note snippets (e.g., a classification task for pancreatic-enzyme-replacement mention, a regression task for a reported FEV1 percentage), then run two or three of the paper's top-tier open models locally via Ollama for a direct, first-hand performance read. Difficulty: S–M.

What to verify first

  • Regression and structured classification were this paper's clear strengths and NER its clear weakness — sort any CF-relevant task into one of those buckets honestly before assuming it will transfer.
  • The entire evaluation ran in Dutch; an English-language CF clinical note is a different linguistic setting, and while that removes the specific low-resource-language penalty measured here, it doesn't guarantee the same tier structure carries over.
  • This is a strict zero-shot, no-prompt-engineering design — the paper's own stated floor, not a ceiling; budget for at least some task-specific prompt iteration before concluding a model can't do something.
  • The DRAGON task labels themselves are not downloadable (only submitted algorithms get scored against a hidden test set), so any CF-relevant replica needs its own gold-standard labels built from scratch.

ALEX Today's paper is from Builtjes, Bosma, Prokop, van Ginneken, and Hering, out of Radboud University Medical Center, published this year in JAMIA Open — "Leveraging open-source large language models for clinical information extraction in resource-constrained settings." 今天这篇论文来自奈梅亨大学医学中心的Builtjes、Bosma、Prokop、van Ginneken和Hering，今年发表在JAMIA Open上——题目是《在资源受限环境下，利用开源大语言模型做临床信息提取》。

JORDAN Resource-constrained — meaning what, exactly? "资源受限"具体指什么？

ALEX It's Track B, it ships real open-source code, and the whole point is doing serious clinical NLP without an API call to a proprietary model and without hospital data ever leaving the building — which is the exact deployment constraint most registry and health-system settings actually live under. 这是B线，它发布了真正开源的代码，而整篇论文的核心就是：在不调用任何专有模型的API、也不让医院数据离开院内的前提下，做严肃的临床自然语言处理——而这恰恰是大多数登记系统和医疗系统实际面对的部署约束。

JORDAN Start with the benchmark — what is DRAGON? 先从基准测试讲起——DRAGON是什么？

ALEX DRAGON（Diagnostic Report Analysis: General Optimization of NLP，诊断报告分析的NLP通用优化基准）is a Dutch clinical-NLP benchmark built from 28,824 annotated medical reports across five Dutch hospitals, covering 28 separate information-extraction tasks — classification, regression, and named entity recognition — all in Dutch, a genuinely low-resource language for most LLMs. DRAGON（诊断报告分析的NLP通用优化基准，英文Diagnostic Report Analysis: General Optimization of NLP）是一个荷兰语临床自然语言处理基准，由来自五家荷兰医院的28,824份标注医疗报告构成，覆盖28个独立的信息提取任务——分类、回归和命名实体识别——全部用荷兰语，而对大多数大语言模型来说，荷兰语确实是一种资源稀缺的语言。

JORDAN And "quantization" — that keeps coming up whenever local models are mentioned. 还有"量化"——每次提到本地部署的模型都会出现这个词。

ALEX Quantization（模型量化，quantization）shrinks a model's numeric weights from their original high-precision format down to a coarser one, like 4-bit, so the whole model fits in far less GPU memory at some cost in precision; it's the difference between needing a data-center GPU and running on a single consumer card, which is exactly the constraint this paper is designed around. 量化（英文quantization）把模型的数值权重从原本的高精度格式压缩成更粗粒度的格式，比如4比特，这样整个模型占用的GPU显存大大减少，代价是精度有所损失；这就是需要一块数据中心级GPU和能在一块消费级显卡上跑起来之间的区别，而这正是这篇论文从一开始就在围绕的约束条件。

JORDAN And Ollama? Ollama又是什么？

ALEX Ollama is the open-source local-model serving tool this framework builds on — point it at a model name on the Ollama hub, and it handles downloading, quantized loading, and running inference locally, no cloud API involved. Ollama是这个框架所依赖的开源本地模型服务工具——只要指定Ollama hub上的一个模型名字，它就会自动处理下载、量化加载和本地推理，整个过程完全不涉及云端API。

JORDAN What was the actual gap this paper is trying to close? 这篇论文到底想填补什么空白？

ALEX Medical reports are a goldmine of structured-extractable information — diagnoses, procedures, medications, findings — but they're unstructured free text, heavy with institution-specific jargon, which has always made extraction hard; rule-based systems struggled, and transformer models like BERT and its medical variant Med-BERT did better but still need large, task-specific labeled training sets for every single extraction task. 医疗报告是一座信息金矿——诊断、操作、用药、检查发现都在里面——但它们是非结构化的自由文本，充斥着机构特有的行话，这一直让信息提取变得困难；基于规则的系统表现不佳，像BERT及其医学变体Med-BERT这样的transformer模型表现更好，但每一个具体的提取任务仍然需要大量针对该任务标注的训练数据。

ALEX Generative LLMs promised a way around that — prompt them instead of fine-tuning them, and in principle you skip the labeled-data bottleneck entirely — but almost all the published evidence for that promise comes from proprietary models like GPT-4, accessed over an API. 生成式大语言模型本应能绕开这个问题——用提示词而不是微调来驱动模型，理论上就能完全跳过标注数据这个瓶颈——但几乎所有已发表的相关证据，都来自像GPT-4这样通过API访问的专有模型。

ALEX That's a real problem for hospitals: sending patient report text to an external API raises genuine privacy and regulatory concerns, and proprietary training data is largely undisclosed, so you can't audit what the model actually learned on or whether it might have been contaminated by similar benchmark data. 对医院来说这是一个真实的问题：把患者报告文本发送给一个外部API，会带来实实在在的隐私和监管顾虑，而专有模型的训练数据大多不公开，你没法审查模型到底学过什么，也没法排除它是否被类似的基准数据污染过。

ALEX Open-source models solve the deployment-location problem — everything runs on local infrastructure — but open-source models are also typically pretrained on more curated, English-and-a-few-major-languages-heavy datasets, so nobody had systematically asked how well they actually perform on a genuinely under-resourced language like Dutch, across a realistic range of clinical extraction task types, in a strict zero-shot setting with no fine-tuning and no in-context examples at all. 开源模型解决了部署位置的问题——一切都在本地基础设施上运行——但开源模型通常也是在更精选、以英语及少数几种主要语言为主的数据上预训练的，所以此前从没有人系统性地研究过，在一种真正资源稀缺的语言——荷兰语上，在一个覆盖多种临床提取任务类型、严格零样本（没有微调、也没有上下文示例）的设定下，这些开源模型到底表现如何。

JORDAN So what did they actually build? 那他们到底搭建了什么？

ALEX They built and open-sourced llm_extractinator — on GitHub as DIAGNijmegen/llm_extractinator — a four-stage pipeline: task specification, where you define the input field, task description, and a JSON or Pydantic output schema, often through a drag-and-drop web studio; prompt construction, where LangChain（一个用于串联提示词与模型调用的开源框架，LangChain）combines the instructions, schema, and a zero-shot chain-of-thought cue into one prompt; model inference, where the prompt goes to whatever model is loaded in Ollama, with context length scaled automatically to the input; and post-processing, where outputs are validated against the schema, with up to three automatic self-correction cycles for the model to fix its own malformed JSON before a placeholder gets substituted in as a last resort. 他们搭建并开源了llm_extractinator——在GitHub上的DIAGNijmegen/llm_extractinator仓库——一个四阶段流程：任务说明阶段，你在这里定义输入字段、任务描述，以及一个JSON或Pydantic格式的输出模式，通常可以通过一个拖拽式网页界面完成；提示词构建阶段，由LangChain（一个用于串联提示词与模型调用的开源框架）把指令、输出模式和一个零样本思维链提示合并成一个完整的提示词；模型推理阶段，提示词被发送给Ollama里加载的任何模型，输入的上下文长度会自动按需调整；以及后处理阶段，输出结果会对照模式做校验，模型最多有三次自动自我修正的机会来修复自己格式错误的JSON，实在不行才会用一个占位符顶上。

ALEX Here's where I'd push — this is a strict zero-shot, single-prompt-per-task design with no task-specific prompt engineering, which the authors themselves admit likely underestimates every model's real ceiling; it's an honest, reproducible floor on performance, not an attempt to extract the best possible number out of any one model. 这里是我想提出异议的地方——这是一个严格的零样本、每个任务只用单一提示词的设计，没有针对任务做提示词工程，作者自己也承认这很可能低估了每个模型的真实上限；这是一个诚实、可复现的性能下限，而不是试图榨出任何一个模型的最佳表现。

ALEX They ran nine open-weight models through this pipeline, from Gemma2-2B up to Llama-3.3-70B, all 4-bit quantized, with the smaller models — under 15 billion parameters — chosen specifically because they fit on a single consumer GPU with 12 gigabytes of memory, which is the realistic ceiling for most hospital IT budgets; Llama-3.3-70B was included separately as a high-end reference point. 他们把九个开放权重模型跑过了这套流程，从Gemma2-2B一直到Llama-3.3-70B，全部采用4比特量化；其中参数量低于150亿的小模型是特意选的，因为它们能装进一块12GB显存的消费级GPU，这才是大多数医院IT预算能承受的现实上限；Llama-3.3-70B则作为一个高端参照点单独纳入。

JORDAN Give me the headline numbers. 给我讲讲最核心的数字。

ALEX Model performance split into three clean tiers on the DRAGON 2024 utility score — the arithmetic mean across all 28 task-level metrics — with the top tier being Llama-3.3-70B at 0.760, Phi-4-14B at 0.751, Qwen-2.5-14B at 0.748, and DeepSeek-R1-14B at 0.744; a middle tier of Gemma2-9B and Mistral-Nemo-12B around 0.688; and a bottom tier where Llama-3.2-3B scored just 0.271 and Gemma2-2B failed to even produce valid JSON often enough to be scored. 在DRAGON 2024效用评分——28个任务级指标的算术平均——上，模型表现清晰地分成了三档：顶层是Llama-3.3-70B的0.760、Phi-4-14B的0.751、Qwen-2.5-14B的0.748，以及DeepSeek-R1-14B的0.744；中间层是Gemma2-9B和Mistral-Nemo-12B，都在0.688左右；底层是Llama-3.2-3B，只有0.271，而Gemma2-2B甚至经常连有效的JSON都生成不出来，没法被正常打分。

ALEX The reference baseline, a RoBERTa-large model fine-tuned directly on all 28 tasks, scored 0.819 overall — higher than every zero-shot LLM — but task by task, Llama-3.3 actually beat that fine-tuned baseline on 14 of the 28 tasks, lost on 11, and landed within the baseline's own cross-validation error bars on the remaining 3. 作为参照的基线模型——一个直接在全部28个任务上微调过的RoBERTa-large模型——总体得分0.819，高于所有零样本大语言模型；但逐个任务看，Llama-3.3在28个任务里有14个实际上超过了这个微调基线，11个落后，剩下3个落在基线自身交叉验证误差范围之内。

ALEX The pattern by task type was sharp — on the six regression tasks, like extracting a lesion size or a PSA value, every single model scored above 0.9, because generative models are simply good at copying a number out of text and reasoning about its units; but on named entity recognition, every model scored under 0.47, and NER's modal result across the board was an outright "Fail" rating, because token-level NER output formats are a poor fit for a model that generates free-flowing text. 按任务类型看模式非常鲜明——在六个回归任务上，比如提取病灶大小或PSA数值，每一个模型得分都超过0.9，因为生成式模型本来就擅长从文本里原样复制一个数字并对单位做推理；但在命名实体识别上，每个模型得分都低于0.47，而且整体最常见的评级结果就是直接判"失败"，因为逐token的命名实体识别输出格式，本来就不适合一个以自由流畅文本生成为本职的模型。

ALEX And one clean negative result: translating the Dutch input into English before inference, hoping to play to the models' English-heavy training data, consistently hurt performance instead of helping — a statistically significant drop for Phi-4-14B, from 0.751 down to 0.533, and for Llama-3.1-8B, from 0.588 down to 0.337. 还有一个干净利落的负面结果：在推理之前先把荷兰语输入翻译成英语，本想借此迎合模型以英语为主的训练数据，结果却持续拉低了表现，而不是提升——Phi-4-14B出现了统计显著的下降，从0.751掉到0.533，Llama-3.1-8B也从0.588掉到0.337。

JORDAN Is the RoBERTa baseline just flatly better, then, or is there more nuance? 那是不是RoBERTa基线就是全面更好，还是说这里面还有别的细节？

ALEX There's real nuance — RoBERTa's overall lead comes almost entirely from two places, named entity recognition and one specific, oddly worded binary task about excluding incomplete skin-histopathology reports, where the zero-shot setup was never going to compete; strip those out, and Llama-3.3's average actually rises to 0.858 while RoBERTa's drops to 0.814. 这里面确实有细节——RoBERTa的整体领先几乎全部来自两个地方：命名实体识别，以及一个措辞特别、关于排除不完整皮肤病理报告的二分类任务，在这两处，零样本设置本来就没有胜算；把这两类任务剔除之后，Llama-3.3的平均分反而升到0.858，而RoBERTa跌到0.814。

ALEX That points to genuinely complementary strengths rather than one model simply being better — fine-tuned encoder models like RoBERTa still win at token-level span extraction, while zero-shot generative models are already competitive, sometimes superior, at structured inference and regression, with none of the per-task labeled-data cost. 这说明两类模型是真正互补的强项，而不是一个模型全面碾压另一个——像RoBERTa这样微调过的编码器模型，在逐token的片段抽取上仍然占优；而零样本生成式模型已经在结构化推理和回归任务上具备竞争力，有时甚至更强，而且完全不需要为每个任务单独标注训练数据。

JORDAN Anything about how trustworthy the ground-truth labels themselves were? 关于金标准标签本身的可信度，还有什么要说的吗？

ALEX Worth flagging — the DRAGON organizers reported real inter-annotator disagreement on several tasks, with a Krippendorff's Alpha（克里彭多夫一致性系数，Krippendorff's Alpha, 一种评估多位标注者之间一致程度的统计量）as low as 0.333 on one cancer-origin classification task, which means some of the ceiling these models are being measured against is itself a somewhat noisy target. 值得一提的是——DRAGON的组织者报告了好几个任务上标注者之间存在真实的分歧，其中一个癌症来源分类任务的Krippendorff's Alpha（克里彭多夫一致性系数，一种评估多位标注者之间一致程度的统计量）低到0.333，这意味着这些模型被拿来对照的"标准答案"，本身就带有一定的噪声。

JORDAN So where does an open-source Dutch clinical-NLP benchmark land for the career track? 那一篇讲开源荷兰语临床自然语言处理基准的论文，怎么落到职业发展这条线上？

ALEX It lands on AI-tooling and career, not on Liz's registry-QC work — that track is specifically about flagging implausible numeric values already sitting in the registry, which is a different problem from pulling new structured values out of free text in the first place, so no claim is being made here about CFFPR's own free-text fields. 它落在AI工具与职业发展这条线上，而不是Liz的登记系统数据质量工作——那条线具体是在标记登记系统里已经存在的不合理数值，这和从自由文本里一开始就提取出结构化数值，是不同的问题，所以这里不对CFFPR自己的自由文本字段做任何断言。

ALEX What transfers directly is the whole llm_extractinator recipe: a task-schema-plus-prompt-template pattern, run locally through Ollama against a handful of 14-billion-parameter-class open models, with automatic schema validation and self-correction — all of it already public on GitHub, nothing to rebuild from scratch. 真正能直接迁移的是llm_extractinator这整套配方：一个任务模式加提示词模板的模式，通过Ollama在几个140亿参数级别的开放模型上本地运行，带自动模式校验和自我修正——这一切都已经在GitHub上公开了，不需要从零重建。

ALEX The buildable artifact is a Mini Clinical-Extraction Benchmark: take llm_extractinator as-is, write a handful of small, hand-labeled extraction tasks against synthetic or de-identified CF-relevant clinical-note snippets — say, a classification task for pancreatic-enzyme-replacement mention and a regression task for a reported FEV1 percentage — and run two or three of the paper's own top-tier open models locally through Ollama, to get a direct, first-hand read on zero-shot performance before any registry-adjacent extraction idea gets taken further. 这个可搭建的工具叫迷你临床信息提取基准：直接拿来llm_extractinator，针对合成的或去标识化的CF相关临床记录片段，写几个小型的、手工标注的提取任务——比如一个针对"是否提到胰酶替代治疗"的分类任务，和一个针对报告中FEV1百分比数值的回归任务——再用论文里这几个表现最好的开放模型，通过Ollama在本地跑两三个，直接拿到第一手的零样本性能数据，再决定要不要把这个思路往登记系统方向进一步推进。
