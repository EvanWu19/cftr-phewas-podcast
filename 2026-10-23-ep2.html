How did this episode land for you?

Ep2 (Track B — AI tooling): An air-gapped LLM that fills the gaps manual curation leaves behind

Posta and colleagues (2026, JMIR) build and validate CIDER, a fully on-premises, schema-guided extraction pipeline running a 32-billion-parameter open-weight vision-language model (Qwen3-VL) through vLLM on institutional GPUs — built specifically because cloud frontier LLMs can't legally touch protected health information. Validated on 2,073 real Hungarian histopathology reports against an expert-curated reference database, CIDER hit near-human agreement (weighted F1 0.87–0.995, Cohen's kappa 0.85–0.99) across seven clinical variables, stayed essentially flat across a 0–2.0 temperature sweep, and — more interestingly — recovered candidate values for 62.8% of missing T stages and 91.5% of missing tumor sizes that manual curation had simply never entered, though these recovered values still need independent validation before use. Buildable artifact: a CIDER-Style Schema Extraction Prototype.

Plain-English glossary

  • Cohen's kappa — a chance-corrected measure of agreement between two raters (here, CIDER vs. the manually curated reference), standard statistics.（中文：对两个评分者之间的一致性进行偶然性校正后的衡量指标（此处为CIDER与人工整理参考标准之间的比较），属于标准统计方法。）
  • FastAPI — a Python web framework for building APIs with built-in request validation; the backbone of CIDER's backend.（中文：一种用于构建API的Python网络框架，内置请求验证功能；是CIDER后端的基础框架。）
  • Histopathology report — the free-text document a pathologist writes after microscopic tissue examination, describing tumor type, grade, size, and margins.（中文：病理医生在显微镜下检查组织样本后撰写的自由文本文档，描述肿瘤类型、分级、大小和切缘情况。）
  • Quantization (FP8) — an 8-bit floating-point precision-reduction technique that shrinks a large model's memory footprint so it fits on hardware not originally built for it.（中文：一种8位浮点精度降低技术，可缩减大模型的内存占用，使其能够运行在原本并非为其设计的硬件上。）
  • TNM staging — the standard cancer-staging system: T for primary tumor invasion depth, N for regional lymph node involvement, M for distant metastasis; one of oncology's strongest prognostic variables.（中文：标准的癌症分期系统：T代表原发肿瘤浸润深度，N代表区域淋巴结受累情况，M代表远处转移；是肿瘤学中最强的预后变量之一。）
  • vLLM — an inference-serving engine exposing an OpenAI-compatible API, optimized for high-throughput concurrent LLM requests.（中文：一种暴露兼容OpenAI接口的推理服务引擎，专为高并发大语言模型请求的吞吐量优化而设计。）

Full citation

Posta M, et al. "A Secure, Scalable Large Language Model-Based System (CIDER) for High-Throughput Clinical Data Extraction From Medical Reports: Retrospective Validation Study." Journal of Medical Internet Research. 2026. PMID: 42686197 | PMC13583534 | DOI: 10.2196/95780

Methods / tools to lift

  • vLLM + Qwen3-VL-32B-Instruct-FP8 — local, open-weight vision-language model served via an OpenAI-compatible inference API, run fully on-premises.
  • FastAPI + pymupdf + langchain — asynchronous API backend, native-text PDF parsing, and extraction-prompt orchestration.
  • Schema-guided, grammar-constrained JSON generation — user-defined column descriptions injected as authoritative rules; invalid output triggers up to 3 automatic regeneration attempts.
  • Temperature sensitivity sweep (0–2.0) — a built-in reproducibility check, run across 3 independent repetitions at the deployment temperature, worth borrowing for any LLM-extraction prototype.

Where it lands + buildable artifact

Serves Liz / CFFPR data quality (method only) — no claim about CFFPR's current field-capture approach, just the transferable idea that a local, air-gapped, schema-guided LLM extraction layer can recover candidate values for missing/incomplete structured fields from whatever free-text source documents are available. MVP (tool sketch): small batch of free-text documents + column schema → local VLM via vLLM with grammar-constrained decoding → extraction accuracy benchmarked against a manually curated reference subset across a few temperatures before trusting a larger run.

What to verify first

  • Whether local GPU hardware of A40 class or similar is actually available, and whether a 32B-parameter FP8 model fits the latency/throughput budget of the intended workflow.
  • Whether any available free-text source material resembles the OnkoBank cohort's reporting style closely enough for the schema-guided approach to transfer, given that document structure varied even across contributing centers within this one study.
  • That any candidate value recovered for a previously missing field gets independent validation before being treated as usable data — the authors are explicit that their own recovered values are candidates, not verified extractions.
  • Whether English-language prompting (vs. source-language prompting) holds up on a different target language or model than Hungarian/Qwen3-VL, since this wasn't systematically tested here.

ALEX Today's paper is from the Journal of Medical Internet Research, 2026 — Posta and colleagues, "A Secure, Scalable Large Language Model-Based System (CIDER) for High-Throughput Clinical Data Extraction From Medical Reports." 今天的论文发表在2026年的《Journal of Medical Internet Research》上——作者是Posta等人，题目是《一种用于高通量临床数据提取的安全可扩展大语言模型系统（CIDER）》。 This is a Track B pick, the AI-tooling lane. 这是Track B的选题，属于AI工具这条线。 The setup: roughly 80 percent of clinical information sits trapped in unstructured narrative text, manual chart abstraction is the traditional fix but it's slow and expensive, and cloud-hosted frontier LLMs would solve the extraction problem technically but can't legally touch protected health information at most institutions — so the authors built and validated an entirely on-premises, air-gapped LLM pipeline instead. 背景是这样的：大约80%的临床信息被困在未结构化的叙述性文本中，传统的解决办法是人工病历摘录，但既慢又贵；云端的前沿大语言模型在技术上可以解决提取问题，但在大多数机构中根本无法合法接触受保护的健康信息——因此作者转而构建并验证了一个完全本地部署、物理隔离（air-gapped）的大语言模型流程。

JORDAN Before the architecture, let's get a couple of registry/EHR terms straight. 在讲架构之前，我们先把几个登记库/电子健康档案相关的术语讲清楚。 TNM staging (TNM分期) is the standard cancer-staging system — T for how deep the primary tumor has invaded, N for how many nearby lymph nodes are involved, M for whether the cancer has spread to distant sites — and it's one of the strongest prognostic variables in oncology, which is exactly why it's so costly when it's missing from a dataset. TNM分期是标准的癌症分期系统——T代表原发肿瘤浸润的深度，N代表邻近淋巴结受累的数量，M代表癌症是否已扩散到远处部位——它是肿瘤学中最强的预后变量之一，这也正是为什么它在数据集中缺失时代价如此高昂。 Histopathology reports (组织病理学报告) are the free-text documents a pathologist writes after examining a tissue sample under a microscope, describing tumor type, grade, size, and margins — this is the raw source material CIDER is built to mine. 组织病理学报告是病理医生在显微镜下检查组织样本后撰写的自由文本文档，描述肿瘤类型、分级、大小和切缘情况——这正是CIDER用来挖掘的原始源材料。 Cohen's kappa (Cohen's kappa系数) measures agreement between two raters correcting for the agreement you'd expect by chance alone — standard stuff, you know it, just flagging it's the agreement metric used throughout. ALEX Architecture first, since this is the Track B lane and the whole point is what's reusable. 先讲架构，因为这是Track B这条线，重点就是什么东西是可复用的。 CIDER runs on an asynchronous FastAPI backend — FastAPI (FastAPI框架) is a Python web framework built for building APIs with built-in request validation — serving a locally deployed Qwen3-VL-32B-Instruct model, a 32-billion-parameter open-weight vision-language model, through vLLM (vLLM推理引擎), an inference-serving engine that exposes an OpenAI-compatible API and is optimized for high-throughput concurrent requests. CIDER运行在一个异步的FastAPI后端上——FastAPI是一个用于构建API的Python网络框架，内置请求验证功能——用它来服务一个本地部署的Qwen3-VL-32B-Instruct模型，这是一个拥有320亿参数的开放权重视觉语言模型，通过vLLM推理引擎运行，这是一种暴露兼容OpenAI接口的推理服务引擎，专门针对高并发请求做了吞吐量优化。 The model runs in FP8 — 8-bit floating point quantization (量化), a precision-reduction trick that shrinks memory footprint so a 32-billion-parameter model fits on institutional hardware that wasn't built for it — on NVIDIA A40 GPUs that don't even have native FP8 acceleration, and the authors cite other large-scale studies showing FP8 preserves model quality with minimal degradation. 模型以FP8运行——也就是8位浮点量化（quantization），一种降低精度以缩减内存占用的技巧，使一个320亿参数的模型能够塞进原本并非为其设计的机构级硬件——运行平台是NVIDIA A40 GPU，甚至并不具备原生的FP8加速能力，而作者引用了其他大规模研究，证明FP8能够以极小的质量损失保留模型性能。 Document parsing uses pymupdf to pull text out of native-text PDFs, extraction logic is orchestrated with langchain, and the final output is schema-guided generation — the model is given a rigorous JSON schema as a structural constraint, and if the output fails to validate, the system automatically retries generation up to three times before giving up on that document. 文档解析使用pymupdf从原生文本PDF中提取文字，提取逻辑通过langchain进行编排，最终输出采用模式引导生成（schema-guided generation）——模型被赋予一个严格的JSON模式作为结构性约束，如果输出验证失败，系统会自动重试生成，最多三次，之后才会放弃处理该文档。

JORDAN And the privacy angle — that's the whole reason this had to be built this way, right? 隐私方面——这正是整套系统必须这样构建的全部理由，对吧? Right. 没错。 Every component — document parsing, prompt assembly, model inference, structured output — runs inside the institution's own servers; no clinical document or extracted value is ever sent to an external API, and operational logs keep only metadata like timestamps and token counts, never report text or extracted clinical values. 每一个环节——文档解析、提示组装、模型推理、结构化输出——都在机构自己的服务器内运行；没有任何临床文档或提取出的数值被发送到外部API，操作日志只保留元数据，比如时间戳和令牌数，绝不保留报告正文或提取出的临床数值。 That's the entire design response to a barrier the authors identify explicitly: GPT-5, Claude, Gemini, and Grok define the performance ceiling but their closed, cloud-hosted nature makes them effectively off-limits under HIPAA and GDPR for anything touching protected health information. 这正是作者针对一个明确指出的障碍所给出的整体设计方案：GPT-5、Claude、Gemini和Grok定义了性能的上限，但它们封闭、云端托管的特性使其在HIPAA和GDPR的约束下，几乎无法用于任何涉及受保护健康信息的场景。 The system prompt, which encodes general extraction rules, and the per-project column schema, which encodes which fields to pull and how, are both written in English even though the input documents are Hungarian — a deliberate choice, not an optimized one, resting on evidence that English prompting tends to transfer reasoning robustly across languages. 系统提示（编码了通用提取规则）和逐项目的字段模式（编码了要提取哪些字段以及如何提取）都是用英文写的，尽管输入文档是匈牙利语——这是一个刻意的选择，而非经过优化的选择，其依据是有证据表明英文提示往往能够稳健地跨语言迁移推理能力。

ALEX I want to push on that prompt-language choice for a second. 我想就这个提示语言的选择稍微质疑一下。 The authors admit they never systematically tested whether prompting in Hungarian — matching the source-document language — would have done better, and they cite other work suggesting target-language prompts can offer marginally better multilingual robustness even while English remains "practically attractive." 作者承认他们从未系统性地测试过，用匈牙利语提示——也就是与源文档语言保持一致——是否会表现得更好，而他们引用的其他研究表明，目标语言提示在某些情况下可能带来略微更好的多语言鲁棒性，即便英文在实践中仍然"颇具吸引力"。 For CIDER specifically this probably doesn't matter much, since Qwen3-VL benchmarks strongly across multilingual tasks — but for anyone replicating this architecture on a lower-resource language, or on a model with weaker multilingual grounding, prompt language is a design knob worth actually testing rather than assuming. 对CIDER来说，这一点或许影响不大，因为Qwen3-VL在多语言任务上的基准表现本身就很强——但对于任何想在资源更匹配匱乏的语言上，或者在多语言能力较弱的模型上复现这套架构的人来说，提示语言是一个值得真正去测试、而不是想当然假设的设计参数。

JORDAN How does this compare to what came before LLMs? 这和LLM出现之前的做法相比如何? Earlier rule-based clinical NLP systems like MetaMap and cTAKES — the clinical Text Analysis and Knowledge Extraction System — used predefined medical ontologies and regular expressions to identify entities, and they achieved high precision in narrow, well-defined domains, but needed labor-intensive customization for every new document type or language. 更早的基于规则的临床自然语言处理系统，比如MetaMap和cTAKES——即临床文本分析与知识提取系统——使用预定义的医学本体和正则表达式来识别实体，它们在狭窄、定义明确的领域内能够达到很高的精确度，但每遇到一种新的文档类型或语言，就需要大量人工定制。 Then BERT-based models like BioBERT and ClinicalBERT improved on that by capturing semantic relationships directly from text, but almost all of that literature is English-centric, leaving non-English clinical NLP comparatively under-studied — which is exactly the gap this Hungarian validation targets. 后来，像BioBERT和ClinicalBERT这类基于BERT的模型通过直接从文本中捕捉语义关系有所改进，但几乎所有这类文献都以英语为中心，使得非英语临床自然语言处理相对缺乏研究——而这正是本文用匈牙利语验证所针对的那个缺口。 The authors argue the real advantage of a schema-guided LLM over either predecessor is contextual selection: a single pathology report might mention several dates, several tumor measurements, and multiple historical diagnoses, and the hard part isn't spotting a number or a keyword, it's figuring out which one actually corresponds to the registry variable being asked for — something rule-based pattern matching struggles with but an LLM reading the full document context can do without any task-specific retraining. 作者认为，相比这两种前身方法，模式引导的大语言模型真正的优势在于上下文选择：一份病理报告可能提到好几个日期、好几个肿瘤测量值，以及多个既往诊断，难点不在于识别出一个数字或一个关键词，而在于判断哪一个数值真正对应登记库所询问的那个变量——这正是基于规则的模式匹配难以应对的问题，而大语言模型通过阅读完整的文档上下文，无需任何针对特定任务的重新训练就能做到。

JORDAN Let's get to the validation. 我们来看验证结果。 2,073 real Hungarian histopathology reports from the OnkoBank registry across multiple oncology centers, 2022 through 2025, checked against a two-stage expert-curated reference database — board-certified pathologists wrote the original reports, then a separate team of clinical experts manually mined seven key variables into structured form. 来自OnkoBank登记库的2073份真实匈牙利语组织病理学报告，涵盖多个肿瘤中心，时间跨度2022年到2025年，与一个经过两阶段专家整理的参考数据库进行比对——专业认证的病理医生撰写了原始报告，随后由另一支临床专家团队手动将七个关键变量整理成结构化形式。 This reference database itself had real gaps worth noting before we get to CIDER's numbers: T stage was missing in 54.8 percent of records and N stage in 76.6 percent, which already tells you how badly this kind of extraction is needed in the first place. 在我们看CIDER的具体数据之前，有一点值得先提一下：这个参考数据库本身就存在真实的缺口——T期在54.8%的记录中缺失，N期在76.6%的记录中缺失——这本身就说明了这类提取工作有多么迫切需要。

ALEX Now the headline numbers, at the default deployment temperature of 0.1. 现在来看核心数据，在默认部署温度0.1下的结果。 CIDER hit exact-match accuracy of 99.5 percent for sex, 98.1 percent for surgery year, 95.8 percent for organ, 95.6 percent for T stage, 92.4 percent for N stage, 87.5 percent for histology, and 78.1 percent for tumor size — with weighted F1 scores from 0.87 up to 0.995 and Cohen's kappa from 0.85 to 0.99, substantial-to-near-perfect agreement across the board. CIDER在默认部署温度0.1下，性别的精确匹配准确率为99.5%，手术年份为98.1%，器官为95.8%，T期为95.6%，N期为92.4%，组织学类型为87.5%，肿瘤大小为78.1%——加权F1分数从0.87到0.995不等，Cohen's kappa系数从0.85到0.99，整体呈现从"实质性一致"到"近乎完美一致"的水平。 Tumor size was the weakest link, with 83.5 to 85.3 percent of predictions landing within 5 millimeters of the manual value and 87.3 to 88.7 percent within 10 millimeters — mostly because reports often list multiple diameters for the same lesion, invasive-component size versus total lesion size, and the model and the human curator didn't always pick the same one. 肿瘤大小是最薄弱的一环，83.5%到85.3%的预测结果落在人工数值的5毫米范围内，87.3%到88.7%落在10毫米范围内——主要原因是报告中常常为同一病灶列出多个直径数值，比如浸润成分大小与总病灶大小，模型和人工整理者并不总是选取同一个数值。 Robustness across temperature settings from 0 all the way to 2.0 was remarkably flat — sex and N stage showed zero variance across three independent repeated runs at temperature 0.1 — which the authors read as evidence that extraction is driven by grounded textual evidence and schema constraints rather than by sampling randomness. 从温度0一直到2.0，模型在不同温度设置下的稳健性都出奇地平稳——在温度0.1下进行的三次独立重复运行中，性别和N期的结果方差为零——作者将此解读为提取结果主要由有依据的文本证据和模式约束驱动，而不是由采样随机性驱动的证据。

ALEX There's a second result here that's arguably more interesting than the headline accuracy numbers: CIDER recovered values the human curators had simply never entered. 这里还有第二个结果，可以说比准确率这个headline数字更有意思：CIDER找回了人工整理者根本从未录入的数值。 Of the 1,136 records missing T stage, CIDER produced a candidate value for 713 of them, 62.8 percent; for the 1,588 missing N stage records it recovered only 164, 10.3 percent; and for tumor size and organ, where 316 and 187 values were missing respectively, it recovered 289 and 182. 在缺失T期的1136条记录中，CIDER为其中713条生成了候选数值，占62.8%；在缺失N期的1588条记录中，它只找回了164条，占10.3%；而对于肿瘤大小和器官，分别有316和187条记录缺失，CIDER分别找回了289条和182条。 The authors are careful here, and so should we be: these recovered values were never checked against an independent reference, so they're candidate annotations, not verified extractions, and the paper explicitly says they'd need separate confirmation before any clinical or research use. 作者在这里非常谨慎，我们也应该如此：这些找回的数值从未与独立参考标准进行核对，因此它们只是候选标注，而不是经过验证的提取结果，论文明确指出，在用于任何临床或研究用途之前，这些结果都需要单独确认。
