How did this episode land for you?

Blurb

Six major clinical data networks — Kaiser Permanente's CESR, Sentinel, PEDSnet, PHIS, Duke's MURDOCK registry, and OHDSI (formerly OMOP) — each had their own mature data-quality-assessment (DQA) programs, built independently, in their own vocabulary, with no shared way to compare what any of them actually checked for. Callahan, Bauck, Bertoch, Brown, Khare, Ryan, Staab, Zozus, and Kahn set out to test whether a single harmonized terminology — the Kahn DQA framework — could absorb all of it. They collected 11,026 real, in-production data-quality checks from these six networks and mapped every one onto the Kahn framework's categories (Conformance, Completeness, Plausibility, and their atemporal/temporal/relational/value/calculation/uniqueness subtypes). 99.97% mapped cleanly, with nearly half of all checks landing in a single category: Atemporal Plausibility. This is not a new detection method and reports no sensitivity, PPV, or gold standard — it's a descriptive taxonomy-mapping exercise. For CFFPR, it lands as vocabulary and framework to borrow rather than a mechanical change to the outlier pipeline. The buildable artifact: a small (S-difficulty) DQA category mapper that tags CFFPR's existing QC check inventory against the eight Kahn subcategories to surface coverage gaps.

Glossary

  • Atemporal Completeness — Whether a data element is present, assessed at a single point in time (e.g., is a height value present for this encounter at all).（中文：在某一时间点上检查数据是否存在。）
  • Atemporal Plausibility — A single-value or cross-field believability check not involving time — e.g., is this height physiologically possible, does it agree with another measurement of the same fact.（中文：不涉及时间的单值或跨字段合理性检查。）
  • Calculation Conformance — Whether a derived/computed field was correctly calculated from its input variables.（中文：检查由其他字段计算得出的派生字段是否计算正确。）
  • CDM (Common Data Model) — A shared data schema that different institutions transform their local data into, so the same analytic query can run identically across sites.（中文：一种共享的数据结构,各机构把本地数据转换成它,以便同一查询能在不同站点上运行。）
  • Conformance — Whether data comply with prespecified formatting (value), structural (relational), or derivation (calculation) constraints.（中文：数据是否符合预先设定的格式、结构或计算规则,属于"一致性"大类。）
  • Data Sharing Network — A group of sites/institutions that pool or jointly query clinical data for research without necessarily centralizing raw records in one place.（中文：多个机构为科研共同汇总或联合查询临床数据的网络,数据未必集中存放。）
  • Data Validation (context) — Confirming data against external benchmarks or gold standards; rarer and harder to standardize, and out of scope for this paper's comparison.（中文：将数据与外部基准或金标准进行比对,本文未纳入分析范围。）
  • Data Verification (context) — Confirming data against local knowledge or prespecified metadata (the only context this paper analyzed).（中文：将数据与本地已知信息或预设元数据进行比对,是本文唯一分析的情境。）
  • DQA (Data Quality Assessment) — The general practice and set of methods for evaluating the quality of a dataset.（中文：评估数据集质量的一整套方法与实践。）
  • EHR (Electronic Health Record) — The digitized clinical record system from which registry and network data are often sourced.（中文：电子化的病历记录系统,登记库和数据网络的数据常源自于此。）
  • Extrinsic DQA categories — Quality dimensions dependent on context of use (timeliness, fitness-for-use, security/privacy) — explicitly excluded from the Kahn framework used here.（中文：依赖于使用场景的质量维度,如及时性、适用性,本框架未纳入。）
  • Intrinsic DQA categories — Quality dimensions pertaining to the data values themselves, independent of use context — what the Kahn framework in this paper actually covers.（中文：与数据值本身相关、不依赖使用场景的质量维度,是本框架实际覆盖的内容。）
  • Kahn DQA (harmonized) terminology — The unifying framework from Kahn and colleagues that organizes data-quality checks into Conformance, Completeness, and Plausibility categories (each with subcategories) across two contexts, verification and validation.（中文：Kahn等人提出的统一框架,将数据质量检查归入一致性、完整性、合理性三大类及其子类,分核查与验证两种情境。）
  • OHDSI (Observational Health Data Sciences and Informatics) — The open collaborative that now stewards the OMOP common data model and associated open-source DQA tools.（中文：一个开放协作组织,目前负责维护OMOP通用数据模型及相关开源DQA工具。）
  • OMOP (Observational Medical Outcomes Partnership) — A widely used common data model; the best-known example of a CDM referenced in this paper.（中文：一种广泛使用的通用数据模型,是本文中提到的CDM的典型代表。）
  • Plausibility — Whether data are believable, assessed via logical/statistical agreement (atemporal), sequences/transitions over time (temporal), or absence of duplication (uniqueness).（中文：数据是否可信,属于"合理性"大类,分非时序、时序、唯一性三个子类。）
  • Relational Conformance — Whether data agree with structural constraints such as primary-key/foreign-key relationships.（中文：检查数据是否符合主键、外键等结构性约束。）
  • Temporal Completeness — Whether a data element is present across multiple points in time.（中文：检查数据在多个时间点上是否都存在。）
  • Temporal Plausibility — Whether a value's change or sequence over time (e.g., between visits) makes physiological sense.（中文：检查数值随时间(如两次就诊之间)的变化顺序在生理上是否合理。）
  • Uniqueness Plausibility — Whether records, measurements, or values are duplicated when they shouldn't be.（中文：检查记录、测量值是否存在不应有的重复。）
  • Value Conformance — Whether a field's value matches the expected type, format, or code set.（中文：检查字段取值是否符合预期的类型、格式或编码集。）

Methods/tools to lift

  • The Kahn harmonized DQA terminology itself — a ready-made, 8-subcategory vocabulary for labeling any existing QC check.
  • The mapping convention of splitting a single check's "point" across multiple categories (e.g., 0.5/0.5) when a check genuinely spans two DQA categories, rather than forcing one bucket.
  • The iterative-consensus mapping process (map, discuss hard cases, remap, repeat) as a lightweight way to get multiple reviewers converging on consistent category labels.
  • The CMMI-inspired DQA maturity model (Level 1 Initial → Level 2 Repeatable/Defined → Level 3 Managed/Optimizing) as a rough lens for describing how formalized a QC program is — offered by the authors as inspiration for future work, not a validated instrument.

Where it lands + buildable artifact

Pipeline stage (e) — no direct mechanical change to candidate generation, adjudication, or review-budget sizing, but a vocabulary/framework worth borrowing to describe and audit existing QC coverage.

  • DQA Category Mapper (S) — tags each check in CFFPR's existing QC check inventory against the eight Kahn DQA subcategories to produce a coverage profile and surface gaps. Input: spreadsheet of existing CFFPR QC check names/descriptions. Difficulty: S.

What to verify first

  • Whether the Kahn categories as defined in 2017 still map cleanly onto whatever QC/check documentation CFFPR currently maintains.
  • Whether a category-mapping exercise is useful without CFFPR's own DQA/QC staff directly involved in the mapping (the paper's own classifications were done only by the research team, not by each organization's operational staff).
  • What fraction of CFFPR's actual QC work falls into categories this paper's taxonomy excludes — data-validation-context checks, and checks based on manual review or visualization — before assuming the taxonomy's coverage is complete for CFFPR's purposes.

Pipeline stage

(e) — vocabulary/framework to borrow; no direct effect on candidate generation, adjudication, or review-budget sizing claimed or implied.

Error types covered / not covered

  • Covered by this taxonomy (as categories, not as a detector): out-of-range or wrong-type/format values (Value Conformance), structural/relational mismatches like key violations (Relational Conformance), incorrectly computed derived fields (Calculation Conformance), missing values at one or many time points (Atemporal/Temporal Completeness), single-value or cross-field implausibility such as physiologically impossible heights (Atemporal Plausibility), implausible changes or sequences over time such as an improbable jump between visits (Temporal Plausibility), and duplicated records/values (Uniqueness Plausibility).
  • Not covered / explicitly out of scope: checks requiring comparison to an external benchmark or gold standard (the data-validation context), checks based on manual expert review of DQA reports, and checks based on visualization/graphical inspection — the paper notes these are likely underrepresented or excluded because they're harder to document and standardize. The taxonomy also does not itself distinguish a genuine data-entry error from a real clinical event (e.g., true rapid weight loss) — it only classifies what kind of check an organization already runs, not whether that check's output is correct.
