Ep3 (Track C — registry QC, 1 of 2): Predicting Causes of Data Quality Issues in a Clinical Data Research Network

Khare and colleagues (2018, AMIA Joint Summits on Translational Science) tackle a step downstream of flagging: once a data-quality issue has been reported in PEDSnet, a pediatric clinical data research network spanning eight children's hospitals on the OMOP common data model, who decides whether it's worth anyone's time? Using metadata from PEDSnet's own GitHub-issue-based data-quality warehouse (83 binary features per issue — affected CDM domain, field type, check type, prevalence bucket, site, and a CDM-version-upgrade flag), the authors trained classifiers to predict whether an issue's eventual cause will be an ETL pipeline bug (fixable), an inherent data characteristic (not fixable by changing code), or a false alarm in the check itself (not a real issue). On a deduplicated "unique-issues" dataset of 4,388 issues, the best three-way classifier reached an overall F1 of 0.9, though the ETL-specific F1 — the number that matters most, since ETL issues are the only fixable ones — was a more modest 0.71. The authors' own experience is that over 60% of data-quality issues in this network deserve lower investigation priority because they're either false alarms or unfixable characteristics, and a reliable cause-classifier could meaningfully cut the review burden before anyone opens a ticket. This maps directly onto the adjudication stage of an outlier pipeline — sorting a flag into actionable, unfixable, or wrong — and secondarily onto the review-budget stage, since correct triage is exactly how that 60% gets shaved off a human review queue.

Plain-English glossary

CDRN (clinical data research network) — A network that pools electronic health record data from multiple institutions into a shared common data model so research can be conducted across sites.（中文：临床数据研究网络，将多家机构的电子健康档案数据汇集到一个共享的通用数据模型中，以便开展跨机构研究。）

ETL (extract-transform-load) — The pipeline that moves data from a hospital's native EHR system into a standardized common data model; a bug in this pipeline is one of three possible causes a flagged data-quality issue can have.（中文：提取-转换-加载，将数据从医院原生EHR系统迁移到标准化通用数据模型的处理流程；该流程中的程序错误是一个被标记的数据质量问题可能存在的三种成因之一。）

False alarm (in data-quality checks) — A flagged issue where the data-quality check itself has a bug or blind spot, so the underlying "problem" isn't real.（中文：数据质量检查中的误报，指数据质量检查本身存在程序错误或盲点，使得所谓的"问题"其实并不真实存在。）

OMOP (Observational Medical Outcomes Partnership) common data model — A standardized schema with fixed tables (Person, Condition_occurrence, Drug_exposure, Measurement, etc.) that different EHR systems' data gets mapped into so it has a consistent shape across institutions.（中文：观察性医学结局合作组织通用数据模型，一套标准化的数据结构，将不同EHR系统的数据映射为统一的表结构，便于跨机构保持一致。）

PEDSnet — A pediatric clinical data research network aggregating EHR data from eight large US children's hospitals onto the OMOP model, which tracks data-quality issues as GitHub issues.（中文：一个儿科临床数据研究网络，将八家美国大型儿童医院的EHR数据汇集到OMOP模型上，并以GitHub issue的形式追踪数据质量问题。）

Full citation

Methods / tools to lift

  • A deduplicated "unique-issues" dataset alongside the full issue set, to avoid a classifier learning "have I seen this recurring issue before" instead of genuine cause discrimination.
  • An 83-feature metadata taxonomy (domain, field type, check type, prevalence bucket, site, CDM-version-upgrade flag) as a template for characterizing a flagged issue without touching the raw data itself.
  • Separate binary (ETL vs. non-ETL) and three-way (ETL / Characteristic / False alarm) classification framings of the same underlying triage problem.

Where it lands + buildable artifact

Serves the Liz-assigned CFFPR registry data-quality work (method only). Pipeline stage: (b) adjudication, primary; (c) review budget, secondary. Buildable: Flag-Cause Triage Classifier — given a flagged anthropometric record's metadata (which check fired, that check's population-wide firing rate, field/domain, proximity to an age/seasonal boundary, within-patient recurrence), predict a cause bucket analogous to ETL/characteristic/false-alarm and route only likely-actionable flags to human review. Input: flagged-record metadata + within-patient history. Difficulty: S-M.

What to verify first

  • Whether a labeled history of past flags with human-assigned causes — the substrate this method requires — currently exists in a usable form; this is a detail about the existing review workflow, not something this paper can answer.
  • Whether any "evolving field" ambiguity (where the ground truth itself shifts as data capture matures, as with PEDSnet's drug_exposure/measurement domains) has analogues in periods where measurement methods, instruments, or source systems changed.
  • That PEDSnet's 83-feature taxonomy is built around its own CDM check types and isn't a drop-in feature set — it's a method to replicate with features built from whatever flag-generating checks are actually in use.

Pipeline stage

(b) Adjudication, primary — sorts an already-flagged issue into actionable vs. unfixable vs. wrong. (c) Review budget, secondary — correct triage is the mechanism behind the paper's own >60%-lower-priority figure.

Error types covered / not covered

Covered (by analogy, at the issue-cause level): ETL/pipeline bugs, inherent/unfixable data characteristics, false alarms from a flagging check's own blind spots. Not covered: no detection of the underlying anthropometric error itself — no unit conversion, digit transposition, decimal shift, or carry-forward logic; this paper only classifies the cause of an issue once something else has already flagged it.

JORDAN And this specific network, PEDSnet — what is it? PEDSnet这个具体的网络是什么？

JORDAN So what wasn't known before this study — why does sorting that matter enough to automate it? 那么，这篇研究之前有什么是未知的——为什么这种分类重要到需要自动化？

ALEX Investigating a reported issue is genuinely expensive: it means locally replicating the problem, reviewing the relevant ETL code, re-checking data assumptions, and talking it through with clinicians, analysts, and administrative staff. 调查一个被报告的问题成本确实很高：需要在本地复现问题、审查相关的ETL代码、重新核查数据假设，还要和临床医生、分析师、行政人员反复沟通讨论。Based on PEDSnet's own six most recent data cycles at the time, a partner site investigates about 26 new issues per cycle, and only 35% of those turn out to be resolvable ETL problems — the rest are characteristics or false alarms that the site spent real investigative effort on anyway, with the average issue staying open for 31 days. 根据PEDSnet当时最近六个数据周期的记录，一个参与机构平均每个周期要调查约26个新问题，而其中只有35%最终被证实是可修复的ETL问题——剩下的都是特征或误报，但机构依然为此投入了实际的调查工作，平均每个问题要开着31天才能关闭。Prior work, including an ontology from Kahn and colleagues, had built frameworks for classifying what kind of check flags a problem, but classifying the cause of an issue once it's already been flagged — automating the triage step itself — was, as the authors put it, "largely undocumented" before this study. 此前的工作，包括Kahn及其同事提出的一套本体（ontology），已经构建了用于分类"哪种检查方式标记出了问题"的框架，但对一个问题一旦被标记之后，去分类它的成因——把分诊这一步本身自动化——按作者的说法，在这项研究之前"基本上没有文献记录过"。
