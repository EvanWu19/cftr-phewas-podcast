Ep4 (Track C — registry QC, 2 of 2): A quality pipeline for a data network that can't eyeball its own data

Hoxhaj and colleagues (2025, Pharmacoepidemiology and Drug Safety) describe INSIGHT, an open-source, R-coded, three-level data quality assessment pipeline built for the ConcePTION Common Data Model, a European distributed research network studying medicine and vaccine safety in pregnancy. Level 1 (356 indicators) and Level 1b (26 indicators) check conformance, completeness, and value characterization across 15 CDM tables; Level 2 (57 indicators) checks temporal plausibility and cross-table consistency, with Data Access Providers (DAPs) expected to stay under a 5% inconsistency threshold; Level 3 (249+ indicators) produces distributions and trends to assess fitness-for-purpose. Each DAP runs the scripts locally and uploads results for centralized review by a data-quality revisor plus the DAP's own representatives, using a structured four-tab Excel approval form. Concrete illustrative catches include implausible dates, observation-period construction failures, a likely coding artifact (gestational diabetes codes in male patients), and date-imputation clustering. One number worth flagging: the abstract states "over 588" indicators, but the methods section's own per-level counts sum to 688 — a discrepancy worth resolving against the primary source before citing either figure. Pipeline stage: (a) candidate generation, primary; (c) review budget, secondary. Buildable artifact: a ConcePTION-style conformance and plausibility checklist.

Plain-English glossary

  • Common Data Model (CDM) — a shared table-and-column schema that every participating site maps its local data into, so one study script runs identically across many sites' data.（中文：通用数据模型，一套共享的表结构与字段架构，每个参与方把本地数据映射进去，这样一份研究脚本就能在多个站点的数据上原样运行。）
  • ETL (Extract, Transform, Load) — the process of pulling data from a site's native system, reshaping it to fit the CDM's rules, and loading it in.（中文：提取-转换-加载，指把数据从站点原生系统中提取出来，按CDM规则重塑格式后加载进去的过程。）
  • Conformance / completeness / plausibility — three data-quality dimensions (from the Kahn framework): conformance is format/structure correctness; completeness is how much of a field is populated; plausibility is whether a value makes logical sense given other known facts about the record.（中文：符合性、完整性、合理性——三个数据质量维度（源自Kahn框架）：符合性指格式/结构是否正确；完整性指字段被填充的程度；合理性指某数值结合该记录已知的其他信息是否讲得通。）
  • Data Access Provider (DAP) — a participating site in a distributed research network that keeps its own data locally and runs scripts against it without pooling raw data centrally.（中文：数据接入方，分布式研究网络中的一个参与站点，把自己的数据保存在本地并在本地运行脚本，不将原始数据集中汇总。）
  • Fit-for-purpose assessment — evaluating whether data, even if structurally clean, actually represents a population suitable for a specific study's aims.（中文：适用性评估，评估数据即便结构上是干净的，是否真的代表了适合某项具体研究目的的人群。）

Full citation

Methods / tools to lift

  • INSIGHT (R scripts, open source, UMC Utrecht RWE GitHub org) — a three-level conformance/completeness/plausibility/distribution pipeline runnable against any CDM-standardized tabular data.
  • Kahn framework + FDA Sentinel quality indicators — reusable vocabulary and categorization scheme for organizing any registry's data-quality checks.
  • Four-tab Excel approval form — a structured template for documenting and signing off on data-quality review decisions across many flagged issues.

Where it lands + buildable artifact

Pipeline stage: (a) candidate generation, primary — Level 1/1b/2 conformance and temporal-plausibility checks are rules flagging specific records or fields as candidates needing attention; (c) review budget, secondary — the centralized revisor role and approval-form workflow is a concrete template for allocating and tracking limited human review capacity across flagged issues from many sources. Buildable artifact: a ConcePTION-style conformance and plausibility checklist. MVP: adapt INSIGHT's Level 1/1b/2 indicator categories (format/completeness checks, value-characterization checks, temporal-plausibility checks like dates before birth or outside the observation period) into a standalone, runnable open-source checklist producing an HTML report plus a structured approval-form summary, applicable to any tabular registry extract. Difficulty: medium.

Error types covered / not covered: Covers format/structural non-conformance, missingness, implausible dates (before birth, future, outside observation period), cross-table referential inconsistency, and population-level distributional anomalies; does not cover individual anthropometric value implausibility, unit conversion, digit transposition, decimal shift, or carry-forward values — this is a general CDM-governance framework, not an anthropometric flagging rule.

What to verify first

  • The indicator-count discrepancy (588 in the abstract vs. 688 summed from the methods section's per-level counts) should be resolved against the paper's own tables or GitHub repo before citing either number.
  • Whether the 5% Level-2 inconsistency threshold is a ConcePTION-specific calibration or a defensible general-purpose number — the paper states it as "a priori" without further justification.
  • Whether a centralized human-revisor governance model is the right shape for any particular registry's review capacity, or whether a more automated triage layer would be needed at larger scale — an open design question this paper doesn't settle.

ALEX Conformance is about format and structure — does this column hold the values it's supposed to, in the format the CDM spec requires, like using the designated codes M, F, U, O for sex instead of someone's leftover "1" and "2." 符合性关注的是格式和结构——这一列里存放的是否是它应该存放的值，并且符合CDM规范所要求的格式，比如用规定的代码M、F、U、O来表示性别，而不是某人遗留下来的"1"和"2"。 Completeness is about presence — how much of a field or table is actually populated versus missing, broken down by table, by field, and by calendar year so you can see whether missingness is getting better or worse over time. 完整性关注的是"有没有"——一个字段或一张表实际被填充的比例有多少、缺失了多少，并按表、按字段、按日历年份进行分解，这样你就能看出缺失情况是在变好还是变差。 And plausibility is about whether values make logical sense given everything else known about the record — a health encounter dated before someone's birth, or a person ID that shows up in one table but was never listed in the master PERSONS table, are both plausibility failures, not formatting or missingness problems.而合理性关注的是，考虑到该记录已知的其他所有信息，这个数值是否在逻辑上讲得通——比如一次医疗就诊的日期早于某人的出生日期，或者某个person ID出现在某张表中、却从未在主PERSONS表中登记过，这两者都属于合理性失败，而不是格式或缺失问题。
