CohortDiagnostics: Phenotype evaluation across a network of observational data sources using population-level characterization — Rao GA, et al., PLoS One, 2025.

Blurb

Every real-world-evidence study begins by running a phenotype algorithm (PA) — a computable definition of "who has this disease" — but validating a PA normally requires a gold standard (chart review or a registry) that is slow, expensive, or simply unavailable. CohortDiagnostics, an open-source OHDSI R package, sidesteps that: instead of comparing a cohort to a reference truth, it characterizes the cohort against your own pre-written clinical expectation, and treats deviations as fingerprints for three specific error types — sensitivity, specificity, and index-date misclassification. Its diagnostics battery (incidence rate over time, index-event breakdown, visit context, cohort overlap, and temporal cohort characterization) was demonstrated on one lupus PA and two Alzheimer's PAs across ten OMOP data sources in several countries — catching, for example, that a lupus PA doesn't travel to two general-practitioner databases, and that a "simple" Alzheimer's PA buys higher sensitivity at the cost of misclassifying some strokes. Output is aggregate-only, privacy-thresholded plain CSV, so it runs federated across a data network (adopted as the phenotype-vetting step in DARWIN EU). Where it lands for us: it's the pre-analysis data-quality gate for registry phenotype work. Buildable artifact — cohort-diagnostics-audit — adapts the diagnostics battery to a CF-relevant phenotype definition and outputs a one-page report flagging error types with the codes driving them.

Plain-English glossary

  • cohort characterization — computing the prevalence of every clinical event before/on/after the index date, to check that expected symptoms, tests, and treatments appear in the right temporal order.（中文：计算索引日期前后各临床事件的患病率，检验预期症状、化验、治疗是否按正确时间顺序出现。）
  • index date — the calendar date a patient enters the cohort (usually first qualifying diagnosis/treatment); the coded date often lags the true onset date.（中文：病人进入队列的日历日期；编码日期常滞后于真实发病日期。）
  • index date misclassification — error where the cohort-entry date doesn't match when the patient truly had the disease.（中文：队列进入日期与真实患病时间不符的误差。）
  • OMOP CDM — the Observational Medical Outcomes Partnership common data model: a standardized schema + vocabularies that datasets convert into so the same analysis runs unchanged everywhere.（中文：OMOP 通用数据模型，标准化的数据结构与术语集，使同一分析可跨数据集运行。）
  • phenotype algorithm (PA) — a computable query defining which patients count as having a condition, in terms of codes, drugs, labs, and timing logic.（中文：用代码、用药、化验、时间逻辑定义"谁算患某病"的可计算查询。）
  • PheValuator — a scalable method that estimates the magnitude of PA measurement error; complementary to CohortDiagnostics, which gives direction and source.（中文：PheValuator，估计表型算法测量误差大小的可扩展方法；与给出方向和来源的 CohortDiagnostics 互补。）
  • SNOMED-CT — a standardized clinical terminology OMOP maps conditions to, so a diagnosis means the same across sources.（中文：SNOMED-CT，OMOP 用来映射疾病的标准化临床术语。）

Full citation

Methods / tools to lift

  • CohortDiagnostics — open-source OHDSI R package; runs on any OMOP CDM (v5.3+) dataset; produces aggregate-only, privacy-thresholded CSV diagnostics; results reviewed in the DiagnosticsExplorer R Shiny app. GitHub: OHDSI/CohortDiagnostics.
  • Diagnostics battery — incidence rate stratified by age×sex×calendar-year; index-event breakdown (which codes trigger entry); visit context (outpatient/inpatient/ED around index); cohort overlap (Venn of two PAs); cohort characterization (event prevalence in time windows around index).
  • Clinical-description-first workflow — write the disease's expected presentation/tests/treatments/epidemiology before running diagnostics; deviations map to sensitivity / specificity / index-date errors.
  • Federated study package — coordinator distributes a self-contained package; partners run locally under their own governance; only aggregate results return for joint review (used in DARWIN EU's 14-step framework).
  • Pairing — designed to complement magnitude-estimating methods (PheValuator) rather than replace gold-standard validation.

Built as an adaptation of the open-source OHDSI package; the pre-analysis data-quality gate a registry study should pass before any downstream result is trusted.

What to verify first

  • OMOP prerequisite — the approach assumes data is in the OMOP CDM and has passed data-quality review; sources not in OMOP require mapping work before the tool runs.
  • Subjectivity — diagnostics point at problems without quantifying them; pair with a magnitude-estimating method (PheValuator) and have someone with CF clinical knowledge review, not read mechanically.
  • Clinical-expectation template is the crux — the audit is only as good as the pre-written description; the CF signs/tests/treatments/epidemiology must be written carefully and honestly up front (a judgment step, not automated).
  • No registry internals — external data-quality method only; makes no claim about any registry's genotype/data internals and decides no research design.

ALEX Today's Track B paper is "CohortDiagnostics: Phenotype evaluation across a network of observational data sources using population-level characterization," by Rao and colleagues, published in PLoS One in 2025. 今天的 B 轨论文是 Rao 等人 2025 年发表在《PLoS One》上的《CohortDiagnostics：使用人群层面特征刻画在多个观察性数据源网络中评估表型》。 It's open access and we read the full text. 它是开放获取的，我们读了全文。 Track B is about AI and tooling for registry and bioinformatics work, and I picked this one because it ships real, installable software and it targets a problem you hit before any model or analysis: is my cohort definition actually finding the patients I think it is? B 轨关注的是用于登记库和生物信息工作的 AI 与工具，我选这篇是因为它交付了真实、可安装的软件，而且它针对的是一个在任何模型或分析之前就会遇到的问题：我的队列定义，真的找到了我以为它找到的那些病人吗？

JORDAN Let me get the vocabulary straight first, because this is clinical-informatics territory more than genomics. 我先把术语理清楚，因为这更多是临床信息学的领域，而不是基因组学。 What is a "phenotype algorithm"? 什么是"表型算法"？

ALEX A phenotype algorithm — the paper abbreviates it PA — is a computable query that identifies patients with a specific condition in a health dataset. 表型算法——论文缩写为 PA (phenotype algorithm)——是一段可计算的查询，用来在健康数据集中识别患有某个特定疾病的病人。 Think of it as the operational definition of "who counts as having systemic lupus," written in terms of diagnosis codes, drug exposures, lab tests, and timing logic. 你可以把它理解为"谁算得上患有系统性红斑狼疮"的可操作定义，用诊断代码、用药记录、化验、以及时间逻辑写成。 It's foundational — almost every real-world-evidence study starts by running one or more PAs to assemble its cohort. 它是基础性的——几乎每一项真实世界证据研究，都从运行一个或多个 PA 来组装队列开始。 And the danger is misclassification: if the PA is too loose it includes people who don't have the disease, too tight and it misses real cases, and either way every downstream result inherits that error. 而危险在于误分类：如果 PA 太宽松，就会纳入没病的人；太严格，就会漏掉真实病例；无论哪种，所有下游结果都会继承这个错误。

JORDAN And "OMOP" — that keeps coming up. 还有"OMOP"——这个词一直出现。

ALEX OMOP is the Observational Medical Outcomes Partnership common data model. OMOP 是观察性医疗结果合作组织的通用数据模型 (Observational Medical Outcomes Partnership common data model)。 It's a standardized schema — a fixed set of tables and vocabularies — that different institutions convert their claims or electronic-health-record data into, so the same analysis code can run unchanged across many datasets. 它是一个标准化的数据结构——一组固定的表和术语集——不同机构把各自的理赔数据或电子病历数据转换成这个格式，于是同一份分析代码就能在许多数据集上原样运行。 The vocabularies matter: conditions get mapped to SNOMED-CT, a standardized clinical terminology, so a diagnosis means the same thing whether it came from a German or an American source. 术语集很关键：疾病被映射到 SNOMED-CT (一套标准化的临床术语)，这样一个诊断无论来自德国还是美国的数据源，含义都一致。 CohortDiagnostics is written to run on any OMOP-formatted dataset. CohortDiagnostics 就是为在任何 OMOP 格式的数据集上运行而编写的。

JORDAN One more — "index date." 还有一个——"索引日期"。

ALEX The index date is the calendar date on which a patient enters the cohort — the moment the algorithm decides "this person now counts." 索引日期是病人进入队列的那个日历日期——算法判定"这个人从此刻起算数"的那一刻。 It's usually the first qualifying diagnosis or treatment. 它通常是第一次符合条件的诊断或治疗。 A lot of subtle error hides in the index date, because the date a disease gets *coded* in the data often lags the date the person actually *had* the disease. 很多微妙的错误都藏在索引日期里，因为疾病在数据中被*编码*的日期，往往滞后于这个人*实际*患病的日期。 The paper calls that index date misclassification, and it's one of three error types the tool is built to expose. 论文称之为索引日期误分类，它是这个工具专门用来暴露的三类错误之一。

JORDAN So what's the gap this paper is filling? 那这篇论文填补的是什么空白？ Don't we already evaluate phenotype algorithms? 我们不是已经在评估表型算法了吗？

ALEX We evaluate them badly, and the paper is honest about why. 我们评估得很差，而论文对原因很坦诚。 The gold-standard way to validate a PA is to compare it against chart review — a human reading medical records — or against a disease registry. 验证一个 PA 的金标准做法，是把它与病历审查（人工阅读病历）或疾病登记库做对比。 But chart review is slow, expensive, prone to reviewer disagreement, and impossible in large de-identified datasets where you can't go back to the record. 但病历审查慢、贵、容易出现审查者之间的分歧，而且在无法回溯到原始记录的大型去标识化数据集里根本做不到。 Registries are rarely available and cover few conditions. 登记库很少能拿到，而且覆盖的疾病也很少。 There are newer scalable methods like PheValuator that estimate the *magnitude* of measurement error, but — and this is the key gap — they tell you *that* an error exists without telling you *where it comes from* or *how to fix the definition*. 也有一些较新的可扩展方法，比如 PheValuator，能估计测量误差的*大小*，但——这正是关键空白——它们告诉你误差*存在*，却不告诉你误差*从哪来*、或*如何修正定义*。 CohortDiagnostics fills that gap: it's diagnostic rather than just evaluative. CohortDiagnostics 填补的正是这个空白：它是诊断性的，而不只是评估性的。

JORDAN So how does it work without a gold standard at all? 那它在完全没有金标准的情况下是怎么工作的？

ALEX This is the clever conceptual move. 这是巧妙的概念转折。 Instead of comparing the cohort to a reference truth, it characterizes the cohort against your own clinical expectations. 它不是把队列与某个参考真相对比，而是把队列与你自己的临床预期做对照刻画。 The workflow starts by writing a clinical description of the disease — its presentation, its typical diagnostic tests, its treatments, its risk factors, its epidemiology. 工作流程从写一份疾病的临床描述开始——它的表现、典型诊断化验、治疗、危险因素、流行病学。 Then the tool computes a battery of population-level summary statistics on the cohort the PA returned, and you check them against that description. 然后工具在 PA 返回的队列上计算一组人群层面的汇总统计量，你再把它们与那份描述对照检查。 If lupus is supposed to be five-times more common in women and peak at a certain age, does your cohort show that? 如果狼疮理应在女性中高出五倍、并在某个年龄段达到高峰，你的队列显示出这个规律了吗？ If a disease has a signature treatment, do you see that drug appearing right around the index date? 如果一种疾病有标志性的治疗，你能看到那种药物恰好在索引日期附近出现吗？ Deviations from clinical expectation become fingerprints for specific error types. 与临床预期的偏离，就成了特定错误类型的"指纹"。

JORDAN Walk me through the actual diagnostics. 带我过一遍具体的诊断项。 What does it compute? 它计算什么？

ALEX There are several, and each maps to an error it can reveal. 有好几项，每一项都对应它能揭示的一种错误。 First, incidence rate — it computes the rate per thousand person-years, stratified by age, sex, and calendar year, in every data source. 第一，发病率——它按年龄、性别、日历年分层，在每个数据源里计算每千人年的发病率。 A stable, monotonic rate over calendar time is reassuring; a sudden jump suggests a change in coding practice, and a rate wildly different in one source suggests the PA doesn't travel there. 一个随日历年稳定、单调的发病率令人放心；一个突然的跳变提示编码实践发生了变化；而某个数据源里发病率异常不同，则提示这个 PA 不适用于该数据源。 Second, index event breakdown — which specific codes actually triggered cohort entry. 第二，索引事件分解——究竟是哪些具体代码触发了队列进入。 If almost everyone enters on a narrow subset of codes, that hints at a specificity problem. 如果几乎所有人都是靠一小撮代码进入的，那就暗示存在特异性问题。 Third, visit context — what kind of visit, outpatient versus inpatient versus emergency, surrounds the index date. 第三，就诊情境——索引日期前后是哪种就诊类型，门诊、住院还是急诊。 An unexpected visit type is a specificity red flag. 出现意料之外的就诊类型，是一个特异性的警示信号。 Fourth, cohort overlap — when you have two PAs for the same disease, a Venn-diagram comparison of who each one catches. 第四，队列重叠——当你对同一疾病有两个 PA 时，用韦恩图比较各自抓到了谁。 And fifth, cohort characterization — the prevalence of every clinical event before, on, and after the index date, which lets you check that expected symptoms, tests, and treatments show up in the right temporal order. 第五，队列特征刻画——每一个临床事件在索引日期之前、当天、之后的患病率，让你能检查预期的症状、化验、治疗是否按正确的时间顺序出现。

JORDAN Let me push on the design. 我想追问一下设计。 This all sounds subjective — you're eyeballing whether a distribution "looks right." 这一切听起来都很主观——你是在用肉眼判断某个分布"看起来对不对"。 Isn't that a weakness? 这不是一个弱点吗？

ALEX It is, and the authors say so outright — it can't numerically quantify the error, and reading the diagnostics is subjective and time-consuming. 确实是，作者也直言不讳——它无法用数字量化误差，而且解读这些诊断项既主观又耗时。 That's why their honest positioning is that CohortDiagnostics is complementary to methods like PheValuator, not a replacement. 这就是为什么他们诚实地定位 CohortDiagnostics 是对 PheValuator 这类方法的*补充*，而非替代。 PheValuator gives you the magnitude of the error; CohortDiagnostics gives you its direction, its likely source, and a lead on which part of the definition to change. PheValuator 给你误差的大小；CohortDiagnostics 给你误差的方向、可能的来源、以及该改动定义哪一部分的线索。 But there's a real design strength worth crediting: it turns evaluation into an *iterative* step. 但有一个真正的设计优点值得肯定：它把评估变成了一个*迭代*步骤。 You run the diagnostics, spot a likely error, adjust the PA, and re-run — the tool is built to sit inside that loop, not to hand down a single verdict. 你运行诊断、发现一个可能的错误、调整 PA、再重跑——这个工具就是为待在那个循环里而设计的，而不是为下达一个一锤定音的判决。

JORDAN Give me the concrete results. 给我具体的结果。 They tested it on real diseases? 他们在真实疾病上测试了它？

ALEX On one lupus PA and two Alzheimer's PAs, across ten observational data sources — six claims databases and four electronic-health-record databases, spanning several countries. 在一个狼疮 PA 和两个阿尔茨海默病 PA 上，跨十个观察性数据源——六个理赔数据库和四个电子病历数据库，覆盖多个国家。 For lupus, the incidence rate was concordant across most sources — 0.51 to 1.24 per thousand person-years — and correctly showed the roughly five-fold female predominance. 对狼疮，发病率在大多数数据源里是一致的——每千人年 0.51 到 1.24——并且正确地显示出约五倍的女性优势。 But two general-practitioner sources, the France and Germany Disease Analyzer databases, gave wildly different rates, flagging that this PA is probably not suitable for those two sources. 但两个全科医生数据源——法国和德国的 Disease Analyzer 数据库——给出的发病率差异极大，这标示出该 PA 大概不适用于这两个数据源。 The index-event breakdown also caught that many lupus patients enter on treatment or symptoms *before* their diagnosis is coded — a textbook index date misclassification. 索引事件分解还捕捉到，许多狼疮病人是靠治疗或症状进入队列的，而这发生在他们的诊断被编码*之前*——这是教科书式的索引日期误分类。

JORDAN And the two Alzheimer's algorithms — what did comparing them show? 那两个阿尔茨海默病算法呢——把它们对比显示出了什么？

ALEX This is a nice illustration of the overlap diagnostic. 这是重叠诊断的一个很好的示例。 A simple PA — enter on the first Alzheimer's diagnosis — was compared to a complex, restrictive one from prior published work. 一个简单的 PA——首次出现阿尔茨海默病诊断即进入——被拿来与一个来自既往发表工作的、复杂而严格的 PA 对比。 The complex PA returned far fewer patients, and the overlap showed only 18 to 45% of people were caught by both, with the majority caught only by the simple one — so the simple PA has higher sensitivity. 复杂 PA 返回的病人少得多，而重叠显示只有 18% 到 45% 的人被两者都抓到，大多数只被简单 PA 抓到——所以简单 PA 的灵敏度更高。 But the characterization revealed the tradeoff: the simple PA had more cerebrovascular-accident events near index — a hint it's misclassifying some strokes as Alzheimer's, a specificity cost. 但特征刻画揭示了这个取舍：简单 PA 在索引附近有更多脑血管意外事件——这暗示它把一些中风误分类成了阿尔茨海默病，是特异性的代价。 The higher sensitivity of the simple definition comes at the price of some false positives. 简单定义更高的灵敏度，是以一些假阳性为代价换来的。 That's exactly the kind of concrete, actionable insight the tool is designed to surface, and it did it without ever touching a gold standard. 这正是这个工具被设计来揭示的那种具体、可操作的洞见，而且它做到这一点时从未触及任何金标准。

JORDAN There's also a network angle you mentioned. 你还提到了一个网络的角度。

ALEX Yes, and it's a big part of why this ships as reusable software rather than a one-off analysis. 对，而这也是它作为可复用软件、而非一次性分析交付的重要原因之一。 The output contains no patient-level data — only aggregate summary statistics with minimum cell-count thresholds for privacy — and it's written as plain CSV files by design, so a data partner can audit exactly what leaves their site. 输出不含任何患者层面的数据——只有带最小单元格计数阈值的汇总统计量以保护隐私——而且它有意写成普通 CSV 文件，这样数据伙伴可以精确审查什么东西离开了他们的站点。 So a coordinating site can send a self-contained study package to many data partners, each runs it locally behind their own governance, and only aggregate results come back to be reviewed together in a Shiny web app. 于是一个协调站点可以把一个自包含的研究包发给许多数据伙伴，每个伙伴在自己的治理规则下本地运行，只有汇总结果返回，供大家在一个 Shiny 网页应用里一起审阅。 That federated design is why it's been adopted as the phenotype-vetting step in large networks like DARWIN EU. 这种联邦式的设计，正是它被 DARWIN EU 等大型网络采纳为表型审核步骤的原因。

JORDAN So where does this land for us? 那这对我们落在哪里？
