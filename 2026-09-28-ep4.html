Ep4 (Track C, 2 of 2) -- A pipeline for harmonising NHS Scotland laboratory data to enable national-level analyses

Gao C, Mumtaz S, McCall S, O'Sullivan K, McGilchrist M, Morales DR, Hall C, Wilde K, Mayor C, Linksted P, Harrison K, Cole C, Jefferson E. 2025. Journal of Biomedical Informatics. PMID 39755323 / DOI 10.1016/j.jbi.2024.104771. Abstract-only -- closed access, no PMCID, Europe PMC has no full text indexed.

The Scottish Safe Haven Network built an open-source pipeline to harmonize laboratory data across Scotland's four regional Safe Havens, which -- unlike national hospitalisation, prescribing, and mortality data -- has historically been captured and reported locally with real cross-regional heterogeneity. The pipeline maps regional data onto 11 FHIR terms plus two Scotland-specific terms, and found that just 180 distinct test codes account for 98.7% of all lab records performed nationally; it built unit-conversion transformations for those 180 codes and encoded tests using both Read Codes and SNOMED CT. Because only the abstract is available, methodological detail on how rigorously the unit conversions were validated is unverified. The paper lands squarely on candidate generation: unit mismatch is one of Track C's core error types, and the buildable artifact is a site-level distributional audit to catch it before any implausible-value rule runs.

Plain-English glossary

  • FHIR (Fast Healthcare Interoperability Resources) -- a widely adopted international standard for representing clinical data in a consistent, structured format that different health-IT systems can exchange.（中文：一种被广泛采用的国际标准，用一致的结构化格式表示临床数据，供不同的医疗信息系统之间交换。）
  • Read Codes -- an older, UK-specific clinical coding system still present in much legacy primary-care data, being phased out in favor of SNOMED CT.（中文：一套较早的、英国特有的临床编码体系，仍存在于大量历史基层医疗数据中，正逐步被SNOMED CT取代。）
  • Safe Haven -- a secure, governed data environment where researchers access de-identified patient data under strict controls without the data leaving that environment; Scotland runs four regional ones rather than one national system.（中文：一种安全的、受治理的数据环境，研究人员在严格管控下访问去标识化的患者数据，数据不会离开该环境；苏格兰运行的是四个区域性的安全港，而不是一个全国统一系统。）
  • SNOMED CT -- the newer, internationally maintained, more granular clinical terminology system that UK healthcare has been migrating toward.（中文：一套更新的、由国际维护、颗粒度更细的临床术语体系，英国医疗系统一直在向它迁移。）
  • Unit harmonization -- converting a measurement recorded in different units at different sites (e.g., a lab value in different concentration units) to one common unit before pooling data for analysis.（中文：在汇总数据进行分析之前，把不同站点以不同单位记录的测量值（例如浓度单位不同的检验值）转换成统一的单位。）

Methods / tools to lift

  • Coverage-driven scoping (Pareto prioritization) -- focus harmonization engineering on the ~180 codes covering 98.7% of records rather than the full code universe.
  • Dual-terminology encoding (Read Codes + SNOMED CT) -- support both a legacy and a current coding system within one pipeline for cross-era compatibility.
  • Cross-region mapping to a shared standard (FHIR + local extensions) -- reconcile heterogeneous regional systems onto common terms once, rather than per-project.

Where it lands + buildable artifact

Serves Liz / CFFPR data quality (method only). Buildable: site-level unit-and-scale harmonization audit (S) -- for a given measurement type, compute each contributing site's value distribution (mean, spread, percentiles) and flag any site whose distribution looks shifted/rescaled relative to the pooled distribution, rather than flagging individual encounters.

What to verify first

  • The actual per-test unit-conversion logic and how rigorously it was validated -- unverified from the abstract alone; the open-source pipeline code is worth tracking down separately.
  • Whether a site-level distributional shift reliably distinguishes a genuine unit-conversion problem from real population differences between sites serving different patient groups.
  • Whether the 1.3% of records outside the top 180 codes represent a population meaningfully different from the harmonised majority.
  • That none of this speaks to how CFFPR's own sites or clinics actually record height and weight, or whether unit inconsistency is a live issue there.

Pipeline stage

(a) candidate generation, primary -- cross-site unit harmonization is an upstream prerequisite before any distributional implausible-value rule runs; a unit-conversion mismatch can manufacture a value that looks like a biologically implausible outlier even when the underlying measurement is correct.

Error types covered / not covered

Covered: unit conversion / unit mismatch across sites. Not covered (per the abstract): digit transposition, decimal-place shift, carry-forward values, or distinguishing a data-entry error from a real clinical event -- the paper is about terminology and unit reconciliation, not implausible-value detection itself.
