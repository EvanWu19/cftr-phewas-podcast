Ep3 — Track C: Registry Data Quality & Anthropometric Outlier Detection

Paper: Van den Broeck J, Argeseanu Cunningham S, Eeckels R, Herbst K. "Data Cleaning: Detecting, Diagnosing, and Editing Data Abnormalities." PLoS Medicine, 2005.

Blurb

This 2005 PLoS Medicine policy forum is a conceptual/narrative methods paper, not an empirical study — it has no dataset, no performance numbers, and ships no software. Its contribution is a structured three-stage cycle for cleaning clinical research data: Screening (spotting four kinds of "oddities" — missing/excess data, outliers including inconsistencies, strange joint-distribution patterns, and unexpected analysis results), Diagnosing (sorting each flagged point into one of four verdicts: erroneous, true extreme, true normal, or idiopathic), and Editing/Treatment (correct, delete, or leave unchanged). Key vocabulary includes "erroneous inliers" (error-generated values that still fall inside a plausible range) and a two-tier "soft cutoff / hard cutoff" distinction for screening thresholds. For the Liz Cromwell CFFPR height/weight outlier-flagging priority, this paper supplies framework and vocabulary worth borrowing, not a tested flagging method — the buildable artifact is a small hard/soft-cutoff triage-queue builder that tags flagged anthropometric records with the paper's four-verdict taxonomy for human review.

Plain-English Glossary

  • Data cleaning — The process of identifying and correcting (or minimizing the impact of) errors in research data after collection.（中文：在数据采集之后，识别并修正错误、或尽量降低其影响的过程。）
  • Data flow — The full chain a measurement travels through after capture: written on a form, entered into a database, extracted, transferred, re-coded, summarized, and displayed; errors can enter or hide at any hop.（中文：一次测量完成后所经历的整条链路——记录、录入、提取、传输、重新编码、汇总、展示，错误可能在任何一个环节产生或被掩盖。）
  • Erroneous inlier — A data point generated by an error that nonetheless falls within the expected/plausible range, so it escapes ordinary range-check detection.（中文：由错误产生、但恰好落在预期合理范围内的数值，因此常规范围检查无法发现它。）
  • Growth curve (growth chart) — A reference plot of a measurement like height or weight against age, used to judge whether a value is typical or extreme, including for a single individual's own repeated measurements over time.（中文：将身高、体重等测量值随年龄变化绘制的参考曲线图，用来判断某个数值是否典型或极端，也可用于描绘单个个体自身随时间重复测量的轨迹。）
  • Hard cutoff — A predefined threshold marking values that are logically or biologically impossible (e.g., negative age); hitting it skips review and goes straight to error diagnosis.（中文：预先设定的阈值，用于标记逻辑上或生物学上不可能的数值（例如负数年龄），一旦触发即跳过复核，直接进入错误诊断。）
  • Idiopathic (diagnostic verdict) — One of the four diagnostic outcomes for a flagged data point: no explanation was found, but the value is still considered suspect.（中文：被标记数值的四种诊断结论之一：未找到解释，但该值仍被视为可疑。）
  • Inlier — A data point that falls within the range you'd expect, as opposed to an outlier.（中文：落在预期范围之内的数据点，与离群值相对。）
  • Outlier — A data point that falls outside the range you'd expect, including values flagged by internal inconsistency rather than just extremity.（中文：落在预期范围之外的数据点，也包括因内部不一致而被标记的数值，不仅限于数值极端。）
  • Soft cutoff — A predefined threshold marking a value as unusual enough to warrant human review, without asserting it is necessarily an error.（中文：预先设定的阈值，用于标记"异常到值得人工复核"的数值，但不直接断定其为错误。）
  • True extreme (diagnostic verdict) — A diagnostic outcome meaning the flagged value is genuinely correct but legitimately extreme.（中文：诊断结论之一，表示被标记的数值确实真实，但属于合理的极端情况。）
  • True normal (diagnostic verdict) — A diagnostic outcome meaning the value is correct and unremarkable, and the prior expectation that flagged it was itself wrong.（中文：诊断结论之一，表示该数值是正确且正常的，而最初触发标记的预期本身是错误的。）
  • Weight-for-age / z-score — A z-score for weight-for-age expresses how many standard deviations a measurement is from the expected value for a child's age and sex on a reference growth curve; zero is the median, very large-magnitude values (e.g., −6) are extreme outliers.（中文：年龄体重的Z值表示某测量值与参照生长曲线上对应年龄、性别的预期值相差多少个标准差；零值位于中位数，绝对值很大的数值（例如−6）属于极端异常值。）

Methods/Tools to Lift

  • Three-stage cyclical process — Screening, Diagnosing, Editing/Treatment — as a repeatable structure for any data-cleaning effort, not a one-shot pass.
  • Four-category screening taxonomy — missing/excess data; outliers including inconsistencies; strange joint-distribution patterns; unexpected analysis results.
  • Soft-cutoff / hard-cutoff threshold vocabulary — a two-tier way to separate "needs review" from "definitionally impossible, diagnose immediately."
  • Four-verdict diagnostic taxonomy — erroneous, true extreme, true normal, idiopathic — a shared label set for what a human reviewer concludes about a flagged point.
  • Diagnostic moves — checking earlier points in the data flow for consistency, seeking independent confirming evidence (e.g., remeasurement), and using subject-matter knowledge to catch input errors such as two fields being swapped (their example: infant length recorded under head circumference).
  • Longitudinal/serial-data check — plotting an individual's own repeated measurements (e.g., growth data) to surface a discordant point that a single cross-sectional range check would miss.

Where It Lands + Buildable Artifact

Priority served: Liz/CFFPR data-quality (method only — no claims about CFFPR's actual internals, flag rates, or cleaning rules).

Buildable artifact: Hard/Soft Cutoff Triage Queue Builder. One-line MVP: given a CSV of height/weight/age/visit-date records with a z-score column already computed upstream, apply two user-configured threshold bands per field (soft, hard — thresholds set explicitly by the implementer, not inherited from this paper) and emit a review queue where hard-cutoff rows are pre-labeled "erroneous-candidate," soft-cutoff rows are labeled "needs-review," and every row carries four empty columns for a human reviewer to mark erroneous / true-extreme / true-normal / idiopathic. Difficulty: S (pandas script + a config file for the per-field thresholds; no model, no training).

What to Verify First

  • Whether a four-way verdict taxonomy (erroneous / true extreme / true normal / idiopathic) maps cleanly onto however a registry review process currently categorizes a flagged value, or whether real-world review notes need additional buckets this framework doesn't anticipate.
  • What threshold-setting approach actually suits pediatric anthropometric z-scores specifically — this paper gives only the soft/hard-cutoff concept, not anthropometry-specific guidance; that choice would need to come from growth-reference literature or statistical methods work.
  • Whether a small set of known-swap field pairs (e.g., length vs. head circumference) is worth a dedicated structural screen, separate from range-based outlier flags — and how often that specific failure mode actually occurs.
  • Whether more recent (post-2005) methodological literature has already formalized, refined, or superseded parts of this framework.

Pipeline Stage

(e) Nothing directly, but supplies vocabulary/framework worth borrowing. The paper names a two-tier soft-cutoff/hard-cutoff threshold concept and a four-way diagnostic-verdict taxonomy, but gives no method for setting either tier, no dataset, no statistic, and no software — so while the cutoff vocabulary is directly relevant to how one would describe and justify candidate-generation threshold design, it does not supply the threshold values or algorithm itself. It is a shared vocabulary for discussing (a) candidate generation, (b) adjudication, and (c) human review budget, not a concrete mechanism for any one of them.

Error Types Covered / Not Covered

  • Covered (conceptually): logically/biologically impossible values (hard-cutoff territory); statistically unusual-but-plausible values (soft-cutoff territory); field-swap input errors (e.g., length recorded under head circumference); discordant points within an individual's own longitudinal series.
  • Not covered / not addressed: unit-conversion errors, digit-transposition errors, decimal-shift errors, and carry-forward (stale-value-repeated) errors are not specifically named or treated as distinct categories; the paper also does not address how to distinguish a true extreme from a real clinical event (e.g., an actual acute illness or growth event) versus a data error — it leaves "true extreme" as a single catch-all verdict without a sub-method for that distinction.
