Ep3 (Track C 1/2 — registry QC): A landscape, not a result

Huser and colleagues' 2018 Pacific Symposium on Biocomputing workshop summary, "Methods for examining data quality in healthcare integrated data repositories," puts one speaker from each of four major clinical-data networks — OHDSI (whose Achilles Heel module runs rule-based checks against the OMOP common data model), PEDSnet (a pediatric EHR research network, the same lineage behind yesterday's Khare et al. episode on PEDSnet's five-state DQ-issue lifecycle), Sentinel (the FDA's claims-data-based active product-safety surveillance system), and the University of Utah (whose contribution is a service-oriented, modular DQ-checking architecture) — in the same room to describe their own infrastructure, share interim OHDSI-wide data-quality study results, and discuss combining the best features of each approach. This is an unusually thin pick: the paper is retrievable only as an 884-character abstract with no sensitivity, specificity, flag-rate, or sample-size numbers of its own, and is flagged abstract-only/thin throughout. The genuine takeaway is the landscape itself — four independently funded, independently built systems on four different underlying data architectures converging on broadly similar conformance/completeness/plausibility goals — which is orientation, not a result to port directly into any pipeline stage. Plain-English glossary

  • PEDSnet — a pediatric clinical data research network built on pooled EHR data from multiple children's hospitals.（中文：PEDSnet，一个基于多家儿童医院合并电子健康记录数据构建的儿科临床数据研究网络。）

  • Service-oriented framework (SOA) — a software-architecture pattern building checks as modular, independently callable services rather than one monolithic script.（中文：面向服务的框架（SOA），一种软件架构模式，把检查做成模块化、可独立调用的服务，而不是单一的庞大脚本。）

JORDAN You mentioned the Kahn framework a moment ago — since it keeps coming up across these Track C episodes, what are conformance, completeness, and plausibility actually pinning down? 你刚才提到了Kahn框架——既然它在Track C这几集里反复出现，符合性、完整性和合理性这三个词到底各自在界定什么？

ALEX Conformance asks whether the data follows its own stated structural rules — is a date actually stored as a valid date, does a coded field only ever contain values from its allowed value set — and it's checkable without knowing anything about the patient at all, purely a syntax-and-schema question. 符合性（conformance）问的是数据是否遵循了它自己声明的结构规则——一个日期字段是否真的存成了合法的日期格式，一个编码字段是否只包含它允许取值范围内的值——这类检查完全不需要了解病人本身的任何情况，纯粹是语法和模式层面的问题。 Completeness asks whether an expected value is actually present at all — is there a height recorded for this visit, is there a value where one should exist given the visit type — which is a presence-or-absence question, distinct from whether a present value makes sense. 完整性（completeness）问的是一个预期应该存在的值是否真的存在——这次就诊有没有记录身高，按就诊类型来说本该有的值是否确实存在——这是一个"有没有"的问题，和"存在的值是否合理"是两件不同的事。 And plausibility — the category anthropometric outlier detection actually lives in — asks whether a present, structurally valid value is clinically believable: a height value can be a syntactically valid number, present exactly where expected, and still be a thirty-centimeter jump from the same child's last visit that no real growth process would produce. 而合理性（plausibility）——人体测量学异常值检测真正归属的那一类——问的是一个确实存在、结构上也合法的数值，在临床上是否可信：一个身高数值可以是一个语法上合法的数字，恰好出现在该出现的位置，却仍然是同一个孩子上次就诊记录相比突然跳升了三十厘米，而这是任何真实的生长过程都不会产生的变化。 Each of these further splits into atemporal — checkable from a single point in time — versus temporal — checkable only by comparing across multiple visits, which is exactly where a within-child growth trajectory check has to live. 这三类又都进一步分为非时序性（atemporal）——只看单一时间点就能检查——和时序性（temporal）——只能通过比较多次就诊记录才能检查，而这正是任何基于同一孩子生长轨迹的检查所必须归属的类别。
