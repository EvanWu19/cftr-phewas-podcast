Ep3 (Track C — registry QC, 1 of 2): What the missing values are already telling you

Wells, Chagin, Nowacki, and Kattan (2013, EGEMS) lay out a Cleveland Clinic methods guide for missing data in EHR-derived research: the central problem that missing often cannot be distinguished from a true negative value, the MCAR/MAR/NMAR missingness taxonomy, why complete-case analysis is almost never unbiased for EHR data, multiple imputation by chained equations (MICE) as the standard fix, and why healthcare-utilization and comorbidity-index covariates belong in any imputation model. This is a framework paper, not a flagging tool — no sensitivity, no PPV, no gold standard — but it's directly linked to tomorrow's companion episode, which cites it as reference 25. Buildable artifact: a Missingness Mechanism Diagnostic.

Plain-English glossary

  • Charlson Comorbidity Index — a validated score summarizing overall disease burden from ICD diagnosis codes, recommended here as a covariate in any EHR imputation model.（中文：一种基于ICD诊断代码汇总整体疾病负担的经验证评分，本文建议将其作为任何电子健康档案填补模型的协变量。）
  • Disease phenotype algorithm — a formalized rule combining diagnosis codes, lab values, and medication orders to classify whether a patient has a given condition, rather than relying on any single field.（中文：一种综合诊断代码、检验值和用药记录来判断患者是否患有某种疾病的形式化规则，而非依赖任何单一字段。）
  • MAR (missing-at-random) — missingness that depends on other measurable variables but not on the missing value itself once those are accounted for; plausible but fundamentally untestable from observational data alone.（中文：缺失情况取决于其他可测量变量，但在考虑了那些变量之后不再取决于缺失值本身；这一假设看似合理，但仅凭观察性数据根本无法验证。）
  • MCAR (missing-completely-at-random) — missingness unrelated to the missing value or any other variable; complete-case analysis is unbiased only under this assumption.（中文：缺失情况与缺失值本身或任何其他变量都无关；只有在这一假设下，完全病例分析才是无偏的。）
  • MICE (multiple imputation by chained equations) — imputes each missing variable by regressing it on all other variables, iterating until estimates stabilize, repeated multiple times to capture genuine uncertainty.（中文：通过将每个含缺失值的变量对所有其他变量进行回归来填补缺失值，反复迭代直至估计值稳定，并重复多次以体现真实的不确定性。）
  • NMAR (not-missing-at-random) — missingness that depends on the unobserved value itself or on something else entirely unmeasured; the hardest case to correct for.（中文：缺失情况取决于未被观测到的数值本身，或取决于某个完全未被测量的其他因素；是最难纠正的一种情况。）
  • National Death Index (NDI) — a CDC-maintained dataset capturing 87–98% of US deaths, used for unbiased mortality ascertainment outside any single institution's own records.（中文：由美国疾病控制与预防中心维护的数据集，捕捉87%至98%的美国死亡事件，用于在任何单一机构自身记录之外进行无偏的死亡结局确认。）

Full citation

Wells BJ, Chagin KM, Nowacki AS, Kattan MW. "Strategies for Handling Missing Data in Electronic Health Record Derived Data." EGEMS (Washington, DC). 2013. PMID: 25848578 | PMC4371484 | DOI: 10.13063/2327-9214.1035

Methods / tools to lift

  • MCAR / MAR / NMAR taxonomy — the standard three-way classification of missingness mechanisms, reusable vocabulary for reasoning about any flagging rule's assumptions about missing values.
  • MICE (R mice package) — multiple imputation by chained equations, the recommended default fix over complete-case deletion.
  • Utilization/comorbidity-aware imputation covariates — including encounter count and a validated comorbidity index (e.g. Charlson) in any imputation model, since missingness itself correlates with both.
  • External-linkage ascertainment (NDI, ACS/GIS geocoding) — reducing bias in outcome and socioeconomic variables by linking to data sources outside the EHR itself.

Where it lands + buildable artifact

Pipeline stage: (e) framework/vocabulary, primary — the MCAR/MAR/NMAR taxonomy and the missing-vs-negative-value ambiguity are reusable concepts for any future flagging-rule design, not a tested method. (a) candidate generation, secondary — a candidate generator trained on complete-case data silently inherits whatever bias this paper describes. Buildable artifact: a Missingness Mechanism Diagnostic — fit a logistic regression predicting field missingness from observed covariates (encounter count, calendar year, other same-visit fields) as a quick pre-check before building any imputation or flagging model.

Error types covered / not covered: Does not address unit conversion, digit transposition, decimal-shift, or carry-forward errors directly — this paper is about missingness, not value-implausibility, and never tests any flagging rule at all; the transfer here is purely conceptual.

What to verify first

  • Whether any registry's own structured-documentation habits resemble Cleveland Clinic's 2013-era practices closely enough for this paper's specific covariate advice to transfer, rather than assuming it generalizes.
  • That any missingness-mechanism diagnostic built from this framework gets its own validation — the paper provides no quantified sensitivity, false-positive rate, or gold standard for anything.
  • That the MAR-plausibility heuristic ("more covariates make MAR more plausible") is treated as a heuristic, not a guarantee of unbiased imputation.

JORDAN Let's build some registry/EHR vocabulary before the substance. 在讲内容之前，我们先建立一些登记库/电子健康档案方面的词汇。 Structured data (结构化数据) in an EHR means quantifiable numeric fields and discrete coded categories — things like a systolic blood pressure value or an ICD diagnosis code — that live in a database and can be reliably queried. 电子健康档案中的结构化数据指的是可量化的数值字段和离散的编码类别——比如收缩压数值或者ICD诊断代码——它们存在于数据库中，可以被可靠地查询。 Textual or narrative data (文本型/叙述性数据) is the free-text part of the chart, like a physician's progress note, and extracting information from it requires natural language processing, or NLP (自然语言处理), a specialized branch of computer science built to handle the breadth of human expression, grammatical errors, and context-dependent phrasing that free text contains. 文本型或叙述性数据是病历中的自由文本部分，比如医生的病程记录，从中提取信息需要用到自然语言处理（NLP），这是计算机科学的一个专门分支，用来应对人类表达的丰富性、语法错误以及自由文本中依赖上下文的措辞。 A disease phenotype algorithm (疾病表型算法) is a formalized rule — built from diagnosis codes, lab values, and medication orders in combination, rather than any single field alone — used to classify whether a patient actually has a given condition; hypertension, for instance, might be established through diagnosis codes, office blood-pressure readings, or antihypertensive prescriptions, any of which alone would be an incomplete signal. 疾病表型算法是一种形式化的规则——由诊断代码、检验值和用药记录组合构建而成，而不是依赖任何单一字段——用来判断某位患者是否真正患有某种疾病；例如高血压，可能需要通过诊断代码、门诊血压读数或抗高血压药物处方来综合确立，而单独依赖其中任何一项都只是不完整的信号。

ALEX One more concept worth planting, because it's the conceptual heart of this whole paper: in an EHR, you often cannot tell the difference between "this value is missing because nobody checked" and "this value is missing because the answer was negative and so nothing was recorded." 还有一个概念值得在这里打下基础，因为它是这整篇论文的概念核心：在电子健康档案中，你常常无法区分"这个数值缺失是因为没人检查过"和"这个数值缺失是因为答案是阴性，所以什么都没被记录下来"这两种情况。 The paper's own example: a patient with no documented history of heart failure may genuinely not have the disease, or a clinician may simply never have written it down — from the data alone, those two situations look identical. 论文自己给出的例子是：一位没有心力衰竭病史记录的患者，可能是真的没有这种疾病，也可能只是临床医生从未把它写下来——单从数据本身来看，这两种情况看起来完全一样。 Most EHR research is forced to assume missing means negative, and that assumption can be badly wrong, especially for conditions that are frequently under-documented. 大多数电子健康档案研究都被迫假设"缺失即阴性"，而这个假设有可能严重错误，尤其是对于那些经常被漏记录的病症而言。

JORDAN So why is this specific ambiguity worth bringing into a registry-QC conversation about height and weight, rather than disease flags? 那为什么要把这个具体的歧义问题，带入一场关于身高体重的登记库质量控制讨论，而不是疾病标记呢? Because the same underlying logic — that absence of data is not evidence of a specific value — applies anywhere a flagging rule has to decide what a missing measurement means before deciding what to do with the record around it, and because this paper's broader taxonomy of missingness mechanisms gives us precise vocabulary for reasoning about that. 因为同样的底层逻辑——数据的缺失并不能证明某个具体数值——适用于任何一种场景，只要一条标记规则在决定如何处理该记录周围的数据之前，首先需要判断一个缺失测量值意味着什么；而且这篇论文提出的更广泛的缺失机制分类体系，为我们思考这个问题提供了精确的词汇。 Statistically, missing data falls into three categories. 从统计学角度看，缺失数据可以分为三类。 Missing-completely-at-random, or MCAR (完全随机缺失), means the probability a value is missing has nothing to do with that value or any other variable — the paper's example is a car accident caused by a meteor strike keeping a patient from a scheduled visit. 完全随机缺失（MCAR）指的是某个数值缺失的概率与该数值本身或任何其他变量都没有关系——论文给出的例子是一次由陨石撞击引发的车祸，使患者无法赴约就诊。 Missing-at-random, or MAR (随机缺失), means missingness depends on other variables you can measure, but not on the missing value itself once you've accounted for those — healthier patients visiting less often and so having fewer recorded blood pressure readings is the paper's example. 随机缺失（MAR）指的是缺失情况取决于你能够测量到的其他变量，但在已经考虑了那些变量之后，就不再取决于缺失值本身——论文给出的例子是：更健康的患者就诊次数更少，因此记录到的血压读数也更少。 Not-missing-at-random, or NMAR (非随机缺失), is the hard case, where the probability of missingness depends on the unobserved value itself or on something else entirely unmeasured. 非随机缺失（NMAR）是最棘手的情况，缺失的概率取决于那个未被观测到的数值本身，或者取决于某个完全未被测量的其他因素。

ALEX Here's where I'd push back a little on how cleanly this gets applied in practice. 这里我想稍微质疑一下，这套分类在实际应用中是否真的能被如此干净利落地套用。 The paper itself admits it's hard to imagine any real dataset being purely one category or another, and MAR specifically is fundamentally untestable from the observational data alone — you can never fully rule out that missingness secretly depends on the unobserved value itself without going back and re-contacting patients, which almost never happens in registry research. 论文本身也承认，很难想象现实中任何数据集会纯粹属于某一类别，而MAR这一假设本身在仅凭观察性数据的情况下根本是无法检验的——你永远无法完全排除缺失情况其实暗中依赖于那个未被观测到的数值本身，除非回头重新联系患者本人，而这在登记库研究中几乎从未发生过。 The paper's own best advice is really just "the more relevant covariates you include in your imputation model, the more plausible the MAR assumption becomes" — which is a reasonable practical heuristic, but it's a plausibility argument, not a proof, and it's worth remembering that distinction every time someone says their imputation "handles" the missingness. 论文给出的最佳建议其实只是"在填补模型中纳入越多相关协变量，MAR假设就越可信"——这是一个合理的实用经验法则，但它只是一种可信度论证，而不是一种证明，每次有人说自己的填补方法"解决了"缺失问题时，都值得记住这个区别。

JORDAN Walk through the actual recommended fix. 讲讲具体推荐的解决方法。 The simplest approach, complete case analysis or listwise deletion — just drop any row with a missing value — is unbiased only under MCAR, and the paper argues that assumption is almost never plausible for EHR data, since patients with more complete records tend to be systematically different: better insured, more compliant, or sicker and therefore seen more often. 最简单的做法——完全病例分析，也叫逐行删除法——即直接丢弃任何含有缺失值的行——只有在MCAR假设下才是无偏的，而论文认为这个假设对电子健康档案数据几乎从不成立，因为记录更完整的患者往往系统性地与其他人不同：保险更好、依从性更高，或者病情更重、因此就诊更频繁。 The recommended alternative is multiple imputation using chained equations, or MICE (多重链式方程填补法), which imputes each variable with missing values by regressing it on every other variable in the dataset, replacing missing values with the regression's predictions, and then repeating this process iteratively — typically five iterations by default in the R MICE package — until estimates stabilize, with the entire imputation cycle repeated multiple times to produce several completed datasets whose variation reflects genuine uncertainty about what the missing values actually were. 推荐的替代方法是多重链式方程填补法（MICE），它对每一个含有缺失值的变量，用数据集中其他所有变量对其进行回归，用回归的预测值替换缺失值，然后反复迭代这个过程——在R语言的MICE包中默认通常是5次迭代——直到估计值趋于稳定，整个填补周期还会重复多次，生成多个已填补完整的数据集，这些数据集之间的差异反映了关于缺失值真实情况的真实不确定性。 The paper's specific, actionable recommendation for which covariates to include is the part most directly useful to us: because the degree of healthcare utilization is itself associated with missingness — more encounters means more chances for something to get documented — any imputation model should include healthcare utilization, measured as something like number of encounters, and overall disease severity, measured with a validated comorbidity index like the Charlson Comorbidity Index, even when those variables aren't obviously related to whatever specific condition is being studied. 论文中关于该纳入哪些协变量这一具体、可操作的建议，是对我们最直接有用的部分：由于医疗系统使用程度本身就与缺失情况相关——就诊次数越多，某项内容被记录下来的机会也就越多——任何填补模型都应该纳入医疗系统使用程度（可以用就诊次数之类的指标衡量）和整体疾病严重程度（可以用经过验证的合并症指数，比如Charlson合并症指数来衡量），即便这些变量与所研究的具体病症并无明显关联。

ALEX The paper also pushes a strategy that's less about statistics and more about data engineering: linking the EHR to outside data sources specifically to get less-biased variables for imputation and for outcome ascertainment. 论文还提出了一种策略，这与统计方法关系不大，更多是一种数据工程的做法：将电子健康档案与外部数据源进行关联，专门用于获取偏倚更小的变量，用于填补以及结局的确认。 Their flagship example is the National Death Index, or NDI (美国国家死亡指数), a dataset maintained by the CDC that captures 87 to 98 percent of US deaths and isn't biased toward patients who happened to die within the originating institution's own system — a huge advantage over relying only on in-system mortality flags, though the paper notes the NDI isn't free to access, unlike the Social Security Death Index, which became less reliable for this purpose after a 2011 policy change stopped it from using state death records. 他们的旗舰案例是美国国家死亡指数（NDI），这是由美国疾病控制与预防中心（CDC）维护的数据集，能够捕捉到87%到98%的美国死亡事件，而且不会偏向于恰好在原机构自身系统内死亡的患者——这相比仅依赖机构内部的死亡标记有巨大优势，不过论文指出，与社会保障死亡指数不同，NDI的使用并非免费，而社会保障死亡指数在2011年一项政策变更之后，由于不再使用各州的死亡记录，可靠性已经下降。 For socioeconomic status, a similarly crude field in most EHRs, they describe geocoding patient addresses and linking to Census Block Group data from the American Community Survey — at their own institution, 80 to 90 percent of patients could be mapped to an exact address, with another 5 to 10 percent matchable at the coarser 5-digit ZIP code level, leaving under 15 percent still requiring imputation. 对于社会经济地位这个在大多数电子健康档案中同样较为粗糙的字段，他们描述了将患者地址进行地理编码，并与美国社区调查（ACS）的人口普查街区组数据进行关联——在他们自己的机构里，80%到90%的患者能够精确匹配到具体地址，另有5%到10%可以在较粗的五位邮编层级匹配，剩下不到15%仍需要进行填补。

JORDAN What's the connection to outlier flagging specifically, since this paper never actually builds or evaluates a flagging rule? 这篇论文从未真正构建或评估一个标记规则，那它和异常值标记具体有什么联系呢? It's mostly vocabulary and a framework rather than a flagging substrate — scope item six on the list, measurement error and missing data interacting with outlier handling. 它主要是提供词汇和一个框架，而不是一个标记的技术基础——对应清单中的第六项范围：测量误差与缺失数据和异常值处理之间的相互作用。 The direct transfer is conceptual but real: before any rule decides a height or weight value looks implausible, it's worth asking whether the surrounding record's missingness pattern itself carries information — for instance, whether a visit with an unusually sparse set of other fields recorded is more or less likely to also contain a data-entry error in the fields that did get recorded, the same way the paper argues missingness correlates with healthcare utilization and disease severity more broadly. 这种迁移是概念性的，但也是真实的：在任何规则判断某个身高或体重数值看起来不合理之前，值得先问一下，周围记录本身的缺失模式是否就携带了某种信息——例如，一次其他字段记录异常稀少的就诊记录，是否更有可能（或更不可能）在那些确实被记录下来的字段中也包含数据录入错误，这与论文所说的缺失情况与医疗系统使用程度和疾病严重程度广泛相关的逻辑是一致的。 There's also a subtler point: if a candidate-generation model is ever trained on complete-case data — dropping any encounter with a missing covariate — that training population is itself a biased sample of the full registry, for exactly the reasons this paper describes, and that bias would silently propagate into whatever the flagging model learns to call normal. 还有一个更微妙的问题：如果某个候选生成模型是基于完全病例数据训练的——也就是剔除了任何含有缺失协变量的就诊记录——那么这个训练人群本身就是整个登记库的一个有偏采样，原因正是这篇论文所描述的那些，而这种偏倚会悄无声息地渗透进标记模型学习到的"正常"定义之中。

ALEX So the buildable piece here is small and diagnostic rather than a full flagging pipeline: a Missingness Mechanism Diagnostic. 所以这里可构建的部分规模较小，更偏向诊断性，而不是一整套标记流程：一个"缺失机制诊断工具"。 Given a longitudinal registry extract, fit a simple logistic regression predicting whether a given field is missing from observed covariates like encounter count, calendar year, and other recorded fields on the same visit — if that model finds strong, explainable structure, the MAR assumption looks more plausible and a standard imputation approach is reasonable; if it finds little structure, missingness is behaving more like MCAR, which is lower-stakes; and if key covariates are themselves full of missingness, that's a warning sign worth surfacing before building anything downstream. 给定一份纵向登记库数据抽取，拟合一个简单的逻辑回归模型，用就诊次数、年份以及同一次就诊中记录的其他字段等可观测协变量，来预测某个字段是否缺失——如果该模型发现了强烈且可解释的结构，那么MAR假设看起来更可信，标准的填补方法就是合理的；如果几乎没有发现结构，那么缺失情况的表现更接近MCAR，风险相对较低；而如果关键协变量本身也存在大量缺失，那就是一个值得在构建任何下游内容之前先提出来的警示信号。 Small difficulty, mostly a diagnostic script rather than a new model. 难度较小，主要是一个诊断脚本，而不是一个全新的模型。
