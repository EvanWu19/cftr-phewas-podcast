Beyond Missingness: Systematizing Methods for Comprehensive Data Fitness Assessment in Clinical Research

A 2026 JMIR paper from Hanieh Razzaghi, Michael Kahn (yes, the Kahn-framework Kahn), and a large multi-network author list, proposing a formal model for study-specific data quality assessment (SSDQA) — the layer of data-quality checking that sits above generic network-wide checks (is a field populated, are codes mapped) and actually tests whether a dataset supports a specific study's clinical question. The model defines any "check type" through four components — clinical goal, check category (reusing Kahn-framework dimensions like completeness/plausibility/conformance), data quality probe, and analysis level — and catalogs 18 such check types across six families, several of which transfer directly to anthropometric QC: quantitative variable distributions, date sequencing, and patient record consistency. The paper's own worked example (a hypothetical pediatric sickle cell disease cohort) is explicitly illustrative, not a systematic evaluation — no sensitivity/specificity, no gold standard, and by the authors' own admission the model currently covers structured data only. Pipeline stage: primarily (e) vocabulary/framework, with a secondary (a) candidate-generation touch via the directly-transferable check types. Paired today with ep4 as framework-for-specifying-checks vs. can-AI-just-extract-the-data-cleanly.

Plain-English glossary

  • Analysis level — one of the four components defining a check type: whether a check runs at the person, visit, or event level.（中文:定义检查类型的四要素之一:检查是在患者层级、就诊层级还是事件层级上运行。）
  • Check category — the data-quality dimension a check measures, reusing Kahn-framework terms like completeness, plausibility, and conformance.（中文:检查所测量的数据质量维度,沿用Kahn框架中完整性、合理性、一致性等术语。）
  • Data quality probe — the data-centric purpose of a check (e.g. misclassification, missing expected data, temporal inconsistency), distinct from the clinical goal it serves.（中文:检查的数据中心目的（如误分类、预期数据缺失、时间不一致),区别于它所服务的临床目标。）
  • Data quality modules — the paper's proposed common code base per check type, taking user-configured parameters so the same check type is reusable across studies without reimplementation.（中文:论文提出的、每种检查类型对应一个通用代码库的概念,接受用户配置参数,使同一检查类型可在不同研究间复用而不必重新实现。）
  • Kahn framework — the harmonized data-quality-dimension vocabulary (completeness, plausibility, conformance) this paper extends rather than replaces.（中文:本文所扩展（而非取代)的、关于数据质量维度（完整性、合理性、一致性)的统一规范词汇。）
  • SSDQA (study-specific data quality assessment) — data-quality testing tailored to whether a dataset supports one specific study's clinical question, as distinct from generic network-wide data quality checks.（中文:针对数据集是否支持某一具体研究的临床问题而定制的数据质量检验,区别于通用的网络层面数据质量检查。）

Methods / tools to lift

  • Four-component check-type taxonomy (clinical goal / check category / data quality probe / analysis level) — a reusable vocabulary for specifying any data-quality check.
  • 18-check-type catalog across six families (cohort identification, cohort fitness, dataset fitness, data conformance, variable testing, concept-set testing) — several directly anthropometric-transferable.
  • Data quality modules (conceptual, code referenced via PEDSpace) — common-code-base pattern for making a check type reusable across studies without reimplementation.
  • Three application decision points — single- vs multi-unit, exploratory vs formal anomaly detection, longitudinal vs cross-sectional — a checklist for how any one check type gets deployed.

Where it lands + buildable artifact

Pipeline stage: primarily (e) nothing directly flagged, but supplies vocabulary/framework; secondary (a) candidate generation, via check types (quantitative variable distributions, date sequencing, patient record consistency) that transfer directly to anthropometric checks without modification.

Buildable artifact (S-M): Check-Type Card Generator — for every anthropometric/registry-QC method already in this project's catalog, fill in the four-component template (clinical goal / check category / probe / analysis level) so the growing catalog becomes searchable and comparable by the same four fields rather than by free-text description alone.

What to verify first

  • Whether these 18 check types, designed and demonstrated against a general pediatric multi-site network use case, map cleanly onto anthropometric-specific checks without modification, or whether growth trajectories need a genuinely new check type of their own.
  • Whether the "data quality modules" code repository referenced via a PEDSpace URL is actually usable today versus a placeholder reference.
  • Nothing here characterizes what the registry's own current cleaning rules check for or how its existing flag rate breaks down — that comparison belongs to CFF's own data team, not to this paper or this podcast.

Error types covered / not covered

Covered (via transferable check types, not anthropometric-specific in the paper itself): implausible/out-of-order dates (date sequencing), anomalous values relative to a variable's own distribution (quantitative variable distributions), internal logical inconsistency within a patient's record (patient record consistency). Not covered: unit conversion errors, digit transposition, decimal-shift errors, carry-forward values, or distinguishing a data-entry error from a genuine clinical event — none of these are addressed by this paper, which operates one level of abstraction above specific error types.
