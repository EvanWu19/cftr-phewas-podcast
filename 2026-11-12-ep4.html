Ep4 (Track C — registry QC, slot 2/2): DQe-v — an interactive tool for exploring cross-site and cross-time EHR variability

Estiri and colleagues (EGEMS, 2017) build DQe-v, an open-source R/Shiny tool for visually exploring whether cross-site and cross-time variability in EHR data reflects a data quality error or a real difference between populations and practice patterns. Built on a minimal location/time/condition aggregation model with population, patient, and prevalence counts, it offers four tabs: an overall box-and-scatter preview, an interactive exploratory-analysis tab highlighting high-dispersion time units via IQR and standard-deviation ratios, smoothed density plots, and a regression-based tab that flags anomalies where two user-chosen polynomial regression models agree. There is no formal sensitivity, specificity, or gold-standard validation anywhere in the paper — it is explicitly a human-facing exploratory framework, not an automated classifier. The buildable artifact is a Site/Time Variability Explorer built over already-flagged candidate aggregates, to help an adjudicator judge whether an unusual site-year combination looks systematically different before committing a specific record to human review.

Plain-English glossary

  • Variability (EHR data quality sense) — The extent of data dispersion, in value and meaning, relative to a similar group of observations; may reflect a real population/practice difference or a data quality error.（中文：数据在数值和含义上相对于一组类似观测值的离散程度；可能反映真实的人群/诊疗差异，也可能反映数据质量错误。）
  • Temporal / atemporal plausibility — Kahn framework sub-dimensions: whether time-varying values change as expected over time, and whether observed values/distributions agree with local knowledge or other measurements of the same fact.（中文：Kahn框架的子维度：随时间变化的数值是否按预期方式改变，以及观测到的数值/分布是否与本地知识或同一事实的其他测量结果相吻合。）
  • ETL (extraction-transformation-loading) — The data pipeline process of pulling data from source systems, converting its format, and loading it into a target database or warehouse.（中文：从源系统中提取数据、转换格式、再加载进目标数据库或数据仓库的数据处理流程。）
  • DARTNet — The Distributed Ambulatory Research in Therapeutics Network, a support organization for practice-based research networks across the US.（中文：一个为美国各地基层诊疗研究网络提供支持的分布式研究网络支持机构。）
  • OHDSI / ACHILLES — OHDSI is an international collaborative network built around the OMOP common data model; ACHILLES is its own tool for visualizing OMOP-standardized data, which DQe-v positions itself as complementing by being database-agnostic.（中文：OHDSI是一个围绕OMOP通用数据模型开展观察性健康数据研究的国际协作网络；ACHILLES是其用于可视化OMOP标准化数据的工具，DQe-v把自己定位为对其的补充，因为它不依赖任何特定数据模型。）

Full citation

Estiri H, et al. "DQe-v: A Database-Agnostic Framework for Exploring Variability in Electronic Health Record Data Across Time and Site Location." EGEMS (Washington, DC). 2017. PMID: 29930954 | PMCID: PMC5994933 | DOI: 10.13063/2327-9214.1277

Methods / tools to lift

  • Minimal location × time × condition aggregation model — a database-agnostic input schema (population/patient/prevalence counts) that lets any EHR system feed a common exploratory tool.
  • Dual dispersion-index highlighting (IQR ratio, SD ratio) — letting a user interactively flag time units with unusually high relative dispersion on two independent indices at once.
  • Dual-polynomial-degree consensus flagging — a lightweight robustness heuristic: flag as higher-confidence only the anomalies two differently-smoothed regression models agree on.

Where it lands + buildable artifact

Pipeline stage: (b) adjudication, primary (helping a human judge noise vs. signal); (d) evaluation, secondary (a general exploratory framework, not a specific metric). Buildable artifact — Site/Time Variability Explorer: a small interactive dashboard (R/Shiny or Python/Streamlit) over aggregates of already-flagged candidate records sliced by site and encounter-year, showing distribution shifts to help an adjudicator decide whether a site-year combination looks systematically different before committing a flagged record to human review. Difficulty: M (medium).

What to verify first

  • Whether site-by-encounter-year slices would have enough volume per cell for a box plot or density plot to be meaningful — an open question about the registry's own data distribution.
  • Whether the arbitrary dual-polynomial-degree heuristic should be replaced with a more principled smoothing reference, such as reusing the residual structure of whatever spline-based model already does primary flagging — untested here and needing its own validation.
  • Whether observed site/time variability in raw anthropometric z-scores reflects a shifting population age-mix or modulator-era weight-trajectory effects rather than a measurement or entry error — a distinction this 2017, pre-growth-reference-aware tool cannot separate on its own.

Pipeline stage

(b) adjudication, primary; (d) evaluation, secondary.

Error types covered / not covered

Covered: cross-site and cross-time dispersion and distributional-shape shifts, surfaced for human interpretation as either signal or noise. Not covered: unit conversion, digit transposition, decimal-shift, or carry-forward errors at the individual-record level, and no automated discrimination between a data-entry error and a real clinical or population event — the tool explicitly leaves that judgment to the human viewer.
