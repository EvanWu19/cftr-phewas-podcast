Blurb

Lighterness, Adcock, Scanlon, and Price (JMIR, 2024) systematically review 39 studies (1945–2023) that both measured and demonstrably tried to improve the quality of structured EHR-derived real-world data, standardizing terminology across them with the DAMA six-dimension framework (completeness, uniqueness, timeliness, consistency, validity, accuracy). They find only 6 of 39 studies used any named DQ framework at all (split between Weiskopf & Weng and Kahn), assessment was largely manual and targeted completeness plus one other dimension, and interventions skewed heavily upstream — DQ reporting/feedback (61%), IT solutions (54%), training (44%) — versus just 8% (3/39) using actual data cleaning. Only one study used a randomized design, and heterogeneity precluded meta-analysis. It's a review of the field, not a method: it supplies the DAMA vocabulary and a real, open tension — review-budget-shrinking tools versus upstream-prevention investment — worth weighing against any registry QC roadmap, without asserting what CFFPR should prioritize.

Plain-English glossary

  • Accuracy (DAMA) — Agreement of the data with a reference or gold standard.（中文:DAMA维度之一,指数据与参考标准或金标准的吻合程度。）
  • Completeness (DAMA) — The presence of the expected data (absence of missingness).（中文:DAMA维度之一,指预期数据是否存在(即是否缺失)。）
  • Consistency (DAMA) — Agreement between multiple sources recording the same data element.（中文:DAMA维度之一,指记录同一数据元素的多个来源之间是否一致。）
  • DAMA framework — The Data Management Association's six core data-quality dimensions (completeness, uniqueness, timeliness, consistency, validity, accuracy), used here to standardize terminology across studies that each used inconsistent language.（中文:数据管理协会提出的六个核心数据质量维度(完整性、唯一性、及时性、一致性、有效性、准确性),本文用它来统一各研究中各不相同的术语。）
  • DMAIC — Define-Measure-Analyze-Improve-Control, a quantitative, statistically rigorous quality-improvement cycle from manufacturing (Motorola).（中文:定义-测量-分析-改进-控制,一种源自制造业(摩托罗拉)的定量、统计严谨的质量改进循环。）
  • PDSA — Plan-Do-Study-Act, a qualitative, flexible quality-improvement cycle well suited to adapting small changes in health care settings.（中文:计划-执行-研究-行动,一种定性、灵活的质量改进循环,适合在医疗场景中测试并调整小规模改动。）
  • Root-cause analysis (Odigos framework) — Classifies the origin of a DQ problem as material world (hardware/infrastructure), personal world (staff behavior), or societal world (job roles/norms), to fix the cause rather than just the symptom.（中文:Odigos框架把数据质量问题的根源分为物质世界(硬件/基础设施)、个人世界(员工行为)或社会世界(岗位角色/规范),目的是修复根本原因而不只是表面症状。）
  • TDQM — Total Data Quality Management, adapting the define-measure-analyze-improve logic specifically to treating data as a product needing quality management.（中文:全面数据质量管理,把"定义-测量-分析-改进"的逻辑专门用于把数据当作需要质量管理的产品来对待。）
  • Timeliness (DAMA) — How current or fresh the data is relative to the event it describes.（中文:DAMA维度之一,指数据相对于其所描述事件的新鲜或及时程度。）
  • Uniqueness (DAMA) — Absence of unexpected duplication of records, objects, or values.（中文:DAMA维度之一,指记录、对象或数值不存在意料之外的重复。）
  • Validity (DAMA) — Conformance of data to expected ranges, patterns, formats, or standards.（中文:DAMA维度之一,指数据是否符合预期的范围、模式、格式或标准。）

Methods/tools to lift

  • DAMA six-dimension framework — a standardized vocabulary for classifying what any given DQ check or intervention actually addresses.
  • PDSA / DMAIC / TDQM comparison — three named quality-improvement cycles, useful as a menu for structuring a DQ-improvement effort rather than running it ad hoc.
  • Odigos root-cause taxonomy — classifies DQ problem origins as material/personal/societal world, useful for diagnosing why an error pattern recurs, not just that it does.

Where it lands + buildable artifact

Buildable artifact: DAMA-dimension × intervention-type scorecard. MVP — tag each existing qc_methods_catalog.md entry against which DAMA dimension(s) it addresses, which QI-cycle stage it would plug into, and whether it's upstream-prevention or downstream-cleaning — a cheap tagging pass to check whether the accumulating catalog skews toward one type. Difficulty: Small (tagging an existing catalog, not new analysis).

What to verify first

  • Whether the 39-study sample, filtered for a demonstrated improvement intervention, is representative of the broader DQ literature or systematically excludes good assessment-only work.
  • Whether the 8% data-cleaning figure reflects a genuine field-wide preference for upstream fixes, or just reflects which studies are easiest to publish.
  • Whether the Odigos root-cause framework, built for general health-data contexts, needs adaptation for registry-specific anthropometric error causes (e.g., clinic-visit transcription versus legacy-migration unit confusion).
  • Note: none of this is a claim about CFFPR's current cleaning rules or improvement priorities.

Pipeline stage

(e) Vocabulary/framework, primary — with a secondary, loose touch on (c) human-review budget, via the open tension between review-budget-shrinking tools and upstream-prevention investment that the 8%-cleaning finding raises.

Error types covered / not covered

This is a review of improvement interventions, not a detector, so it names no specific anthropometric error type (no unit-swap, decimal-shift, or transcription-error detection of its own). It does supply a framework for classifying what kind of fix any given error-detection or correction method represents (upstream prevention vs. downstream cleaning vs. a specific DAMA dimension), which is useful for categorizing other methods in this catalog rather than for detecting errors itself.
