How did this episode land for you?

Ep3 (Track C 1/2 — registry QC): FIDDLE — a flexible data-driven preprocessing pipeline

Tang et al.'s 2020 JAMIA paper introduces FIDDLE (Flexible Data-Driven Pipeline), an open-source tool that doesn't flag outliers itself but solves the problem underneath any such flagger: turning messy, irregularly-sampled structured EHR data into feature vectors a downstream model can actually use. The paper's motivating observation is that two groups predicting the same outcome from the same database made wildly different, unstandardized preprocessing choices — different variable counts, different imputation strategies — making cross-study comparison unreliable. FIDDLE's four-step pipeline (pre-filter, transform, discretize, post-filter) classifies variables as time-invariant or time-dependent, and time-dependent variables as frequent or non-frequent, encoding frequent variables with a value/mask/delta-time-plus-summary-statistics scheme designed explicitly around the idea that EHR missingness is informative, not random. Applied to MIMIC-III and eICU across five ICU prediction tasks, FIDDLE matched the discriminative performance of the hand-curated MIMIC-Extract pipeline while running far faster and porting directly to a second database MIMIC-Extract's design couldn't reach. The episode maps this onto the CFFPR anthropometric pipeline as a candidate-generation substrate: the value/mask/delta-time encoding is a cheap way to preserve exactly the missingness and measurement-staleness signal a spline or mixed-effects flagger needs. One important terminology caution raised on-air: FIDDLE's "carry-forward imputation" (a missing-data-filling technique) is unrelated to the "carry-forward error" growth-chart cleaning algorithms flag (a data-entry artifact).

Plain-English glossary

Carry-forward imputation (FIDDLE's sense) — Filling a missing time-bin with the last known real measurement; a standard missing-data technique, distinct from the "carry-forward error" data-entry artifact that anthropometric cleaning algorithms flag.（中文：用上一次真实测量值填补缺失的时间段，是一种标准的缺失数据处理技术，与人体测量清洗算法所标记的"前向携带错误"数据录入伪影是不同的概念。）

Delta-time — A feature recording how long it has been since a variable's last real (non-imputed) measurement.（中文：记录距某变量上次真实（非插补）测量过去了多久的特征。）

Fiducial marker — A reference time point (e.g., hospital admission) that all timestamps in a patient's record are measured relative to, so "t=0" is consistent across patients.（中文：一个参照时间点（如入院时间），患者记录中所有时间戳都相对它计量，使"t=0"在不同患者之间保持一致。）

Frequent / non-frequent variable — FIDDLE's data-driven classification of time-dependent variables by how often they're actually recorded on average; frequent variables get a richer value/mask/delta-time encoding.（中文：FIDDLE根据平均实际记录频率，对时变变量所做的数据驱动分类；高频变量会获得更丰富的数值/掩码/delta-time编码。）

Mask (missingness mask) — A binary feature indicating whether a value in a given time bin was actually measured or imputed.（中文：一个二元特征，指示某时间段内的值是真实测得的还是插补出来的。）

Missing not at random (MNAR) — The assumption that the fact a value wasn't recorded is itself informative, rather than happening independently of the underlying clinical state.（中文：假设某个值未被记录这件事本身具有信息量，而不是独立于潜在临床状态随机发生的。）

Time-invariant / time-dependent variable — FIDDLE's split between variables recorded once with no timestamp (e.g., age, sex) and variables recorded repeatedly over the observation window (e.g., vital signs, labs).（中文：FIDDLE对变量的划分——前者只记录一次、没有时间戳（如年龄、性别），后者在观察窗口内反复记录（如生命体征、检验值）。）

Methods / tools to lift

  • FIDDLE pipeline — pre-filter / transform / discretize / post-filter, open source, data-driven EHR-to-feature-vector conversion.
  • Value/mask/delta-time encoding — the specific representation for frequent time-dependent variables, designed around MNAR missingness.
  • Data-driven frequent/non-frequent variable classification — automatically recovers a clinically sensible "important variable" set (demonstrated: 6 vital signs) without hand-curation.

Where it lands + buildable artifact

Pipeline stage: (a) candidate generation, primary — supplies the feature representation any anthropometric flagger would run on top of; (e) framework/vocabulary, secondary — the frequent/non-frequent split and explicit MNAR framing are reusable concepts.

Error types covered / not covered: FIDDLE does not itself detect errors of any kind — it is strictly upstream of detection. It covers none of: unit conversion, digit transposition, decimal shift, carry-forward error (the data-entry artifact), or real-clinical-event confusion.

Buildable artifact: FIDDLE-Style Value/Mask/Delta-Time Feature Builder for Anthropometric Series — encode a height/weight measurement stream as value, presence mask, and time-since-last-real-measurement plus rolling summary statistics, as a reusable feature layer for any downstream spline, mixed-effects, or anomaly-detection model. Rough difficulty: S-M.

What to verify first

  • Keep FIDDLE's "carry-forward imputation" (missing-data filling) strictly distinct from the "carry-forward error" (data-entry artifact) that anthropometric cleaning algorithms flag — same term, two unrelated meanings.
  • Check whether FIDDLE's default thresholds and frequent/non-frequent classification, tuned on ICU vitals recorded many times an hour, make sense at the much sparser clinic-visit time scale of anthropometric registry data.
  • Remember this paper reports no outlier-detection performance at all — its AUROCs are for downstream ICU clinical-outcome prediction, not for any flagging task.
