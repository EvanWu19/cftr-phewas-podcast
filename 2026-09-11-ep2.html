Ep2 (Track B) — LLMs for Converting Trial Criteria to OMOP CDM Queries

Lee and colleagues (2025, JMIR Medical Informatics) build a three-module pipeline — preprocessing (segmentation/filtering/simplification, 58.2% token reduction), information extraction (seven structured elements, GPT-4-based OMOP concept mapping), and SQL generation — that converts free-text clinical trial eligibility criteria into OMOP CDM-compliant SQL. Their real contribution is the systematic hallucination audit that follows: 760 SQL-generation attempts across 19 trials, 8 LLMs, and 5 prompting strategies against the synthetic SynPUF dataset, scored with a five-category severity schema. GPT-4 beats USAGI on concept mapping (48.5% vs. 32.0%, P<.001) but the open-source llama3:8b beats GPT-4 on effective SQL rate (75.8% vs. 45.3%) because of a much lower hallucination rate (21.1% vs. 33.7%). Overall hallucination rate across all models: 32.7%. Clinical validation against real N3C reference cohorts is the most sobering number — Jaccard concordance ranges from 0.81 (type 1 diabetes) down to 0.03 (type 2 diabetes) and 0.00 (pregnancy), despite the pipeline reporting perfect overlap coefficients in both diabetes cases. Ships full pipeline and hallucination-detection code on GitHub. Serves AI-tooling/career positioning: the buildable artifact is a standalone hallucination-classification harness built on the paper's own five-category severity schema, reusable against any auto-generated OMOP SQL or concept-mapping output.

Plain-English glossary

  • OMOP CDM (Observational Medical Outcomes Partnership Common Data Model) — a standard table structure plus standard vocabulary that different health systems map their data into, so the same analysis code runs unchanged across sources.（中文:一套标准表结构加标准词汇体系,不同医疗系统把数据映射进去后,同一套分析代码就能在不同来源上直接运行。）
  • Standard vocabularies (SNOMED CT, ICD-10, RxNorm, LOINC) — the coding systems underneath OMOP CDM for clinical concepts, diagnoses, drugs, and lab tests respectively; a "concept" is a fixed numeric ID in one of these, not free text.（中文:OMOP CDM底层的编码体系,分别用于临床概念、诊断、药物和化验项目;"概念"是这些体系里固定的数字编号,不是自由文本。）
  • USAGI — an OHDSI-built semi-automated tool that suggests standard-concept mappings for free-text source terms; the baseline this paper's LLM pipeline is compared against.（中文:OHDSI团队开发的半自动概念映射工具,为自由文本术语建议标准概念映射,是本文大语言模型流程的对比基线。）
  • Concept mapping — resolving a free-text clinical phrase (e.g. "type 2 diabetes") to the one correct standard concept ID in an OMOP vocabulary.（中文:把自由文本的临床短语解析成OMOP词汇体系里唯一正确的标准概念编号。）
  • Feasibility assessment — estimating, before a trial opens, how many real patients in a given database would qualify under its eligibility criteria.（中文:在试验开始前,估算某数据库中有多少真实患者符合其入组标准。）
  • SynPUF (Synthetic Public Use Files) — a fully synthetic, publicly released OMOP-formatted dataset from CMS, built so pipelines can be tested without touching real patient data.（中文:美国医疗保险和医疗补助服务中心发布的完全合成、OMOP格式公开数据集,供在不接触真实患者数据的情况下测试流程使用。）
  • N3C (National COVID Cohort Collaborative) — a real multi-site OMOP-based research network whose reference concept sets were used as ground truth for clinical cohort validation here.（中文:一个真实的多机构OMOP研究网络,本文用其参考概念集作为临床队列验证的真值标准。）
  • Hallucination (in this pipeline) — an LLM-generated SQL element that is wrong in a specific, classifiable way: nonexistent concept ID, wrong-domain assignment, natural language in a concept field, placeholder value, or syntax error.（中文:大语言模型生成的SQL元素以某种可分类方式出错:不存在的概念编号、错误域分配、概念字段中混入自然语言、占位符数值,或语法错误。）
  • Jaccard concordance — a set-overlap metric comparing a pipeline-generated cohort against a reference cohort (not re-explained on air — assumed known as a concept, values reported here range from 0.00 to 0.81).（中文:比较流程生成队列与参考队列重叠程度的集合相似度指标,本文报告的数值范围为0.00到0.81。）

Methods / tools to lift

  • Three-stage preprocessing (segmentation/filtration/simplification) — cuts eligibility-criteria token count 58.2% before any LLM call, preserving Boolean structure and dropping non-queryable items.
  • Five-category hallucination severity schema (A critical / B, C major / D moderate / E minor) — a reusable taxonomy for auditing any auto-generated OMOP SQL or concept mapping.
  • Public GitHub repo (github.com/sujeong-jang/ctos) — full pipeline plus hallucination-detection code, including concept-ID-existence and domain-appropriateness checks against CDM specs.
  • Prompt-strategy comparison (zero-shot / few-shot / error-aware / explicit-uncertainty) — a tested set of prompting approaches with no single universal winner across models.

Where it lands + buildable artifact

Serves AI-tooling / career positioning. MVP: implement the paper's five-category hallucination severity schema as a standalone validator — input a batch of LLM-generated OMOP SQL/concept-mapping output plus target OMOP vocabulary tables, output a per-query severity-tagged report (concept-ID existence, domain match, field-type validity) instead of an opaque pass/fail. Realistic first step: read and adapt the hallucination-detection module already in the paper's public repo rather than starting from scratch. Difficulty: S.

What to verify first

  • Study covered only three disease areas (breast cancer, diabetes, cardiovascular disease); rare disease, pediatric populations, and biomarker-driven studies were explicitly not tested.
  • Vague, physician-interpreted phrasing (their example: "significant cardiac disease") gets overgeneralized or loses temporal qualifiers — a known failure mode for any clinically-interpreted, non-standardized language.
  • The llama3:8b advantage was measured against SynPUF's synthetic concept distribution; unclear whether it holds on a real, messier vocabulary with a different long tail of rare concepts.
  • The Jaccard collapse for type 2 diabetes/pregnancy despite reported perfect overlap coefficients shows a single aggregate metric can hide a cohort-defining failure — any adoption needs per-condition validation against a real reference cohort.
  • All reported accuracy/hallucination numbers are tied to a specific GPT-4 snapshot (March 2024), not to "GPT-4" as a stable long-term baseline.
