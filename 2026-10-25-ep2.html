Ep2 (Track B — AI tooling): Let the LLM write the regex, not run the extraction

Hwang and colleagues (2026, Sleep Advances) present PromptNLP, a two-step pipeline that uses a large language model exactly once, offline, to author a regex pattern library for extracting apnea-hypopnea index (AHI) and Epworth Sleepiness Scale (ESS) values from free-text sleep clinical notes — then runs that plain regex, not the LLM, as the actual production extraction engine. Across development at Kaiser Permanente Southern California and external validation at Beth Israel Deaconess Medical Center and Emory University, PromptNLP's "Targeted" regexes beat manually coded regex on recall (AHI 95–96% vs. 80.8%; ESS 98–100% vs. 88%) while holding 100% precision, and an iterative adaptation process recovered performance after each cross-site transfer. Applied at scale to 207,404 KPSC reports, the final regex matched structured AHI ground truth with 99.8% precision in a validation subset, at a fraction of manual development time (under 20 minutes vs. ~25 hours). The transfer serves Runyu's AI-tooling/career priority directly: an LLM-authored, regex-executed architecture is a reusable, auditable pattern for registry phenotyping tasks generally. Buildable artifact: an LLM-Authored Regex Phenotyping Kit.

Plain-English glossary

  • Apnea-hypopnea index (AHI) — the number of apnea and hypopnea breathing-disruption events per hour of sleep; the primary severity measure for obstructive sleep apnea.（中文：每小时睡眠中呼吸暂停和低通气事件的次数，是阻塞性睡眠呼吸暂停的主要严重程度指标。）
  • EHR phenotyping — turning unstructured narrative text in electronic health records into a reliable, structured variable that can be queried at scale.（中文：把电子健康记录中非结构化的叙述性文本，转化为一个可靠的、可大规模查询的结构化变量。）
  • Epworth Sleepiness Scale (ESS) — an eight-item self-reported questionnaire score from 0 to 24 quantifying daytime sleepiness.（中文：一份包含八个条目的自评问卷，得分范围0到24，用于量化日间嗜睡程度。）
  • Philter — an automated tool for removing protected health information (PHI) from clinical text.（中文：一种用于从临床文本中自动去除受保护健康信息（PHI）的工具。）
  • Target trial emulation (TTE) — a causal-inference design that specifies a hypothetical randomized trial and then emulates it as closely as possible using observational data.（中文：一种因果推断设计方法，先设定一个假想的随机对照试验，再尽可能用观察性数据去模拟该试验。）

Full citation

Hwang N, et al. "Large language model derived regular expressions for sleep phenotyping from electronic health record: a feasibility study." Sleep Advances. 2026. PMID: 42460030 | PMC13372092 | DOI: 10.1093/sleepadvances/zpag059

Methods / tools to lift

  • Two-step LLM-authors-regex pipeline — build a phrase library (manual "Targeted" or LLM-identified "General"), then prompt an LLM once to generate the regex code; production extraction runs as plain regex with no further LLM calls.
  • Precision/recall/F1 benchmarking against manually annotated ground truth — the validation framework used across all three phases (development, external validation, large-scale application).
  • Iterative cross-site adaptation — applying a prior site's regex to a new site's notes, then re-running the LLM-authoring step on the new site's phrase variations to recover performance.
  • SPELL (contrasting design) — a hybrid approach that runs regex first to locate relevant text snippets, then hands those snippets to an LLM for interpretation — the reverse order from PromptNLP, better suited to tasks requiring inference (negation, family-history exclusion) rather than explicit numeric extraction.

Where it lands + buildable artifact

Serves AI-tooling / career: an LLM-authored, regex-executed extraction architecture is a reusable registry-phenotyping pattern, independent of CF specifically. Tool sketch — LLM-Authored Regex Phenotyping Kit: pick a numerically explicit text-extraction task, assemble a small phrase library, prompt an LLM once to generate a regex library, validate against a held-out labeled sample with precision/recall/F1, and package the finalized regex as a standalone, no-ongoing-LLM-cost script.

What to verify first

  • Generalization beyond this paper's scope: all three sites were US-based, used Epic as their EHR system, and worked in English — performance on other EHR vendors, non-English notes, or different documentation conventions is unverified.
  • Regex's inherent brittleness to unseen phrasings and misspellings (the paper itself missed an extraction due to "residaul" vs. "residual") — any production deployment needs an ongoing edge-case-patching process, not a one-time build.
  • Which category a candidate field actually falls into — explicit numeric/categorical value (favors PromptNLP's design) vs. a judgment requiring inference like negation (favors a SPELL-style, LLM-at-the-end design) — before choosing an architecture.
  • The de-identification inconsistency flagged on-air: KPSC notes were only manually stripped of MRN/name/DOB before reaching a commercial web-based LLM interface, a lighter touch than the automated Philter tool used for BIDMC/Emory notes — a governance gap to close, not just note, before adopting this pattern under stricter data-handling requirements.

ALEX Today's paper is from Sleep Advances, 2026 — Hwang and colleagues, "Large language model derived regular expressions for sleep phenotyping from electronic health record: a feasibility study." 今天的论文发表在2026年的《Sleep Advances》上——作者是Hwang等人，题目是《基于大语言模型生成的正则表达式用于电子健康记录的睡眠表型提取：一项可行性研究》。 This is a Track B pick, and it ships real code on GitHub, which is exactly the kind of thing we prioritize for this track. 这是Track B的选题，而且它在GitHub上发布了真实可用的代码，这正是这条track优先选取的那类内容。 The idea, called PromptNLP, is almost perversely simple once you hear it: instead of asking an LLM to extract clinical values directly from free text every single time, use the LLM exactly once, offline, to author a regex pattern library — and then let that plain regex code, not the LLM, do the actual extraction at scale. 这个被称为PromptNLP的想法，一旦听明白之后，会觉得简单到近乎"反直觉"：不是每次都让大语言模型直接从自由文本中提取临床数值，而是只让大语言模型离线地、一次性地去撰写一套正则表达式（regex）模式库——然后让这套普通的regex代码本身，而不是大语言模型，去完成真正的大规模提取工作。 That's a lightweight, auditable alternative to black-box LLM extraction, and it's squarely in the career-target lane — registry phenotyping tooling that ships as inspectable code rather than an opaque model call. 这是一种轻量级、可审查的方案，用来替代黑箱式的大语言模型提取，而且它正好落在职业发展目标的方向上——以可检视代码的形式交付的注册登记表型提取工具，而不是一个不透明的模型调用。

JORDAN A couple of clinical-domain terms before the method. 在讲方法之前，先讲两个临床领域的术语。 This paper phenotypes two sleep metrics: the apnea-hypopnea index, or AHI (呼吸暂停低通气指数) — the number of apnea and hypopnea breathing-disruption events per hour of sleep, the primary severity measure for obstructive sleep apnea — and the Epworth Sleepiness Scale, or ESS (Epworth嗜睡量表) — an eight-item self-reported questionnaire score from 0 to 24 quantifying daytime sleepiness. 这篇论文提取的是两个睡眠相关指标：呼吸暂停低通气指数（apnea-hypopnea index，缩写AHI）——即每小时睡眠中呼吸暂停和低通气这类呼吸中断事件的次数，是阻塞性睡眠呼吸暂停的主要严重程度指标；以及Epworth嗜睡量表（Epworth Sleepiness Scale，缩写ESS）——一份包含八个条目的自评问卷，得分范围为0到24，用于量化日间嗜睡程度。 Both values routinely get buried in free-text clinical notes rather than captured as structured fields, which is exactly the "EHR phenotyping" problem: turning unstructured narrative text into a reliable, structured variable researchers can actually query at scale. 这两个数值通常都被埋没在自由文本的临床记录中，而不是以结构化字段的形式被记录下来，这正是"EHR表型提取（EHR phenotyping）"问题的核心：把非结构化的叙述性文本转化为一个可靠的结构化变量，供研究者能够在大规模数据上进行查询。 One more piece of vocabulary: a target trial emulation, or TTE (目标试验模拟) — a causal-inference design that specifies the hypothetical randomized trial you'd ideally run, then emulates it as closely as possible using observational data — is the downstream use case this whole extraction pipeline was built to feed. 还有一个术语：目标试验模拟（target trial emulation，缩写TTE）——一种因果推断设计方法，先明确设定一个理想情况下你会去开展的假想随机对照试验，然后尽可能用观察性数据去模拟该试验——这正是这整套提取流程所要服务的下游应用场景。

ALEX The motivating problem is familiar if you've ever maintained extraction rules across more than one site: manual regex is slow to build, brittle to format changes, and doesn't adapt when you move to a new institution with differently formatted notes, while asking an LLM to extract values directly, every time, at scale, raises real concerns about cost, hallucination, and exposing protected health information if it's not run in a secure, API-based environment. 如果你曾经在不止一个站点维护过提取规则，这个动机问题会很熟悉：手工编写的regex构建起来很慢，对格式变化很脆弱，换到一个笔记格式不同的新机构时也无法自动适应；而如果每次都让大语言模型直接大规模提取数值，又会带来真实的成本、幻觉（hallucination）风险，以及如果不是在安全的、基于API的环境中运行，还可能暴露受保护健康信息（protected health information）的问题。 PromptNLP's bet is to push the expensive, risky LLM step to a one-time development phase — author the regex once — and let the actual production extraction run as plain, local, inspectable code with no ongoing LLM calls and no ongoing exposure of patient notes to any model at all. 而PromptNLP的做法，是把昂贵且有风险的大语言模型这一步，推到一次性的开发阶段——只让它撰写一次regex——然后让真正的生产环境提取工作，以普通、本地、可检视的代码方式运行，不再需要持续调用大语言模型，也不再需要持续把患者笔记暴露给任何模型。 Data came from sleep-related clinical notes at three institutions — Kaiser Permanente Southern California, Beth Israel Deaconess Medical Center, and Emory University — chosen specifically because their note formats differ sharply: KPSC notes are largely templated sleep-study interpretations, while BIDMC and Emory notes are non-templated, free-text clinic narratives. 数据来自三家机构的睡眠相关临床记录——南加州凯撒医疗（Kaiser Permanente Southern California）、贝斯以色列女执事医疗中心（Beth Israel Deaconess Medical Center）和埃默里大学（Emory University）——之所以特意选择这三家，是因为它们的笔记格式差异很大：KPSC的笔记大多是模板化的睡眠检测报告，而BIDMC和Emory的笔记则是非模板化的自由文本门诊叙述。

JORDAN Walk me through the actual two-step process. 跟我说说这个两步流程具体是怎么做的。 Step one builds a "phrase library" capturing the different ways AHI and ESS values show up in text — done either "Targeted," by manually copying and pasting specific phrases like "AHI: 5" or "Epworth Sleepiness Scale is 5/24," or "General," by feeding whole sample reports to the LLM and letting it identify the relevant phrases itself. 第一步构建一个"phrase library（短语库）"，用来捕捉AHI和ESS的数值在文本中出现的各种不同写法——这一步可以是"Targeted（定向）"方式，即手动复制粘贴像"AHI: 5"或"Epworth Sleepiness Scale is 5/24"这样的具体短语；也可以是"General（通用）"方式，即把整份样本报告直接交给大语言模型，让它自己去识别相关短语。 Step two feeds that phrase library into an LLM with a structured prompt, asking it to generate the actual regex code — multiple patterns, each with a capturing group to pull out the AHI or ESS value. 第二步把这份短语库输入给大语言模型，并配上一个结构化的提示（prompt），要求它生成实际的regex代码——多个模式，每个模式都带有一个用于提取AHI或ESS数值的捕获组（capturing group）。 The study ran three phases: development at KPSC, comparing PromptNLP regexes from three different LLMs — ChatGPT-o3, Gemini 2.5 Pro, and Claude Sonnet 4 — against manually coded regex; external validation, iteratively adapting the KPSC-trained regex first to BIDMC notes and then to Emory notes; and large-scale application, running the final adapted regex against 207,404 KPSC reports. 这项研究分为三个阶段：在KPSC进行开发阶段，比较来自三种不同大语言模型——ChatGPT-o3、Gemini 2.5 Pro和Claude Sonnet 4——生成的PromptNLP regex与手工编写regex的表现；外部验证阶段，将在KPSC上训练出的regex依次迭代适配到BIDMC笔记、再到Emory笔记；以及大规模应用阶段，将最终适配好的regex运用到207404份KPSC报告上。

ALEX One design choice is worth pushing on before the numbers. 在看具体数字之前，有一个设计选择值得追问一下。 The LLMs used for regex authoring were commercial, web-based chat versions, not private API deployments — and while the KPSC sample reports were manually de-identified first, that de-identification only removed medical record numbers, names, and dates of birth, which is a noticeably lighter touch than Philter, the automated PHI-removal tool used for the BIDMC and Emory notes. 用于regex撰写的大语言模型，是商业的、基于网页的聊天版本，而不是私有的API部署——尽管KPSC的样本报告在使用前经过了人工去标识化处理，但这一去标识化仅去除了医疗记录号、姓名和出生日期，相比用于BIDMC和Emory笔记的自动化PHI去除工具Philter而言，这种处理明显更为轻量。 That's a real inconsistency in de-identification rigor across sites feeding the exact same consumer-facing LLM interface, and it's the kind of governance gap that would need to be closed, not just noted, before adopting this pattern anywhere with stricter data-handling requirements. 这是一个真实存在的不一致之处——不同站点在送入同一个面向消费者的大语言模型界面之前，所采用的去标识化严谨程度并不一致——在任何有更严格数据处理要求的环境中采用这种模式之前，这类治理上的缺口需要被真正弥合，而不仅仅是被记录在案。

JORDAN So, numbers. 那么，来看数字。 In the development phase at KPSC, PromptNLP's "Targeted" regexes beat manual regex clearly on recall — 95 to 96% for AHI versus 80.8% manual, and 98 to 100% for ESS versus 88% manual — while achieving 100% precision across every PromptNLP regex tested, meaning performance differences came almost entirely from recall, not false positives. 在KPSC的开发阶段，PromptNLP的"Targeted"版regex在召回率（recall）上明显优于手工regex——AHI方面为95%到96%，而手工为80.8%；ESS方面为98%到100%，而手工为88%——同时所有被测试的PromptNLP regex都达到了100%的精确率（precision），这意味着性能差异几乎全部来自召回率，而不是假阳性。 The "General" approach also beat manual but trailed "Targeted," likely limited by each LLM's context window when scanning whole sample reports for phrases. "General"方式也优于手工方案，但落后于"Targeted"方式，这很可能是因为各个大语言模型在扫描整份样本报告以寻找短语时，受到了自身上下文窗口（context window）的限制。 In external validation, directly transferring the KPSC-trained regex to BIDMC's unfamiliar, non-templated notes crashed performance to 30%/12% recall for AHI/ESS — but PromptNLP's update process recovered it to 96%/84% after adaptation, and the same pattern held moving to Emory, improving from 85%/86% to 94%/89% after a further adaptation round, all while holding 100% precision throughout both phases. 在外部验证阶段，把在KPSC上训练出的regex直接迁移到BIDMC那些陌生、非模板化的笔记上，表现骤降至AHI/ESS召回率30%/12%——但经过PromptNLP的更新流程适配后，恢复到了96%/84%；迁移到Emory时也出现了同样的模式，经过进一步适配后，由85%/86%提升到94%/89%，而整个两个阶段始终保持着100%的精确率。

ALEX The large-scale application result is the one that matters most for anyone thinking about registry-scale deployment. 对于任何考虑在注册登记（registry）规模上部署此方法的人来说，大规模应用阶段的结果才是最重要的。 Applied to 207,404 KPSC reports, the final adapted regex extracted AHI from 8,231 of 8,602 notes (95.7%) that had a matched structured AHI value, and 8,216 of those 8,231 extractions (99.8%) matched the structured ground truth exactly — the fifteen misses traced back to a specific, now-corrected labeling bug where CPAP-trial data got mislabeled as a diagnostic study. 在应用于207404份KPSC报告时，最终适配好的regex从8602份带有匹配结构化AHI数值的笔记中，成功提取了8231份（95.7%）的AHI数值，其中8231份提取结果中有8216份（99.8%）与结构化真实值完全一致——另外15处未命中的情况，可追溯到一个特定的、如今已被修正的标签错误：持续气道正压（CPAP）试验数据被错误地标记为了诊断性检测。 ESS was extracted from 6,808 of those 8,602 notes (79.1%), and manual chart review of 500 extracted plus 100 non-extracted notes confirmed 100% positive and negative predictive value, after removing three correct-but-out-of-range extractions like "ESS is 624" being misread from "6/24." ESS数值从这8602份笔记中的6808份（79.1%）被提取出来，对500份已提取结果和100份未提取笔记的人工图表审查，证实了100%的阳性预测值和阴性预测值，不过需要剔除三个"提取正确但数值超出合理范围"的情况，例如把"6/24"误读成了"ESS is 624"。 Development time for the KPSC regex, by the authors' own estimate, dropped from roughly 25 hours manually to under 20 minutes with PromptNLP, and across the full 207,404-report corpus, applying the target trial's AHI-15-plus and ESS-under-16 inclusion criteria identified 41,359 potential trial participants. 根据作者自己的估算，KPSC版regex的开发时间，从手工编写大约25小时，缩短到使用PromptNLP不到20分钟；而在整个207404份报告的语料库中，应用该目标试验的"AHI≥15且ESS<16"纳入标准，识别出了41359名潜在的受试者。

ALEX One more results detail worth having, since it bears directly on which LLM to reach for if anyone builds on this: among the Targeted regexes, the three LLMs performed comparably, with ChatGPT-o3 edging out Gemini 2.5 Pro and Claude Sonnet 4 without the gap reaching statistical significance, but among the weaker "General" regexes, the two high-reasoning models, ChatGPT-o3 and Gemini 2.5 Pro, clearly outperformed Claude Sonnet 4's hybrid-reasoning mode on both AHI and ESS recall. 还有一个结果细节值得记住，因为它直接关系到如果有人要在此基础上继续构建，应该选用哪个大语言模型：在"Targeted"版regex中，三个大语言模型表现相当，ChatGPT-o3略微领先于Gemini 2.5 Pro和Claude Sonnet 4，但差距未达到统计学显著；而在表现较弱的"General"版regex中，两个高推理模型——ChatGPT-o3和Gemini 2.5 Pro——在AHI和ESS的召回率上都明显优于处于混合推理模式的Claude Sonnet 4。 The authors attribute the General approach's weaker showing overall to each model's context-window limits when it has to scan whole sample reports itself to find relevant phrases, rather than being handed a pre-curated phrase list the way the Targeted approach works. 作者将"General"方式整体表现较弱的原因，归结为每个模型在需要自行扫描整份样本报告以寻找相关短语时所受到的上下文窗口限制，而不是像"Targeted"方式那样，直接获得一份已经整理好的短语清单。 They also flagged a subtler issue worth remembering: running the identical Targeted and General prompts three separate times on identical source notes produced slightly different regex code each time, though performance stayed broadly stable across those runs — a reminder that LLM-authored code, even when the downstream execution is deterministic regex, still inherits some of the model's own non-determinism at generation time. 他们还提出了一个更细微、但值得记住的问题：在完全相同的源笔记上，分别三次运行完全相同的Targeted和General提示，每次生成的regex代码都略有不同，尽管这几次运行的表现总体保持稳定——这提醒我们，即便下游执行的是确定性的regex，由大语言模型撰写的代码本身，在生成阶段仍然继承了模型自身的一部分不确定性。

JORDAN Where does this land for the AI-tooling, career-target priority specifically? 这对AI工具开发、职业发展这条优先事项具体意味着什么?
