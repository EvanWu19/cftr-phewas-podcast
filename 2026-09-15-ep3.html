Ep3 (Track C, paper 1 of 2) — lab2clean: automated cleaning of retrospective clinical laboratory results data

Blurb. Laboratory results make up an estimated 70% of EMR data by volume, but LOINC and similar standards fix only which test was done, not how the result is formatted — leaving huge variability across labs. lab2clean ships two R functions splitting cleaning into conformance (clean_lab_result: regex-based cleaning, LOINC-aligned categorization, format standardization across 19 languages) and plausibility (validate_lab_result: duplicate flagging, reportable-limit checks, four logic-consistency rules, and a temporal delta check comparing successive same-test values). Evaluated on 218M records from the multicentric Flemish INTEGO primary-care network (94.5% of records standardized in under 5 minutes) and 100.87M quantitative records from MIMIC-IV ICU data (0.406% flagged in under 2 hours, 81% of flags being duplicates, 18% delta-check violations, logic/reportable-limit violations near zero). No comparison to other tools was possible (none existed) and no human-adjudicated ground truth was used to validate flag rates. The directly transplantable piece for a CFFPR-style height/weight pipeline is the delta-check architecture itself — a parameterized successive-measurement comparison — as a candidate-generation complement to a spline/mixed-effects growth model, plus the conformance-vs-plausibility vocabulary split.

Plain-English glossary

  • Conformance (data quality dimension) — whether data matches an established internal or external formatting standard.（中文：合规性——数据是否符合既定的内部或外部格式标准。）
  • Plausibility (data quality dimension) — whether a value is credible given context; atemporal (the value alone or vs. another variable) or temporal (whether a sequence over time makes sense).（中文：合理性——在给定情境下数值是否可信；分为非时序合理性（数值本身或与另一变量对比）和时序合理性（一段时间内的数值序列是否合理）。）
  • LOINC (Logical Observation Identifiers Names and Codes) — the standard vocabulary for lab tests and measurements; defines scale types (Quantitative, Ordinal, Nominal) but not result-value formatting.（中文：实验室检验与测量的标准词汇表，定义量表类型——定量、序数、名义——但不规定结果数值的格式。）
  • Delta check — a temporal-plausibility check comparing a patient's current value against their own prior value for the same test, flagging an implausibly large change over a given time interval.（中文：delta检测——一种时序合理性检测，将患者当前数值与其此前同一检测项目的数值比较，标记出在给定时间间隔内不合理的大幅变化。）
  • Reportable limits — the boundary values beyond which a lab result is considered incompatible with life and should not be reported.（中文：可报告限值——超出该边界的实验室结果被视为与生存不相容、不应被报告的数值范围。）
  • Logic consistency rules — checks that related test results maintain an expected relationship (e.g., total bilirubin should never be less than direct bilirubin when both are measured together).（中文：逻辑一致性规则——检查相关检测结果是否保持预期关系，例如同时检测时，总胆红素不应低于直接胆红素。）
  • UCUM — Unified Code for Units of Measure, a standard for units that plausibility checks assume test results already conform to.（中文：统一计量单位编码，合理性检测假设检验结果已经符合该单位标准。）

Full citation

Zayed A, Janssens A, Mamouris P, Delvaux N. "lab2clean: a novel algorithm for automated cleaning of retrospective clinical laboratory results data for secondary uses." BMC Medical Informatics and Decision Making, 2024. PMID: 39227951 | PMC: 11370074 | DOI: 10.1186/s12911-024-02652-7

Methods / tools to lift

  • Conformance/plausibility split as two separate, independently-testable functions — a clean architectural boundary between "wrong format" and "not believable."
  • Parameterized delta check — successive-measurement comparison over a defined time interval, directly portable to anthropometric trajectories.
  • Duplicate-record flagging as a first-pass, low-cost check — run before any statistical outlier model; caught 81% of all flags in this paper's ICU dataset.
  • Regex-based three-step conformance pipeline (clean → categorize → standardize) — a reusable pattern for any free-format clinical field, not lab-specific.

Where it lands + buildable artifact

Pipeline stage: (a) candidate generation, primary — the delta-check architecture ports directly to height/weight time series as a complement (not replacement) to a spline/mixed-effects candidate generator, catching abrupt jumps a smooth trajectory fit might under-weight. (e) supplies vocabulary, secondary — the conformance-vs-plausibility distinction is a clean, citable framing for two failure modes a single flagging rule can blur together.

MVP: port the delta-check logic, same parameterization approach, onto a height/weight time series, and run it side-by-side against a spline/mixed-effects candidate generator to compare which specific records each one catches. Difficulty: S (the check is a short comparison-and-threshold rule; the work is choosing growth-appropriate time-interval buckets).

What to verify first

  • No gold standard: reported flag rates describe what lab2clean's rules caught, not a validated sensitivity/PPV against human-adjudicated true errors.
  • Plausibility checks assume test identifiers and units are already LOINC/UCUM-compliant — this assumption broke down in the multicentric INTEGO database per the authors' own account, a real caution for any multi-site setting.
  • Reportable-limit and logic-consistency thresholds are lab-test-specific and would need entirely separate, anthropometric-appropriate thresholds before those two checks (as opposed to the delta-check architecture) could transfer directly.
  • No claims made about CFFPR's current cleaning rules or flag rates — this paper's numbers are lab2clean's own, on lab (not anthropometric) data.

Error types covered / not covered

Covered: format/unit-and-flag conflation in a single field (conformance), duplicate records, extreme/incompatible-with-life values, cross-field logical inconsistency, and successive-measurement (delta) implausibility. Not covered: digit transposition or decimal-shift errors specifically, carry-forward (stale value repeated across visits) as a distinct category, real-clinical-event vs. data-error discrimination beyond the delta threshold itself, and anything at the growth-trajectory (multi-point pattern) level rather than pairwise successive-value comparison.

ALEX Today is a Track C double-header, and this is the first of two — Zayed and colleagues, 2024, BMC Medical Informatics and Decision Making: "lab2clean, a novel algorithm for automated cleaning of retrospective clinical laboratory results data for secondary uses." 今天是C轨道的双集特别篇，这是其中第一篇——Zayed等人于2024年发表在《BMC Medical Informatics and Decision Making》上的论文：《lab2clean：一种用于自动清理回顾性临床实验室结果数据以供二次利用的新算法》。 It ships an actual R package with two functions, and its architecture — split cleaning into a conformance step and a plausibility step, then run both at electronic-medical-record scale — is exactly the kind of transplantable package design we want for a growthcleanr-style height and weight tool. 它提供了一个真正可用的R包，包含两个函数，其架构——将数据清理拆分为"合规性"（conformance）步骤和"合理性"（plausibility）步骤，并在电子病历（EMR）规模上运行两者——正是我们希望为一款growthcleanr风格的身高体重清理工具所借鉴的那种可迁移的包设计。 It's not about anthropometrics directly, it's about laboratory results, but the underlying decision architecture — what counts as a format problem versus a value problem, and how to check each — transfers cleanly. 它本身并不是直接针对人体测量数据（anthropometrics），而是针对实验室结果，但其底层的决策架构——什么算格式问题、什么算数值问题，以及如何分别检测——可以很干净地迁移过来。

JORDAN Before the numbers, walk me through the vocabulary — specifically conformance versus plausibility. 在讲数字之前，先讲讲术语——尤其是合规性（conformance）和合理性（plausibility）的区别。

ALEX These are two of the standard data quality dimensions from the Kahn framework, the widely-used taxonomy for characterizing electronic health data quality. 这是Kahn框架中两个标准的数据质量维度，Kahn框架是描述电子健康数据质量的一套广泛使用的分类体系。 Conformance asks whether data matches an established internal or external formatting standard — does a lab result look the way it's supposed to look, structurally — while plausibility asks whether a value is credible or believable given context, either atemporal plausibility, meaning the value alone or against another related variable at the same moment, or temporal plausibility, meaning whether a sequence of values over time makes sense. 合规性关心的是数据是否符合既定的内部或外部格式标准——一个实验室结果在结构上是否长得该有的样子——而合理性关心的是，在给定上下文下，一个数值是否可信、可以接受，可以是非时序合理性（atemporal plausibility），即该数值本身、或与同一时刻另一相关变量对比是否合理，也可以是时序合理性（temporal plausibility），即一段时间内的一系列数值变化是否说得通。 A related idea from LOINC, Logical Observation Identifiers Names and Codes, the standard vocabulary for lab tests: it defines scale types like Quantitative, Ordinal, and Nominal for a result, but doesn't prescribe how that result should be formatted — so the same quantitative result might show up as "+", "positive", or a plain number depending on which lab reported it. 一个相关的概念来自LOINC（Logical Observation Identifiers Names and Codes，逻辑观察指标名称与编码），这是实验室检验的标准词汇表：它为一个结果定义了量表类型，比如定量（Quantitative）、序数（Ordinal）和名义（Nominal），但并不规定该结果应该以什么格式呈现——于是同一个定量结果，可能因为报告实验室不同，而以"+"、"positive"或一个普通数字的形式出现。

JORDAN And the delta check specifically? 那delta检测具体是什么？

ALEX A delta check, in this paper's temporal-plausibility check, compares a patient's current lab value against their own prior value for the same test and flags an implausibly large jump over a given time interval — the logic being that a real biological change of that magnitude in that short a window is unlikely, so a huge delta is more likely a data error than a true clinical event. 在这篇论文中，delta检测属于时序合理性检测的一部分，它将患者当前的实验室数值，与该患者同一检测项目此前的数值进行比较，并在给定时间窗口内标记出不合理的大幅跳变——其逻辑是，在如此短的时间窗口内出现这种幅度的真实生物学变化并不太可能，因此，一个巨大的delta更可能是数据错误，而非真实的临床事件。 That's the same core idea Runyu would want for a height or weight trajectory — a successive-measurement jump that's biologically implausible over the observed interval. 这正是Runyu在处理身高或体重轨迹时，会想要用到的同一核心思路——在观察到的时间间隔内，出现一次生物学上不合理的连续测量跳变。

JORDAN So what problem was this actually solving — why did clinical laboratory data need its own cleaning algorithm? 那么这篇论文究竟解决了什么问题——为什么临床实验室数据需要一个专门的清理算法？

ALEX Laboratory results make up an estimated 70% of all electronic medical record data by volume, so any quality problem in how it's recorded and reported has an outsized effect on secondary research and clinical machine learning downstream. 实验室结果按数据量估计，约占电子病历数据总量的70%，因此其记录和报告方式中的任何质量问题，都会对下游的二次研究和临床机器学习产生不成比例的巨大影响。 The problem is that LOINC and similar standards fix which test was done and roughly what kind of result it produces, but they leave the actual formatting of the reported value completely up to each lab — so the same quantitative glucose result might come through as a clean number in one system and as a number plus a unit plus an interpretive flag like "high" all crammed into one field in another, and a canceled test might show up as a text string like "canceled" sitting in the numeric result column. 问题在于，LOINC及类似标准，规定了做的是哪项检测、大致产生什么类型的结果，但对实际报告数值的具体格式，则完全交由各实验室自行决定——于是同一个定量的血糖结果，在一个系统中可能是一个干净的数字，在另一个系统中却可能是数字加单位加"high"这样的解释性标记全部挤在同一个字段里，而一次被取消的检测，也可能以"canceled"这样的文本字符串出现在本应是数值结果的那一列。 Before this paper, there wasn't a general-purpose, openly available algorithm that systematically separated the format-conformance problem from the value-plausibility problem and handled both at real EMR scale — researchers either wrote one-off, dataset-specific cleaning scripts or skipped the problem and hoped the noise averaged out. 在这篇论文之前，还没有一种通用、公开可用的算法，能够系统性地区分格式合规性问题与数值合理性问题，并在真实EMR规模上同时处理两者——研究者们此前只能编写一次性的、针对特定数据集的清理脚本，或者干脆跳过这个问题，希望噪声能够在整体上被平均掉。

JORDAN What did the two functions actually do? 这两个函数具体做了什么？

ALEX Function one, clean_lab_result, handles conformance in three steps using R's base regular-expression tools: first it strips out extraneous information crammed into the result field, like units or interpretive flags such as "high" or "low"; then it categorizes each distinct result format into a LOINC-aligned scale-type subcategory — simple numeric, inequality, range, or titer results within Quantitative, for instance; then it standardizes every format within a subcategory into one preferred form, following published reporting-format guidelines, and it does all of this across 19 supported languages. 第一个函数clean_lab_result，使用R自带的正则表达式工具，分三步处理合规性问题：首先，剔除塞进结果字段中的多余信息，比如单位，或"high"、"low"之类的解释性标记；然后，将每种不同的结果格式，归类到与LOINC对齐的量表类型子类别中——例如，在定量类型下区分简单数值、不等式、范围或滴度结果；最后，依照已发布的报告格式指南，把每个子类别内的所有格式统一为一种首选形式，并且这整个过程支持19种语言。 Function two, validate_lab_result, handles plausibility with three checks after first flagging duplicate records for the same test, patient, and timestamp: reportable limits, meaning extreme values flagged as incompatible with life; logic consistency rules, four established rules — like total bilirubin never being less than direct bilirubin when both are ordered together — adapted from prior auto-verification literature; and the delta check we just described for temporal plausibility. 第二个函数validate_lab_result处理合理性问题，先标记出同一患者、同一检测项目、同一时间点下的重复记录，再进行三项检测：可报告限值检测，即标记出与生存不相容的极端数值；逻辑一致性规则，共四条已确立的规则——例如，当总胆红素和直接胆红素同时被检测时，总胆红素绝不应低于直接胆红素——这些规则改编自此前的自动审核文献；以及我们刚才提到的、用于时序合理性的delta检测。 Here's where I'd push back a little: the authors state plainly that they didn't benchmark lab2clean against any comparable tool, because none existed for direct comparison — that's a fair statement about the field, but it also means every number that follows is a description of what lab2clean itself flags, not evidence that it flags the right things at the right rate. 这里我想稍微提出一点质疑：作者明确表示，他们没有将lab2clean与任何可比工具进行基准测试，因为当时并不存在可直接比较的对象——这对整个领域现状而言是一个公允的说法，但这也意味着，接下来的所有数字，描述的都是lab2clean自身标记了什么，而不是它以正确的比率标记了正确的对象的证据。

JORDAN What did they actually find running it at scale? 他们在大规模运行时实际发现了什么？

ALEX On the INTEGO database, a Flemish multicentric primary-care network, they started with about 218 million lab result records and, after deduplication, roughly 928,000 distinct result values; function one processed all of it in under 5 minutes, standardizing 42.5% of those distinct values, which translated to 94.5% of the total records once you weight by how often each value actually occurs. 在INTEGO数据库——一个佛兰德的多中心初级医疗网络中，他们从约2.18亿条实验室结果记录出发，去重后剩下约92.8万个不同的结果值；第一个函数在不到5分钟内处理了全部数据，标准化了这些不同结果值中的42.5%，按每个值出现的实际频次加权后，相当于覆盖了总记录数的94.5%。 On MIMIC-IV, the single-center intensive care database, function two processed about 100.87 million quantitative records in under 2 hours and flagged 409,921 of them, just 0.406%, as potentially inaccurate, validating the remaining 99.594%. 在MIMIC-IV这个单中心重症监护数据库上，第二个函数在不到2小时内处理了约1.0087亿条定量记录，其中409,921条，仅占0.406%，被标记为可能不准确，其余99.594%通过了验证。 Duplicates dominated the flags at 81% of everything caught, 333,574 records; the delta check caught 18% of flags, split between a short-interval flag within 7 days and a longer-interval flag from 8 to 90 days; logic consistency violations and reportable-limit breaches were both vanishingly rare, at 0.004% and effectively 0.000% of all records respectively. 重复记录在所有被标记的记录中占比最高，达到81%，共333,574条；delta检测捕获了18%的标记记录，分为7天内的短间隔标记和8到90天的长间隔标记；逻辑一致性违规和可报告限值突破都极为罕见，分别仅占全部记录的0.004%和几乎0.000%。 That flag-rate profile — dominated by duplicates, then temporal jumps, with logic and extreme-value violations both rare — is itself useful information about where the real mess tends to concentrate in a large single-center EMR lab dataset.

这种标记结果的分布特征——以重复记录为主，其次是时序跳变，逻辑与极端值违规都很罕见——本身就是关于大型单中心EMR实验室数据集中，真实混乱究竟集中在哪里的有用信息。

JORDAN Does this change anything about the CFFPR outlier pipeline specifically — candidate generation, adjudication, review budget, or evaluation? 这对CFFPR的异常值检测流程具体有什么改变——候选生成、裁定、审查预算，还是评估？

ALEX This lands mainly on (a), candidate generation, and secondarily on (e) — it supplies vocabulary and architecture rather than a ready-made anthropometric model. 这主要落在(a)候选生成上，其次是(e)——它提供的是词汇和架构，而不是一个现成的人体测量学模型。 The transplantable piece is the delta-check design itself: a successive-measurement comparison, parameterized by time interval, flagging jumps that are implausible over that specific window — that structure ports directly onto a height or weight time series as a complement to, not a replacement for, a spline or mixed-effects growth-curve candidate generator, since a delta check catches abrupt jumps a smooth trajectory model might under-weight if the jump gets partially absorbed into the fitted curve. 可迁移的部分正是delta检测本身的设计：一种以时间间隔为参数的连续测量比较，标记出在该特定窗口内不合理的跳变——这种结构可以直接迁移到身高或体重时间序列上，作为对样条或混合效应生长曲线候选生成模型的补充，而非替代，因为delta检测能够捕捉到突然的跳变，而这种跳变如果被部分吸纳进拟合曲线中，平滑轨迹模型可能会对其权重不足。 The conformance-versus-plausibility split is also a genuinely useful vocabulary borrow: it gives a clean, citable name to the distinction between "this number is in the wrong format" and "this number, correctly formatted, is still not believable" — two failure modes that a single flagging rule can easily blur together. 合规性与合理性的划分本身也是一个真正有用的词汇借用：它为"这个数字格式不对"和"这个数字格式正确、但依然不可信"这两种失效模式，提供了一个清晰、可引用的命名——单一的标记规则很容易把这两者混为一谈。 The buildable artifact: port the delta-check logic, exactly as parameterized here, onto a height and weight time series, and run it side by side against whatever spline or mixed-effects candidate generator we already have in mind, to see which specific records each one catches and which it misses. 可构建的产物是：把这里的delta检测逻辑，按照相同的参数化方式，迁移到身高和体重时间序列上，并与我们已经在考虑的样条或混合效应候选生成模型并行运行，看看两者各自能捕捉到哪些具体记录、又会漏掉哪些。 That's an S-difficulty build — the check itself is a short comparison-and-threshold rule; the work is choosing sensible time-interval buckets for a growth context instead of the lab-result buckets used here.

这是一个小型难度的项目——检测本身只是一个简单的比较加阈值规则；真正的工作在于，为生长背景选择合适的时间间隔分档，而不是照搬这里为实验室结果设定的分档。

JORDAN What would we need to check before leaning on any of this? 在依赖这些结论之前，我们需要核实什么？
