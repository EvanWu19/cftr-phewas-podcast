Ep2 (Track B — AI/registry tooling): Self-service feasibility, without a SQL analyst in the loop

Herman and colleagues (2026, Computational Biology and Chemistry) present PCORsearch, a web-based platform letting investigators independently run cohort-discovery and feasibility analysis against deidentified EHR-derived data mapped into the PCORnet Common Data Model (CDM), without directly querying the underlying EHR data servers themselves. Cohorts are built through a custom grammar tailored to PCORnet's own vocabulary and table structure, designed for usability and security rather than exposing raw SQL; the platform also supports summary statistics and visualizations, saving and sharing cohorts between users, and a companion application letting analysts use the same grammar and interface to obtain line-level data access when a full patient-level pull is genuinely warranted. The stated motivation is a real bottleneck: regulatory and privacy restrictions mean investigators can't directly query EHR servers themselves, so feasibility requests are routed through independent analysts, producing delays the paper describes as several weeks or more. No quantitative benchmark — latency, a user study, before/after timing, or count accuracy against a known baseline — is given in the retrievable abstract; this is a systems/architecture description, not a measured evaluation. The transferable idea for the AI-tooling/career track isn't PCORsearch's code, but its architecture: a self-service, grammar-constrained query layer over a common data model, with saveable/shareable cohorts and a built-in escalation path to line-level access, directly portable to a CF-focused OMOP instance.

Plain-English glossary

  • PCORnet CDM — the Patient-Centered Outcomes Research Network's own Common Data Model: a standardized table-and-field schema multiple health systems' EHR data is mapped into, conceptually parallel to OMOP but a distinct schema built for the US patient-centered outcomes research community.（中文：PCORnet通用数据模型，以患者为中心的结局研究网络自有的通用数据模型——一套标准化的表和字段结构，多家医疗系统的EHR数据被映射进其中，理念上与OMOP相似，但是专为美国以患者为中心的结局研究社区打造的一套独立架构。）
  • Feasibility analysis — the pre-study step of counting how many patients meeting given inclusion criteria exist in a network's data, without pulling patient-level records or running the full study.（中文：可行性分析，研究正式启动前的一步，统计满足给定纳入标准的患者在网络数据中实际有多少，而不拉取患者层面的记录或运行完整研究。）
  • Deidentified data — data with direct identifiers stripped or obscured so it no longer points back to a specific named individual, the standard mechanism enabling researcher access without full patient-level authorization.（中文：去标识化数据，直接标识信息被剥离或模糊处理后的数据，使其不再能指向某个具体的、有名字的个体，这是让研究者能够访问数据而无需完整患者层面授权的标准机制。）
  • Custom query grammar — a constrained, purpose-built query syntax sitting between a rigid point-and-click form (safe but limited) and raw SQL (expressive but a security/training burden).（中文：自定义查询语法，一种受限、专门设计的查询语法，介于死板的点选式表单（安全但表达有限）和原始SQL（表达力强但存在安全与培训负担）之间。）
