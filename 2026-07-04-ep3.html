How did this episode land for you?

Track C — In-silico modifier-gene search for pancreatic & liver disease in CF (Trouve et al., 2017)

Blurb. Trouve, Genin, and Ferec (PLoS ONE, 2017) run a purely computational systems-biology pipeline to nominate new CF modifier genes for lung, pancreatic, and liver outcomes: database mining (OMIM, CTD, HuGE Navigator), re-analysis of public GEO expression datasets, protein-protein interaction (PPI) networks, and pathway enrichment. Candidates: IFI16, CCNE2, IGFBP2 (lung); EPHX1, HLA-DQA1, HLA-DQB1 (pancreas); DSP, SLC33A1, GPNMB, NCF2, RASGRP1, LGALS3, PTPN13 (liver). Pathways implicate the immune system; Ubiquitin C (UBC) is flagged as a network hub linking CF to liver and pancreatic disease. The authors stress the list needs functional validation, and the expression step used surrogate datasets (type-1 diabetes for pancreas, NASH for liver) because no CF expression dataset was available. Where it lands: summary-stats colocalization. Buildable artifact: a reproducible CF-modifier candidate-triage notebook that regenerates the intersection/PPI/enrichment candidates with pinned provenance and keeps only candidates with orthogonal GWAS + GTEx eQTL support.

Plain-English glossary

  • CTD (Comparative Toxicogenomics Database) — a curated database of gene–disease–chemical relationships (kept in English).（中文:CTD 是经过审编的基因-疾病-化学物关系数据库。)
  • eQTL — a genetic variant that shifts a gene's expression level (kept in English).（中文:eQTL 是改变某基因表达量的遗传变异位点。)
  • GEO — a public repository of gene-expression datasets (kept in English).（中文:GEO 是公开的基因表达数据集仓库。)
  • GWAS summary statistics — the per-variant association results from a genetic study.（中文:GWAS 汇总统计是遗传研究里逐个变异的关联结果。)
  • HuGE Navigator — a database mining the human genetic-association literature (kept in English).（中文:HuGE Navigator 挖掘人类遗传关联文献。)
  • In silico — done entirely on a computer, with no wet-lab experiment.（中文:in silico 指完全在计算机上完成、没有湿实验。)
  • Modifier gene — a gene other than the disease gene (CFTR) whose variation nudges the severity of a CF phenotype up or down.（中文:修饰基因是致病基因 (CFTR) 之外、其变异会改变某 CF 表型严重程度的基因。)
  • NASH (non-alcoholic steatohepatitis) — a fatty-liver disease used here as a surrogate for CF liver disease (kept in English).（中文:NASH 是非酒精性脂肪性肝炎,这里被用作 CF 肝病的替代。)
  • OMIM — the curated catalog of human genes and genetic disorders (kept in English).（中文:OMIM 是经过审编的人类基因与遗传病目录。)
  • Pancreatic insufficiency — the pancreas fails to deliver digestive enzymes.（中文:胰腺功能不全指胰腺无法输送消化酶。)
  • Pathway enrichment — testing whether candidate genes cluster into known biological processes more than chance predicts.（中文:通路富集检验候选基因是否比随机预期更集中地落入已知生物学过程。)
  • PPI network / hub — a network where an edge means two proteins bind or act together; a highly connected node is a hub.（中文:PPI 网络中一条边表示两个蛋白质结合或协同,连接极多的节点是枢纽。)

Methods / tools to lift

  • Multi-database intersection: query OMIM + CTD + HuGE with disease keywords, then intersect via Venn diagrams as a crude confidence filter (a gene surfacing in >1 source is less likely a single-source fluke).
  • Expression re-analysis: pull and re-analyze GEO datasets for differentially expressed genes — but note the surrogate-dataset substitution when no direct dataset exists.
  • Network layer: build a PPI network, identify hubs, run pathway enrichment to see which processes the candidates cluster into.
  • Discipline to add: pin database versions/query dates for reproducibility; use a degree-corrected null before trusting a hub.

Where it lands + buildable artifact

  • Serves: summary-stats colocalization (modifier-locus arm).
  • MVP (paste-ready): cf-modifier-candidate-triage-notebook — regenerate the multi-database intersection + PPI-hub + pathway-enrichment candidate list with full provenance (DB versions, query dates); then auto-cross-check every candidate against public CF-modifier GWAS summary statistics and GTEx eQTL, keeping only candidates with orthogonal genetic support at/near the locus; validate the filter by confirming it recovers already-established CF modifier loci. Difficulty: M. Public summary-level data only — no controlled genotype data.

What to verify first

  • The whole list is in-silico; the authors say it needs functional validation — no candidate here is a demonstrated modifier.
  • Surrogate expression data (T1D for pancreas, NASH for liver) — re-run the expression step on genuinely CF-relevant tissue before trusting organ-specific nominees.
  • Database mining is sensitive to keyword choice and DB version — the list is not reproducible unless every query date and version is pinned.
  • Network hubs (Ubiquitin C) need a degree-corrected null model before being called biologically meaningful rather than connectivity artifacts.
  • External, published-data method only — no use of or claim about any internal registry data; no research design is settled.

Gap-map / catalog

  • Closes: produces a concrete, organ-specific in-silico candidate set for the under-mapped pancreatic and liver CF phenotypes, plus a mild convergence on the immune/detoxification theme (HLA-DQ, GSTs) that echoes prior CF-modifier work.
  • Leaves open: functional/genetic validation of every candidate; whether any candidate colocalizes with a real CF-modifier GWAS/eQTL signal; the surrogate-tissue problem; whether the Ubiquitin C hub is real signal or connectivity artifact; and organ-specific mechanism for each nominee.

ALEX Today's Track C paper is "In silico search for modifier genes associated with pancreatic and liver disease in Cystic Fibrosis," by Pascal Trouve, Emmanuelle Genin, and Claude Ferec, published in PLoS ONE in 2017. 今天的 Track C 论文是 Pascal Trouve、Emmanuelle Genin 和 Claude Ferec 于 2017 年发表在《PLoS ONE》上的《在计算机中搜寻与囊性纤维化胰腺和肝脏疾病相关的修饰基因》。 One note up front: because the Track C queue was exhausted, I seeded this one fresh from a Europe PMC search of the CF-modifier literature. 先说明一点:因为 Track C 的队列已经读完了,我是从 Europe PMC 对 CF 修饰基因文献的检索中新挑出这一篇的。 We are reading it because it is a purely computational attempt to nominate new CF modifier genes, and the method — not the gene list — is what transfers. 我们读它,是因为它是一次纯计算的尝试,去提名新的 CF 修饰基因 (modifier gene),而可迁移的是它的方法,而不是那份基因清单。

JORDAN Start with the core concept. 从核心概念开始。 What is a modifier gene, and how is it different from the disease gene itself? 什么是修饰基因,它和致病基因本身有什么不同?

ALEX In cystic fibrosis the disease gene is CFTR — two broken CFTR copies cause the disease. 在囊性纤维化中,致病基因是 CFTR——两个坏掉的 CFTR 拷贝导致了疾病。 But two patients with the exact same CFTR genotype can have very different lungs, pancreas, and liver outcomes, and a modifier gene is any other gene whose variation nudges that outcome up or down. 但两个 CFTR 基因型完全相同的病人,其肺、胰腺和肝脏的结局却可能大不相同,而修饰基因就是任何其变异会把这个结局向上或向下推动的其他基因。 So a modifier does not cause CF; it shapes how severe CF is in a given organ. 所以修饰基因不导致 CF;它塑造的是 CF 在某个特定器官里有多严重。 Two CF phenotypes to define here: pancreatic insufficiency, where the pancreas fails to deliver digestive enzymes, and CF liver disease, where bile-duct injury scars the liver. 这里要定义两个 CF 表型:胰腺功能不全 (pancreatic insufficiency),即胰腺无法输送消化酶;以及 CF 肝病,即胆管损伤使肝脏结疤。

JORDAN And "in silico" — that just means done entirely on a computer? “In silico”——就是完全在计算机上完成的意思吗?

ALEX Exactly, no wet-lab experiment; they mine existing databases and public data to generate hypotheses. 正是如此,没有湿实验;他们挖掘已有的数据库和公开数据来生成假说。 The engine is a systems-biology workflow, which means they treat genes as nodes in a network rather than a flat list. 引擎是一套系统生物学 (systems biology) 工作流,意思是他们把基因当作网络中的节点,而不是一张扁平的清单。 Two network ideas matter: a protein-protein interaction network, where an edge means two proteins physically bind or act together, and pathway enrichment, which asks whether your candidate genes cluster into known biological processes more than chance would predict. 有两个网络概念很重要:蛋白质-蛋白质相互作用网络 (protein-protein interaction,PPI),其中一条边表示两个蛋白质在物理上结合或协同作用;以及通路富集 (pathway enrichment),它检验你的候选基因是否比随机预期更集中地落入已知的生物学过程里。 A node with many connections is called a hub, and hubs often sit at biologically important control points. 一个连接很多的节点被称为枢纽 (hub),枢纽往往处于生物学上重要的控制点。

JORDAN Why go computational instead of just running a genetic study? 为什么走计算路线,而不直接做一项遗传研究? ALEX: Because a well-powered modifier study needs thousands of patients with matched phenotypes and genotypes, which is slow and expensive to assemble. 因为一项有足够统计效力的修饰基因研究需要成千上万个表型与基因型都匹配的病人,而这样的样本组建起来既慢又贵。 An in-silico pass costs almost nothing and can pre-filter the genome down to a short list worth testing, so it is a triage step, not a replacement for genetics. 一次计算机模拟的扫描几乎不花成本,能把整个基因组预先筛到一份值得检验的短清单上,所以它是一个分诊步骤,而不是遗传学的替代品。

JORDAN What was unknown before that made this worth doing? 在此之前有什么未知,使得这件事值得做?

ALEX The background puzzle is that CF is monogenic in cause but wildly variable in expression, and the known modifier genes explain only a slice of that variability. 背景难题在于:CF 在病因上是单基因病,但在表现上却变化极大,而已知的修饰基因只能解释这种变异性中的一小部分。 Most modifier discovery had focused on the lung, because lung disease drives survival, leaving the pancreatic and liver complications comparatively under-mapped. 大多数修饰基因发现都集中在肺上,因为肺病决定生存,这就让胰腺和肝脏的并发症相对研究不足。 So the authors asked whether combining several independent knowledge sources computationally could surface fresh candidate modifiers specifically for the pancreatic and liver phenotypes, without waiting for a large genetic cohort. 于是作者们发问:能否通过计算方式整合若干独立的知识来源,专门为胰腺和肝脏表型浮现出新的候选修饰基因,而不必等待一个大型遗传队列。 It is candidate generation, explicitly upstream of validation. 这是候选生成,明确地处于验证的上游。

JORDAN How much of the variability is actually genetic rather than environment or luck? 这种变异性里,究竟有多少真的是遗传性的,而不是环境或运气? ALEX: Twin and sibling studies in CF show that a substantial part of lung-disease variability is heritable beyond CFTR itself, which is the empirical license for hunting modifier genes at all. CF 的双胞胎和同胞研究显示,肺病变异性中有相当一部分是在 CFTR 之外可遗传的,这正是"去搜寻修饰基因"这件事在经验上的依据。 That heritable fraction is what a modifier search is trying to explain, organ by organ. 修饰基因搜索试图解释的,正是这个可遗传的部分,一个器官一个器官地解释。

JORDAN Walk me through the pipeline. 带我过一遍这条流水线。

ALEX They pulled gene lists from three curated databases using disease keywords, then intersected them. 他们用疾病关键词从三个人工审编的数据库里拉取基因清单,然后取交集。 OMIM, the catalog of human genes and genetic disorders, gave 100 genes for CF, 109 for CF-associated, 152 for pancreatic insufficiency, and 1,192 for liver disease. OMIM(人类基因与遗传病目录,OMIM)为 CF 给出 100 个基因、CF 相关 109 个、胰腺功能不全 152 个、肝病 1,192 个。 The genes shared by CF, CF-associated, and pancreatic-insufficiency keywords were S100A8/S100A9, CFTR, SCNN1G, TGFB1, SERPINA1, and PKD1. 由 CF、CF 相关和胰腺功能不全三个关键词共享的基因是 S100A8/S100A9、CFTR、SCNN1G、TGFB1、SERPINA1 和 PKD1。 A second database, the Comparative Toxicogenomics Database, gave 11, 142, and 813 genes and its own three-way overlap of TGFB1, TNFRSF1A, and CFM1. 第二个数据库——比较毒理基因组学数据库 (CTD,Comparative Toxicogenomics Database)——给出 11、142 和 813 个基因,其三方重叠为 TGFB1、TNFRSF1A 和 CFM1。 A third, HuGE Navigator, which mines the human genetic-association literature, returned CFTR, SPINK1, GSTP1, PRSS1, ADRB2, GSTM1, GSTT1, HRAS, MIF, OGG1, and TNF at its score threshold. 第三个——HuGE Navigator(挖掘人类遗传关联文献的数据库,HuGE),在其评分阈值下返回了 CFTR、SPINK1、GSTP1、PRSS1、ADRB2、GSTM1、GSTT1、HRAS、MIF、OGG1 和 TNF。 They then re-analyzed gene-expression datasets from GEO, the public expression repository, and layered on protein-protein interactions and pathway enrichment. 然后他们重新分析了来自 GEO(公共表达数据仓库,GEO)的基因表达数据集,并叠加了蛋白质-蛋白质相互作用和通路富集。

JORDAN Why use three databases instead of just the best one? 为什么用三个数据库,而不只用最好的那一个? ALEX: Because each is built from a different evidence type, so their intersection is a crude confidence filter. 因为每一个都建立在不同类型的证据之上,所以它们的交集是一种粗略的置信度过滤器。 OMIM leans on curated Mendelian phenotype-genotype relationships, CTD on curated gene-disease-chemical relationships, and HuGE on the population genetic-association literature, so a gene surfacing in more than one is less likely to be a single-source fluke. OMIM 倚重经过审编的孟德尔式表型-基因型关系,CTD 倚重经过审编的基因-疾病-化学物关系,而 HuGE 倚重人群遗传关联文献,因此一个在不止一个数据库里冒出来的基因,更不可能只是单一来源的偶然。

JORDAN There is a design choice in there I want you to push on. 这里面有一个设计选择我想让你质疑一下。

ALEX The one that jumps out is the expression data. 最扎眼的是表达数据。 Because searching GEO for cystic fibrosis, chronic pancreatitis, and liver disease returned no usable dataset, they substituted proxies — type-1-diabetes-versus-control for the pancreas and control-liver-versus-NASH for the liver. 因为在 GEO 里检索囊性纤维化、慢性胰腺炎和肝病没有返回可用的数据集,他们就用了替代数据集——用 1 型糖尿病对照(T1D)代表胰腺,用正常肝脏对 NASH(非酒精性脂肪性肝炎,NASH)代表肝脏。 That is a real leap: type 1 diabetes is not CF pancreatic disease, and NASH is not CF liver disease, so any expression signal borrowed from them is a surrogate, not the real tissue context. 这是一次真正的跳跃:1 型糖尿病不是 CF 的胰腺病,NASH 也不是 CF 的肝病,所以从它们借来的任何表达信号都是替身,而非真实的组织情境。 The authors are candid about this, but it is the single biggest caveat on the whole gene list. 作者对此很坦诚,但这是整份基因清单上最大的一个警示。

JORDAN So what genes did the pipeline actually nominate? 那么这条流水线到底提名了哪些基因?

JORDAN Before the list — how should I weight a name that comes out of this versus a GWAS hit? 在看清单之前——我该如何权衡一个从这里冒出来的名字,相比一个 GWAS 命中? ALEX: Much lower, and for a specific reason: this pipeline nominates by shared annotation and network proximity, which reflects what has already been studied and written down, so it inherits the literature's biases. 权重要低得多,原因很具体:这条流水线是靠共享注释和网络邻近度来提名的,而这反映的是"已经被研究和记录下来的东西",所以它继承了文献本身的偏倚。 A GWAS hit, by contrast, is anchored to an actual allele frequency difference in patients, so treat these as leads to check, not findings to cite. 相比之下,一个 GWAS 命中锚定的是病人中真实的等位基因频率差异,所以把这些当作待核查的线索,而不是可引用的发现。

ALEX For altered lung function, the candidates were IFI16, CCNE2, and IGFBP2. 对于肺功能改变,候选基因是 IFI16、CCNE2 和 IGFBP2。 For the pancreas, EPHX1, HLA-DQA1, and HLA-DQB1; and for the liver, DSP, SLC33A1, GPNMB, NCF2, RASGRP1, LGALS3, and PTPN13. 对于胰腺,是 EPHX1、HLA-DQA1 和 HLA-DQB1;对于肝脏,是 DSP、SLC33A1、GPNMB、NCF2、RASGRP1、LGALS3 和 PTPN13。 The pathway analysis pointed repeatedly at the immune system, and the network analysis flagged Ubiquitin C as a probable central hub linking CF to both the liver and pancreatic phenotypes. 通路分析反复指向免疫系统,而网络分析把泛素 C(Ubiquitin C,UBC)标记为可能的中心枢纽,连接 CF 与肝脏及胰腺两种表型。 Two things are worth holding in mind: several nominees, like the HLA-DQ genes and the glutathione-S-transferases from HuGE, recur in the immune-and-detoxification theme that older CF-modifier work already circled, which is mild corroboration. 有两点值得记住:若干被提名者,比如 HLA-DQ 基因,以及来自 HuGE 的谷胱甘肽-S-转移酶,反复出现在免疫与解毒这一主题里,而更早的 CF 修饰基因研究就已围绕这一主题,这算是轻度的印证。 But Ubiquitin C as a hub deserves suspicion, because ubiquitin is a promiscuous interactor that shows up as a hub in almost every network by sheer connectivity, not necessarily by CF-specific relevance. 但把泛素 C 当作枢纽值得怀疑,因为泛素是一个"来者不拒"的相互作用者,几乎在每个网络里都因纯粹的连接数而现身为枢纽,并不一定是因为与 CF 有特异关联。

JORDAN Where does this land for our priorities? 这落在我们哪个优先项上?

ALEX This lands on summary-stats colocalization — the modifier-locus arm of the project. 这落在汇总统计共定位 (summary-stats colocalization) 上——项目里修饰位点的那条分支。 An in-silico list like this is exactly the kind of hypothesis generator that is cheap to produce and dangerous to trust, so the transferable move is to pair candidate generation with orthogonal genetic filtering. 像这样的计算机模拟清单,正是那种生产成本很低、却危险到不能轻信的假说发生器,所以可迁移的做法是把候选生成和正交的遗传学过滤配对起来。 The buildable artifact is a reproducible CF-modifier candidate-triage notebook. 可构建的产物是一个可复现的 CF 修饰基因候选分诊笔记本 (notebook)。 The MVP: re-implement the multi-database intersection and PPI-hub-plus-pathway-enrichment steps with full provenance — recording each database version and query date — to regenerate a candidate list; then automatically cross-check every candidate against public CF-modifier GWAS summary statistics and GTEx eQTL data, keeping only candidates that also carry orthogonal genetic support at or near their locus. MVP 是这样:带着完整的来源记录重新实现多数据库取交集,以及"PPI 枢纽加通路富集"这些步骤——记录每个数据库的版本和查询日期——以重新生成一份候选清单;然后自动地把每个候选基因与公开的 CF 修饰基因 GWAS 汇总统计和 GTEx eQTL 数据进行交叉核对,只保留在其位点处或附近同样带有正交遗传学支持的候选者。 GWAS summary statistics are the per-variant association results from a genetic study, GTEx is a public tissue eQTL resource, and an eQTL is a variant that shifts a gene's expression level. GWAS 汇总统计是一项遗传研究里逐个变异的关联结果,GTEx 是一个公开的组织 eQTL 资源,而 eQTL(影响基因表达水平的遗传变异位点)是一个改变某基因表达量的变异。 Difficulty is medium, and it uses only public summary-level data — no controlled genotype data. 难度中等,而且它只用公开的汇总层数据——不使用任何受控的基因型数据。

JORDAN Why colocalization specifically, rather than just checking if the gene shows up in a GWAS? 为什么偏偏是共定位,而不只是查这个基因是否出现在某个 GWAS 里? ALEX: Because a candidate gene sitting near a GWAS signal is not enough — the association peak might be driven by a different nearby gene entirely. 因为一个候选基因坐落在某个 GWAS 信号附近还不够——那个关联峰可能完全是由附近另一个不同的基因驱动的。 Colocalization tests whether the same variant that changes the trait is also the one that changes the candidate gene's expression, which is the evidence that ties the locus to that specific gene. 共定位检验的是:那个改变性状的变异,是否也正是改变该候选基因表达量的变异,而这正是把位点系到那个特定基因上的证据。

JORDAN What would we need to verify before believing any candidate on this list? 在相信这份清单上的任何候选基因之前,我们需要核实什么?
