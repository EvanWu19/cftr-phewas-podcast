Ep3 — Automated standardization and harmonization of laboratory units in large-scale clinical data using open-source R functions

Zayed AM, Sarikakis I, Delvaux N (2025), International Journal of Medical Informatics. Abstract-only — genuinely closed access, no PMCID on record. Two open-source R functions for cleaning lab-result units at scale: one standardizes messy free-text unit strings to valid UCUM codes (deterministic mapping + rule-based correction, no ML), the other harmonizes UCUM-valid units and values to a single reference unit within each LOINC group. Applied to 163.9 million LOINC-mapped results from the Belgian Intego-II primary-care database, standardization cut 2,019 distinct raw unit strings down to 381 UCUM-valid codes (96.2% of records standardized, 99.97% verified correctness) and harmonization converted 83.4% of those to reference units, also correcting LOINC property inconsistencies in 2.8 million records and improving distributional characteristics in up to 23% of LOINC groups. The paper is about lab data broadly, not anthropometrics — this episode's transfer to height/weight cm/inch and kg/lb errors is the podcast's own framing, not a finding in the paper. The buildable idea: a unit-standardization pre-check layer that runs before any outlier model sees a height/weight value, catching a distinct error class a biological-plausibility check alone would likely miss.

Plain-English glossary

  • UCUM (Unified Code for Units of Measure) — A machine-readable standard giving every unit of measurement one unambiguous code, so "cm," "CM," and "centimeter" all resolve to the same thing.（中文：一种机器可读标准，为每种计量单位赋予唯一编码，使"cm"、"CM"、"centimeter"都能解析为同一单位。）
  • LOINC (Logical Observation Identifiers Names and Codes) — The standard vocabulary giving each specific lab test or clinical measurement a unique identifier, independent of the source lab or EHR system.（中文：为每种检验项目或临床测量赋予唯一标识符的标准词汇表，与产生结果的实验室或系统无关。）
  • Reference unit — The single designated SI or Conventional unit that all results within a LOINC group are converted to during harmonization, so every source system's results become directly comparable.（中文：协调统一过程中，某LOINC分组内所有结果被统一转换成的单一指定SI或常规单位，使不同来源系统的结果可直接比较。）
  • Dimensional mismatch — When a recorded unit measures a fundamentally different physical quantity than expected for that test (e.g. a concentration unit where a mass unit was expected), making conversion to a reference unit impossible without additional information.（中文：记录的单位与该检验项目预期测量的物理量种类不同（如本应是质量单位却记为浓度单位），导致无法在不补充信息的情况下转换为参考单位。）

Full citation

Methods / tools to lift

  • Deterministic mapping + rule-based correction (no ML) for unit-string standardization — a controlled, auditable pipeline rather than a learned model, well-suited to a small known vocabulary like height/weight units.
  • Two-stage separation of standardization and harmonization — first get to a valid coded unit, then separately convert to one reference unit; keeps the "is this parseable at all" question distinct from "does this need a numeric conversion."
  • Validation against an external authority (UCUM web service / API) — every standardized unit and every numeric conversion checked against an independent source rather than only internal consistency.

Where it lands + buildable artifact

Pipeline stage: (a) candidate generation, primary — this operates entirely upstream of any residual-based outlier model, catching a class of error (wrong unit, silently plausible-looking value) that a biological-plausibility check alone would likely miss.

MVP: standardize every incoming height/weight record's unit string to a small controlled vocabulary (cm, in, kg, lb and common misspellings) via deterministic mapping + rule-based correction, convert to one reference unit, and flag any record that fails standardization or triggers an implausible-magnitude numeric conversion as its own distinct error category, separate from and prior to biological-implausibility flagging. Difficulty: S.

What to verify first

  • Whether the free-text-entry failure modes this paper describes for lab results are the same mechanism that produces anthropometric unit errors, given height/weight fields are often structured numeric entry rather than free text.
  • The actual rule-based correction logic (not just headline percentages) before calibrating how conservative an anthropometric-specific version should be — over-aggressive auto-correction risks silently "fixing" a value that was actually correct.
  • What happens downstream to the ~3.8% standardization failures and 16.6% unharmonized residual cases — flagged for review, dropped, or something else is not stated in the abstract.

Error types covered / not covered

Covered: unit-string heterogeneity/typos (deterministic mapping), unit-to-value numeric conversion errors, LOINC-property-vs-unit inconsistency.

Not covered: decimal-shift errors, digit transposition, carry-forward/duplicate values, real-clinical-event vs. data-entry-error confusion — none of these are addressed by a unit-standardization layer; this is a strictly upstream, narrow-scope check.
