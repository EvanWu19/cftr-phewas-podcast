Blurb

Johnson and colleagues (2025, BMJ Open Gastroenterology) built an LLM-based pipeline to extract colorectal dysplasia and adenocarcinoma diagnoses from colonoscopy pathology reports across the VA's Corporate Data Warehouse (15.2M patients) and Million Veteran Program cohort (913,318 patients), using small open-weight models — Gemma-2-9B and Llama-3-8B, run locally via llama.cpp in GGUF format inside the VA's secure VINCI environment — with zero task-specific fine-tuning. Against blinded human chart review (Cohen's kappa 89–97% across tasks), calibrated F1 scores reached 98.6–99.3% for IBD-cohort tasks and matched or beat decades of hospital-specific rule-based NLP development, including on the harder, more realistic full-pathology-report generalizability test (F1 86.7–97.1%). The buildable artifact: package the same harness — regex pre-filter, frozen yes/no prompts, a local GGUF model via llama.cpp, and the calibrated-F1 evaluation method — into a reusable, registry-adjacent diagnostic-extraction tool, tested first against a public clinical-text corpus.

Plain-English glossary

  • Adenoma — a benign glandular polyp that can itself harbor dysplasia.（中文：一种良性腺性息肉，其内部本身也可能含有异型增生。）
  • Calibrated F1 score (F1c) — a variant of the F1 score corrected for the positive class's prevalence, so tasks with very different base rates (e.g. a rare finding like IND) can be compared fairly.（中文：对正类发生率进行校正后的F1分数，使得基础发生率差异很大的任务（例如像IND这样的罕见发现）之间也能进行公平比较。）
  • Dysplasia (low-grade / high-grade) — abnormal, pre-cancerous cell growth, graded by severity; "indefinite for dysplasia" (IND) is a category for IBD cases ambiguous between reactive inflammation and true dysplasia.（中文：异常的、癌前病变性的细胞生长，按严重程度分级；"不确定性异型增生"（IND）用于IBD病例中介于反应性炎症和真正异型增生之间难以判断的情形。）
  • GGUF — a file format bundling a model's architecture, weights, tokenizer, and metadata into a single file, used by the llama.cpp inference engine.（中文：一种将模型架构、权重、分词器和元数据打包进单个文件的格式，供llama.cpp推理引擎使用。）
  • llama.cpp — a lightweight, open-source C++ inference engine for running LLMs locally without a GPU-heavy framework.（中文：一个轻量级的开源C++推理引擎，可在本地运行大语言模型，不依赖庞大的GPU框架。）
  • Open-weight model — a model whose trained parameters are publicly downloadable and can be run locally, as opposed to a closed, API-only proprietary model.（中文：训练好的参数可公开下载、可在本地运行的模型，与封闭的、仅通过API访问的专有模型相对。）
  • Quantization — storing a model's weights at reduced numerical precision (e.g. 8-bit instead of 16-bit) to shrink file size and memory footprint, at some cost to accuracy.（中文：以更低的数值精度（例如8比特而非16比特）存储模型权重，以缩小文件体积和内存占用，但会在一定程度上牺牲准确率。）

Full citation

Johnson, et al. (2025). Large language models for extracting histopathologic diagnoses of colorectal cancer and dysplasia from electronic health records. BMJ Open Gastroenterology. PMID: 40973184 | PMC: PMC12458811 | DOI: 10.1136/bmjgast-2025-001896

Methods / tools to lift

  • llama.cpp + GGUF — lightweight local inference stack for open-weight LLMs, no GPU-framework dependency required.
  • Gemma-2-9B-It-SPPO / Llama-3-8B-Instruct — the two main open-weight models benchmarked, run at FP16.
  • Regex pre-filter — a cheap first-pass filter on location + histology terms to cut report volume before LLM inference.
  • Calibrated F1 (Siblini et al. method) — corrects F1/precision for a reference positive-class ratio, enabling fair comparison across tasks of very different prevalence.
  • Blinded multi-reviewer chart review + Cohen's kappa — the validation design against which the LLM pipeline was benchmarked.

Where it lands + buildable artifact

Serves AI-tooling / career positioning. Tool sketch: a reusable open-weight diagnostic-extraction harness — llama.cpp + a GGUF Gemma-2/Llama-3 model, a yes/no-prompt template system, and the calibrated-F1 evaluation code — benchmarked first against a public clinical-text corpus (e.g. de-identified MIMIC-IV-style notes) before pointing it at any registry-adjacent extraction task. Difficulty: M.

What to verify first

  • Generalization beyond the VA's own reporting conventions — all validation here stayed inside VA data, so performance on a genuinely different institution's report style is untested.
  • Whether a prompt frozen on just 48 development reports surfaces new edge cases on a different text style.
  • The choice of reference positive-class ratio (π0) for calibrated F1 — it should be re-justified for any new task, not inherited from this paper's setting.

ALEX Track B today is Johnson and colleagues, 2025, in BMJ Open Gastroenterology — PMID 40973184, PMCID PMC12458811, DOI 10.1136/bmjgast-2025-001896. Track B今天读的是Johnson及同事2025年发表在《BMJ Open Gastroenterology》上的论文——PMID 40973184，PMCID PMC12458811，DOI 10.1136/bmjgast-2025-001896。 This is a paper that ships code and runs entirely on open-weight models small enough to fit on a single GPU, which is exactly the tool-development lens this track is built for. 这是一篇附带代码、完全运行在小到单张GPU就能承载的开源权重模型上的论文，正好契合这个栏目"工具开发视角"的定位。

JORDAN What are they actually extracting? 他们具体要提取的是什么？

ALEX Histopathologic diagnoses from colonoscopy pathology reports — specifically, whether a report documents dysplasia, high-grade dysplasia or adenocarcinoma together as HGD/CRC, or invasive adenocarcinoma, CRC, on its own. 从结肠镜病理报告中提取组织病理学诊断——具体来说，是报告中是否记录了异型增生（dysplasia）、高级别异型增生或腺癌合并计为HGD/CRC，或单独的浸润性腺癌（即CRC）。 Let's get the clinical vocabulary straight first, since it matters for the results later. 我们先把临床术语理清楚，因为这对后面理解结果很重要。 Dysplasia is abnormal, pre-cancerous cell growth, graded low or high; an adenoma is a benign glandular polyp that can itself harbor dysplasia; adenocarcinoma is invasive cancer arising from glandular tissue. 异型增生是异常的、癌前病变性的细胞生长，分为低级别和高级别；腺瘤是一种良性腺性息肉，其内部本身也可能含有异型增生；腺癌则是源自腺体组织的浸润性癌。 In patients with inflammatory bowel disease, IBD, pathologists also use a category called indefinite for dysplasia, or IND, for cases that are ambiguous between reactive inflammatory change and true dysplasia — and historically there's an older term, dysplasia-associated lesion or mass, DALM, that still shows up in IBD pathology reports. 在炎症性肠病（inflammatory bowel disease，IBD）患者中，病理医生还会使用一个叫"不确定性异型增生"（indefinite for dysplasia，IND）的分类，用于介于反应性炎症改变和真正异型增生之间难以判断的病例——而且历史上还有一个旧术语，叫异型增生相关病变或肿块（dysplasia-associated lesion or mass，DALM），至今仍会出现在IBD病理报告中。 These grading distinctions directly drive surveillance colonoscopy intervals — guidelines recommend anywhere from one to ten years for the general population, tighter, one to five years, for IBD patients — so getting the grade right in a structured dataset isn't just an NLP exercise, it's the thing risk-stratification models are actually built on. 这些分级区分直接决定了随访结肠镜检查的间隔——指南对普通人群建议一到十年不等，对IBD患者则更紧，一到五年——所以在结构化数据集中把分级提取准确，不仅是一项NLP练习，更是风险分层模型真正赖以建立的基础。

JORDAN So before LLMs, how was this data extracted at scale? 那在LLM出现之前，这类数据是如何大规模提取的？

ALEX Rule-based NLP — pattern-matching systems that enumerate every way a diagnosis could be phrased, handle negation explicitly, and tie terms to anatomical location. 基于规则的NLP——通过枚举诊断可能出现的每一种表述方式、显式处理否定表达、并将术语与解剖位置绑定的模式匹配系统。 These systems hit F1-scores above 99% for common findings like adenoma in general-population cohorts, which sounds great, but the catch is that every one of those rules is tailored to a specific hospital's reporting style, specific cohort, specific time period. 这类系统在普通人群队列中，对诊断腺瘤这种常见发现可以达到99%以上的F1分数，听起来很棒，但问题在于，每一条规则都是针对特定医院的报告风格、特定队列、特定时间段量身定制的。 Port it to a new site, or a different population like IBD patients — who use different terminology, including that DALM term, and have far more cases where the pathologist explicitly rules out dysplasia rather than simply omitting it — and the rules largely break. 一旦移植到新的机构，或者像IBD患者这样不同的人群——他们使用不同的术语（包括那个DALM术语），而且病理医生明确排除异型增生而非简单不提的情况要多得多——这些规则大多就会失效。 That's the exact adaptability gap the authors are targeting with an LLM-based approach instead. 这正是作者想用基于LLM的方法来弥补的适配性缺口。

JORDAN What did they actually build, and what's the infrastructure? 他们到底搭建了什么，基础设施是什么样的？

ALEX The pipeline has two stages. 这个流程分为两个阶段。 First, a cheap regex-based filter scans every colonoscopy pathology report for colorectal-location terms and dysplasia- or neoplasia-related histology terms, just to cut the volume down to a "plausible set" before anything expensive happens. 第一阶段，一个廉价的基于正则表达式的过滤器扫描每一份结肠镜病理报告，寻找结直肠部位术语和与异型增生或肿瘤相关的组织学术语，仅仅是为了在进行任何昂贵操作之前先把数据量缩减到一个"可能相关集合"。 Second, the filtered Microscopic Exam section — or, in a separate generalizability test, the full pathology report — gets fed into an LLM with a yes-or-no prompt, one prompt per diagnostic concept: any dysplasia, HGD/CRC, CRC, and for IBD patients, IND. 第二阶段，经过过滤的"镜下检查"（Microscopic Exam）部分——或者在另一项通用性测试中，完整的病理报告——会被输入LLM，并配以一个是/否问题，每个诊断概念对应一个提示词：是否有任何异型增生、HGD/CRC、CRC，以及针对IBD患者的IND。 The main model is Gemma-2-9B-It-SPPO, nine billion parameters, with Llama-3-8B-Instruct, eight billion parameters, run in parallel for comparison; they also tried quantized, smaller Llama-3.2-3B and Gemma-2-2B for a scaling comparison. 主模型是Gemma-2-9B-It-SPPO，九十亿参数，并行运行Llama-3-8B-Instruct，八十亿参数作对比；他们还尝试了量化、更小的Llama-3.2-3B和Gemma-2-2B用于规模对比。 All models run as GGUF files — a packaging format that bundles architecture, weights, tokenizer, and metadata into one file — through llama.cpp, a lightweight C++ inference engine, inside VINCI, the VA's secure compute workspace, so nothing ever leaves VA infrastructure and nothing gets sent to a third-party API. 所有模型都以GGUF文件格式运行——这是一种把架构、权重、分词器和元数据打包进单个文件的封装格式——通过llama.cpp（一个轻量级的C++推理引擎）运行，运行环境是VINCI，即VA的安全计算工作区，因此数据从未离开VA的基础设施，也不会被发送给任何第三方API。 The data itself is the VA's Corporate Data Warehouse, 15.2 million patients and roughly 6.2 billion notes, plus the Million Veteran Program cohort of over 913,000 genetically-consented veterans — genuinely registry-scale. 数据本身来自VA的企业数据仓库（Corporate Data Warehouse），涵盖1520万患者、约62亿份记录，再加上超过91.3万名已签署遗传学知情同意的"百万退伍军人计划"（Million Veteran Program）队列——真正的注册库规模。

ALEX Here's the design choice I'd push back on. 这里有一个设计选择，我想提出质疑。 Prompts were developed on just 48 manually reviewed reports before being frozen and applied at scale — that's a tiny development set for something meant to generalize across both IBD and non-IBD populations and four separate diagnostic concepts. 提示词是在仅仅48份人工审核的报告上开发出来的，然后就被冻结并大规模应用——对于一个要在IBD和非IBD两种人群、四个不同诊断概念上都具备泛化能力的东西来说，这个开发集的规模实在太小了。 They partly address this by validating on a completely separate corpus using blinded human chart review, which is the right instinct, but the prompt-development stage itself is still thin. 他们部分地通过在一个完全独立的语料库上进行盲法人工病历审查来验证，弥补了这一点，这个直觉是对的，但提示词开发阶段本身仍然比较薄弱。

JORDAN How did they actually validate it, then? 那他们实际是怎么验证的？

ALEX Two independent, blinded human reviewers chart-reviewed randomly selected putative-positive and putative-negative cases for each task — 100 of each from the Corporate Data Warehouse, 150 of each from the Million Veteran Program — with disagreements resolved by a third, and if needed a fourth, blinded reviewer. 两名独立的盲法人工审查员对每个任务随机抽取的疑似阳性和疑似阴性病例进行病历审查——企业数据仓库每类100份，百万退伍军人计划队列每类150份——分歧由第三名、必要时第四名盲法审查员裁定。 Inter-reviewer agreement, measured by Cohen's kappa, ranged 89 to 97% across the three main tasks, and 78.1 to 93.1% for the harder IND category, out of 3,816 total reviewed reports with fewer than 4% disagreements. 以Cohen's kappa衡量的审查员间一致性，在三个主要任务上为89%到97%，在更难判断的IND分类上为78.1%到93.1%，在总共3816份被审查报告中，分歧率低于4%。 They also report a calibrated F1 score, which corrects standard F1 for the fact that precision depends heavily on how rare the positive class is — IND, for instance, is a rare finding in the filtered set, so raw precision would look artificially low without that correction. 他们还报告了一个校准F1分数（calibrated F1 score），用以纠正标准F1分数对正类稀有程度的依赖——例如IND在经过过滤的数据集中是一个罕见发现，如果不做这个校正，原始精确率看起来会人为地偏低。

JORDAN Give me the actual numbers. 具体数字是多少？

ALEX Using Gemma-2 on IBD patients, the calibrated F1 for IND was 98.6%, 95% confidence interval 96.9 to 99.8%, in the MVP cohort, and 95.6%, CI 93.0 to 98.9%, in CDW. 在IBD患者中使用Gemma-2，IND的校准F1分数在MVP队列中为98.6%，95%置信区间为96.9%到99.8%，在CDW队列中为95.6%，置信区间为93.0%到98.9%。 The best-performing task overall was CRC detection in MVP, calibrated F1 of 99.3%, CI 98.7 to 99.8%. 整体表现最好的任务是在MVP队列中检测CRC，校准F1分数为99.3%，置信区间为98.7%到99.8%。 In non-IBD patients, F1 for plain dysplasia detection hit about 99% with both Gemma-2 and Llama-3; HGD/CRC exceeded 96%, and CRC exceeded 95%, using Gemma-2. 在非IBD患者中，单纯异型增生检测的F1分数在Gemma-2和Llama-3上均达到约99%；使用Gemma-2时，HGD/CRC超过96%，CRC超过95%。 When they fed entire full-text pathology reports instead of just the filtered Microscopic Exam section — the harder, more realistic generalizability test — performance dropped somewhat but stayed strong: F1 of 97.1%, CI 93.5 to 100%, for any dysplasia in IBD, down to 86.7%, CI 78.6 to 94.6%, for the hardest task, HGD/CRC. 当他们改用完整的病理报告全文而不是经过过滤的镜下检查部分时——这是更难、更贴近实际的通用性测试——表现有所下降但仍然强劲：IBD中任何异型增生的F1分数为97.1%，置信区间93.5%到100%，最难的任务HGD/CRC则降到86.7%，置信区间78.6%到94.6%。 Both models stayed within their 8,192-token context window on every report; the smaller 2–3 billion parameter models were consistently less accurate across all four tasks. 两个模型在每份报告上都没有超出8192个token的上下文窗口；而更小的、20到30亿参数的模型在所有四个任务上的准确率都持续较低。

JORDAN You mentioned quantization for the smaller models — what's actually happening there? 你提到了小模型用到了量化（quantization）——这具体是在做什么？

ALEX Quantization stores a model's weights at reduced numerical precision — think 8-bit integers instead of 16-bit floating point — which shrinks the file size and memory footprint substantially, at some cost to accuracy. 量化是把模型的权重以更低的数值精度存储——比如用8比特整数代替16比特浮点数——这会大幅缩小文件体积和内存占用，但会在一定程度上牺牲准确率。 The two main models, Gemma-2-9B and Llama-3-8B, ran at full FP16 precision; the smaller Llama-3.2-3B and Gemma-2-2B were quantized to Q8_0, specifically to make them small enough to upload into VINCI's secured environment at all. 两个主模型Gemma-2-9B和Llama-3-8B以完整的FP16精度运行；而更小的Llama-3.2-3B和Gemma-2-2B被量化到Q8_0精度，正是为了让它们小到能够上传进VINCI这个受限安全环境中。 That infrastructure constraint is itself worth noting for anyone planning a similar on-prem deployment: model size isn't just a compute-cost decision, it can be a hard gate on what a secure research environment will even accept. 这个基础设施限制本身值得注意：模型大小不仅是计算成本上的权衡，在某些安全研究环境中，它甚至可能是能否被接受的硬性门槛。

JORDAN Why does running entirely on-prem matter so much here? 为什么完全在本地运行这件事这么重要？

ALEX Because none of this data — VA patient records — is allowed to leave VA infrastructure, and a model that needs no fine-tuning also carries no risk of memorizing or leaking patient information back out through its weights. 因为所有这些数据——VA患者记录——都不允许离开VA的基础设施，而一个不需要微调的模型，也不存在通过其权重"记住"或泄露患者信息的风险。 That's a very different risk profile from calling a third-party API, and it's exactly the kind of constraint any CFF-registry-adjacent extraction task would also have to satisfy, independent of what specific extraction task it is. 这与调用第三方API的风险状况截然不同，而这正是任何与CFF注册库相关的提取任务同样必须满足的那类约束，无论具体提取任务是什么。

JORDAN And how does that stack up against the historical rule-based benchmarks? 这和历史上基于规则的基准相比如何？

ALEX Favorably. 非常有利。 The closest apples-to-apples comparison is dysplasia detection in non-IBD patients, where Gemma-2 and Llama-3 both scored F1 of 99.2%, essentially matching or beating published rule-based results like Bae et al.'s 99% and Nayor et al.'s 100% for identifying adenoma — but without the months of rule-engineering those systems required, and without being locked to one hospital's report formatting. 最接近的对等比较是非IBD患者的异型增生检测，Gemma-2和Llama-3都取得了99.2%的F1分数，基本达到或超过了已发表的基于规则结果，例如Bae等人报告的99%和Nayor等人报告的100%（针对腺瘤检测）——但却不需要那些系统所需的数月规则工程，也不会被锁定在某一家医院的报告格式上。 The authors also point out that Gemma-2-9b-it, released June 2024, generally outperforms GPT-4, released a year earlier in June 2023 — a nine-billion-parameter open-weight model beating last year's best proprietary model, which is the broader trend this whole paper is riding. 作者还指出，2024年6月发布的Gemma-2-9b-it，总体上优于一年前2023年6月发布的GPT-4——一个九十亿参数的开源权重模型，击败了去年最好的专有模型，而这正是这整篇论文所顺应的更大趋势。

JORDAN So where does this land for Runyu's own priorities? 那这对Runyu自己的优先事项意味着什么？

ALEX This is squarely AI-tooling and career positioning. 这正好落在"AI工具开发/职业发展"这一优先事项上。 The transferable piece isn't the gastroenterology — it's the whole harness: a cheap regex pre-filter, a frozen yes-or-no prompt per concept, a small open-weight model run locally through llama.cpp, and a calibrated-F1 evaluation that corrects for rare positive classes. 可迁移的部分不是消化道病理学本身，而是整套工具链：一个廉价的正则表达式预过滤器、每个概念一个冻结的是/否提示词、一个通过llama.cpp本地运行的小型开源权重模型，以及一个针对稀有正类做了校正的校准F1评估方法。 The buildable artifact is a reusable open-weight diagnostic-extraction harness: package llama.cpp plus a GGUF-format Gemma-2 or Llama-3 model, a yes/no-prompt template system, and the calibrated-F1 evaluation code from Siblini et al. into one repo, then test it against a public clinical-text corpus — something like de-identified MIMIC-IV discharge or pathology-style notes — to benchmark the method itself before pointing it at any registry-adjacent extraction task. 可构建的产物是一个可复用的开源权重诊断提取工具链：把llama.cpp、GGUF格式的Gemma-2或Llama-3模型、是/否提示词模板系统，以及来自Siblini等人的校准F1评估代码打包进一个代码仓库，然后用一个公开的临床文本语料库——比如去标识化的MIMIC-IV出院记录或病理风格的笔记——对这套方法本身做基准测试，之后再将其指向任何与注册库相关的提取任务。 That's an M-difficulty build: the inference stack is mostly off-the-shelf, but prompt development and the calibrated evaluation code both need real engineering time. 这是一个M难度的构建：推理栈大部分是现成的，但提示词开发和校准评估代码都需要实际的工程投入。

JORDAN Were there any other robustness checks baked in? 还有没有其他稳健性检查？
