Ep2 — Track B — ADEpedia-on-OHDSI (Yu 2019)

A pharmacovigilance-tooling paper that ships a full open-source ETL pipeline converting the FDA's spontaneous adverse-event reporting system (FAERS) into the OHDSI common data model. The team mapped 8 of OHDSI's 39 tables from 6 FAERS source tables, standardized drug names to RxNorm and adverse-event terms to SNOMED CT, and loaded 4.6 million adverse-event cases. Drug-name mapping hit 93.94% of records but only 47% of unique name strings; a manual accuracy check on 500 mappings found ~97% agreement between annotators. Information loss stayed under 1% for most fields except route-of-administration, which lost 34% — a direct reflection of how poorly FAERS itself standardizes that field. A replication study on triptan vascular safety signals found the CDM-based version detected slightly more positive signals than raw FAERS, because standardized names retrieved more complete matching record sets. This isn't a CF paper, but the ETL-to-common-data-model pattern is a direct blueprint for the AI-tooling/career track — the buildable artifact is a small mapping probe against generic registry fields using the public OHDSI vocabulary, not CFFPR data itself.

Plain-English glossary

Common data model (CDM) — A shared logical table structure that different source datasets get mapped into, so the same analytic query can run across all of them.（中文:不同来源数据集统一映射进入的共享逻辑表结构,使同一条分析查询能在所有数据集上运行。）

ETL (extraction, transformation, loading) — The process of pulling data from a source system, converting it into a target structure, and loading it into the destination database.（中文:从源系统抽取数据、转换为目标结构、再载入目标数据库的过程。）

FAERS — The FDA Adverse Event Reporting System, a spontaneous reporting system where clinicians, pharmacists, and patients voluntarily submit suspected drug side-effect reports.（中文:FDA不良事件报告系统,一个由临床医生、药剂师和患者自愿提交疑似药物副作用报告的自发报告系统。）

MedDRA — A standardized medical terminology for adverse events, organized into five hierarchical levels from System Organ Class down to Lowest Level Term.（中文:用于不良事件的标准化医学术语体系,分为从系统器官分类到最低位术语共五个层级。）

OHDSI — Observational Health Data Sciences and Informatics, the open-source multi-stakeholder collaboration behind the OMOP common data model.（中文:观察性健康数据科学与信息学联盟,OMOP通用数据模型背后的多方参与开源协作组织。）

Reporting odds ratio (ROR) — The standard disproportionality statistic in pharmacovigilance, comparing how often an adverse event co-occurs with a drug versus how often it occurs without it.（中文:药物警戒领域标准的不成比例性统计量,比较某不良事件在使用某药物时与不使用时的发生比例。）

RxNorm — The standard OHDSI vocabulary for normalizing drug names to a shared set of concepts.（中文:OHDSI用于将药物名称归一化为统一概念集的标准词汇表。）

SNOMED CT — The standard OHDSI vocabulary for normalizing clinical concepts like conditions and outcomes.（中文:OHDSI用于将疾病、结局等临床概念归一化的标准词汇表。）

Full citation

Yu Y, et al. (2019). ADEpedia-on-OHDSI: A Next Generation Pharmacovigilance Signal Detection Platform Using the OHDSI Common Data Model. Journal of Biomedical Informatics. PMID: 30738946 | PMC6432939 | DOI: 10.1016/j.jbi.2019.103119

Methods / tools to lift

  • Structure-mapping-then-field-mapping ETL process: choose target CDM tables first, then map individual fields.
  • Dictionary-lookup drug-name normalization to RxNorm, checking non-standard names against the FDA Orange Book before giving up.
  • Manual-verification protocol for mapping accuracy: random sample, two independent annotators, inter-rater agreement statistic.
  • Replication study design as an ETL-validation method: rerun a known published analysis on both the raw and converted data and compare.

Where it lands + buildable artifact

Serves the AI-tooling / career track. Buildable: registry-omop-mapping-probe (S) — take a handful of generic registry-style demographic/encounter fields, draft a candidate OMOP CDM table-and-field mapping plus concept_id lookups against the public OHDSI Athena vocabulary browser, following this paper's structure-then-field mapping process. Input: field names + example values. Output: draft mapping table + notes on which fields hit clean matches.

What to verify first

  • Whether a given field's information loss reflects genuine mapping difficulty or just poor standardization in the source system (route-of-administration here lost 34% for the latter reason).
  • Whether the replication study's positive result (one drug class, one safety question) generalizes to other kinds of downstream analysis.
  • No claims made here about CFFPR's actual data structure or mapping needs — this is entirely about which external ETL pattern is worth prototyping first.
