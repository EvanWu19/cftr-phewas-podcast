Track B — Extending an Open-Source Tool to Measure Data Quality: Case Report on OHDSI

Blurb

Dixon, Wen, French, Gibson, and Grannis (Regenstrief Institute / Indiana University, BMJ Health Care Informatics, 2020) document a real, merged-into-production case study of extending OHDSI's ATLAS analytics platform with three new data-quality metrics — completeness, timeliness, and information entropy of a categorical field — operationalizing the Kahn data-quality framework's conformance/completeness/plausibility triad. Tested against 9,014,601 emergency department encounters from 124 Indiana hospitals (2011–2014), completeness and entropy were adopted into ATLAS/WebAPI 2.3+ and now run as standard reports for any OHDSI cohort analysis; timeliness was rejected by the OHDSI community because, once data lands via a fixed-interval batch ETL, the metric collapses into an uninformative linear trend that can't detect a broken feed. The paper is as much a case study in open-source governance — working-group review, conference-call approval, GitHub merge — as it is a technical one. Buildable artifact: registry-quality-probe, a standalone completeness/entropy audit module (M-difficulty) serving the AI-tooling/career track, with a direct secondary relevance to Liz's registry-QC scope as an upstream field-level audit layer.

Plain-English glossary

  • OHDSI (Observational Health Data Sciences and Informatics) — a multistakeholder collaborative building open-source tools to standardize observational health data for large-scale analytics.（中文：一个跨学术界、产业界与政府部门的协作组织,构建开源工具将观察性健康数据标准化以支持大规模分析。）
  • OMOP CDM (Common Data Model) — the shared schema that different health systems' EHR data is transformed into, so the same analytic code runs unmodified across institutions.（中文：一套共享的数据结构规范,不同医疗系统的电子病历数据被转换为该格式后,同一套分析代码即可跨机构复用。）
  • ATLAS — OHDSI's unified web interface for querying, characterizing, and reporting on CDM-formatted data, built on an extensible WebAPI layer.（中文：OHDSI用于查询、刻画和报告CDM格式数据的统一网页界面,建立在可扩展的WebAPI层之上。）
  • Kahn framework — a generic data-quality framework organized around conformance (matches expected format), completeness (data present where expected), and plausibility (value is believable given clinical/biological constraints).（中文：一套通用数据质量框架,围绕一致性（符合预期格式）、完整性（该有数据处确有数据）和合理性（在临床/生物学约束下该值可信）三方面组织。）
  • ACHILLES — OHDSI's existing database-profiling and characterization tool, which this paper's contribution extends rather than replaces.（中文：OHDSI现有的数据库画像与特征刻画工具,本文的贡献是在其基础上扩展,而非取代它。）
  • Information entropy (applied here) — a measure of variability or "surprise" in a categorical data field's distribution over time; used here to monitor drift in a hospital's reported chief-complaint categories, potentially signaling an emerging health event.（中文：衡量分类数据字段取值分布随时间变化的变异性或"意外程度";本文用它监测医院上报主诉类别的漂移,可能预示新发健康事件。）

Methods / tools to lift

  • Completeness metric — proportion of patients with a non-missing value per field, visualized stratified by age group.
  • Information-entropy metric — Shannon entropy of a categorical field (chief complaint) tracked as a time series, for drift monitoring.
  • The governance pattern itself — working-group proposal, community review, GitHub merge — as a template for shipping a data-quality feature that outlives the original project.

Where it lands + buildable artifact

Serves AI-tooling / career (Track B's primary lane), with direct secondary relevance to Liz / CFFPR data quality (method only) as an upstream, pre-outlier-detection field-level audit layer. Tool sketch: registry-quality-probe — a standalone module (not tied to any specific registry's internals) that computes per-field completeness percentages and per-categorical-field Shannon entropy trends over time against synthetic or de-identified registry-shaped data, following the Kahn framework's conformance/completeness/plausibility structure. Difficulty: M.

What to verify first

  • How well an entropy-of-categories approach transfers from a free-text-derived field (chief complaint) to structured numeric fields like anthropometric measurements, where "entropy of a value distribution" means something different from "entropy of a coded category."
  • Whether a binary present/missing completeness metric is the right granularity for a registry context, or whether plausibility needs to be folded in alongside completeness.
  • This paper says nothing about CFFPR's own current completeness rates, entropy patterns, or existing data-quality tooling — not assumed either way.
