Track B — Breaking data silos: incorporating the DICOM imaging standard into the OMOP CDM to enable multimodal research

Blurb

Park and colleagues (JAMIA, 2025), from the OHDSI Medical Imaging Workgroup, close a long-standing gap between structured EHR data and medical imaging: DICOM-format images live in a separate PACS/VNA system, disconnected from the OMOP Common Data Model researchers already use for everything else, so a "Brain MRI" order tells you nothing about the actual acquisition protocol that determines whether an image is usable for a given research question. The team parsed DICOM's own specification (Parts 3, 6, 16), converted its Attributes and coded values into 16,958 new custom OMOP concepts, and validated the pipeline on real data from ADNI (the Alzheimer's Disease Neuroimaging Initiative) — ingesting 545 imaging studies and defining a 252-patient cohort of T1-weighted volumetric MRI scans directly through OHDSI's point-and-click ATLAS tool. Code is public on GitHub. The transferable idea for the AI-tooling/career track isn't DICOM itself, it's the pattern: extract an external domain's structured vocabulary, mint custom OMOP concept IDs, build "Maps to"/"Maps to value" relationships, and validate on one real cohort. Buildable artifact: omop-genomic-vocab-extension, applying the same recipe to a genomic-annotation vocabulary (e.g. ClinVar review tiers or VCF INFO-field conventions) that doesn't yet live inside OMOP.

Plain-English glossary

  • DICOM (Digital Imaging and Communications in Medicine) — the international standard defining how medical images and their metadata are structured, stored, and exchanged.（中文:国际通用标准,定义医学影像及其元数据应如何组织、存储和交换。）
  • OMOP CDM (Observational Medical Outcomes Partnership Common Data Model) — the OHDSI-maintained data standard that harmonizes EHR/claims data across institutions into a shared table structure and vocabulary.（中文:OHDSI社区维护的数据标准,将不同机构的电子健康记录/理赔数据统一为共享表结构和词汇体系。）
  • OHDSI (Observational Health Data Science and Informatics) — the international community that develops and maintains OMOP CDM and its tooling.（中文:开发并维护OMOP CDM及其配套工具的国际社区。）
  • FHIR (Fast Healthcare Interoperability Resources) — a separate interoperability standard for real-time clinical data exchange between systems.（中文:另一套用于系统间实时临床数据交换的互操作性标准。）
  • ATLAS — OHDSI's web-based, point-and-click cohort-discovery tool for querying an OMOP database without writing raw SQL.（中文:OHDSI开发的基于网页的点选式队列发现工具,可在OMOP数据库上查询而无需手写SQL。）
  • PACS / VNA (Picture Archive and Communication System / Vendor Neutral Archive) — the separate systems where DICOM-format medical images are actually stored, disconnected from the structured EHR.（中文:实际存储DICOM格式医学影像的独立系统,与结构化电子健康记录相互隔离。）
  • ADNI (Alzheimer's Disease Neuroimaging Initiative) — a long-running study combining serial MRI, PET, and clinical assessment to track Alzheimer's disease progression, used here as the demonstration dataset.（中文:一项结合连续MRI、PET扫描和临床评估以追踪阿尔茨海默病进展的长期研究,本文用作演示数据集。）

Methods / tools to lift

  • Vocabulary-extension pattern — parse an external standard's own specification (attributes, tags, coded value sets), assign custom concept IDs in OMOP's reserved 2-billion+ range, and build "Maps to"/"Maps to value" relationships back to existing standard terminologies (e.g. SNOMED) where they exist.
  • MI-CDM (medical imaging extension) — two new OMOP tables, Image_occurrence (study-level) and Image_feature (granular acquisition parameters), now populated via the DICOM vocabulary.
  • Public code: extraction/transformation pipeline on GitHub (DICOM2OMOP), demonstrated end-to-end on ADNI via OHDSI ATLAS cohort definition.

Where it lands + buildable artifact

AI-tooling / career. Buildable: omop-genomic-vocab-extension (M–L) — pick one external genomic-annotation vocabulary not yet native to OMOP (ClinVar review-status/classification tiers, or VCF INFO-field conventions from a pipeline like MuSA), extract its attribute-and-value structure the way this paper parsed DICOM Parts 6/16, mint custom OMOP concept IDs, build mapping relationships to existing standard vocabularies, and validate on one public demonstration dataset — enabling genotype+phenotype cohort queries through the same ATLAS-style tooling used here for imaging.

What to verify first

  • DICOM metadata quality varies by manufacturer (same anatomical info can span up to three different Attributes) — genomic-annotation output will likewise vary by which variant caller/pipeline produced it; check cross-source consistency before trusting any single "Maps to value" mapping.
  • Custom OMOP concept IDs live in a reserved range specifically to avoid collisions with other groups' extensions — check OHDSI's own vocabulary registration process before minting new IDs.
  • The paper's own scalability caveat (manageable at ~61 metadata elements/series across a few hundred patients) may not hold at typical genomic-annotation data volumes — check expected database size before assuming this scales the same way.
  • Only one image per series was extracted (not every instance) — the approach hasn't been stress-tested at full instance-level granularity.

ALEX So here's the gap this paper is closing. 这就是这篇论文要填补的空白。Electronic health records give you structured tables — diagnoses, labs, procedures — but a huge amount of clinically valuable information sits in medical images, and those images live in a completely separate system, a PACS or VNA, speaking DICOM, disconnected from the EHR's structured world. 电子健康记录能提供结构化的表格数据——诊断、化验、操作记录——但大量具有临床价值的信息藏在医学影像里,而这些影像存放在一个完全独立的系统中,也就是PACS或VNA(图像归档和通信系统或供应商中立归档系统),使用DICOM格式,与EHR的结构化世界彼此隔绝。When a hospital's EHR says "Brain MRI," that's enough for scheduling and billing, but it tells a researcher nothing about which acquisition protocol was used — was it T1-weighted, T2-weighted, or FLAIR — information that actually determines whether that image is usable for a given research question. 当医院的EHR里写着"脑部MRI"时,这对排班和计费已经足够,但对研究者来说毫无意义,因为它完全没说清楚用的是哪种采集协议——是T1加权、T2加权还是FLAIR——而这类信息恰恰决定了这张影像能不能用于某个具体的研究问题。
